# त्रुटि कोड {#error-codes}

हर JSON त्रुटि प्रतिक्रिया का आकार एक जैसा होता है:

```json
{
  "error": "Job not found",
  "code": "NOT_FOUND",
  "requestId": "req-42"
}
```

| फ़ील्ड | हमेशा मौजूद | अर्थ |
|-------|----------------|---------|
| `error` | हाँ | मनुष्यों के पढ़ने योग्य संदेश। उपयोगकर्ताओं को दिखाना सुरक्षित है। इसे पार्स न करें। |
| `code` | हाँ | एक स्थिर, मशीन-पठनीय कोड। इसी पर शाखा बनाएँ। |
| `requestId` | हाँ | इस अनुरोध के लिए सर्वर की ID। समस्या की रिपोर्ट करते समय इसे उद्धृत करें; यह सर्वर लॉग से मेल खाती है। |
| `details` | कभी-कभी | कुछ 4xx त्रुटियों के लिए अधिक संदर्भ, जैसे सत्यापन संदेश। |

संदेश रिलीज़ के बीच बदल सकते हैं। कोड नहीं बदलते, इसलिए क्लाइंट लॉजिक `code` के आधार पर लिखें।

## HTTP स्टेटस से मिलने वाले कोड {#status-codes}

जब कोई रूट अपना कोड सेट नहीं करता, तो सर्वर स्टेटस से एक कोड निकालता है:

| HTTP स्टेटस | `code` |
|-------------|--------|
| 400 | `BAD_REQUEST` |
| 401 | `AUTH_REQUIRED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `UNPROCESSABLE_ENTITY` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` |
| 501 | `NOT_IMPLEMENTED` |
| 503 | `SERVICE_UNAVAILABLE` |
| 507 | `INSUFFICIENT_STORAGE` |

कोई भी अन्य 4xx `BAD_REQUEST` पर लौटता है, और कोई भी अन्य 5xx `INTERNAL_ERROR` पर।

कोई रूट अधिक विशिष्ट कोड सेट कर सकता है, और तब प्रतिक्रिया में वही कोड होता है। उदाहरण के लिए, जो टूल अपने AI बंडल के अभाव में नहीं चल सकता, वह फ़ीचर-विशिष्ट कोड लौटाता है। ऐसे कोड उस फ़ीचर के साथ वर्णित हैं जो उन्हें उठाता है।

## प्रमाणीकरण और पहुँच {#auth-codes}

| `code` | स्टेटस | क्या करें |
|--------|--------|------------|
| `AUTH_REQUIRED` | 401 | सेशन टोकन या API कुंजी (`si_...`) के साथ `Authorization: Bearer <token>` भेजें। |
| `FORBIDDEN` | 403 | क्रेडेंशियल मान्य है लेकिन उसके पास अनुमति नहीं है। किसी एडमिन से अनुमति माँगें। |
| `MUST_CHANGE_PASSWORD` | 403 | अन्य एंडपॉइंट कॉल करने से पहले खाते को अपना पासवर्ड बदलना होगा। सेशन टोकन के साथ `POST /api/auth/change-password` कॉल करें, फिर दोबारा प्रयास करें। |
| `USER_DISABLED` | 403 | खाता अक्षम है। किसी एडमिन को इसे फिर से सक्षम करना होगा। |
| `LOGIN_THROTTLED` | 429 | साइन-इन के बहुत अधिक असफल प्रयास हुए। दोबारा प्रयास करने से पहले प्रतीक्षा करें। |
| `VALIDATION_ERROR` | 400 | अनुरोध की बॉडी या पैरामीटर सत्यापन में विफल रहे। `details` समस्या का नाम बताता है। |

पहली बार चलाने पर बनने वाला एडमिन खाता `admin` है, जिसका पासवर्ड `admin` है, जब तक `DEFAULT_USERNAME` या `DEFAULT_PASSWORD` ने इसे न बदला हो। जब तक `SKIP_MUST_CHANGE_PASSWORD` सेट नहीं है, पासवर्ड बदलने तक उस खाते को हर कॉल पर `MUST_CHANGE_PASSWORD` मिलता है।

## जॉब {#job-codes}

विफल हुआ जॉब अपना कारण जॉब पर ही बताता है, HTTP त्रुटि में नहीं। `GET /api/v1/jobs/{jobId}` से `error.code` और `error.message` पढ़ें। देखें [प्रगति ट्रैकिंग](/hi/api/rest#progress-tracking)।

## अभी तक सूचीबद्ध नहीं {#not-yet-cataloged}

अलग-अलग फ़ीचर (उदाहरण के लिए एन्क्रिप्शन, OIDC, SCIM और टीमें) द्वारा उठाए गए कोड अभी इस पेज पर वर्णित नहीं हैं। हर एक स्थिर कोड है; किसी असूचीबद्ध कोड को अपारदर्शी मानें और उसे उसके स्टेटस के आधार पर संभालें।
