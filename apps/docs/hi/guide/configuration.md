# कॉन्फ़िगरेशन {#configuration}

सारा कॉन्फ़िगरेशन environment variables के ज़रिए किया जाता है। हर variable का एक उचित डिफ़ॉल्ट मान है, इसलिए इनमें से कोई भी सेट किए बिना SnapOtter सीधे काम करता है।

## Environment variables {#environment-variables}

### सर्वर {#server}

| Variable | डिफ़ॉल्ट | विवरण |
|---|---|---|
| `PORT` | `1349` | वह पोर्ट जिस पर सर्वर सुनता है। |
| `HOST` | `0.0.0.0` | वह IP पता जिस पर सर्वर सुनता है। bridge नेटवर्क पर (`docker run` और Compose का डिफ़ॉल्ट) `0.0.0.0` (या `::`) ही रखें, वरना published पोर्ट काम करना बंद कर देते हैं। नेटिव इंस्टॉल पर या होस्ट नेटवर्क पर चल रहे कंटेनर में, `127.0.0.1` API को नेटवर्क से दूर रखता है; रिमोट एक्सेस के लिए सामने एक reverse proxy लगाएँ। [Embedded मोड](#embedded-mode) केवल `0.0.0.0`, `::` या `127.0.0.1` के साथ काम करता है, क्योंकि इसकी स्टार्टअप जाँच `127.0.0.1` को कॉल करती है। किसी भी अन्य पते के साथ, `::1` सहित, कंटेनर को कभी शुरू हुआ नहीं माना जाता, और बाद में कोई क्रैश होने पर सर्वर को रीस्टार्ट करने की जगह कंटेनर रुक जाता है। जो कुछ भी IP पता नहीं है, `localhost` सहित, वह स्टार्टअप पर सर्वर को रोक देता है। |
| `BASE_PATH` | (खाली) | सार्वजनिक डिप्लॉयमेंट पाथ, जैसे `/snapotter`। खाली या `/` होने पर डोमेन के रूट पर सर्व होता है। रनटाइम पर लागू होता है; इमेज को दोबारा बनाने की ज़रूरत नहीं। |
| `RATE_LIMIT_PER_MIN` | `1000` | प्रति IP प्रति मिनट अधिकतम अनुरोध। रेट लिमिटिंग बंद करने के लिए 0 सेट करें। |
| `API_KEYS_RATE_LIMIT_PER_MIN` | `30` | API कुंजी प्रबंधन endpoints (सूची, बनाना, रद्द करना) पर प्रति IP प्रति मिनट अधिकतम अनुरोध। टूल कॉल के लिए उपयोग में आ रही कुंजियाँ प्रभावित नहीं होतीं। बिना सीमा के लिए `0` सेट करें। |
| `CORS_ORIGIN` | (खाली) | CORS के लिए अल्पविराम से अलग की गई अनुमत origins, या केवल same-origin के लिए खाली। |
| `LOG_LEVEL` | `info` | लॉग का विस्तार स्तर। इनमें से एक: `fatal`, `error`, `warn`, `info`, `debug`, `trace`। |
| `TRUST_PROXY` | `loopback,linklocal,uniquelocal` | कौन से peers `X-Forwarded-For` के ज़रिए क्लाइंट IP सेट कर सकते हैं। डिफ़ॉल्ट केवल प्राइवेट-नेटवर्क peer पर भरोसा करता है, इसलिए Docker नेटवर्क या LAN पर मौजूद reverse proxy पर भरोसा किया जाता है और किसी सार्वजनिक क्लाइंट के जाली header पर नहीं। `true` तभी सेट करें जब आपके नियंत्रण वाला कोई proxy सार्वजनिक पते पर सामने बैठा हो। |
| `SNAPOTTER_ANALYTICS_DEFAULT` | (सेट नहीं) | पहले रन पर पूछे जाने वाले analytics सवाल का जवाब पहले से दे देता है, ताकि किसी से पूछा न जाए। सेट न होने पर, नया instance अपने एडमिन से पूछता है और जवाब मिलने तक कुछ नहीं भेजता। `off` उसे "Anonymous Product Analytics" बंद करके शुरू करता है; `on` उसे चालू करके शुरू करता है। यह सेटिंग को केवल तब तक भरता है जब तक किसी ने कोई मान नहीं चुना हो। एक बार सेटिंग सहेज दी जाए, चाहे एडमिन द्वारा या इस variable द्वारा, तो variable बदलने से कुछ नहीं होता; एडमिन फिर भी Settings > System > Privacy में इसे बदल सकता है। |

### प्रमाणीकरण {#authentication}

नीचे के दोनों boolean केवल `true` और `false` स्वीकार करते हैं। इसके अलावा कुछ भी, `1` या `yes` या `on`, सत्यापन में विफल होता है और सर्वर सुनना शुरू करने से पहले ही बंद हो जाता है।

| Variable | डिफ़ॉल्ट | विवरण |
|---|---|---|
| `AUTH_ENABLED` | `true` | लॉगिन आवश्यक करें। इसे `false` पर सेट करने से बिना किसी खाते के चलता है, जिससे हर अनुरोध को एडमिन अधिकार मिल जाते हैं, इसलिए इसे केवल भरोसेमंद नेटवर्क तक सीमित रखें। |
| `DEFAULT_USERNAME` | `admin` | शुरुआती एडमिन खाते का उपयोगकर्ता नाम। केवल पहली बार चलाने पर उपयोग होता है। |
| `DEFAULT_PASSWORD` | `admin` | शुरुआती एडमिन खाते का पासवर्ड। पहले लॉगिन के बाद इसे बदल दें। |
| `MAX_USERS` | `0` (असीमित) | पंजीकृत उपयोगकर्ता खातों की अधिकतम संख्या। असीमित के लिए 0 सेट करें। |
| `SESSION_DURATION_HOURS` | `168` | लॉगिन सत्र की अवधि घंटों में (डिफ़ॉल्ट 7 दिन है)। |
| `SKIP_MUST_CHANGE_PASSWORD` | `false` | पहले लॉगिन पर ज़बरदस्ती पासवर्ड बदलने का प्रॉम्प्ट छोड़ने के लिए `true` पर सेट करें। |
| `LOGIN_ATTEMPT_LIMIT` | `30` | प्रति IP प्रति मिनट अधिकतम लॉगिन अनुरोध। इसके बाद के प्रयासों को मिनट पूरा होने तक `429` मिलता है। एक उपयोगकर्ता नाम की बार-बार की विफलताएँ आमतौर पर पहले `LOGIN_THROTTLE_MAX_FAILURES` तक पहुँचती हैं। एडमिन इसे सेटिंग्स > सिस्टम में बदल सकता है। बिना सीमा के लिए `0` सेट करें। सोर्स बिल्ड 10 से शुरू होता है। |
| `LOGIN_THROTTLE_MAX_FAILURES` | `10` | `LOGIN_THROTTLE_WINDOW_S` के भीतर एक उपयोगकर्ता नाम के जितने असफल पासवर्ड लॉगिन हो सकते हैं, उसके बाद उसके आगे के प्रयासों को `429` मिलता है, चाहे वे किसी भी IP से आएँ। सबसे पुरानी विफलताएँ विंडो से बाहर होते ही उन्हें फिर से अनुमति मिल जाती है। थ्रॉटल बंद करने के लिए 0 सेट करें। |
| `LOGIN_THROTTLE_WINDOW_S` | `900` | उस विंडो की लंबाई, सेकंड में। कम से कम 1 होना चाहिए; 0 पर सर्वर शुरू होने से मना कर देता है। |

### स्टोरेज {#storage}

| Variable | डिफ़ॉल्ट | विवरण |
|---|---|---|
| `STORAGE_MODE` | `local` | `local` या `s3`। S3 और MinIO के लिए s3_storage फ़ीचर वाला लाइसेंस और नीचे दिए गए `S3_*` variables चाहिए। |
| `DATABASE_URL` | `postgres://snapotter:snapotter@localhost:5432/snapotter` | PostgreSQL कनेक्शन स्ट्रिंग, और वह कनेक्शन जिस पर हर अनुरोध सर्व होता है। 2.3.0 और बाद के संस्करणों में `DATABASE_MIGRATION_URL` भी सेट करें और यह सबसे कम विशेषाधिकार वाली रनटाइम भूमिका बन जाती है, जिसके पास ऐप की तालिकाओं पर केवल DML होता है और कुछ नहीं। Compose स्टैक इसे अपनी `postgres` सेवा की ओर इंगित करता है; embedded मोड पाने के लिए इसे (`REDIS_URL` के साथ) अनसेट छोड़ दें। unix socket पर कनेक्ट करने के लिए socket डायरेक्टरी का नाम `host` में दें, जैसे `postgres://user:pass@localhost/snapotter?host=/var/run/postgresql`, और उस डायरेक्टरी को कंटेनर में माउंट करें। |
| `DATABASE_MIGRATION_URL` | (खाली) | विशेषाधिकार प्राप्त कनेक्शन, जो केवल boot के दौरान migrations चलाने और रनटाइम भूमिका को अनुमतियाँ देने के लिए उपयोग होता है, फिर पहले अनुरोध से पहले बंद हो जाता है। इसे खाली छोड़ें तो SnapOtter एकल-भूमिका में चलता है, जहाँ `DATABASE_URL` दोनों काम करता है। देखें [सबसे कम विशेषाधिकार वाली भूमिकाएँ](/hi/guide/database#least-privilege-roles)। |
| `REDIS_URL` | `redis://localhost:6379` | Redis कनेक्शन स्ट्रिंग (BullMQ जॉब कतारों के लिए उपयोग होती है)। Compose इसे अपनी `redis` सेवा की ओर इंगित करता है। unix socket के लिए `unix:///run/redis/redis.sock?db=5` का उपयोग करें (Redis को पासवर्ड चाहिए तो `&password=...` जोड़ें) और socket को कंटेनर में माउंट करें। |
| `WORKSPACE_PATH` | `./tmp/workspace` | प्रोसेसिंग के दौरान अस्थायी फ़ाइलों की डायरेक्टरी। अपने आप साफ़ हो जाती है। इमेज `/tmp/workspace` सेट करती है। |
| `FILES_STORAGE_PATH` | `./data/files` | स्थायी उपयोगकर्ता फ़ाइलों (अपलोड की गई इमेज, सहेजे गए परिणाम) की डायरेक्टरी। इमेज `/data/files` सेट करती है। |
| `MAX_STORAGE_PER_USER_MB` | `5000` | हर उपयोगकर्ता Files लाइब्रेरी में जितना रख सकता है, उसकी मेगाबाइट में सीमा। जो सेव इसे पार करेगा उसे उपयोग की गई मात्रा और सीमा के साथ अस्वीकार कर दिया जाता है। उपयोगकर्ता पर तय किया गया कोटा इसे बदल देता है। असीमित के लिए 0 सेट करें। |

### S3 ऑब्जेक्ट स्टोरेज {#s3-object-storage}

केवल तब पढ़ा जाता है जब `STORAGE_MODE=s3`। तीन ज़रूरी में से कोई भी छूट जाए तो स्टार्टअप उस variable के नाम के साथ विफल हो जाता है जिसे आपने छोड़ा।

| Variable | डिफ़ॉल्ट | विवरण |
|---|---|---|
| `S3_BUCKET` | (खाली) | वह bucket जिसमें अपलोड और आउटपुट रहते हैं। आवश्यक। |
| `S3_ACCESS_KEY_ID` | (खाली) | एक्सेस की। आवश्यक। कंटेनर में आप इसे `S3_ACCESS_KEY_ID_FILE` के ज़रिए माउंट भी कर सकते हैं। |
| `S3_SECRET_ACCESS_KEY` | (खाली) | सीक्रेट की। आवश्यक। वही फ़ाइल परिपाटी: `S3_SECRET_ACCESS_KEY_FILE`। |
| `S3_REGION` | `us-east-1` | Bucket का क्षेत्र। |
| `S3_ENDPOINT` | (खाली) | MinIO, R2, Backblaze और अन्य S3-संगत स्टोर के लिए कस्टम endpoint। खाली का अर्थ AWS है। |
| `S3_FORCE_PATH_STYLE` | `false` | MinIO और ऐसी किसी भी चीज़ के लिए `true` पर सेट करें जो virtual-host एड्रेसिंग की जगह `endpoint/bucket/key` चाहती है। |
| `S3_PREFIX` | (खाली) | Key का prefix, ताकि एक bucket में कई instances रह सकें। |

### विश्राम अवस्था में एन्क्रिप्शन {#encryption-at-rest}

| Variable | डिफ़ॉल्ट | विवरण |
|---|---|---|
| `DATA_ENCRYPTION_KEY` | (खाली) | 64 hex अक्षर (32 बाइट)। डेटाबेस में सहेजी गई संवेदनशील सेटिंग्स को एन्क्रिप्ट करता है। 64 hex अक्षरों से अलग कुछ भी स्टार्टअप पर अस्वीकार कर दिया जाता है। |
| `DATA_ENCRYPTION_KEY_PREVIOUS` | (खाली) | वह key जिसे आप बदल रहे हैं, उसी प्रारूप में। रोटेशन के दौरान दोनों सेट करें ताकि मौजूदा पंक्तियाँ अब भी डिक्रिप्ट हों, फिर इसे हटा दें। |

### Embedded मोड {#embedded-mode}

इमेज को `DATABASE_URL` और `REDIS_URL` के बिना चलाएँ और यह कंटेनर के अंदर अपना PostgreSQL 17 और Redis शुरू कर लेता है, जो loopback से बंधे होते हैं और सारा डेटा `/data` वॉल्यूम पर रहता है। यह quick start, homelab और 1.x से अपग्रेड के लिए एक-कमांड वाला `docker run` अनुभव लौटाता है। यह सुविधा का रास्ता है, प्रोडक्शन डिप्लॉयमेंट नहीं: प्रोडक्शन के लिए अलग PostgreSQL और Redis के साथ 3-कंटेनर Compose स्टैक चलाएँ। Embedded मोड के लिए कंटेनर को root के रूप में चलाना ज़रूरी है और यह मनमाने-UID वाले रनटाइम (OpenShift, Kubernetes `runAsNonRoot`) के साथ असंगत है; वहाँ Compose का उपयोग करें।

| Variable | डिफ़ॉल्ट | विवरण |
|---|---|---|
| `EMBEDDED` | `auto` | जब `DATABASE_URL` और `REDIS_URL` दोनों अनसेट हों तो अपने आप चालू हो जाता है। इसे बंद करने के लिए `0` पर सेट करें (तब ऐप चुपचाप कंटेनर के अंदर डेटाबेस शुरू करने की जगह तुरंत विफल हो जाता है यदि कोई बाहरी `DATABASE_URL`/`REDIS_URL` सेट नहीं है)। |
| `REDIS_MAXMEMORY` | `512mb` | Embedded Redis की मेमोरी सीमा (केवल embedded मोड में)। Raspberry Pi जैसे कम मेमोरी वाले होस्ट पर इसे घटाएँ। |
| `EMBEDDED_PG_PORT` | `5432` | Embedded PostgreSQL के लिए loopback पोर्ट (केवल embedded मोड में)। इसे तभी बदलें जब कंटेनर ऐसा नेटवर्क साझा करता हो जहाँ 5432 पहले से उपयोग में है, जैसे `--network host`। यह `EMBEDDED_REDIS_PORT` से अलग और 1023 से ऊपर होना चाहिए, क्योंकि PostgreSQL एक बिना विशेषाधिकार वाले उपयोगकर्ता के रूप में चलता है जो होस्ट नेटवर्क पर किसी विशेषाधिकार प्राप्त पोर्ट से bind नहीं कर सकता। |
| `EMBEDDED_REDIS_PORT` | `6379` | वही, embedded Redis के लिए, जो भी बिना विशेषाधिकार वाले उपयोगकर्ता के रूप में चलता है। |

1.x से अपग्रेड: अपनी पुरानी `snapotter.db` को वॉल्यूम में `/data/snapotter.db` पर रखें और embedded मोड पहले boot पर उसे embedded PostgreSQL में आयात कर लेता है। आयात एक बार चलता है; बाद के boot इसे छोड़ देते हैं।

Telemetry नोट: embedded मोड इमेज का analytics डिफ़ॉल्ट वैसे ही अपनाता है जैसे कोई अन्य कॉन्फ़िगरेशन। प्रकाशित इमेज analytics भेज सकती है, लेकिन नया instance पहले अपने एडमिन से पूछता है और जवाब मिलने तक कुछ नहीं भेजता। इसे बंद करने के लिए ना में जवाब दें, `--build-arg SNAPOTTER_ANALYTICS=off` के साथ बिल्ड करें, पहले boot से पहले `SNAPOTTER_ANALYTICS_DEFAULT=off` सेट करें, या ऐप में एडमिन opt-out का उपयोग करें।

| `SUBPROCESS_MEMORY_LIMIT_MB` | `0` (बंद) | इन helper प्रोसेस में से हर एक के लिए एड्रेस-स्पेस सीमा, मेगाबाइट में: मीडिया और दस्तावेज़ इंजन में ffmpeg, ffprobe, Ghostscript, qpdf, LibreOffice, pandoc और pdfcpu, साथ ही इमेज के लिए exiftool, HEIF, JPEG XL और JPEG 2000 डिकोडर और एन्कोडर, RAW डिकोडर और ffmpeg फ़ॉलबैक डिकोडर। ImageMagick सीमित नहीं है, क्योंकि उसकी अपनी मेमोरी सीमाएँ हैं, और AI sidecar भी नहीं। जो प्रोसेस इस सीमा को पार करता है उसे पूरे कंटेनर को आउट-ऑफ़-मेमोरी killer की ओर धकेलने की जगह बंद कर दिया जाता है। यह वर्चुअल मेमोरी को सीमित करता है, resident मेमोरी को नहीं, इसलिए इसे किसी प्रोसेस के असल उपयोग से काफ़ी ऊपर सेट करें। JPEG XL एन्कोडर को सबसे ज़्यादा चाहिए: 24 MP की इमेज को लगभग 1.8 GB चाहिए था और 1 GB पर वह विफल रही, और ज़्यादा threads या CPUs से इसमें ज़्यादा फ़र्क नहीं पड़ता। सीमा सेट रहने पर HEIF एन्कोडर को दो worker threads तक रखा जाता है, जिससे 24 MP का एन्कोड धीमे एन्कोड की कीमत पर लगभग 0.8 GB तक आ जाता है। `2048` से शुरू करें और इसे तभी घटाएँ जब आपने अपनी सबसे बड़ी फ़ाइलों पर जाँच कर ली हो। इसे बंद करके कंटेनर की मेमोरी सीमा पर भरोसा करने के लिए 0 सेट करें। |
| `MAX_SETTINGS_PAYLOAD_KB` | `64` | किसी टूल अनुरोध में आ सकने वाला सबसे बड़ा `settings` फ़ील्ड, किलोबाइट में, UTF-8 बाइट्स में गिना गया। सीमा से बड़े अनुरोधों को `400` मिलता है। बिना सीमा के लिए 0 सेट करें। वास्तविक टूल सेटिंग्स 64 KB से बहुत छोटी होती हैं, इसलिए इसे तभी बढ़ाएँ जब कोई क्लाइंट असामान्य रूप से बड़ी सेटिंग्स भेजता हो। |
| `MAX_SUBTITLE_SIZE_MB` | `1` | सबसे बड़ी सबटाइटल फ़ाइल (`.srt`, `.vtt`, `.ass`) जो सबटाइटल जलाएँ और सबटाइटल एम्बेड करें स्वीकार करते हैं, मेगाबाइट में। इससे बड़ी फ़ाइलों को `400` मिलता है, जिसमें फ़ाइल का आकार और सीमा बताई जाती है। बिना सीमा के लिए 0 सेट करें। फ़ीचर-लेंथ फ़िल्म की सबटाइटल फ़ाइल आमतौर पर 1 MB से काफ़ी कम होती है। |
| `MAX_METADATA_TAG_LENGTH` | `10000` | मेटाडेटा संपादित करें किसी एक टैग (कलाकार, विवरण, कीवर्ड आदि) में जो सबसे लंबा मान लिखता है, अक्षरों में। इससे लंबे मानों को `400` मिलता है, जिसमें टैग और सीमा बताई जाती है। बिना सीमा के लिए 0 सेट करें। अगर आप लंबे कैप्शन या विवरण सहेजते हैं तो इसे बढ़ाएँ। टैग के मान को `MAX_SETTINGS_PAYLOAD_KB` और ऑपरेटिंग सिस्टम की प्रति-आर्गुमेंट सीमा (Linux पर 128 KB) के भीतर भी आना चाहिए। |

### इंजन {#engines}

SnapOtter कंटेनर के अंदर `$PATH` पर हर प्रोसेसिंग binary को खोजता है, इसलिए ये खाली रहते हैं जब तक आप अपना खुद का बिल्ड माउंट न करें।

| Variable | डिफ़ॉल्ट | विवरण |
|---|---|---|
| `FFMPEG_PATH` | (खाली) | वीडियो और ऑडियो टूल के पीछे की `ffmpeg` binary का पाथ। |
| `FFPROBE_PATH` | (खाली) | `ffprobe` का पाथ, जो मीडिया फ़ाइलों को प्रोसेस होने से पहले पढ़ता है। इसे `FFMPEG_PATH` के उसी बिल्ड की ओर इंगित करें। |
| `QPDF_PATH` | (खाली) | `qpdf` का पाथ, जो PDF टूल में और अपलोड किए गए PDF जाँचने में उपयोग होता है। |
| `SOFFICE_PATH` | (खाली) | LibreOffice के `soffice` का पाथ, जो ऑफ़िस दस्तावेज़ रूपांतरण के लिए उपयोग होता है। |
| `PDFCPU_PATH` | (खाली) | `pdfcpu` का पाथ, जो कुछ PDF टूल में उपयोग होता है। |
| `GS_PATH` | (खाली) | Ghostscript के `gs` का पाथ, जो PDF टूल और PDF OCR में उपयोग होता है। |
| `PANDOC_PATH` | (खाली) | `pandoc` का पाथ, जो दस्तावेज़ रूपांतरण के लिए उपयोग होता है। |
| `SNAPOTTER_FONT_FILE` | (खाली) | वीडियो पर बनाए जाने वाले टेक्स्ट के लिए फ़ॉन्ट फ़ाइल (सबटाइटल burn करना, वीडियो वॉटरमार्क)। खाली होने पर इमेज को मिलने वाला पहला फ़ॉन्ट उपयोग होता है। |
| `SNAPOTTER_FONT_FAMILY` | (खाली) | `SNAPOTTER_FONT_FILE` का फ़ैमिली नाम। खाली का अर्थ `Sans` है। |
| `SNAPOTTER_HW_ACCEL` | (खाली) | हार्डवेयर वीडियो एन्कोडर परिवार, `nvenc` या `vaapi`। खाली होने पर सॉफ़्टवेयर से एन्कोड होता है। |

`SNAPOTTER_HW_ACCEL` के लिए उस एन्कोडर परिवार के साथ बना ffmpeg चाहिए, और इमेज के ffmpeg में दोनों में से कोई नहीं है। इमेज की अपनी binary के साथ यह सेटिंग सॉफ़्टवेयर एन्कोडिंग पर लौट जाती है और स्टार्टअप लॉग में यह बताती है। इसका उपयोग करने के लिए अपना ffmpeg बिल्ड माउंट करें, `FFMPEG_PATH` और `FFPROBE_PATH` को उसकी ओर इंगित करें, और कंटेनर को GPU डिवाइस दें। `nvenc` के लिए `NVIDIA_DRIVER_CAPABILITIES=compute,utility,video` भी सेट करें: इमेज केवल `compute,utility` माँगती है, और `video` के बिना NVIDIA रनटाइम एन्कोड लाइब्रेरी माउंट नहीं करता, इसलिए एन्कोडर सूचीबद्ध तो होता है पर हर एन्कोड विफल होता है। ऐसा पाथ ओवरराइड जो मौजूद नहीं है या executable नहीं है, वह भी स्टार्टअप लॉग में नामित होता है, और उस binary की ज़रूरत वाला हर जॉब तब तक विफल होता है जब तक आप पाथ ठीक नहीं करते या उसे अनसेट नहीं करते।

प्रकाशित Compose फ़ाइलें ये सभी `.env` से आगे पास करती हैं, इसलिए उन्हें वहीं सेट करना पर्याप्त है।

## Docker उदाहरण {#docker-example}

```yaml
services:
  SnapOtter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - SnapOtter-data:/data
      - SnapOtter-workspace:/tmp/workspace
    environment:
      - AUTH_ENABLED=true
      - DEFAULT_USERNAME=admin
      - DEFAULT_PASSWORD=changeme
      - DATABASE_URL=postgres://snapotter:snapotter@postgres:5432/snapotter
      - REDIS_URL=redis://redis:6379
      - MAX_UPLOAD_SIZE_MB=200
      - CONCURRENT_JOBS=4
      - FILE_MAX_AGE_HOURS=12
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: snapotter
      POSTGRES_PASSWORD: snapotter     # Change this for non-local deployments
      POSTGRES_DB: snapotter
    volumes:
      - SnapOtter-pgdata:/var/lib/postgresql/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U snapotter -d snapotter"]
      interval: 10s
      timeout: 5s
      retries: 12

  redis:
    image: redis:8-alpine
    command: ["redis-server", "--maxmemory-policy", "noeviction", "--appendonly", "yes"]
    volumes:
      - SnapOtter-redisdata:/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 12

volumes:
  SnapOtter-data:
  SnapOtter-workspace:
  SnapOtter-pgdata:
  SnapOtter-redisdata:
```

## वॉल्यूम {#volumes}

Docker Compose स्टैक चार वॉल्यूम का उपयोग करता है:

- `/data` (app) - AI मॉडल, Python venv और उपयोगकर्ता फ़ाइलें। रीस्टार्ट के बीच अपलोड की गई फ़ाइलें और इंस्टॉल किए गए AI bundles बनाए रखने के लिए इसे माउंट करें।
- `/tmp/workspace` (app) - प्रोसेस हो रही फ़ाइलों के लिए अस्थायी स्टोरेज। यह अस्थायी हो सकता है, लेकिन इसे माउंट करने से कंटेनर की writable layer भरने से बचती है।
- `SnapOtter-pgdata` (postgres) - PostgreSQL डेटा डायरेक्टरी। इसमें सारा रिलेशनल डेटा रहता है (उपयोगकर्ता, सेटिंग्स, pipelines, जॉब, ऑडिट लॉग)। `pg_dump` या वॉल्यूम स्नैपशॉट से बैकअप लें।
- `SnapOtter-redisdata` (redis) - टिकाऊ जॉब कतारों के लिए Redis append-only फ़ाइल।
