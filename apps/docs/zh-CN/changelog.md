# 更新日志 {#changelog}

## 未发布 {#unreleased}

### 已弃用 {#unreleased-deprecated}

- **五个图片按大小压缩操作已弃用。** `/api/v1/tools/image/compress-image-to-20kb`、`-50kb`、`-100kb`、`-200kb` 和 `-500kb` 在 OpenAPI 规范中已标记为弃用，并将至少保留一个次要版本。请发送 `POST /api/v1/tools/image/compress`，并将 `settings` 设为 `{"mode":"targetSize","targetSizeKb":20}`（或 50、100、200、500）。输出相同。PDF 预设路径不变。

## v2.3.0 {#v2-3-0}

SnapOtter 在 Docker Hub 和 GHCR 上的镜像拉取量刚刚突破一百万次，GitHub 星标也达到了 3,000 个。这意味着有大量自托管服务器在运行，所以这个版本是我们对每一位使用者的感谢。

请尽快升级。2.3.0 修复了六个安全公告，其中一个为高危。详情见下方的安全部分。

除了修复之外，还有新工具：PDF Multi-Tool 页面编辑器、图片和 PDF 的一键压缩到指定大小预设，以及 Organize PDF 中的拖放页面排序。OCR 现在可以识别阿拉伯语，pdf-to-text 在遇到扫描版 PDF 时会提供 OCR 选项。SnapOtter 可以在反向代理后运行于子路径下，例如 `/snapotter`。应用运行不再需要 Postgres 超级用户。被锁定在外的管理员可以通过命令行恢复。其余是大约 1,400 项修复，其中大部分针对的是你们报告的问题。

> [!IMPORTANT]
> 下列六个公告都影响 2.2.0，其中一些可追溯到 2.0.0。如果你与其他用户共用一个实例，或将其暴露在自己的网络之外，请升级。

### 安全 {#v2-3-0-security}

- **SVG 上传可能跳过清理（GHSA-9c7h-xjrp-8gh3，高危）。** 图片解码器拒绝的 SVG 会被原样存储和提供，而不是经过清理。受影响版本：2.2.0 及更早版本。由 @xaferima 报告。(#1211)
- **作业进度流没有检查请求者身份（GHSA-ff22-w6x2-fm98，中危）。** 现在需要登录并验证作业所有权。受影响版本：2.0.0 至 2.2.0。(#1750)
- **结果下载链接也会提供原始上传文件（GHSA-jgv3-2jc6-f628，中危）。** 受影响版本：2.2.0 及更早版本。由 @emirhancatkin 报告。(#3623)
- **证件照和背景效果信任客户端提供的作业 id（GHSA-3c8g-8v4x-qq9j，中危）。** 受影响版本：2.2.0 及更早版本。由 @shaoyuuuuu 报告。(#3623)
- **URL 导入、上传和预览跳过了角色和 API 密钥权限检查（GHSA-8xxr-g2w8-7f9r，中危）。** 受影响版本：2.2.0 及更早版本。由 @nguyenvantiennani 报告。(#3780, #707)
- **SSO 强制模式泄露了应急账户用户名（GHSA-q6fg-vvw9-cr8r，低危）。** 被拒绝的本地登录现在与其他失败登录一样返回 401。受影响版本：2.0.0 至 2.2.0。(#2148)
- **Postgres 不再以超级用户运行。** 应用现在使用只能读写数据的角色连接。迁移使用单独的可选连接。参见升级说明。(#918)
- **已修补的依赖**：dompurify 和 handlebars 的覆盖下限已提高到修复后的版本。(#4247)

### 新功能 {#v2-3-0-new-features}

- **PDF Multi-Tool**：一个页面编辑器，可以重新排序、复制、旋转和删除页面，并从其他 PDF 中提取页面。最终文件由服务器组装。(#1338)
- **一键压缩到目标大小**：五个图片预设（20、50、100、200、500 KB）和五个 PDF 预设（100、200、500 KB、1 MB、2 MB）。(#1250, #1377)
- **在子路径下运行 SnapOtter**：设置 `BASE_PATH=/snapotter` 后，同一个镜像即可从该路径提供服务。结果链接、Cookie、SSO 重定向和 API 文档都会跟随该路径。(#1252, #1324)
- **阿拉伯语 OCR**：可以显式选择阿拉伯语，也可以让自动模式检测。适用于图片和 PDF OCR。(#4130, #4183)
- **当 PDF 或整个批次没有文本层时，pdf-to-text 会提供 OCR 选项**，而不是返回空文件。(#4142, #4198)
- **Organize PDF 中的拖放页面排序**，支持鼠标和触摸。(#1249, #2601)
- **多文件运行前可重新排序文件**：merge、stitch、collage 和其他多文件工具会保留你设定的顺序。(#756, #757)
- **取消批处理和管道运行**，服务器上的工作也会真正停止。(#807)
- **`snapotter-admin` 恢复命令**：`reset-password`、`create-admin`、`unlock-user` 以及 MFA 重置，供无法进入 Web 界面的管理员使用。(#4016)
- **登录时注册 MFA**：当要求使用 MFA 时，尚未设置的用户可以当场完成设置，而不是被拦住。
- **相机拍摄和可安装的应用**：在移动设备上直接拍照并送入工具，也可以将 SnapOtter 安装为 PWA。(#773)
- **编辑器的画布大小对话框支持透明填充。**(#4111)
- **管理员更新通知**：当有更新的 SnapOtter 发布时，管理员会看到一条可关闭的通知，附带发布说明的链接。检查通过现有的分析连接进行，因此关闭分析后该功能也会关闭。

### 改进 {#v2-3-0-improvements}

- **重复运行时背景移除更快**：模型会在请求之间保持加载，而不是每次都重新加载。(#4144)
- **批量上传占用的内存大幅减少**：每个文件写入临时磁盘并逐个处理，而不是一直留在内存中。(#2687)
- **AI 组件包安装失败时会干净地回滚**，而不是留下安装了一半的 venv。Proxmox LXC 上的背景移除安装恢复正常，低内存主机在作业开始前会获得合理的 CPU 限制。(#2628, #2597, #2526, #2546)
- **GPU 检测更可靠**：通过驱动程序检测 CUDA，RTX 50 系列显卡会回退到 CPU 而不是失败，硬件视频编码器在使用前会先试运行。(#4225, #4075, #3980, #3983)
- **`MAX_WORKER_THREADS` 现已生效。** 它之前只被解析，从未被应用。(#3249)
- **耗时较长的工具使用较长的超时**：pdf-to-word、compress-pdf、convert-document 和内容感知缩放在处理大文件时不再过早超时。(#3276)
- **Compress PDF 保持扫描件可读**，并在无法达到目标大小时明确告知，而不是生成无法阅读的文件。(#4112)
- **登录失败按用户名限流**：十五分钟内超过十次会返回 429，并带有 `Retry-After`。(#827)
- **错误信息会说明出了什么问题**：缺失的二进制文件、存储故障、内存不足导致的终止以及上传限制现在都有具体的提示，而不是笼统的 500 或 422。
- **审计日志涵盖工具、批处理和管道运行**，用户、角色、团队和 GDPR 事件会记录谁对谁做了什么。(#3991, #3984)
- **一体化容器在首次启动失败时会停止**，而不是无限重启，内置的 Postgres 和 Redis 也有启动期限。(#3008, #1130)
- **日期和复数形式遵循你的语言**，最后残留的硬编码英文字符串也已翻译。
- **移动端和编辑器的细节打磨**：手机上的滑块、Sign PDF 和裁剪布局，触摸拖动，更快的像素画笔，以及 Levels 和 Curves 纳入撤销和自动保存。

### 错误修复 {#v2-3-0-bug-fixes}

- **Adjust Colors 错误地合并了设置**：色温、饱和度、色相、对比度和棕褐色调会互相覆盖，而不是叠加。(#3153, #3120, #3469)
- **Pixelate 没有像素化**，并且 PNG 输出在各个图片工具中被悄悄缩减了调色板。(#709, #716)
- **动画 GIF 和 WebP 在多个工具中丢失帧**，GIF 调色板和透明度也出现错误。(#1184, #1225, #3407, #2573)
- **旋转后的上传文件画质下降**：自动定向丢弃了无损编码、透明度和 16 位深度。动画 WebP 现在会旋转每一帧。(#2384, #2529)
- **带透明度的 TIFF、AV1 HEIF 文件和若干 RAW 格式**处理失败或丢失 alpha 通道。(#2609, #2572, #1120)
- **调整编辑器画布大小时图像被缩放**，而不是在周围增加空间。(#2081)
- **输出文件名被改乱**：`.jpeg` 和 `.tif` 变成了别的名字，以点开头的文件或主名与扩展名重复的文件名也会出错。(#3495, #3382)
- **库自动保存忽略了存储配额**，存储计数器还可能变成负数。(#2389, #2585)
- **重启后卡住的作业**现在会在启动时被结算，而不是永远显示“处理中”。(#3219, #3193)
- **OIDC 登录把每个新用户都命名为 “admin”**，iOS Safari 登录成功后却停在错误页面。(#862, #4021)
- **已禁用的密码规则在创建用户时仍被强制执行。**(#1028)
- **损坏的 PDF 会挂起 30 秒**才失败。(#920)
- **AI 组件包的磁盘检查要求约 18 GB**才能安装单个组件包。(#1248)
- **Compress Video 在可变帧率的屏幕录像上失败。**(#2427)
- **浏览器重试请求时，批量背景移除丢失了已完成的结果。**(#2015)
- **设置中的数字字段在输入时无法清空。**(#1449)
- **关闭分析后，排队的事件仍会在约 30 秒后发送。** 现在选择退出时它们会被丢弃。(#4270)

### 升级说明 {#v2-3-0-upgrade-notes}

迁移会在启动时自动运行。你不需要执行任何 SQL。

- **数据库角色。** 规范的 Compose 文件现在为应用提供一个只能读写数据的角色（`DATABASE_URL`），以及一个单独的特权连接（`DATABASE_MIGRATION_URL`），后者仅在启动时用于迁移和授权。现有的 Compose 文件仍像以前一样可用：不设置 `DATABASE_MIGRATION_URL`，SnapOtter 就以单一角色运行。对于非本地部署，请在设置 `POSTGRES_APP_PASSWORD` 的同时设置 `POSTGRES_PASSWORD`。
- **更严格的启动检查。** 这些问题以前会在之后才失败，或者悄无声息。现在它们会停止容器，并给出点名相关变量的消息：不受支持的 `DEFAULT_LOCALE`（请使用受支持的代码，如 `de`，而不是 `de_DE`）、格式错误的 `SAML_IDP_SSO_URL`、`SAML_CALLBACK_URL`，或启用 SSO 时的 `OIDC_ISSUER_URL`、无效的 `TRUST_PROXY` 列表、错误的 `BASE_PATH`，以及不可写的 `LOG_DIR`。
- **`TRUST_PROXY` 不再接受跳数。** 像 `TRUST_PROXY=2` 这样的数字现在会在启动时停止容器，而不是悄悄地不信任任何代理。请将其设置为代理地址或命名范围（默认值为 `loopback,linklocal,uniquelocal`）；当没有代理位于 SnapOtter 前面时设置为 `false`；仅当你控制的代理位于公网地址之前时才设置为 `true`。(#998)
- **`MAX_WORKER_THREADS` 现已生效。** 如果你之前设置了它却没有看到变化，现在就会看到了。
- **API 状态码。** 引擎和存储故障返回 503 `ENGINE_UNAVAILABLE`（批处理端点以前返回 422）。超出限制的上传返回 413（以前是 400）。格式错误的 `clientJobId` 返回 400，重复使用的返回 409（以前是 500）。重放你自己的管道批处理返回 202。缺少 `mode=targetSize` 的 `targetSizeKb` 返回 400。在 SSO 强制模式下被拒绝的本地登录返回 401，而不是 403 `SSO_ENFORCED`。被限流的登录返回 429 `LOGIN_THROTTLED`。remove-background 的结果不再包含 `originalUrl`。
- **新增可选变量**：`BASE_PATH`、`DATABASE_MIGRATION_URL`、`GDPR_EXPORT_TIMEOUT_MS`（默认 15 分钟，`0` 表示禁用）、`EMBEDDED_REDIS_TIMEOUT_S`（180）和 `EMBEDDED_POSTGRES_TIMEOUT_S`（600）。
- **Compose 文件随版本发布。** `docker-compose.yml` 和 `docker-compose-gpu.yml` 已附在此版本上，你可以直接从发布页面下载。

## v2.2.0 {#v2-2-0}

2.2 的大部分内容是加固。持有委派的 `users:manage` 角色的非管理员可以接管一个实例，而且每个工具端点都缺少权限检查。如果你有多个用户，请升级。

其余的是自托管中的长尾问题：开始后从未完成的下载、添加第二个文件就失效的预设，以及在 Postgres 仍在启动时反复崩溃重启的容器。另外还新增了两个工具。文档和网站现在已翻译成 21 种语言，界面也终于达到了 WCAG AA 对比度。

> [!IMPORTANT]
> 如果你通过自定义角色向非管理员授予了 `users:manage`，那么在 2.0.0 至 2.1.0 中，该角色可以接管管理员账户。详情见安全部分。

### 安全 {#v2-2-0-security}

- **通过委派的 `users:manage` 角色提升权限（GHSA-9xgh-95qh-2x7h）。** 通过自定义角色持有 `users:manage` 的非管理员可以重置更高权限账户的密码或将其删除，包括内置管理员，从而接管实例。密码重置和账户删除现在会验证调用者对目标的权限，因此委派角色无法越过自身级别。受影响版本：2.0.0 至 2.1.0。由李春来 (Chunlai Li) 报告。(#616)
- **现在每个工具端点都有访问控制。** 工具访问以前是逐个路由强制执行的，所以全部 45 个手写路由都必须记得调用同一个检查，而它们都没有做到。没有 `tools:use` 的角色仍然可以运行 image-to-pdf、erase-object、upscale、sign-pdf 等工具。现在该检查集中在一个以匹配路由为键的 preHandler 中，因此覆盖子路径以及以后添加的任何路由。(#646)
- **Docker 安装上的速率限制可以被绕过。** 镜像默认设置了 `TRUST_PROXY=true`，因此客户端 IP 来自请求头，伪造的 `X-Forwarded-For` 就能绕过登录限流器。默认值现在是私有网络信任列表。(#649)
- **设置写入按单项设置检查**，而不是只在入口检查一次，配置导入现在是事务性的，因此被拒绝的键不会留下只应用了一半的配置。(#618)
- **库文件名无法逃出其存储根目录。** 恶意的 1.x SQLite 导入会原样复制精心构造的存储名称，它可以读取或删除文件目录之外的文件。只有在运维人员导入攻击者提供的 1.x SQLite 数据库之后才可触达，这是唯一能让存储名称被选定的路径。由 @Alpastx 报告。(GHSA-55w2-8cqf-w969, #600)
- **作业取消会强制检查所有权**，因此已认证用户不能再通过作业 id 取消其他用户的作业。由 @Alpastx 报告。(GHSA-wqxf-gj2p-689x, #599)
- **对整个 2.0 代码树的重新审计发现了仍未解决的问题**：捕获的 SAML 断言可以被重放，MFA 质询在任意次数的错误验证码后仍然有效，每次请求的 API 密钥查找是全表扫描，`MAX_WORKSPACE_SIZE_GB` 是无效配置，SVG 清理器放过了未加引号的 `javascript:` href。(#620)
- **修补了九个已披露的 CVE**：fast-uri、svgo、sharp 和 tar（传递依赖）(#619)，以及 Pillow 12.3.0 (#517)。arm64 上的 RAW 解码现在从源码构建 LibRaw 0.22.2，而不是链接未打补丁的系统副本。(#649)

### 新功能 {#v2-2-0-new-features}

- **Rounded Crop**：圆角方形和 iOS 风格的超椭圆（squircle）蒙版，带有圆角半径控制。适用于 favicon 和应用图标。(#602)
- **Remove GIF Background**：逐帧移除动画 GIF、WebP 或 APNG 的背景，并返回透明动画。(#502)
- **Object Eraser 套索和高质量模式**：拖动自由绘制的环线，而不是涂抹每个像素，并可选择安装扩散修复组件包，以获得更干净的大面积填充。(#503, #566)
- **另存为新文件，或覆盖。** 以前编辑库文件会悄悄取代原始文件。现在你可以为每次编辑选择，默认保留原始文件。(#564, #577)
- **Resize 中的宽高比预设。** 选择 1:1、4:3 或 16:9 后两个尺寸保持锁定，且不会放大。(#530)
- **两级 OCR**：快速级内置于镜像中，无需下载即可离线运行，更准确的运行时按需安装。(#519)
- **随处输入即可搜索。** 在仪表板或主页上开始输入，内容会进入搜索框。(#644)
- **21 种语言的文档和网站**：文档站、落地页和 API 参考现在都已翻译，与应用界面保持一致。新的低资源部署指南涵盖 Raspberry Pi 和 2 GB 内存的机器。(#548)
- **更清晰的工具名称**：18 个含义模糊的名称现在自带限定词，例如 “Compress” 变为 “Compress Image”。工具 id 和路由保持不变，因此已加入书签的内容不会失效。(#520)

### 改进 {#v2-2-0-improvements}

- **整个界面达到 WCAG AA 对比度**：调色板经过重新调整，鲜艳的橙色只用于填充，文字和标签使用可访问的墨色令牌，全部 57 个焦点指示器都达到了 3:1 的非文本标准。(#567, #574)
- **Upscale 和背景移除不再看起来像卡住了**：进度条在推理期间会推进，而不是停在 30%，并且两个工具现在都会警告纯 CPU 主机要慢得多。(#605, #608)
- **超时消息会指出真正的原因**，并考虑到纯 CPU 主机，而不是责怪上传。(#596)
- **SnapOtter 在启动时会等待 Postgres 和 Redis**，而不是反复崩溃重启，Compose 和一体化镜像都是如此。在此之前，一个 Proxmox LXC 安装曾重启了 76 次。(#537, #595)
- **下载可以经受住反向代理**：SnapOtter 会要求 nginx 及兼容的代理不要缓冲文件响应，这通常是自托管下载开始后从未完成的原因。(#604, #607)
- **Compress PDF 的结果接近目标大小**，并在目标无法达到时如实说明。(#522)
- **移动端工具控件保持可触达**，因为应用外壳现在按动态视口调整大小。(#559)
- **Convert Audio 提供采样率设置。**(#561)
- **管理员可以放宽最小密码长度**，在受信任的局域网实例中最低可设为 1。(#543)
- **MFA 支持自助服务**，策略锁定问题已解决，OIDC 或 SAML 登录会得到真正的 MFA 质询，而不是被直接拦截。(#531, #536)
- **单独的 `Error: Error` 现在会指出原因。** Sharp 编码失败、AI sidecar 退出、文档 sidecar 的非 JSON 输出以及背景移除失败，过去都是在原因被抹去的情况下送达的。(#532, #534, #535, #538, #612)
- **帮助对话框已翻译。** 它的快捷键标签和入门文字原本是硬编码的英文，而完成的翻译却在全部 21 个语言文件中闲置。(#647)

### 升级说明 {#v2-2-0-upgrade-notes}

无需迁移，但有两个默认值发生了变化：

- **`TRUST_PROXY` 现在默认为 `loopback,linklocal,uniquelocal`**，而不是信任每个对端。Docker 桥接和 Compose 网络位于该范围内，所以大多数部署无需改动。如果你的反向代理从公网地址访问 SnapOtter，请显式设置 `TRUST_PROXY`，否则速率限制和审计日志会把每个请求都归到代理名下。

## v2.0.0 {#v2-0-0}

SnapOtter 2.0 将图片工具包变成了完整的文件处理套件：跨五种模态（图片、视频、音频、PDF 和文件）的 200 多个工具，基于 Postgres 17 和由 Redis 支持的作业队列重建，并提供单命令的 `docker run`。这是一个主要版本；从 1.x 升级之前请阅读重大变更。

### 新功能 {#new-features}

- **四种新的工具模态**：视频、音频、PDF 和文件加入图片，使工具目录达到 200 多个工具。
- **持久的后台作业**：由 Redis 支持的队列 (BullMQ) 将每个工具作为带跟踪的作业运行，并提供实时 SSE 进度。
- **一体化单容器模式**：一个 `docker run` 即可启动包含内置 Postgres 和 Redis 的完整实例。
- **按需 AI 组件包**：背景移除、OCR、转录、放大、人脸检测与增强、对象擦除、上色和照片修复均可从界面安装。GPU 加速按框架检测。
- **Sign PDF**：在浏览器中绘制、输入或上传签名，并将其放置到 PDF 上。
- **Automate**：可视化管道构建器，可串联工具，带有九个预置模板。
- **83 个一键转换预设**：专用的 JPG-to-PNG、MP4-to-GIF 等转换器，支持模糊搜索。
- **基于图层的图像编辑器**：位于 `/editor` 的 Konva 编辑器，带有画笔、形状、调整、滤镜和曲线。
- **文件库**：保存任意结果，并将其作为另一个工具的输入重复使用。
- 固定工具、画布内缩放与平移、21 种语言，以及企业功能（OIDC/SSO、SAML、SCIM、S3 存储、按工具的权限、审计导出、分布式追踪）。

### 改进 {#improvements}

- 可取消正在运行的进程。(#137)
- 通过 LibRaw 进行全分辨率 RAW 解码，包括 DNG。(#289)
- 支持非 root 和外来 UID 部署（TrueNAS、Unraid、OpenShift、PUID/PGID）。(#230, #127)
- 准确的 AI 安装检测和加固的安装流程。(#214, #352)
- 隐私加固：不自动向第三方外发数据，并提供可选的严格离线模式。
- 始终可用的反馈按钮，即使关闭了分析。

### 错误修复 {#bug-fixes}

- `RATE_LIMIT_PER_MIN=0` 再次对工具路由禁用速率限制。(#271)
- 修复了 Docker 镜像内的 AI 虚拟环境路径。(#390)
- 兼容 sharp 0.35.2 及以上版本。(#362)
- 图像编辑器布局修复：标尺、填充行为、侧边栏和画布尺寸。(#258, #259)
- 完成了意大利语翻译。(#231, #206, #425)
- 音频 normalize 和 loudnorm 会保留源采样率。
- SSRF 加固：数字形式的 IPv6 CIDR 匹配和更广泛的 URL 预扫描。(#287)
- 生成的 PDF 会标记 SnapOtter 为 Producer。
- mediapipe 可在 Python 3.13 和 Debian 13 上安装。

### 重大变更 {#breaking-changes}

2.0 用 Postgres 17 取代了内置的 SQLite 数据库，并为作业队列添加了 Redis 8。你的 1.x 数据会在首次启动时自动迁移，但容器栈已发生变化，所以请先备份整个 `/data` 卷（1.x 以 WAL 模式运行 SQLite，因此已提交的数据通常存放在 `snapotter.db-wal` 中）。然后选择单容器镜像（内置 Postgres 和 Redis，仅限 root）或 Compose 栈（应用加 Postgres 17 和 Redis 8）。参见[迁移指南](https://github.com/snapotter-hq/SnapOtter/blob/main/MIGRATING.md)和[升级指南](/zh-CN/guide/upgrading)。

## v1.17.0 {#v1-17-0}

五个新工具、完整的图像编辑器、SSO 登录、20 种语言。这本该拆成三个独立的版本，但现在就是这样。

### 新功能 {#new-features-3}

- **图像编辑器** - 图层、画笔、形状、调整、滤镜、曲线、键盘快捷键。在浏览器中运行，在你的硬件上处理。
- **OIDC / SSO 认证** - 使用 Google、GitHub、Okta 或任何 OpenID Connect 提供商登录。设置几个环境变量，你的团队就能使用现有账户。
- **表情包生成器** - 100 个内置模板，通过 opentype.js 渲染文字。也可以上传自己的图片。
- **Beautify** - 放入一张截图，得到一张精美的图片。设备边框（macOS、Windows、浏览器）、阴影、渐变、社交媒体预设。
- **色盲模拟** - 预览图像在红色盲、绿色盲、蓝色盲及其他色觉缺陷下的样子。
- **PNG 透明度修复** - 检测假透明的 PNG，并用 BiRefNet HR-matting 修复。可选通过 LaMa 修复去除水印。
- **AI 画布扩展** - 用 AI 填充扩展图像边界。三个质量档位（快速、均衡、高质量），取决于你愿意投入多少 GPU 时间。
- **20 种语言** - 阿拉伯语、中文（简体/繁体）、捷克语、荷兰语、法语、德语、印地语、印度尼西亚语、意大利语、日语、韩语、波兰语、葡萄牙语、俄语、西班牙语、泰语、土耳其语、乌克兰语、越南语。阿拉伯语支持 RTL。
- **URL 导入** - 将 URL 粘贴到拖放区，或从列表批量导入。服务端抓取，带 SSRF 防护。
- **多文件橡皮擦** - 在多张图片上绘制擦除蒙版，一键处理全部。笔触按图片分别保留。
- **管道导入/导出** - 将工具链保存为 JSON，与他人分享。
- **通过 exiftool 支持 17 种新的相机 RAW 格式**，以及 QOI、JP2、EPS、DDS、CUR、DPX、FITS、PPM/PGM/PBM、SVGZ 和 APNG 输入。BMP、ICO、JP2、QOI 的新输出编解码器。AVIF、TIFF、GIF、JXL 和 PSD 导出从此前丢失的分支中恢复。

### 改进 {#improvements-2}

- **图像增强** - 用 CLAHE + normalise + gamma 取代了旧的管道。新的 Deep Enhance 开关使用 AI 模型获得更强的效果。
- **照片修复** - 划痕检测以 8 角度 Otsu 过滤重写。LaMa 修复现在以原始分辨率运行。
- **各处都支持特殊格式** - OCR、image-to-PDF、favicon 生成器、composition、stitch 和 vectorize 现在都能解码 HEIC、RAW、PSD。
- **Compress** - 目标大小容差从 5% 收紧到 1%。目标大小成为默认模式。添加了步进按钮和 KB/MB 单位选择器。
- **Sentry 清理** - 过滤了 644 个无需处理的事件。真正的错误现在得到了妥善处理。
- **GPU 检测** - 针对存在 CUDA 但没有 nvidia-smi 的容器提供了更好的诊断。
- **禁用认证模式** - 匿名用户以管理员角色写入数据库。API 密钥、管道和用户文件不再因外键约束而出错。
- **2,705 多个新测试**，涵盖单元、集成和 E2E。

### 错误修复 {#bug-fixes-3}

- 在 CPU 上放大不再于 NAS 设备和低功耗硬件上超时。
- 二维码 logo 不再使预览永久消失。
- 修复了高纵向图片的裁剪溢出。
- 带 alpha 的 TIFF 文件现在会正确强制输出 PNG，而不是产生损坏。
- HDR/EXR 解码在 CLAHE 之前转换为 8 位，修复了解码失败。
- 人脸关键点输入缓冲区在送入 Python sidecar 之前转换为 PNG，修复了崩溃。
- Find duplicates 可处理混合格式的批次和网络错误。
- Beautify 预览实时更新。
- stitch 和 vectorize 增加了进度条。
- SVG-to-raster 现在可处理 SVGZ。
- 通过百分号编码的 X-File-Results 头修复了非 ASCII 文件名。
