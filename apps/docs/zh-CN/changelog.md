# 更新日志 {#changelog}

## v2.2.0 {#v2-2-0}

2.2 的大部分工作都是安全加固。持有被委派 `users:manage` 角色的非管理员可能接管整个实例，而且每个工具端点都被发现缺少权限检查。如果你运行的不止一个用户，请升级。

其余部分是自托管的长尾问题：开始却永远不结束的下载、添加第二个文件就失效的预设、Postgres 尚未启动完成时反复崩溃重启的容器。还新增了两个工具。文档和网站现已翻译为 21 种语言，界面的对比度也终于符合 WCAG AA。

> [!IMPORTANT]
> 如果你通过自定义角色向非管理员授予了 `users:manage`，该角色可以在 2.0.0 到 2.1.0 上接管管理员账户。详情见“安全”。

### 安全 {#v2-2-0-security}

- **通过被委派的 `users:manage` 角色提权（GHSA-9xgh-95qh-2x7h）。** 通过自定义角色持有 `users:manage` 的非管理员可以重置权限更高账户的密码或删除该账户（包括内置管理员），从而接管实例。密码重置和账户删除现在会校验调用者对目标账户的权限，因此被委派的角色无法触及高于自身级别的账户。受影响版本：2.0.0 到 2.1.0。由李春来（Chunlai Li）报告。（#616）
- **每个工具端点现在都受权限控制。** 工具访问此前按路由逐一实施，因此全部 45 条手写路由都必须记得同一处调用，而它们都没有做到。没有 `tools:use` 的角色仍然可以运行 image-to-pdf、erase-object、upscale、sign-pdf 等工具。该检查现在位于一个基于匹配路由的 preHandler 中，因此覆盖子路径以及以后新增的任何路由。（#646）
- **Docker 安装中的速率限制可被绕过。** 镜像曾随附 `TRUST_PROXY=true`，因此客户端 IP 来自请求头，伪造的 `X-Forwarded-For` 可以绕过登录限制器。现在的默认值是私有网络信任列表。（#649）
- **设置写入按设置项校验**，而不是只在入口校验一次；配置导入现在是事务性的，因此被拒绝的键不会留下只应用了一半的配置。（#618）
- **库文件名无法逃出存储根目录。** 一个精心构造的存储名称（恶意的 1.x SQLite 导入会原样复制它）可能读取或删除文件目录之外的文件。只有在运维人员导入攻击者提供的 1.x SQLite 数据库后才能触及，而这是唯一能让他人决定存储名称的路径。由 @Alpastx 报告。（GHSA-55w2-8cqf-w969，#600）
- **作业取消会强制校验所有权**，因此已认证用户不能再通过 id 取消其他用户的作业。由 @Alpastx 报告。（GHSA-wqxf-gj2p-689x，#599）
- **对整个 2.0 代码树的复审发现了仍然存在的问题**：被捕获的 SAML 断言可以被重放，MFA 挑战在输入任意多次错误验证码后仍然不会被作废，每次请求的 API 密钥查找都是一次全表扫描，`MAX_WORKSPACE_SIZE_GB` 是无效配置，而且 SVG 净化器放过了未加引号的 `javascript:` href。（#620）
- **修复了九个已披露的 CVE**：fast-uri、svgo、sharp 和 tar（传递依赖）（#619），以及 Pillow 12.3.0（#517）。arm64 上的 RAW 解码现在从源码构建 LibRaw 0.22.2，而不是链接未修补的系统副本。（#649）

### 新功能 {#v2-2-0-new-features}

- **圆角裁剪**：圆角方形和 iOS 风格的超椭圆蒙版，带有圆角半径控制。专为 favicon 和应用图标设计。（#602）
- **移除 GIF 背景**：逐帧去除动画 GIF、WebP 或 APNG 的背景，并得到透明动画。（#502）
- **对象擦除的套索和高画质模式**：拖动自由形状的环，而不是逐像素涂抹；还可选择安装扩散图像修复功能包，以获得更干净的大面积填充。（#503, #566）
- **另存为新文件，或覆盖。** 以前编辑库文件会静默取代原文件。现在每次编辑都由你选择，默认保留原文件。（#564, #577）
- **调整大小中的宽高比预设。** 选择 1:1、4:3 或 16:9，两个尺寸保持锁定，且不会放大。（#530）
- **两级 OCR**：快速层已内置在镜像中，可离线运行且无需下载；更准确的运行时按需安装。（#519）
- **随处输入即可搜索。** 在仪表板或主页上开始输入，内容就会进入搜索框。（#644）
- **文档和网站支持 21 种语言**：文档站点、落地页和 API 参考现已全部翻译，与应用界面一同覆盖。新增的低资源部署指南涵盖 Raspberry Pi 和 2 GB 内存的机器。（#548）
- **更清晰的工具名称**：18 个含义模糊的名称现在会自我限定，例如 “Compress” 变为 “Compress Image”。工具 id 和路由保持不变，因此已收藏的链接都不会失效。（#520）

### 改进 {#v2-2-0-improvements}

- **整个界面的 WCAG AA 对比度**：调色板经过重新调整，鲜艳的橙色保留在填充区域，而文本和标签使用符合无障碍要求的文字色令牌，全部 57 个焦点指示器现在都达到 3:1 的非文本标准。（#567, #574）
- **放大和背景去除不再看起来像卡住了**：进度条会在推理期间推进，而不是停在 30%；这两个工具现在都会提示仅 CPU 的主机会慢得多。（#605, #608）
- **超时消息会指出真正的原因**，并考虑仅 CPU 的主机，而不是归咎于上传。（#596）
- **SnapOtter 在启动时等待 Postgres 和 Redis**，而不是反复崩溃重启，Compose 和一体化镜像都是如此。一个 Proxmox LXC 安装在此修复前重启了 76 次。（#537, #595）
- **下载可以顺利通过反向代理**：SnapOtter 会请求 nginx 及兼容代理不要缓冲文件响应，这通常是自托管下载开始却永远无法完成的原因。（#604, #607）
- **压缩 PDF 会接近目标大小**，并在目标无法达到时如实说明。（#522）
- **移动端工具控件保持可触达**，因为应用外壳现在会按动态视口调整尺寸。（#559）
- **转换音频提供采样率设置。**（#561）
- **管理员可以放宽最小密码长度**，在受信任的局域网实例中最低可设为 1。（#543）
- **MFA 支持自助服务**，策略锁定漏洞已关闭，OIDC 或 SAML 登录会得到真正的 MFA 挑战，而不是直接拒绝。（#531, #536）
- **只显示 `Error: Error` 的错误现在会说明原因。** Sharp 编码失败、AI sidecar 退出、非 JSON 的文档 sidecar 输出以及背景去除失败，以前都会在原因被抹掉后返回。（#532, #534, #535, #538, #612）
- **帮助对话框已翻译。** 其快捷键标签和入门文本曾硬编码为英文，而 21 个语言文件中已完成的翻译却闲置未用。（#647）

### Bug 修复 {#v2-2-0-bug-fixes}

- **iPhone HEIC 文件曾被拒绝**，在到达能够处理它们的解码器之前就被判定为无法读取。（#631）
- **转换预设在第二个文件上失败**：jpg-to-pdf 及其 image-to-pdf 同类工具，以及 pdf-to-png、pdf-to-jpg 和 pdf-to-tiff，在上传两个文件后都会返回 `Tool not found`。（#633, #643）
- **PDF 转换预设丢失了下载按钮。**（#629）
- **无限制的处理超时未被遵守**，停滞的进度流现在会恢复，而不是让界面一直等待。（#638）
- **下载会挂起而不是失败**：当存储文件比记录的长度短时。（#617）
- **PDF 页面工具在短文件和加密文件上失败**：移除页面默认使用了一个少于六页的文档根本不存在的页码范围；受密码保护的 PDF 在 worker 内部以晦涩的方式失败。（#594）
- **PDF 转文本对扫描版 PDF 静默返回空文件。** 现在会提示你使用 OCR，并以 UTF-8 提供文本。（#603）
- **PDF 转 Word 丢失彩色文本块**，并将其拆分到页面各处。（#500）
- **对象擦除会残留鬼影**，并在高分辨率图像中模糊小物体。（#501）
- **稳定视频会写出无法播放的输出**，因为没有 faststart。（#593）
- **图像编辑器修复**：旋转、翻转、调整大小、色阶、曲线、滤镜和图层锁定。（#597）
- **签署 PDF 显示空白画布**，而不是报告 PDF 加载失败的原因。（#545）
- **文件库记录了 0x0 尺寸**，并跳过了 HEIC、RAW 和 PSD 上传的预览。（#636, #637）
- **安装多个 AI 功能包**会让共享虚拟环境混入多个版本，并悄悄破坏三个工具。（#649）
- **以 1 到 4 的画质转换为 JXL 时会返回 500**，而缺少 ffmpeg 会被报告为损坏的上传。（#649）
- **Postgres 的短暂中断会搁置已完成的作业**，把输出留在磁盘上却没有对应记录。现在有一个协调器会接管这些工作，而不是丢弃它们。（#649）
- **地址发生变化的 Redis 端点会卡住所有消费者**，而健康检查仍然返回 200。（#649）
- **网站和文档修复**：本地化链接不再丢失 `#` 片段或小写化 `zh-CN`，文档导航在平板电脑上保持在视口内，两个站点都不再从你的浏览器调用 GitHub API。（#516, #562, #570, #560）

### 升级说明 {#v2-2-0-upgrade-notes}

无需迁移，但有两个随附默认值发生了变化：

- **`TRUST_PROXY` 现在默认为 `loopback,linklocal,uniquelocal`**，而不是信任所有对端。Docker 网桥和 Compose 网络都位于该范围内，因此大多数配置无需更改。如果你的反向代理从公网地址访问 SnapOtter，请显式设置 `TRUST_PROXY`，否则速率限制和审计日志会把每个请求都归因于代理。
- **`MAX_AI_JOBS_PER_USER` 默认为 5**，即每个用户同时进行的单文件 AI 作业数。批处理和流水线 AI 运行仍然不设上限。

新增的可选配置项：`DB_STARTUP_TIMEOUT_MS`、`SUBPROCESS_MEMORY_LIMIT_MB`（默认关闭）和 `GIF_BG_MAX_FRAMES`。

## v2.0.0 {#v2-0-0}

SnapOtter 2.0 将图像工具箱升级为完整的文件处理套件：跨五种模态（图像、视频、音频、PDF 和文件）的 200+ 工具，基于 Postgres 17 和 Redis 支持的作业队列重建，并提供一条命令即可完成的 `docker run`。这是一次重大版本发布；从 1.x 升级之前，请先阅读“重大变更”部分。

### 新功能 {#new-features}

- **四种全新工具模态**：视频、音频、PDF 和文件加入图像模态，使工具目录达到 200+ 个工具。
- **持久化后台作业**：由 Redis 支持的队列（BullMQ）将每个工具作为可追踪的作业运行，并通过 SSE 实时反馈进度。
- **一体化单容器模式**：一条 `docker run` 即可启动一个内置 Postgres 和 Redis 的完整实例。
- **按需 AI 组件包**：背景移除、OCR、转录、放大、人脸检测与增强、对象擦除、上色以及照片修复均可从界面中安装。GPU 加速会按框架分别检测。
- **签署 PDF**：在浏览器中绘制、输入或上传签名，并将其放置到 PDF 上。
- **Automate（自动化）**：一个可视化的流水线构建器，用于串联多个工具，并附带九个预置模板。
- **83 个一键转换预设**：专用的 JPG-to-PNG、MP4-to-GIF 等转换器，支持模糊搜索。
- **基于图层的图像编辑器**：位于 `/editor` 的 Konva 驱动编辑器，具备画笔、形状、调整、滤镜和曲线功能。
- **文件库**：保存任意处理结果，并将其作为另一个工具的输入重复使用。
- 固定工具、画布内缩放与平移、21 种语言，以及企业级能力（OIDC/SSO、SAML、SCIM、S3 存储、按工具权限、审计导出、分布式追踪）。

### 改进 {#improvements}

- 可取消正在运行的处理过程。（#137）
- 通过 LibRaw 进行全分辨率 RAW 解码，包括 DNG。（#289）
- 支持非 root 及外部 UID 部署（TrueNAS、Unraid、OpenShift、PUID/PGID）。（#230, #127）
- 更准确的 AI 安装检测以及经过加固的安装流程。（#214, #352）
- 隐私加固：不再有任何自动的第三方外发请求，并新增可选的严格离线模式。
- 常驻反馈按钮，即使在关闭分析功能时也可用。

### Bug 修复 {#bug-fixes}

- `RATE_LIMIT_PER_MIN=0` 重新为工具路由禁用限流。（#271）
- 修复了 Docker 镜像内部的 AI 虚拟环境路径。（#390）
- 兼容 sharp 0.35.2+。（#362）
- 图像编辑器布局修复：标尺、填充行为、侧边栏和画布尺寸。（#258, #259）
- 完成了意大利语翻译。（#231, #206, #425）
- 音频归一化和 loudnorm 会保留源采样率。
- SSRF 加固：数值型 IPv6 CIDR 匹配以及更广泛的 URL 预扫描。（#287）
- 生成的 PDF 会将 SnapOtter 标注为 Producer。
- mediapipe 可在 Python 3.13 和 Debian 13 上安装。

### 重大变更 {#breaking-changes}

2.0 用 Postgres 17 替代了内置的 SQLite 数据库，并新增 Redis 8 用于作业队列。你的 1.x 数据会在首次启动时自动迁移，但容器栈发生了变化，因此请先备份整个 `/data` 卷（1.x 以 WAL 模式运行 SQLite，因此已提交的数据通常位于 `snapotter.db-wal`）。然后选择单容器镜像（内置 Postgres 和 Redis，仅限 root）或 Compose 栈（应用外加 Postgres 17 和 Redis 8）。请参阅[迁移指南](https://github.com/snapotter-hq/SnapOtter/blob/main/MIGRATING.md)和[升级指南](/zh-CN/guide/upgrading)。

### 升级 {#upgrade}

```bash
docker pull snapotter/snapotter:2.0.0
```

或使用 Docker Compose：

```bash
docker compose pull && docker compose up -d
```

[在 GitHub 上查看完整 diff](https://github.com/snapotter-hq/SnapOtter/compare/v1.17.2...v2.0.0)

## v1.17.2 {#v1-17-2}

新增 HTML to Image 工具、WCAG 2.2 AA 无障碍支持、来自渗透测试的安全加固，以及 5 个关键的 Docker 修复。

### 新功能 {#new-features-1}

- **HTML to Image**：将 URL 或原始 HTML 截图保存为 PNG/JPEG/WebP。支持整页截图、自定义视口和深色模式。

## v1.17.0 {#v1-17-0}

五个新工具、一个完整的图像编辑器、SSO 登录、20 种语言。本该分成三次单独发布，但事已至此。

### 新功能 {#new-features-3}

- **图像编辑器** - 图层、画笔、形状、调整、滤镜、曲线、键盘快捷键。在你的浏览器中运行，在你的硬件上处理。
- **OIDC / SSO 认证** - 使用 Google、GitHub、Okta 或任意 OpenID Connect 提供方登录。设置几个环境变量，你的团队即可使用已有账户。
- **表情包生成器** - 100 个内置模板，通过 opentype.js 渲染文本。也可上传你自己的图像。
- **Beautify（美化）** - 放入一张截图，得到一张精致的图像。设备边框（macOS、Windows、浏览器）、阴影、渐变、社交媒体预设。
- **色盲模拟** - 预览图像在红色盲、绿色盲、蓝色盲及其他色觉缺陷下的观感。
- **PNG 透明度修复器** - 检测伪透明 PNG，并使用 BiRefNet HR-matting 修复它们。可选通过 LaMa 图像修补移除水印。
- **AI 画布扩展** - 用 AI 填充扩展图像边界。三个质量档位（快速、平衡、高质量），取决于你愿意投入多少 GPU 时间。
- **20 种语言** - 阿拉伯语、简体/繁体中文、捷克语、荷兰语、法语、德语、印地语、印度尼西亚语、意大利语、日语、韩语、波兰语、葡萄牙语、俄语、西班牙语、泰语、土耳其语、乌克兰语、越南语。阿拉伯语支持 RTL。
- **URL 导入** - 将 URL 粘贴到拖放区，或从列表批量导入。带 SSRF 防护的服务端抓取。
- **多文件擦除器** - 在多张图像上绘制擦除蒙版，一键处理全部。笔画按图像分别保留。
- **流水线导入/导出** - 将工具链保存为 JSON，与他人分享。
- 通过 exiftool 支持 **17 种新的相机 RAW 格式**，另加 QOI、JP2、EPS、DDS、CUR、DPX、FITS、PPM/PGM/PBM、SVGZ 和 APNG 输入。新增 BMP、ICO、JP2、QOI 的输出编解码。AVIF、TIFF、GIF、JXL 和 PSD 导出从此前丢失的分支中恢复。

### 改进 {#improvements-2}

- **图像增强** - 用 CLAHE + normalise + gamma 替换了旧流水线。新的 Deep Enhance 开关使用 AI 模型以获得更激进的效果。
- **修复照片** - 划痕检测用 8 角度 Otsu 滤波重写。LaMa 图像修补现以原始分辨率运行。
- **处处支持特殊格式** - OCR、image-to-PDF、favicon 生成器、合成、拼接和矢量化现在均可解码 HEIC、RAW、PSD。
- **压缩** - 目标尺寸容差从 5% 收紧到 1%。目标尺寸成为默认模式。新增步进按钮和 KB/MB 单位选择器。
- **Sentry 清理** - 过滤了 644 个不可处理的事件。现在能正确处理真实错误。
- **GPU 检测** - 针对存在 CUDA 但没有 nvidia-smi 的容器提供更好的诊断。
- **禁用鉴权模式** - 在数据库中以 admin 角色播种匿名用户。API 密钥、流水线和用户文件不再因外键约束而中断。
- 跨单元、集成和 E2E 的 **2,705+ 项新测试**。

### Bug 修复 {#bug-fixes-3}

- CPU 上的放大在 NAS 设备和低功耗硬件上不再超时。
- 二维码 logo 不再使预览永久消失。
- 修复了高竖版图像的裁剪溢出。
- TIFF alpha 文件现在会正确强制 PNG 输出，而不是产生损坏。
- HDR/EXR 解码在 CLAHE 之前转换为 8 位，修复了解码失败。
- 人脸关键点的输入缓冲在进入 Python 边车之前转换为 PNG，修复了崩溃。
- 查找重复项可处理混合格式的批次和网络错误。
- Beautify 预览可实时更新。
- 为拼接和矢量化添加了进度条。
- SVGZ 由 SVG-to-raster 处理。
- 通过百分号编码的 X-File-Results 头修复了非 ASCII 文件名。
