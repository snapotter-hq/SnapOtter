# Начало работы {#getting-started}

::: tip Попробуйте перед установкой
Изучите полный интерфейс на [demo.snapotter.com](https://demo.snapotter.com), регистрация и установка не нужны.
:::

## Быстрый старт {#quick-start}

```bash
docker run -d --name SnapOtter -p 1349:1349 -v SnapOtter-data:/data snapotter/snapotter:latest
```

Этот единственный контейнер запускает всё необходимое: если `DATABASE_URL` не задан, он поднимает собственные PostgreSQL и Redis на loopback-интерфейсе (встроенный режим) и хранит все данные в томе `SnapOtter-data`. Это самый быстрый способ попробовать SnapOtter или развернуть его на домашнем сервере. Для продакшена используйте [стандартный стек Docker Compose](#docker-compose), в котором PostgreSQL и Redis работают в отдельных контейнерах. Встроенный режим запускается от root (по умолчанию) и отключается автоматически, как только вы задаёте `DATABASE_URL`.

Устанавливаете на Raspberry Pi, старый ноутбук или небольшой VPS? См. [Настройки для слабого оборудования](/ru/guide/low-resource): там есть настроенное пошаговое руководство и описание того, чего ждать от ограниченного железа.

При первом входе вам предложат сменить пароль.

::: tip Анонимная продуктовая аналитика
SnapOtter по умолчанию включает анонимную продуктовую аналитику. Чтобы отключить её, откройте **Настройки → Система → Конфиденциальность** и выключите **Анонимную продуктовую аналитику**. Она сразу прекращается для всего экземпляра.

Также можно задать переменную окружения `SNAPOTTER_TELEMETRY=0` (подходят и `false` с `off`), чтобы отключить всю телеметрию экземпляра без пересборки.

Мониторинг ошибок работает на [Sentry](https://sentry.io), который спонсирует SnapOtter через свою программу для открытого ПО.

Подробнее о том, что собирается, см. [Что собирает SnapOtter](/ru/guide/telemetry).
:::

::: tip Ускорение NVIDIA CUDA
Добавьте `--gpus all`, чтобы удаление фона, увеличение, улучшение лиц и восстановление работали на NVIDIA CUDA. OCR по-прежнему работает на CPU и функционирует в том же образе как с доступом к GPU, так и без него:

```bash
docker run -d --name SnapOtter -p 1349:1349 --gpus all -v SnapOtter-data:/data snapotter/snapotter:latest
```

Требуется [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html). Если CUDA недоступна, автоматически используется CPU. Ускорение на встроенных GPU Intel/AMD через VA-API, Quick Sync или OpenCL для ИИ-вывода сейчас не поддерживается. Результаты тестов см. в разделе [Теги Docker](/ru/guide/docker-tags). Если инструменты ИИ работают на CPU, несмотря на `--gpus all`, см. [Проверка ускорения GPU](/ru/guide/deployment#verify-gpu-acceleration).
:::

::: details Также в GHCR
```bash
docker run -d --name SnapOtter -p 1349:1349 -v SnapOtter-data:/data ghcr.io/snapotter-hq/snapotter:latest
```

Оба реестра публикуют один и тот же образ при каждом выпуске.
:::

## Docker Compose {#docker-compose}

Используйте продакшен-файл, который сопровождается и тестируется с каждым выпуском, вместо копирования сокращённого примера Compose с этой страницы:

```bash
install -d -m 700 snapotter && cd snapotter
curl --proto '=https' --tlsv1.2 -fsSLo docker-compose.yml \
  https://raw.githubusercontent.com/snapotter-hq/SnapOtter/v2.3.0/docker/docker-compose.yml

# Keep generated service credentials out of shell history and world-readable files.
umask 077
POSTGRES_PASSWORD="$(openssl rand -hex 32)"
REDIS_PASSWORD="$(openssl rand -hex 32)"
printf 'POSTGRES_PASSWORD=%s\nREDIS_PASSWORD=%s\n' \
  "$POSTGRES_PASSWORD" "$REDIS_PASSWORD" > .env

docker compose -f docker-compose.yml pull
docker compose -f docker-compose.yml up -d --no-build
```

Стандартный [`docker/docker-compose.yml`](https://github.com/snapotter-hq/SnapOtter/blob/v2.3.0/docker/docker-compose.yml) включает все четыре тома среды выполнения, проверки состояния, ограничения ресурсов, устойчивую конфигурацию Redis, зафиксированные образы базы данных и кэша и актуальное усиление защиты контейнеров. Сразу после первого входа смените пароль администратора по умолчанию. Для воспроизводимого развёртывания закрепите образ приложения SnapOtter на проверенном вами теге выпуска или дайджесте, а не следуйте за `latest`.

Все переменные окружения описаны в разделе [Конфигурация](/ru/guide/configuration), а рекомендации по секретам, сетевой политике и резервному копированию в разделе [Безопасность и усиление защиты](/ru/guide/security).

## Сборка из исходников {#build-from-source}

**Требования:** Node.js 22.22+, pnpm 9+, Docker (для Postgres и Redis), Python 3.11+ (для функций ИИ), Git.

```bash
git clone https://github.com/snapotter-hq/SnapOtter.git
cd SnapOtter
docker compose -f docker-compose.dev.yml up -d   # start Postgres + Redis
pnpm install
pnpm dev
```

- Фронтенд: [http://localhost:1351](http://localhost:1351)
- Бэкенд: [http://localhost:13490](http://localhost:13490)

### Конвейеры {#pipelines}

Объединяйте инструменты в многошаговые рабочие процессы и применяйте их к одному изображению или к целой пачке:

1. Откройте **Конвейеры** на боковой панели.
2. Добавьте шаги (любой инструмент с любыми настройками).
3. Запустите для одного файла или сразу для всей пачки.
4. Сохраните конвейер для повторного использования.

По умолчанию конвейер допускает 20 шагов. Задайте `MAX_PIPELINE_STEPS=0`, чтобы снять ограничение.

### Библиотека файлов {#file-library}

Каждый обработанный файл можно сохранить в библиотеку **Файлы**. SnapOtter ведёт полную историю версий, так что вы можете проследить каждый шаг обработки от исходной загрузки до итогового результата.

Сохранение выполняется явно: результаты, сохранённые в библиотеку, хранятся до тех пор, пока вы их не удалите, а необработанные и несохранённые результаты автоматически удаляются через 72 часа (настраивается через `FILE_MAX_AGE_HOURS`).

### REST API и ключи API {#rest-api-api-keys}

Каждый инструмент доступен по HTTP:

```bash
curl -X POST http://localhost:1349/api/v1/tools/image/resize \
  -H "Authorization: Bearer si_<your-api-key>" \
  -F "file=@photo.jpg" \
  -F 'settings={"width":800,"height":600,"fit":"cover"}'
```

Создавайте ключи API в разделе **Настройки → Ключи API**. Все конечные точки описаны в [справочнике REST API](/ru/api/rest), а интерактивный справочник доступен по адресу [http://localhost:1349/api/docs](http://localhost:1349/api/docs).

### Несколько пользователей и команды {#multi-user-teams}

Включите работу нескольких пользователей с ролевым управлением доступом:

- **Администратор**: полный доступ, управление пользователями, командами, настройками, всеми файлами, конвейерами и ключами API
- **Пользователь**: работа с инструментами, управление собственными файлами, конвейерами и ключами API

Создавайте команды в разделе **Настройки → Команды**, чтобы группировать пользователей.

Задайте `AUTH_ENABLED=true` (или `false` для одного пользователя или личного использования без входа).

## Использование с телефона {#use-it-from-your-phone}

SnapOtter работает в мобильных браузерах, и его можно установить как приложение. Откройте свой экземпляр на телефоне, затем:

- **iPhone / iPad (Safari):** нажмите «Поделиться», затем **На экран «Домой»**.
- **Android (Chrome):** откройте меню браузера и нажмите **Установить приложение**.

Установленное приложение открывается в отдельном окне сразу на вашем экземпляре.

Есть одно ограничение: браузеры предлагают установку только по HTTPS. Обычный HTTP-адрес в вашей локальной сети по-прежнему отлично работает во вкладке браузера; для полноценной установки разместите экземпляр за обратным прокси с сертификатом (см. [руководство по развёртыванию](/ru/guide/deployment)).

На телефонах и планшетах инструменты для изображений показывают кнопку **Сделать фото** рядом с кнопкой загрузки. Сфотографируйте чек или доску, и снимок сразу попадёт в инструмент.
