# Конфигурация {#configuration}

Вся настройка выполняется через переменные окружения. У каждой переменной есть разумное значение по умолчанию, поэтому SnapOtter работает сразу, без их задания.

## Переменные окружения {#environment-variables}

### Сервер {#server}

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `1349` | Порт, который слушает сервер. |
| `BASE_PATH` | (пусто) | Публичный путь развертывания, например `/snapotter`. Пустое значение или `/` обслуживает корень домена. Применяется во время выполнения; пересборка образа не требуется. |
| `RATE_LIMIT_PER_MIN` | `1000` | Максимальное число запросов в минуту с одного IP. Задайте 0, чтобы отключить ограничение частоты. |
| `CORS_ORIGIN` | (пусто) | Разрешенные источники для CORS через запятую или пусто для одного и того же источника. |
| `LOG_LEVEL` | `info` | Подробность журнала. Одно из: `fatal`, `error`, `warn`, `info`, `debug`, `trace`. |
| `TRUST_PROXY` | `loopback,linklocal,uniquelocal` | Какие узлы могут задавать IP клиента через `X-Forwarded-For`. По умолчанию доверяется только узлу из частной сети, поэтому обратный прокси в сети Docker или в локальной сети считается доверенным, а поддельный заголовок публичного клиента нет. Задавайте `true` только если подконтрольный вам прокси стоит перед сервером на публичном адресе. |

### Аутентификация {#authentication}

Два приведенных ниже логических значения принимают только `true` и `false`. Все остальное, `1`, `yes` или `on`, не проходит проверку, и сервер завершается до начала прослушивания.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AUTH_ENABLED` | `true` | Требовать вход. Задайте `false`, чтобы работать вообще без учетных записей, что дает права администратора каждому запросу, поэтому используйте это только в доверенной сети. |
| `DEFAULT_USERNAME` | `admin` | Имя пользователя для начальной учетной записи администратора. Используется только при первом запуске. |
| `DEFAULT_PASSWORD` | `admin` | Пароль для начальной учетной записи администратора. Смените его после первого входа. |
| `MAX_USERS` | `0` (без ограничения) | Максимальное число зарегистрированных учетных записей. Задайте 0 для отсутствия ограничения. |
| `SESSION_DURATION_HOURS` | `168` | Срок жизни сессии входа в часах (по умолчанию 7 дней). |
| `SKIP_MUST_CHANGE_PASSWORD` | `false` | Задайте `true`, чтобы пропустить принудительный запрос смены пароля при первом входе. |

### Хранилище {#storage}

| Переменная | По умолчанию | Описание |
|---|---|---|
| `STORAGE_MODE` | `local` | `local` или `s3`. S3 и MinIO требуют лицензию с функцией s3_storage, а также переменные `S3_*` ниже. |
| `DATABASE_URL` | `postgres://snapotter:snapotter@localhost:5432/snapotter` | Строка подключения к PostgreSQL и подключение, через которое обслуживается каждый запрос. В версии 2.3.0 и новее задайте также `DATABASE_MIGRATION_URL`, и это станет ролью времени выполнения с минимальными привилегиями, имеющей только DML на таблицах приложения и ничего больше. Стек Compose направляет ее на свой сервис `postgres`; оставьте ее незаданной (вместе с `REDIS_URL`), чтобы получить встроенный режим. |
| `DATABASE_MIGRATION_URL` | (пусто) | Привилегированное подключение, используемое только при загрузке для выполнения миграций и выдачи прав роли времени выполнения, затем закрываемое до первого запроса. Оставьте пустым, и SnapOtter будет работать с одной ролью, а `DATABASE_URL` будет выполнять обе задачи. См. [Роли с минимальными привилегиями](/ru/guide/database#least-privilege-roles). |
| `REDIS_URL` | `redis://localhost:6379` | Строка подключения к Redis (используется для очередей задач BullMQ). Compose направляет ее на свой сервис `redis`. |
| `WORKSPACE_PATH` | `./tmp/workspace` | Каталог для временных файлов во время обработки. Очищается автоматически. Образ задает `/tmp/workspace`. |
| `FILES_STORAGE_PATH` | `./data/files` | Каталог для постоянных файлов пользователей (загруженные изображения, сохраненные результаты). Образ задает `/data/files`. |

### Объектное хранилище S3 {#s3-object-storage}

Читаются только при `STORAGE_MODE=s3`. Если пропустить любую из трех обязательных, запуск завершится ошибкой с именем пропущенной переменной.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `S3_BUCKET` | (пусто) | Бакет, в котором хранятся загрузки и результаты. Обязательно. |
| `S3_ACCESS_KEY_ID` | (пусто) | Ключ доступа. Обязательно. В контейнере вместо этого его можно смонтировать через `S3_ACCESS_KEY_ID_FILE`. |
| `S3_SECRET_ACCESS_KEY` | (пусто) | Секретный ключ. Обязательно. То же соглашение о файлах: `S3_SECRET_ACCESS_KEY_FILE`. |
| `S3_REGION` | `us-east-1` | Регион бакета. |
| `S3_ENDPOINT` | (пусто) | Пользовательский эндпоинт для MinIO, R2, Backblaze и других S3-совместимых хранилищ. Пусто означает AWS. |
| `S3_FORCE_PATH_STYLE` | `false` | Задайте `true` для MinIO и всего остального, что требует `endpoint/bucket/key` вместо адресации virtual-host. |
| `S3_PREFIX` | (пусто) | Префикс ключа, чтобы один бакет мог содержать несколько экземпляров. |

### Шифрование при хранении {#encryption-at-rest}

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATA_ENCRYPTION_KEY` | (пусто) | 64 шестнадцатеричных символа (32 байта). Шифрует чувствительные настройки, хранящиеся в базе данных. Все, что не состоит из 64 шестнадцатеричных символов, отклоняется при запуске. |
| `DATA_ENCRYPTION_KEY_PREVIOUS` | (пусто) | Ключ, от которого вы отказываетесь, в том же формате. Задайте оба при ротации, чтобы существующие строки по-прежнему расшифровывались, а затем уберите этот. |

### Встроенный режим {#embedded-mode}

Запустите образ без `DATABASE_URL` и без `REDIS_URL`, и он запустит собственные PostgreSQL 17 и Redis внутри контейнера, привязанные к loopback, со всеми данными на томе `/data`. Это возвращает привычный запуск одной командой `docker run` для быстрого старта, домашней лаборатории и обновлений с 1.x. Это удобный путь, а не продакшен-развертывание: для продакшена запускайте стек Compose из трех контейнеров с отдельными PostgreSQL и Redis. Встроенный режим требует запуска контейнера от root и несовместим со средами с произвольным UID (OpenShift, Kubernetes `runAsNonRoot`); используйте там Compose.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `EMBEDDED` | `auto` | Включается автоматически, когда `DATABASE_URL` и `REDIS_URL` не заданы. Задайте `0`, чтобы отключить его (тогда приложение сразу завершается с ошибкой, если не задан внешний `DATABASE_URL`/`REDIS_URL`, а не молча запускает базу данных внутри контейнера). |
| `REDIS_MAXMEMORY` | `512mb` | Ограничение памяти для встроенного Redis (только встроенный режим). Уменьшите его на хостах с ограниченной памятью, например на Raspberry Pi. |
| `EMBEDDED_REDIS_TIMEOUT_S` | `180` | Секунды, в течение которых загрузка ждет ответа встроенного Redis на `PING`, прежде чем сдаться. По истечении времени контейнер останавливается и записывает причину в журнал, а не зависает. Целое число секунд от 1 до 999999; значения «без ограничения» нет, потому что бесконечное ожидание и есть сбой, для предотвращения которого нужен этот предел. Увеличивайте, только если медленный хост его превышает. |
| `EMBEDDED_POSTGRES_TIMEOUT_S` | `600` | То же для встроенного PostgreSQL. Отсчет начинается после завершения `initdb` при первой загрузке, поэтому охватывает запуск сервера и восстановление после сбоя, а не первоначальное создание базы данных. |

Обновление с 1.x: положите старый `snapotter.db` по пути `/data/snapotter.db` в томе, и встроенный режим импортирует его во встроенный PostgreSQL при первой загрузке. Импорт выполняется один раз; последующие загрузки его пропускают.

Примечание о телеметрии: встроенный режим наследует значение аналитики по умолчанию из образа, как любая другая конфигурация. Опубликованный образ поставляется с включенной аналитикой; соберите с `--build-arg SNAPOTTER_ANALYTICS=off` или используйте отказ администратора в приложении, чтобы ее отключить.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `MAX_UPLOAD_SIZE_MB` | `0` (без ограничения) | Максимальный размер файла на одну загрузку в мегабайтах. Задайте 0 для отсутствия ограничения. Опубликованный образ поставляется с `0`; сборка из исходников начинается со 100. |
| `MAX_BATCH_SIZE` | `0` (без ограничения) | Максимальное число файлов в одном пакетном запросе. Задайте 0 для отсутствия ограничения. Опубликованный образ поставляется с `0`; сборка из исходников начинается со 100. |
| `CONCURRENT_JOBS` | `0` (авто) | Число пакетных задач, выполняемых параллельно. Задайте 0 для автоопределения по доступным ядрам ЦП. |
| `MAX_MEGAPIXELS` | `0` (без ограничения) | Максимально допустимое разрешение изображения в мегапикселях. Задайте 0 для отсутствия ограничения. |
| `MAX_WORKER_THREADS` | `0` (авто) | Максимальное число рабочих потоков для обработки изображений. Задайте 0 для автоопределения по доступным ядрам ЦП. |
| `PROCESSING_TIMEOUT_S` | `0` (без ограничения) | Максимальное время обработки одного запроса в секундах. Задайте 0, чтобы отключить тайм-аут. |
| `MAX_PIPELINE_STEPS` | `20` | Максимальное число шагов в конвейере. Задайте 0 для отсутствия ограничения. |
| `MAX_CANVAS_PIXELS` | `0` (без ограничения) | Максимальный размер холста в пикселях для выходных изображений. Задайте 0 для отсутствия ограничения. |
| `MAX_SVG_SIZE_MB` | `50` | Наибольший SVG, принимаемый до санитизации, в мегабайтах. `0` здесь ведет себя иначе, чем в соседних строках. Он полностью снимает ограничение размера перед разбором, а не повышает его, поэтому оставьте это значение заданным. |
| `MAX_PDF_PAGES` | `0` (без ограничения) | Максимальное число страниц PDF для преобразования PDF в изображение. Задайте 0 для отсутствия ограничения. |

### Движки {#engines}

SnapOtter ищет каждый бинарный файл обработки в `$PATH` внутри контейнера, поэтому эти переменные остаются пустыми, пока вы не смонтируете собственную сборку.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `FFMPEG_PATH` | (пусто) | Путь к бинарному файлу `ffmpeg`, на котором работают инструменты для видео и аудио. |
| `FFPROBE_PATH` | (пусто) | Путь к `ffprobe`, который читает медиафайлы перед обработкой. Укажите ту же сборку, что и для `FFMPEG_PATH`. |
| `QPDF_PATH` | (пусто) | Путь к `qpdf`, используется инструментами PDF и для проверки загруженных PDF. |
| `SOFFICE_PATH` | (пусто) | Путь к `soffice` из LibreOffice, используется для преобразований офисных документов. |
| `PDFCPU_PATH` | (пусто) | Путь к `pdfcpu`, используется некоторыми инструментами PDF. |
| `SNAPOTTER_HW_ACCEL` | (пусто) | Семейство аппаратных видеокодеров, `nvenc` или `vaapi`. Пусто означает программное кодирование. |

`SNAPOTTER_HW_ACCEL` требует ffmpeg, собранный с этим семейством кодеров, а в ffmpeg из образа нет ни того, ни другого. С собственным бинарным файлом образа настройка откатывается к программному кодированию и сообщает об этом в журнале запуска. Чтобы ее использовать, смонтируйте собственную сборку ffmpeg, направьте на нее `FFMPEG_PATH` и `FFPROBE_PATH` и передайте контейнеру устройство GPU. Для `nvenc` задайте также `NVIDIA_DRIVER_CAPABILITIES=compute,utility,video`: образ запрашивает только `compute,utility`, а без `video` среда выполнения NVIDIA не монтирует библиотеку кодирования, поэтому кодер указан в списке, но каждое кодирование завершается ошибкой. Переопределение пути, которого не существует или который не исполняемый, также называется в журнале запуска, и каждая задача, которой нужен этот бинарный файл, завершается ошибкой, пока вы не исправите путь или не уберете его.

Опубликованные файлы Compose передают все шесть из `.env`, поэтому достаточно задать их там.

## Пример Docker {#docker-example}

```yaml
services:
  SnapOtter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - SnapOtter-data:/data
      - SnapOtter-workspace:/tmp/workspace
    environment:
      - AUTH_ENABLED=true
      - DEFAULT_USERNAME=admin
      - DEFAULT_PASSWORD=changeme
      - DATABASE_URL=postgres://snapotter:snapotter@postgres:5432/snapotter
      - REDIS_URL=redis://redis:6379
      - MAX_UPLOAD_SIZE_MB=200
      - CONCURRENT_JOBS=4
      - FILE_MAX_AGE_HOURS=12
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: snapotter
      POSTGRES_PASSWORD: snapotter     # Change this for non-local deployments
      POSTGRES_DB: snapotter
    volumes:
      - SnapOtter-pgdata:/var/lib/postgresql/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U snapotter -d snapotter"]
      interval: 10s
      timeout: 5s
      retries: 12

  redis:
    image: redis:8-alpine
    command: ["redis-server", "--maxmemory-policy", "noeviction", "--appendonly", "yes"]
    volumes:
      - SnapOtter-redisdata:/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 12

volumes:
  SnapOtter-data:
  SnapOtter-workspace:
  SnapOtter-pgdata:
  SnapOtter-redisdata:
```

## Тома {#volumes}

Стек Docker Compose использует четыре тома:

- `/data` (app) - модели ИИ, виртуальное окружение Python и файлы пользователей. Смонтируйте его, чтобы сохранять загруженные файлы и установленные пакеты ИИ между перезапусками.
- `/tmp/workspace` (app) - временное хранилище для обрабатываемых файлов. Он может быть временным, но его монтирование не дает заполнить записываемый слой контейнера.
- `SnapOtter-pgdata` (postgres) - каталог данных PostgreSQL. Здесь хранятся все реляционные данные (пользователи, настройки, конвейеры, задачи, журнал аудита). Резервное копирование через `pg_dump` или снимок тома.
- `SnapOtter-redisdata` (redis) - файл Redis только для добавления для надежных очередей задач.
