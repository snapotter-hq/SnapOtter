# Конфигурация {#configuration}

Вся настройка выполняется через переменные окружения. У каждой переменной есть разумное значение по умолчанию, поэтому SnapOtter работает сразу, без их задания.

## Переменные окружения {#environment-variables}

### Сервер {#server}

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `1349` | Порт, который слушает сервер. |
| `HOST` | `0.0.0.0` | IP-адрес, который слушает сервер. В сети bridge (по умолчанию для `docker run` и Compose) оставьте `0.0.0.0` (или `::`), иначе опубликованные порты перестанут работать. При нативной установке или для контейнера в сети хоста `127.0.0.1` закрывает API от сети; для удаленного доступа поставьте перед ним обратный прокси. [Встроенный режим](#embedded-mode) работает только с `0.0.0.0`, `::` или `127.0.0.1`, потому что его проверка запуска обращается к `127.0.0.1`. С любым другим адресом, включая `::1`, контейнер никогда не считается запущенным, а последующий сбой останавливает его вместо перезапуска сервера. Любое значение, которое не является IP-адресом, включая `localhost`, останавливает сервер при запуске. |
| `BASE_PATH` | (пусто) | Публичный путь развертывания, например `/snapotter`. Пустое значение или `/` обслуживает корень домена. Применяется во время выполнения; пересборка образа не требуется. |
| `RATE_LIMIT_PER_MIN` | `1000` | Максимальное число запросов в минуту с одного IP. Задайте 0, чтобы отключить ограничение частоты. |
| `API_KEYS_RATE_LIMIT_PER_MIN` | `30` | Максимальное число запросов в минуту с одного IP к конечным точкам управления ключами API (список, создание, отзыв). Ключи, используемые для вызовов инструментов, это не затрагивает. Задайте `0` для отсутствия ограничения. |
| `CORS_ORIGIN` | (пусто) | Разрешенные источники для CORS через запятую или пусто для одного и того же источника. |
| `LOG_LEVEL` | `info` | Подробность журнала. Одно из: `fatal`, `error`, `warn`, `info`, `debug`, `trace`. |
| `TRUST_PROXY` | `loopback,linklocal,uniquelocal` | Какие узлы могут задавать IP клиента через `X-Forwarded-For`. По умолчанию доверяется только узлу из частной сети, поэтому обратный прокси в сети Docker или в локальной сети считается доверенным, а поддельный заголовок публичного клиента нет. Задавайте `true` только если подконтрольный вам прокси стоит перед сервером на публичном адресе. |
| `SNAPOTTER_ANALYTICS_DEFAULT` | `on` | Задайте `off`, чтобы запустить новый экземпляр с выключенной настройкой «Anonymous Product Analytics»: тогда он ничего не отправляет с самой первой загрузки. Переменная лишь заполняет настройку, пока ее никто не выбрал. Как только настройка сохранена, администратором или этой переменной, изменение переменной ни на что не влияет; администратор по-прежнему может включить аналитику в Settings > System > Privacy. |

### Аутентификация {#authentication}

Два приведенных ниже логических значения принимают только `true` и `false`. Все остальное, `1`, `yes` или `on`, не проходит проверку, и сервер завершается до начала прослушивания.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AUTH_ENABLED` | `true` | Требовать вход. Задайте `false`, чтобы работать вообще без учетных записей, что дает права администратора каждому запросу, поэтому используйте это только в доверенной сети. |
| `DEFAULT_USERNAME` | `admin` | Имя пользователя для начальной учетной записи администратора. Используется только при первом запуске. |
| `DEFAULT_PASSWORD` | `admin` | Пароль для начальной учетной записи администратора. Смените его после первого входа. |
| `MAX_USERS` | `0` (без ограничения) | Максимальное число зарегистрированных учетных записей. Задайте 0 для отсутствия ограничения. |
| `SESSION_DURATION_HOURS` | `168` | Срок жизни сессии входа в часах (по умолчанию 7 дней). |
| `SKIP_MUST_CHANGE_PASSWORD` | `false` | Задайте `true`, чтобы пропустить принудительный запрос смены пароля при первом входе. |
| `LOGIN_ATTEMPT_LIMIT` | `30` | Максимальное число запросов на вход в минуту с одного IP. Последующие попытки получают `429` до конца минуты. Повторные неудачи для одного имени пользователя обычно достигают `LOGIN_THROTTLE_MAX_FAILURES` раньше. Администратор может переопределить значение в Настройки > Система. Задайте `0` для отсутствия ограничения. Сборка из исходников начинается с 10. |
| `LOGIN_THROTTLE_MAX_FAILURES` | `10` | Число неудачных входов по паролю, которое может быть у одного имени пользователя в пределах `LOGIN_THROTTLE_WINDOW_S`, прежде чем следующие попытки для него получат `429`, с какого бы IP они ни приходили. Их снова пропускают, по мере того как самые старые неудачи выходят за пределы окна. Задайте 0, чтобы отключить ограничение. |
| `LOGIN_THROTTLE_WINDOW_S` | `900` | Длительность этого окна в секундах. Должна быть не меньше 1; при 0 сервер отказывается запускаться. |

### Хранилище {#storage}

| Переменная | По умолчанию | Описание |
|---|---|---|
| `STORAGE_MODE` | `local` | `local` или `s3`. S3 и MinIO требуют лицензию с функцией s3_storage, а также переменные `S3_*` ниже. |
| `DATABASE_URL` | `postgres://snapotter:snapotter@localhost:5432/snapotter` | Строка подключения к PostgreSQL и подключение, через которое обслуживается каждый запрос. В версии 2.3.0 и новее задайте также `DATABASE_MIGRATION_URL`, и это станет ролью времени выполнения с минимальными привилегиями, имеющей только DML на таблицах приложения и ничего больше. Стек Compose направляет ее на свой сервис `postgres`; оставьте ее незаданной (вместе с `REDIS_URL`), чтобы получить встроенный режим. Чтобы подключиться через unix-сокет, укажите каталог сокета в `host`, как в `postgres://user:pass@localhost/snapotter?host=/var/run/postgresql`, и примонтируйте этот каталог в контейнер. |
| `DATABASE_MIGRATION_URL` | (пусто) | Привилегированное подключение, используемое только при загрузке для выполнения миграций и выдачи прав роли времени выполнения, затем закрываемое до первого запроса. Оставьте пустым, и SnapOtter будет работать с одной ролью, а `DATABASE_URL` будет выполнять обе задачи. См. [Роли с минимальными привилегиями](/ru/guide/database#least-privilege-roles). |
| `REDIS_URL` | `redis://localhost:6379` | Строка подключения к Redis (используется для очередей задач BullMQ). Compose направляет ее на свой сервис `redis`. Для unix-сокета используйте `unix:///run/redis/redis.sock?db=5` (добавьте `&password=...`, если Redis его требует) и примонтируйте сокет в контейнер. |
| `WORKSPACE_PATH` | `./tmp/workspace` | Каталог для временных файлов во время обработки. Очищается автоматически. Образ задает `/tmp/workspace`. |
| `FILES_STORAGE_PATH` | `./data/files` | Каталог для постоянных файлов пользователей (загруженные изображения, сохраненные результаты). Образ задает `/data/files`. |
| `MAX_STORAGE_PER_USER_MB` | `5000` | Ограничение в мегабайтах на то, что каждый пользователь хранит в библиотеке Files. Сохранение, которое превысило бы его, отклоняется с указанием занятого объема и лимита. Квота, заданная для пользователя, имеет приоритет. Задайте 0 для отсутствия ограничения. |

### Объектное хранилище S3 {#s3-object-storage}

Читаются только при `STORAGE_MODE=s3`. Если пропустить любую из трех обязательных, запуск завершится ошибкой с именем пропущенной переменной.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `S3_BUCKET` | (пусто) | Бакет, в котором хранятся загрузки и результаты. Обязательно. |
| `S3_ACCESS_KEY_ID` | (пусто) | Ключ доступа. Обязательно. В контейнере вместо этого его можно смонтировать через `S3_ACCESS_KEY_ID_FILE`. |
| `S3_SECRET_ACCESS_KEY` | (пусто) | Секретный ключ. Обязательно. То же соглашение о файлах: `S3_SECRET_ACCESS_KEY_FILE`. |
| `S3_REGION` | `us-east-1` | Регион бакета. |
| `S3_ENDPOINT` | (пусто) | Пользовательский эндпоинт для MinIO, R2, Backblaze и других S3-совместимых хранилищ. Пусто означает AWS. |
| `S3_FORCE_PATH_STYLE` | `false` | Задайте `true` для MinIO и всего остального, что требует `endpoint/bucket/key` вместо адресации virtual-host. |
| `S3_PREFIX` | (пусто) | Префикс ключа, чтобы один бакет мог содержать несколько экземпляров. |

### Шифрование при хранении {#encryption-at-rest}

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATA_ENCRYPTION_KEY` | (пусто) | 64 шестнадцатеричных символа (32 байта). Шифрует чувствительные настройки, хранящиеся в базе данных. Все, что не состоит из 64 шестнадцатеричных символов, отклоняется при запуске. |
| `DATA_ENCRYPTION_KEY_PREVIOUS` | (пусто) | Ключ, от которого вы отказываетесь, в том же формате. Задайте оба при ротации, чтобы существующие строки по-прежнему расшифровывались, а затем уберите этот. |

### Встроенный режим {#embedded-mode}

Запустите образ без `DATABASE_URL` и без `REDIS_URL`, и он запустит собственные PostgreSQL 17 и Redis внутри контейнера, привязанные к loopback, со всеми данными на томе `/data`. Это возвращает привычный запуск одной командой `docker run` для быстрого старта, домашней лаборатории и обновлений с 1.x. Это удобный путь, а не продакшен-развертывание: для продакшена запускайте стек Compose из трех контейнеров с отдельными PostgreSQL и Redis. Встроенный режим требует запуска контейнера от root и несовместим со средами с произвольным UID (OpenShift, Kubernetes `runAsNonRoot`); используйте там Compose.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `EMBEDDED` | `auto` | Включается автоматически, когда `DATABASE_URL` и `REDIS_URL` не заданы. Задайте `0`, чтобы отключить его (тогда приложение сразу завершается с ошибкой, если не задан внешний `DATABASE_URL`/`REDIS_URL`, а не молча запускает базу данных внутри контейнера). |
| `REDIS_MAXMEMORY` | `512mb` | Ограничение памяти для встроенного Redis (только встроенный режим). Уменьшите его на хостах с ограниченной памятью, например на Raspberry Pi. |
| `EMBEDDED_PG_PORT` | `5432` | Порт loopback для встроенного PostgreSQL (только встроенный режим). Меняйте его, только если контейнер находится в общей сети, где порт 5432 занят, например при `--network host`. Он должен отличаться от `EMBEDDED_REDIS_PORT` и быть больше 1023, потому что PostgreSQL работает от непривилегированного пользователя, который не может занять привилегированный порт в сети хоста. |
| `EMBEDDED_REDIS_PORT` | `6379` | То же для встроенного Redis, который тоже работает от непривилегированного пользователя. |
| `EMBEDDED_DB_PASSWORDS` | (пусто) | Задайте `1`, чтобы при следующей загрузке сгенерировать случайные пароли для ролей встроенного PostgreSQL и для Redis; они хранятся в `/data/.embedded-db-secrets`. После этого для входа по TCP нужны эти пароли. На томе, впервые созданном версией 2.3.0 или новее, суперпользователь PostgreSQL вообще не может войти по TCP; на более старом томе владелец базы данных является суперпользователем, и защищает его именно его пароль. Используйте эту настройку всегда, когда сеть контейнера используют и другие программы, например при `--network host`. Для этого тома она остается включенной: пароли используются при каждой загрузке, даже если вы уберете эту переменную, а удаление `/data/.embedded-db-secrets` дает лишь новые пароли или, если переменная не задана, загрузку, которая завершается ошибкой. Если контейнер не запускается, потому что один из этих файлов поврежден, удалите этот файл командой `docker run --rm -v <volume>:/data --entrypoint rm snapotter/snapotter:<your tag> -r /data/.embedded-db-secrets/<name>` и снова запустите контейнер; следующая загрузка создаст новый. Переменная принимает `1`, `0` или пустое значение, а любое другое значение останавливает загрузку. |
| `EMBEDDED_REDIS_TIMEOUT_S` | `180` | Секунды, в течение которых загрузка ждет ответа встроенного Redis на `PING`, прежде чем сдаться. По истечении времени контейнер останавливается и записывает причину в журнал, а не зависает. Целое число секунд от 1 до 999999; значения «без ограничения» нет, потому что бесконечное ожидание и есть сбой, для предотвращения которого нужен этот предел. Увеличивайте, только если медленный хост его превышает. |
| `EMBEDDED_POSTGRES_TIMEOUT_S` | `600` | То же для встроенного PostgreSQL. Отсчет начинается после завершения `initdb` при первой загрузке, поэтому охватывает запуск сервера и восстановление после сбоя, а не первоначальное создание базы данных. |

Обновление с 1.x: положите старый `snapotter.db` по пути `/data/snapotter.db` в томе, и встроенный режим импортирует его во встроенный PostgreSQL при первой загрузке. Импорт выполняется один раз; последующие загрузки его пропускают.

Примечание о телеметрии: встроенный режим наследует значение аналитики по умолчанию из образа, как любая другая конфигурация. Опубликованный образ поставляется с включённой аналитикой; чтобы отключить её, соберите с `--build-arg SNAPOTTER_ANALYTICS=off`, задайте `SNAPOTTER_ANALYTICS_DEFAULT=off` до первой загрузки или используйте отказ администратора в приложении.

### Ограничения обработки {#processing-limits}

| Переменная | По умолчанию | Описание |
|---|---|---|
| `MAX_UPLOAD_SIZE_MB` | `0` (без ограничения) | Максимальный размер файла на одну загрузку в мегабайтах. Задайте 0 для отсутствия ограничения. Опубликованный образ поставляется с `0`; сборка из исходников начинается со 100. |
| `MAX_BATCH_SIZE` | `0` (без ограничения) | Максимальное число файлов в одном пакетном запросе. Задайте 0 для отсутствия ограничения. Опубликованный образ поставляется с `0`; сборка из исходников начинается со 100. |
| `CONCURRENT_JOBS` | `0` (авто) | Число пакетных задач, выполняемых параллельно. Задайте 0 для автоопределения по доступным ядрам ЦП. |
| `MAX_MEGAPIXELS` | `0` (без ограничения приложения) | Максимально допустимое разрешение изображения в мегапикселях. Задайте 0, чтобы снять собственное ограничение SnapOtter. Декодер изображений всё равно отклоняет всё, что больше примерно 268 Мпикс (16383 x 16383 пикселей), поэтому значение выше 268 дополнительного эффекта не даёт. |
| `MAX_CPU_UPSCALE_MP` | `4` | Наибольший вход в мегапикселях, который ИИ-увеличение принимает на хосте без GPU. Увеличенный результат также ограничен 16-кратным значением этого параметра (по умолчанию 64 MP), поэтому высокий коэффициент масштабирования дополнительно снижает лимит входа. Более крупное изображение уменьшается до нужного размера перед увеличением; если после этого результат не будет больше оригинала, запрос отклоняется. Lanczos пропускает ограничение входа, но не ограничение результата. Задайте 0 для отсутствия ограничения, что требует много ОЗУ: RealESRGAN всегда создает внутри буфер 4x. |
| `MAX_WORKSPACE_SIZE_GB` | `0` (без ограничения) | Ограничение в ГБ на суммарный размер загрузок и сохраненных результатов в рабочем пространстве. После его превышения загрузки и запросы к инструментам получают 503, пока файлы не истекут по `FILE_MAX_AGE_HOURS`. Задайте 0 для отсутствия ограничения; локальное хранилище все равно отклоняет запись с 503, когда на диске остается менее 0,5 ГБ. Опубликованный образ поставляется с `0`; сборка из исходников начинается с 10. |
| `MAX_WORKER_THREADS` | `0` (авто) | Максимальное число рабочих потоков для обработки изображений. Задайте 0 для автоопределения по доступным ядрам ЦП. |
| `PROCESSING_TIMEOUT_S` | `0` (без ограничения) | Тайм-аут каждого вызова Python sidecar, который запускает инструменты ИИ, в секундах. Задайте 0, чтобы не ограничивать. Он не ограничивает задачи с изображениями, PDF или медиа; это делают `JOB_TIMEOUT_FAST_S` и `JOB_TIMEOUT_LONG_S`. |
| `AI_SIDECAR_IDLE_TIMEOUT` | `600` | Сколько секунд Python sidecar для ИИ и среда выполнения точного OCR простаивают, прежде чем завершиться и освободить память (около 1,3 GB и 0,7 GB после прогрева). Оба снова запускаются при следующем запросе, поэтому первый вызов ИИ после завершения из-за простоя оплачивает запуск библиотек, это несколько секунд. Задайте 0, чтобы они продолжали работать. Значение по умолчанию совпадает с `AI_SESSION_IDLE_TIMEOUT`, поэтому загруженные модели не выгружаются раньше, чем предусматривает эта настройка. Если вы увеличиваете `AI_SESSION_IDLE_TIMEOUT`, увеличьте и это значение соответственно. |
| `AI_SESSION_IDLE_TIMEOUT` | `0` (авто) | Число секунд, в течение которых загруженная ИИ-модель остается в кеше sidecar после последнего использования. Автоматическое значение: 600. Читается Python sidecar, который также сбрасывает все кешированные модели при завершении после `AI_SIDECAR_IDLE_TIMEOUT`. |
| `AI_SESSION_CACHE_BYTES` | `0` (авто) | Бюджет памяти для кешированных ИИ-моделей в байтах. Автоматическое значение: 40% памяти GPU, а на хосте только с ЦП кеширования нет вообще. Задайте его на хосте с ЦП, чтобы кешировать модели в ОЗУ; задайте 1, чтобы отключить кеширование на хосте с GPU. Читается Python sidecar. |
| `MAX_AI_JOBS_PER_USER` | `5` | Число ИИ-задач для одного файла, которое один пользователь может иметь в очереди или в работе одновременно. Остальные получают `429`, пока одна не завершится. Пул ИИ выполняет по одной задаче, поэтому это не дает одному пользователю занять его целиком. Пакетные и конвейерные запуски ИИ не учитываются. Задайте 0 для отсутствия ограничения. |
| `JOB_TIMEOUT_FAST_S` | `120` | Предельное время одной задачи в быстрых пулах (инструменты для изображений и документов), в секундах. Задача, которая выполняется дольше, завершается ошибкой тайм-аута. Задайте 0 для отсутствия ограничения. |
| `JOB_TIMEOUT_LONG_S` | `7200` | Предельное время одной задачи в длинных пулах (инструменты ИИ и медиа, а также любой инструмент, помеченный как длительный), в секундах. Задайте 0 для отсутствия ограничения. PDF OCR в режимах Balanced и Best сам продлевает свое предельное время в зависимости от числа страниц (2 и 5 минут на страницу), до 6 часов, поэтому для большого PDF повышать это значение не нужно. |
| `SYNC_WAIT_MS` | `8000` | Сколько запрос к инструменту ждет свою задачу, прежде чем API перестанет ждать и вернет `202` с идентификатором задачи для отслеживания через SSE, в миллисекундах. Задача при этом не останавливается. Задайте 0, чтобы ждать задачу сколько бы она ни выполнялась. |
| `MAX_PIPELINE_STEPS` | `20` | Максимальное число шагов в конвейере. Задайте 0 для отсутствия ограничения. |
| `MAX_PIPELINE_STEP_PIXELS` | `67108864` | Наибольший результат, который может запросить шаг конвейера, как ширина на высоту в пикселях (по умолчанию 8192 x 8192). Шаг, настройки которого запрашивают больше, отклоняется до запуска конвейера. Задайте 0 для отсутствия ограничения. |
| `MAX_CANVAS_PIXELS` | `0` (без ограничения) | Максимальный размер холста в пикселях для выходных изображений. Задайте 0 для отсутствия ограничения. |
| `MAX_SVG_SIZE_MB` | `50` | Наибольший SVG, принимаемый до санитизации, в мегабайтах. `0` здесь ведет себя иначе, чем в соседних строках. Он полностью снимает ограничение размера перед разбором, а не повышает его, поэтому оставьте это значение заданным. |
| `MAX_PDF_PAGES` | `0` (без ограничения) | Максимальное число страниц PDF для преобразования PDF в изображение. Задайте 0 для отсутствия ограничения. |
| `MAX_VIDEO_DURATION_S` | `0` (без ограничения) | Самое длинное видео, которое принимают видеоинструменты, в секундах. Более длинные файлы отклоняются до обработки, а в ошибке указываются длительность и лимит. Задайте 0 для отсутствия ограничения. |
| `MAX_AUDIO_DURATION_S` | `0` (без ограничения) | То же для аудиоинструментов. |
| `MAX_VIDEO_BITRATE_KBPS` | `0` (без ограничения) | Наибольший общий битрейт, который принимают видеоинструменты, в килобитах в секунду. Задайте 0 для отсутствия ограничения. |
| `PREVIEW_TIMEOUT_S` | `300` | Предельное время кодирования одного клипа предпросмотра видео- или аудиофайла в браузере, в секундах. Предпросмотр документов использует вместо этого `LIBREOFFICE_TIMEOUT_S`. Задайте 0 для отсутствия ограничения. |
| `LIBREOFFICE_TIMEOUT_S` | `120` | Предельное время одного преобразования LibreOffice (Word, Excel и PowerPoint в PDF, конвертеры документов и предпросмотр документов), в секундах. Задайте `0` для отсутствия ограничения. |
| `GIF_BG_MAX_FRAMES` | `150` | Наибольшее число кадров в одной анимации, которое принимает инструмент «Удалить фон GIF». Более длинные анимации получают `400` с указанием числа кадров. Задайте 0 для отсутствия ограничения по кадрам; отдельный пиксельный бюджет все равно действует. |
| `SUBPROCESS_MEMORY_LIMIT_MB` | `0` (выкл.) | Ограничение адресного пространства в мегабайтах для каждого из этих вспомогательных процессов: ffmpeg, ffprobe, Ghostscript, qpdf, LibreOffice, pandoc и pdfcpu в медиа- и документных движках, а для изображений также exiftool, декодеры и кодировщики HEIF, JPEG XL и JPEG 2000, декодер RAW и запасной декодер ffmpeg. ImageMagick не ограничивается, потому что у него есть собственные лимиты памяти, как и ИИ-sidecar. Процесс, превысивший лимит, завершается принудительно, а не загоняет весь контейнер под действие механизма нехватки памяти. Ограничивается виртуальная, а не резидентная память, поэтому задавайте значение заметно выше того, что процесс реально использует. Больше всего нужно кодировщику JPEG XL: для изображения в 24 Мпикс требовалось около 1,8 ГБ, а при 1 ГБ он завершался ошибкой, и увеличение числа потоков или процессоров мало что меняет. Пока лимит задан, кодировщик HEIF работает не более чем в двух рабочих потоках, что снижает потребление при кодировании 24 Мпикс примерно до 0,8 ГБ ценой более медленного кодирования. Начните с `2048` и уменьшайте значение только после проверки самых больших файлов. Задайте 0, чтобы отключить и полагаться на лимит памяти контейнера. |
| `MAX_SETTINGS_PAYLOAD_KB` | `64` | Наибольший размер поля `settings`, которое может содержать запрос к инструменту, в килобайтах, с подсчетом в байтах UTF-8. Запросы сверх ограничения получают `400`. Задайте 0 для отсутствия ограничения. Реальные настройки инструментов намного меньше 64 KB, поэтому увеличивайте это значение, только если клиент отправляет необычно большие настройки. |
| `MAX_SUBTITLE_SIZE_MB` | `1` | Наибольший файл субтитров (`.srt`, `.vtt`, `.ass`), который принимают «Вжечь субтитры» и «Встроить субтитры», в мегабайтах. Более крупные файлы получают `400` с указанием размера файла и лимита. Задайте 0 для отсутствия ограничения. Файл субтитров к полнометражному фильму обычно намного меньше 1 MB. |
| `MAX_METADATA_TAG_LENGTH` | `10000` | Самое длинное значение, которое «Редактировать метаданные» записывает в один тег (исполнитель, описание, ключевые слова и так далее), в символах. Более длинные значения получают `400` с указанием тега и лимита. Задайте 0 для отсутствия ограничения. Увеличьте его, если храните длинные подписи или описания. Значение тега также должно уместиться в `MAX_SETTINGS_PAYLOAD_KB` и в ограничение операционной системы на один аргумент (128 KB в Linux). |

### Инструменты ИИ {#ai-tools}

Эти переменные читает Python sidecar. Задайте их в окружении контейнера (или в `.env` для опубликованных файлов Compose) и перезапустите.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SNAPOTTER_GPU` | (пусто) | Задайте `0`, `false` или `no`, чтобы все инструменты ИИ работали на ЦП, даже если GPU есть. Любое другое значение или пустое поле позволяет SnapOtter использовать обнаруженный GPU. Применяйте, если у небольшого GPU посреди задачи заканчивается память или если из-за проблемы с драйвером запуски на GPU завершаются ошибкой. Чаще это актуально для нативных установок и LXC, которые теперь используют GPU, когда установлен pip-пакет cuDNN. На ЦП задачи выполняются медленнее, а для увеличения действует `MAX_CPU_UPSCALE_MP`. |
| `SD15_INPAINT_DIR` | `$MODELS_PATH/sd15-inpainting` | Папка с моделью Stable Diffusion 1.5 для инпейнтинга (формат diffusers), которую «Удаление объектов» использует в режиме высокого качества. Сюда ее кладет пакет функций `inpaint-hq`, поэтому меняйте путь, только если храните модель в другом месте. `MODELS_PATH` SnapOtter задает как `ai/models` внутри каталога данных. |
| `SD15_INPAINT_STEPS` | `28` | Число шагов шумоподавления на одно удаление. Больше шагов может добавить детализации, а время растет пропорционально. |
| `SD15_INPAINT_STRENGTH` | `0.95` | Насколько сильно модель может перерисовать область под маской, от 0 до 1. Меньшие значения сохраняют больше исходных пикселей (область сначала заполняется по окружению, затем слегка дорабатывается). Большие значения позволяют модели перерисовывать свободнее, а `1` игнорирует окружение и рисует с нуля из шума, из-за чего чаще появляется выдуманный новый объект. |
| `SD15_INPAINT_GUIDANCE` | `7.0` | Насколько строго модель следует подсказкам. Чем выше значение, тем буквальнее она им следует; очень высокие значения могут давать резкий результат. |
| `SD15_INPAINT_PROMPT` | (пусто) | Текст, описывающий, что дорисовать в удаленной области. Для удаления лучше всего оставить пустым, тогда модель продолжает окружение. |
| `SD15_INPAINT_NEGATIVE` | `object, person, text, watermark, artifact, blurry, distorted, extra limbs` | Текст, описывающий, чего в удаленной области быть не должно. Значение по умолчанию не дает дорисовывать на месте пробела новый объект. |
| `SD15_INPAINT_SEED` | `0` | Начальное значение генератора случайных чисел. При фиксированном значении одно и то же изображение с той же маской каждый раз обрабатывается одинаково. Измените его, чтобы получить другой результат. |

### Движки {#engines}

SnapOtter ищет каждый бинарный файл обработки в `$PATH` внутри контейнера, поэтому эти переменные остаются пустыми, пока вы не смонтируете собственную сборку.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `FFMPEG_PATH` | (пусто) | Путь к бинарному файлу `ffmpeg`, на котором работают инструменты для видео и аудио. |
| `FFPROBE_PATH` | (пусто) | Путь к `ffprobe`, который читает медиафайлы перед обработкой. Укажите ту же сборку, что и для `FFMPEG_PATH`. |
| `QPDF_PATH` | (пусто) | Путь к `qpdf`, используется инструментами PDF и для проверки загруженных PDF. |
| `SOFFICE_PATH` | (пусто) | Путь к `soffice` из LibreOffice, используется для преобразований офисных документов. |
| `PDFCPU_PATH` | (пусто) | Путь к `pdfcpu`, используется некоторыми инструментами PDF. |
| `GS_PATH` | (пусто) | Путь к `gs` из Ghostscript, используется инструментами PDF и PDF OCR. |
| `PANDOC_PATH` | (пусто) | Путь к `pandoc`, используется для преобразований документов. |
| `SNAPOTTER_FONT_FILE` | (пусто) | Файл шрифта для текста, наносимого на видео (вшивание субтитров, водяной знак на видео). Пусто означает первый шрифт, который найдется в образе. |
| `SNAPOTTER_FONT_FAMILY` | (пусто) | Имя семейства шрифта `SNAPOTTER_FONT_FILE`. Пусто означает `Sans`. |
| `SNAPOTTER_HW_ACCEL` | (пусто) | Семейство аппаратных видеокодеров, `nvenc` или `vaapi`. Пусто означает программное кодирование. |

`SNAPOTTER_HW_ACCEL` требует ffmpeg, собранный с этим семейством кодеров, а в ffmpeg из образа нет ни того, ни другого. С собственным бинарным файлом образа настройка откатывается к программному кодированию и сообщает об этом в журнале запуска. Чтобы ее использовать, смонтируйте собственную сборку ffmpeg, направьте на нее `FFMPEG_PATH` и `FFPROBE_PATH` и передайте контейнеру устройство GPU. Для `nvenc` задайте также `NVIDIA_DRIVER_CAPABILITIES=compute,utility,video`: образ запрашивает только `compute,utility`, а без `video` среда выполнения NVIDIA не монтирует библиотеку кодирования, поэтому кодер указан в списке, но каждое кодирование завершается ошибкой. Переопределение пути, которого не существует или который не исполняемый, также называется в журнале запуска, и каждая задача, которой нужен этот бинарный файл, завершается ошибкой, пока вы не исправите путь или не уберете его.

Опубликованные файлы Compose передают их все из `.env`, поэтому достаточно задать их там.

## Пример Docker {#docker-example}

```yaml
services:
  SnapOtter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - SnapOtter-data:/data
      - SnapOtter-workspace:/tmp/workspace
    environment:
      - AUTH_ENABLED=true
      - DEFAULT_USERNAME=admin
      - DEFAULT_PASSWORD=changeme
      - DATABASE_URL=postgres://snapotter:snapotter@postgres:5432/snapotter
      - REDIS_URL=redis://redis:6379
      - MAX_UPLOAD_SIZE_MB=200
      - CONCURRENT_JOBS=4
      - FILE_MAX_AGE_HOURS=12
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: snapotter
      POSTGRES_PASSWORD: snapotter     # Change this for non-local deployments
      POSTGRES_DB: snapotter
    volumes:
      - SnapOtter-pgdata:/var/lib/postgresql/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U snapotter -d snapotter"]
      interval: 10s
      timeout: 5s
      retries: 12

  redis:
    image: redis:8-alpine
    command: ["redis-server", "--maxmemory-policy", "noeviction", "--appendonly", "yes"]
    volumes:
      - SnapOtter-redisdata:/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 12

volumes:
  SnapOtter-data:
  SnapOtter-workspace:
  SnapOtter-pgdata:
  SnapOtter-redisdata:
```

## Тома {#volumes}

Стек Docker Compose использует четыре тома:

- `/data` (app) - модели ИИ, виртуальное окружение Python и файлы пользователей. Смонтируйте его, чтобы сохранять загруженные файлы и установленные пакеты ИИ между перезапусками.
- `/tmp/workspace` (app) - временное хранилище для обрабатываемых файлов. Он может быть временным, но его монтирование не дает заполнить записываемый слой контейнера.
- `SnapOtter-pgdata` (postgres) - каталог данных PostgreSQL. Здесь хранятся все реляционные данные (пользователи, настройки, конвейеры, задачи, журнал аудита). Резервное копирование через `pg_dump` или снимок тома.
- `SnapOtter-redisdata` (redis) - файл Redis только для добавления для надежных очередей задач.
