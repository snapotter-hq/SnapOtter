# Настройки для слабого оборудования {#low-resource-setups}

SnapOtter хорошо работает на небольшом оборудовании: Raspberry Pi 4 или 5, старом ноутбуке или VPS с 2 ГБ памяти. Эта страница служит практическим руководством для таких машин: чего ожидать, готовая настройка с разумными ограничениями и какие функции стоит пропустить. Полные данные тестов, на которых основаны эти цифры, приведены в разделе [Требования к оборудованию](/ru/guide/deployment#hardware-requirements).

Два жёстких ограничения сразу:

- **Только 64-разрядные системы.** Образ собран для `linux/amd64` и `linux/arm64`. 32-разрядная ARM (`armv7`/`armhf`) не поддерживается, поэтому Pi первого поколения и семейство Pi Zero не подходят.
- **Минимум 2 ГБ памяти (для инструментов без ИИ).** С 512 МБ стек не запустится, а 1 ГБ не справляется с пакетной обработкой нескольких файлов. 2 ГБ и 2 ядра: минимальная конфигурация, на которой инструменты без ИИ работают комфортно.

## Что хорошо работает на небольшом оборудовании {#what-runs-well}

Все инструменты без ИИ работают на машине с 2 ГБ и 2 ядрами: весь раздел «Изображения» и «Файлы», инструменты PDF, а также операции с видео и аудио без перекодирования (обрезка, отключение звука, смена контейнера). Большинство завершается быстрее секунды.

Две нагрузки являются исключениями:

- **Перекодирование видео** (конвертация между кодеками) упирается в CPU. Клип 1080p, который на быстром настольном CPU обрабатывается за ~40 с, на процессоре уровня Pi может занять несколько минут. Операции без перекодирования остаются мгновенными.
- **Инструменты ИИ** имеют собственные нижние пределы памяти CPU для каждого пакета: 2 ГБ оперативной памяти хоста (0,5 ГБ свободно) для распознавания лиц и встроенного быстрого OCR, 4 ГиБ настроенной эффективной памяти для точного OCR, 4 ГБ оперативной памяти хоста (2-3 ГБ свободно) для транскрибации, удаления объектов и раскрашивания, удаления фона, увеличения и улучшения и восстановления фотографий, а также 8 ГБ оперативной памяти хоста (6 ГБ свободно) для высококачественной дорисовки. Машина с 2 ГБ не сможет запустить Whisper, RealESRGAN, rembg или LaMa без завершения процесса из-за нехватки памяти, поэтому SnapOtter проверяет свободную память перед передачей задачи в Python-сайдкар и сразу отклоняет запуски ниже предела пакета.

Ничто из этого не устанавливается и не работает, пока вы этим не пользуетесь: без установленных пакетов ИИ приложение в простое занимает около 360 МБ, а пакеты ИИ загружаются только после того, как их включит администратор.

## Руководство для Raspberry Pi и старого ноутбука {#walkthrough}

Это стандартная установка Compose из раздела [Начало работы](/ru/guide/getting-started) плюс ограничения ресурсов и осторожные лимиты. Предполагается 64-разрядная ОС (на Pi: Raspberry Pi OS 64-bit или Ubuntu Server arm64).

```yaml
services:
  snapotter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - ./snapotter-data:/data
    environment:
      - DATABASE_URL=postgres://${POSTGRES_APP_USER:-snapotter_app}:${POSTGRES_APP_PASSWORD:-snapotter_app}@db:5432/${POSTGRES_DB:-snapotter}
      - DATABASE_MIGRATION_URL=postgres://${POSTGRES_USER:-snapotter}:${POSTGRES_PASSWORD:-snapotter}@db:5432/${POSTGRES_DB:-snapotter}
      - REDIS_URL=redis://redis:6379
      # Small-box profile: see the table below for what each cap does.
      - CONCURRENT_JOBS=1
      - MAX_WORKER_THREADS=2
      - MAX_BATCH_SIZE=5
      - MAX_UPLOAD_SIZE_MB=100
      - MAX_MEGAPIXELS=50
      - MAX_VIDEO_DURATION_S=300
    deploy:
      resources:
        limits:
          cpus: "2"
          memory: 2G
    depends_on:
      - db
      - redis
    restart: unless-stopped

  db:
    image: postgres:17-alpine
    environment:
      - POSTGRES_USER=${POSTGRES_USER:-snapotter}
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD:-snapotter}     # Change this for non-local deployments
      - POSTGRES_DB=${POSTGRES_DB:-snapotter}
    volumes:
      - ./postgres-data:/var/lib/postgresql/data
    restart: unless-stopped

  redis:
    image: redis:8-alpine
    command: redis-server --maxmemory 256mb --maxmemory-policy noeviction
    restart: unless-stopped
```

Заметки для машин уровня Pi:

- **Для тома данных и Postgres лучше использовать USB SSD, а не SD-карту.** Рабочие каталоги задач активно используют диск, а SD-карты и медленные, и быстро изнашиваются.
- **Универсальный одиночный контейнер здесь тоже подходит** (встроенные Postgres и Redis, когда `DATABASE_URL`/`REDIS_URL` не заданы), а на хосте с ограниченной памятью следует уменьшить предел встроенного Redis через `REDIS_MAXMEMORY` (см. [Конфигурация](/ru/guide/configuration)). Compose даёт более тонкий контроль над каждым сервисом, поэтому в этом руководстве используется именно он.
- **Добавьте swap на устройствах с 2 ГБ.** Он не даёт случайному всплеску (большой PDF, пакет, который вы забыли ограничить) закончиться завершением процесса из-за нехватки памяти. zram: вариант, щадящий SD-карту.
- Образ для arm64 работает только на CPU; CUDA на платах ARM нет.

## Параметры настройки {#tuning-knobs}

Все ограничения задаются переменными окружения, полностью описанными в разделе [Конфигурация](/ru/guide/configuration). `0` означает «без ограничений» или «автоматически». Параметры, важные на небольшом оборудовании:

| Переменная | Рекомендация для слабой машины | Что защищает |
|---|---|---|
| `CONCURRENT_JOBS` | `1` | Сколько задач выполняется параллельно. Автоопределение использует число ядер CPU минус один: для больших машин это нормально, а для двухъядерной машины при нехватке памяти слишком агрессивно. |
| `MAX_WORKER_THREADS` | `2` | Пул потоков обработки изображений. |
| `MAX_BATCH_SIZE` | `5` | Именно на пакетах у машин с 1-2 ГБ память заканчивается в первую очередь. |
| `MAX_UPLOAD_SIZE_MB` | `100` | Не даёт одному огромному файлу занять всё рабочее пространство. |
| `MAX_MEGAPIXELS` | `50` | Декодирование изображения более 100 Мпикс требует памяти независимо от размера файла. |
| `MAX_VIDEO_DURATION_S` | `300` | Долгие перекодирования занимают слабый CPU на минуты и часы. |
| `PROCESSING_TIMEOUT_S` | `600` | Жёсткий предел, чтобы зависшая задача рано или поздно освободила машину. |

Эти ограничения применяются к тому, что принимает сервер, поэтому задавайте их по реальному использованию, а не как можно меньше. Если вы не работаете с видео, предел `MAX_VIDEO_DURATION_S` ничего не стоит; если вы ежедневно сканируете документы, не ограничивайте `MAX_PDF_PAGES`.

## Что стоит пропустить {#what-to-skip}

- **Тяжёлые пакеты ИИ.** Увеличение, восстановление фотографий и удаление фона требуют GPU или быстрого многоядерного CPU, а каждый пакет занимает 4-5 ГБ на диске. На слабой машине просто не устанавливайте их; инструменты, пакет которых отсутствует, показывают приглашение к установке вместо запуска.
- **Перекодирование видео как регулярная нагрузка.** Редкие перекодирования допустимы (они просто медленные); постоянная очередь перекодирования требует ядер CPU, а не Pi.
- **Неиспользуемые инструменты в целом.** Администратор может отключить отдельные инструменты в настройках: они исчезнут из интерфейса, а их маршруты API перестанут регистрироваться. Это само по себе не экономит память, но не позволит использовать небольшой общий экземпляр для той единственной нагрузки, которую оборудование не вытянет.

Если позже вы перенесёте экземпляр на более мощное оборудование, уберите ограничения (верните им значение `0`), и тот же том данных продолжит работать.
