# Что собирает SnapOtter {#what-snapotter-collects}

Анонимная продуктовая аналитика включена по умолчанию и задаётся для всего экземпляра администратором. Отключите её в разделе Settings > System > Privacy.

## События, которые мы отправляем (когда включено) {#events-we-send-when-enabled}

- tool_used: id инструмента, статус, длительность, категория, является ли он инструментом ИИ, код ошибки при сбое.
- pipeline_executed: количество шагов, id инструментов, флаг пакетной обработки, количество файлов, длительность, статус.
- ai_bundle_action: id набора, действие, длительность.
- Использование интерфейса: какие страницы инструментов открываются, добавленные файлы (только количество), запуск инструмента, загрузки, сохранения, поиск (только количество результатов), пакетная обработка.
- Отчёты о сбоях: тип ошибки, очищенное сообщение об ошибке (без имён файлов, путей, адресов электронной почты и значений в кавычках), стек исходников с базовыми именами файлов, а для инструментов ИИ — трассировка Python только с базовыми именами файлов.

## Что мы никогда не собираем {#what-we-never-collect}

- Имена или пути файлов
- Содержимое файлов
- Текст вывода OCR
- Метаданные изображений (EXIF)
- Извлечённый текст документов
- Идентичность вашей учётной записи

Как и любой сервер, PostHog видит IP-адрес, с которого пришёл каждый запрос. Наш проект в PostHog отбрасывает его, а не сохраняет, а собственные серверные события SnapOtter передают вместо него заглушку.

## Уведомления об обновлениях {#update-notices}

Пока аналитика включена, сервер раз в несколько часов спрашивает у PostHog, какой выпуск SnapOtter самый новый, передавая анонимный идентификатор экземпляра и его версию. Если есть более новый выпуск, администраторы видят уведомление со ссылкой на примечания к выпуску. Закрытое уведомление не появится до следующего выпуска. Ничего не устанавливается и не скачивается автоматически, а при выключенной аналитике сервер не делает запросов.

## Как отключить {#turning-it-off}

Администраторам: Settings > System > Privacy, переключите «Anonymous Product Analytics» в положение «выключено». Сбор прекращается немедленно, для всего экземпляра. Чтобы собрать образ, который никогда не сможет ничего отправлять, задайте аргумент сборки `SNAPOTTER_ANALYTICS=off`.

Чтобы запустить новый экземпляр с уже выключенной аналитикой, добавьте `SNAPOTTER_ANALYTICS_DEFAULT=off` в окружение сервера до его первого запуска. В Docker Compose укажите её в `environment:` сервиса приложения: если задать её только в `.env`, до контейнера она не дойдёт.
