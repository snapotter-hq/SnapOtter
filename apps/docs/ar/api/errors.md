# رموز الأخطاء {#error-codes}

لكل استجابة خطأ بصيغة JSON البنية نفسها:

```json
{
  "error": "Job not found",
  "code": "NOT_FOUND",
  "requestId": "req-42"
}
```

| الحقل | موجود دائمًا | المعنى |
|-------|----------------|---------|
| `error` | نعم | رسالة مقروءة للبشر. آمنة للعرض على المستخدمين. لا تحلّلها برمجيًا. |
| `code` | نعم | رمز ثابت مقروء آليًا. استخدمه في التفرّع المنطقي. |
| `requestId` | نعم | معرّف الخادم لهذا الطلب. اذكره عند الإبلاغ عن مشكلة، فهو يطابق سجل الخادم. |
| `details` | أحيانًا | سياق إضافي لبعض أخطاء 4xx، مثل رسالة التحقق من الصحة. |

قد تتغير الرسائل بين الإصدارات. أما الرموز فلا تتغير، لذا اكتب منطق العميل بالاعتماد على `code`.

## الرموز المشتقة من حالة HTTP {#status-codes}

عندما لا يحدد المسار رمزه الخاص، يشتق الخادم رمزًا من الحالة:

| حالة HTTP | `code` |
|-------------|--------|
| 400 | `BAD_REQUEST` |
| 401 | `AUTH_REQUIRED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `UNPROCESSABLE_ENTITY` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` |
| 501 | `NOT_IMPLEMENTED` |
| 503 | `SERVICE_UNAVAILABLE` |
| 507 | `INSUFFICIENT_STORAGE` |

أي حالة 4xx أخرى تعود إلى `BAD_REQUEST`، وأي حالة 5xx أخرى تعود إلى `INTERNAL_ERROR`.

يمكن للمسار تحديد رمز أكثر تخصيصًا، وعندها تحمل الاستجابة ذلك الرمز بدلًا منه. فمثلًا، الأداة التي لا تستطيع العمل بسبب غياب حزمة الذكاء الاصطناعي الخاصة بها تعيد رمزًا خاصًا بالميزة. تُوصف هذه الرموز مع الميزة التي تُصدرها.

## المصادقة والوصول {#auth-codes}

| `code` | الحالة | ما يجب فعله |
|--------|--------|------------|
| `AUTH_REQUIRED` | 401 | أرسل `Authorization: Bearer <token>` مع رمز جلسة أو مفتاح API (`si_...`). |
| `FORBIDDEN` | 403 | بيانات الاعتماد صالحة لكنها تفتقر إلى الصلاحية. اطلب الصلاحية من مسؤول. |
| `MUST_CHANGE_PASSWORD` | 403 | يجب على الحساب تغيير كلمة مروره قبل أن يتمكن من استدعاء نقاط نهاية أخرى. استدعِ `POST /api/auth/change-password` باستخدام رمز الجلسة، ثم أعد المحاولة. |
| `USER_DISABLED` | 403 | الحساب معطّل. يجب على مسؤول إعادة تفعيله. |
| `LOGIN_THROTTLED` | 429 | محاولات تسجيل دخول فاشلة كثيرة جدًا. انتظر قبل المحاولة مرة أخرى. |
| `VALIDATION_ERROR` | 400 | فشل التحقق من صحة جسم الطلب أو معاملاته. `details` يحدد المشكلة. |

حساب المسؤول عند أول تشغيل هو `admin` بكلمة المرور `admin` ما لم يغيّرها `DEFAULT_USERNAME` أو `DEFAULT_PASSWORD`. وما لم يُضبط `SKIP_MUST_CHANGE_PASSWORD`، يحصل ذلك الحساب على `MUST_CHANGE_PASSWORD` في كل استدعاء إلى أن تتغير كلمة المرور.

## المهام {#job-codes}

المهمة الفاشلة تُبلغ عن سببها في المهمة نفسها، لا في خطأ HTTP. اقرأ `error.code` و`error.message` من `GET /api/v1/jobs/{jobId}`. راجع [تتبع التقدم](/ar/api/rest#progress-tracking).

المهمة الفاشلة تحتفظ بالحقل `error.code` فقط عندما يكون الفشل خطأ في المدخلات أو عطلًا في الخادم. أما حالات الفشل الأخرى فتحمل الرسالة وحدها.

| `code` | المعنى | ما يجب فعله |
|--------|---------|------------|
| `CANCELED` | ألغى مستخدم المهمة. وهو ليس حالة HTTP. تحمل أحداث التقدم `phase: failed` بهذا الرمز. | تعامل معه على أنه إلغاء من المستخدم. لا تعد المحاولة تلقائيًا. |
| `INPUT_MISSING` | أُزيل المدخل قبل تشغيل المهمة. | ارفع الملف مرة أخرى. |
| `ENGINE_UNAVAILABLE` | تعذّر تشغيل محرك مطلوب على الخادم. | أعد المحاولة بعد أن يصلح المسؤول التثبيت. |

## المصادقة وMFA {#mfa-codes}

| `code` | الحالة | المعنى | ما يجب فعله |
|--------|--------|---------|------------|
| `MFA_ENROLLMENT_REQUIRED` | 403 | تشترط سياسة MFA التسجيل، ولا تستطيع هذه النسخة تسجيل المستخدم (لا يوجد ترخيص مؤسسي). أما النسخ المرخّصة فتعيد 200 مع `requiresMfaEnrollment: true` وترشد المستخدم خلال التسجيل. | لا تعد المحاولة. يجب على المسؤول تغيير السياسة أو استخدام أداة الاسترداد دون اتصال عبر سطر الأوامر. |
| `MFA_POLICY_UNAVAILABLE` | 503 | تعذّر على الخادم قراءة سياسة MFA أثناء تسجيل الدخول. | أعد محاولة تسجيل الدخول بعد قليل. |
| `INVALID_CODE` | 401 | رمز TOTP أو رمز الاسترداد غير صحيح. | اطلب من المستخدم رمزًا جديدًا وأعد المحاولة. تنتهي المحاولات الفاشلة المتكررة بالرمز `MFA_ATTEMPTS_EXHAUSTED`. |
| `MFA_ATTEMPTS_EXHAUSTED` | 401 | رموز خاطئة كثيرة جدًا. يُهمَل التحدي. | ابدأ تسجيل الدخول من جديد للحصول على تحدٍّ جديد. |
| `MFA_EXPIRED` | 401 | انتهت صلاحية تحدي MFA أو التسجيل أو أنه لا يطابق. | ابدأ تسجيل الدخول من جديد. |
| `MFA_NOT_CONFIGURED` | 401 | ليس للحساب سر TOTP، لذا لا يمكن التحقق من الرمز. | سجّل MFA قبل تسجيل الدخول برمز. |
| `MFA_ALREADY_ENABLED` | 409 | MFA مفعّلة بالفعل على الحساب. | لا تسجّلها مرة أخرى. |
| `NO_PENDING_ENROLLMENT` | 400 | وصل تأكيد تسجيل دون وجود تسجيل معلّق. | استدعِ نقطة نهاية التسجيل أولًا. |
| `MFA_NOT_ENABLED` | 400 | يتطلب الإجراء تفعيل MFA، وهي معطلة لهذا المستخدم. | تخطَّ الإجراء، أو فعّل MFA أولًا. |
| `MFA_DECRYPTION_FAILED` | 500 | تعذّر فك تشفير سر TOTP المخزَّن. | إجراء على المشغّل. يعني هذا عادةً أن مفتاح التشفير تغيّر. تحقق من `DATA_ENCRYPTION_KEY` و`DATA_ENCRYPTION_KEY_PREVIOUS`. |
| `DECRYPTION_FAILED` | 500 | تعذّر فك تشفير قيمة مخزَّنة (إعداد، أو ترويسة مصادقة webhook، أو سر TOTP). | إجراء على المشغّل، كما سبق. لا تعد المحاولة. |
| `IDLE_TIMEOUT` | 401 | انتهت صلاحية الجلسة بعد فترة من عدم النشاط. | سجّل الدخول مرة أخرى. |
| `INVALID_PASSWORD` | 401 | كلمة المرور الحالية خاطئة عند تغيير كلمة المرور. | اطلب من المستخدم كلمة المرور الحالية. |
| `PASSWORD_CHANGED` | 409 | تغيّرت كلمة المرور في جلسة أخرى، أو أعاد مسؤول تعيينها، أثناء تنفيذ هذا الطلب. | سجّل الدخول مرة أخرى. |
| `OIDC_NO_PASSWORD` | 400 | طُلب تغيير كلمة المرور أو إعادة تعيينها لحساب أُنشئ عبر SSO. | وجّه المستخدم إلى موفّر الهوية. |

## OIDC {#oidc-codes}

لا تعيد إخفاقات OIDC أثناء تسجيل الدخول جسم JSON. يعيد مسار تسجيل الدخول التوجيه إلى صفحة تسجيل الدخول مع سبب عام، ويسجّل سجل التدقيق الرمز. ويظل مسار تسجيل الخروج ينهي الجلسة المحلية عندما يتعذّر الوصول إلى موفّر الهوية.

| `code` | الحالة | المعنى | ما يجب فعله |
|--------|--------|---------|------------|
| `OIDC_ISSUER_SCHEME_MISMATCH` | لا شيء (إعادة توجيه) | عنوان URL للمُصدِر هو `http`، لكن `EXTERNAL_URL` هو `https`، لذا يرفض العميل الاكتشاف. | المسؤول: قدّم المُصدِر عبر `https`، أو شغّل النسخة عبر `http`. |
| `OIDC_DISCOVERY_TIMEOUT` | لا شيء (إعادة توجيه) | انتهت مهلة اكتشاف المُصدِر. | تحقق من أن الخادم يستطيع الوصول إلى المُصدِر، ثم أعد المحاولة. |
| `OIDC_DISCOVERY_FAILED` | لا شيء (إعادة توجيه) | فشل الاكتشاف لسبب آخر. | تحقق من عنوان URL للمُصدِر ومن الوصول الصادر للخادم. |
| `OIDC_END_SESSION_INVALID` | لا شيء (يستمر تسجيل الخروج) | `end_session_endpoint` الخاص بموفّر الهوية ليس عنوان URL صالحًا. ما زالت الجلسة المحلية تُمسح. | المسؤول: أصلح بيانات موفّر الهوية الوصفية. |
| `OIDC_END_SESSION_SCHEME` | لا شيء (يستمر تسجيل الخروج) | يستخدم `end_session_endpoint` مخططًا لا يسمح به الخادم. ما زالت الجلسة المحلية تُمسح. | المسؤول: أصلح بيانات موفّر الهوية الوصفية. |

## SAML {#saml-codes}

لا تضبط إخفاقات SAML الحقل `code`. يعيد التأكيد الفاشل التوجيه إلى صفحة تسجيل الدخول مع `saml_auth_failed`، ويسجّل حدث التدقيق `SAML_LOGIN_FAILED` السبب.

## SCIM {#scim-codes}

تجيب مسارات SCIM بغلاف الأخطاء الوارد في RFC 7644 (`schemas` و`detail` و`status`، وأحيانًا `scimType`). ولا تضبط `code`. تفرّع بحسب حالة HTTP.

## الفرق والأدوار والمستخدمون {#team-role-codes}

تعيد أسماء الفرق أو الأدوار المكررة الرمز العام `CONFLICT`، ويعيد الفريق أو الدور المفقود `NOT_FOUND`.

| `code` | الحالة | المعنى | ما يجب فعله |
|--------|--------|---------|------------|
| `ESCALATION_DENIED` | 403 | دور المستدعي لا يسمح بالتغيير. الهدف يعلو سلطة المستدعي، أو الدور مدمج، أو يمنح الطلب صلاحيات لا يملكها المستدعي. | لا تعد المحاولة. اطلب من مستخدم يملك سلطة أكبر. |
| `UNKNOWN_ROLE` | 400 | معرّف الدور لا يطابق دورًا موجودًا. | صحّح معرّف الدور. اعرض الأدوار لتجده. |
| `UNKNOWN_TEAM` | 400 | معرّف الفريق لا يطابق فريقًا موجودًا. | صحّح معرّف الفريق. |
| `SELF_DEMOTE` | 400 | حاول مسؤول إزالة دوره الإداري عن نفسه. | اطلب من مسؤول آخر إجراء التغيير. |
| `SELF_DELETE` | 400 | حاول مسؤول حذف حسابه بنفسه. | اطلب من مسؤول آخر حذفه. |
| `LAST_ADMIN` | 400 في مسارات المستخدمين، 409 في مسارات الحذف النهائي وفق GDPR | سيترك التغيير النسخة بلا مسؤول، أو سيحذف فريقًا يضم كل المسؤولين. | اجعل مستخدمًا آخر مسؤولًا أولًا. |
| `USER_LIMIT_REACHED` | 403 | بلغت النسخة حدّ `MAX_USERS`. | أزل مستخدمًا، أو ارفع `MAX_USERS`. |

## الميزات وحزم الذكاء الاصطناعي {#feature-codes}

الأدوات وعمليات الدفعات وخطوط المعالجة التي تحتاج إلى حزمة ذكاء اصطناعي اختيارية تستخدم هذه الرموز.

| `code` | الحالة | المعنى | ما يجب فعله |
|--------|--------|---------|------------|
| `FEATURE_NOT_INSTALLED` | 501 | تحتاج الأداة، أو إحدى خطوات خط المعالجة أو الدفعة، إلى حزمة غير مثبّتة. يتضمن الجسم `feature` (معرّف الحزمة) و`featureName`. | ثبّت الحزمة من الإعدادات، ثم أعد المحاولة. |
| `FEATURE_INCOMPATIBLE` | 501 | الميزة المثبّتة لا تستطيع تقديم الجودة أو اللغة المطلوبة. | غيّر الإعداد، أو ثبّت حزمة تدعمه. |
| `ENGINE_UNAVAILABLE` | 503 | تعذّر تشغيل محرك مطلوب، أو أُزيل وقت تشغيل OCR بعد التحقق من صحة الطلب. | أعد المحاولة بعد أن يصلح المسؤول الميزة أو يعيد تثبيتها. |
| `BROWSER_NOT_AVAILABLE` | 503 | Chromium غير مثبّت، لذا لا يمكن تشغيل HTML إلى صورة. | اطلب من المسؤول تثبيت المتصفح. |
| `BROWSER_CRASHED` | 503 | تعطّل متصفح لقطات الشاشة أثناء العرض. | أعد الطلب. |

|--------|--------|---------|------------|
| `STORAGE_QUOTA_EXCEEDED` | 413 | سيتجاوز الحفظ في الملفات حصة تخزين المستخدم. | احذف ملفات، أو اطلب مساحة أكبر من المسؤول. |

## خطوط المعالجة والدفعات {#pipeline-codes}

تعيد طلبات خطوط المعالجة والدفعات رموز الميزات المذكورة أعلاه لكل خطوة تحتاج إلى حزمة. ومعرّف المهمة المستخدم بالفعل يعيد `CONFLICT` بالحالة 409. أرسل معرّف مهمة جديدًا.

## الإعدادات {#settings-codes}

| `code` | الحالة | المعنى | ما يجب فعله |
|--------|--------|---------|------------|
| `UNKNOWN_SETTING` | 400 | المفتاح ليس إعدادًا معروفًا. | تحقق من اسم المفتاح. |
| `READONLY_SETTING` | 400 | لا يمكن تغيير الإعداد عبر API. | غيّره عبر متغيرات البيئة أو واجهة المسؤول. |
| `DEPENDENCY_VALIDATION_FAILED` | 400 | القيمة الجديدة تتعارض مع إعدادات أخرى. يسمّي الجسم الإعداد في `setting` ويسرد المشكلات في `validationErrors`. | أصلح الإعدادات المذكورة، ثم أعد المحاولة. |
| `SETTING_DECRYPTION_FAILED` | 500 | تعذّر فك تشفير إعداد مخزَّن. | إجراء على المشغّل، كما في `DECRYPTION_FAILED`. |

عند ظهور `VALIDATION_ERROR` على إعداد، يحمل `details` مشكلات المخطط.

## المؤسسات {#enterprise-codes}

| `code` | الحالة | المعنى | ما يجب فعله |
|--------|--------|---------|------------|
| `FEATURE_NOT_LICENSED` | 403 | يحتاج الإعداد أو السياسة إلى ترخيص مؤسسي، مثل فرض SSO أو سياسة MFA. | استخدم نسخة مرخّصة، أو اترك الإعداد معطّلًا. |
| `IP_NOT_ALLOWED` | 403 | عنوان IP الخاص بالطلب ليس في قائمة السماح. | اتصل من شبكة مسموح بها. |
| `INVALID_CIDR` | 400 | أحد إدخالات قائمة السماح ليس CIDR صالحًا. تسرد الرسالة الإدخالات الخاطئة. | أصلح الإدخالات واحفظ مرة أخرى. |
| `SELF_LOCKOUT` | 400 | سيؤدي حفظ قائمة السماح إلى حظر عنوان IP الحالي للمستدعي. | أضف عنوان IP الحالي إلى القائمة أولًا. |

تعيد مسارات الحذف النهائي وفق GDPR الرمز العادي `CONFLICT` بالحالة 409 عندما يكون مستخدم أو فريق تحت حجز قانوني.

## رموز لا يتلقاها العملاء {#internal-codes}

توجد هذه الرموز في مصدر الخادم للسجلات أو القياس عن بُعد أو لأخطاء Fastify نفسه. ولا يصل العميل إليها في جسم استجابة أو صف مهمة، فلا تكتب منطق العميل بالاعتماد عليها.

| `code` | وجهتها |
|--------|---------------|
| `ALERT_DECRYPTION_FAILED` | تُبلَّغ إلى تتبع الأخطاء من مُقيِّم التنبيهات. تعذّر فك تشفير ترويسة مصادقة webhook الخاص بالتنبيه. |
| `SIEM_DECRYPTION_FAILED` | تُبلَّغ إلى تتبع الأخطاء من إعادة توجيه SIEM. تعذّر فك تشفير ترويسة مصادقة SIEM. |
| `WEBHOOK_DECRYPTION_FAILED` | تُبلَّغ إلى تتبع الأخطاء. الطلب الذي واجه الفشل نفسه يجيب بـ `DECRYPTION_FAILED`. |
| `STAGED_DISCARD_FAILED` | تُبلَّغ إلى تتبع الأخطاء عندما يتعذّر حذف ملف مرفوع مرحليًا. |
| `USERNAME_RACE_EXHAUSTED` | تُثار عندما يخسر الإنشاء التلقائي عبر SSO سباق اسم المستخدم في كل محاولة إعادة. تعرض صفحة تسجيل الدخول خطأً بدلًا منها. |
| `ERR_OUT_OF_RANGE` | يطلقها قارئ التخزين الكائني عند نطاق بايتات غير صالح. |
| `ETIMEDOUT` | تُضبط على خطأ المهلة في تصدير GDPR. يفشل التصدير، ويمكن طلبه مرة أخرى. |
| `FST_REQ_FILE_TOO_LARGE` | رمز Fastify لرفع يتجاوز الحد. يتلقى العملاء الحالة 413 مع `PAYLOAD_TOO_LARGE`، أو رسالة 413 الخاصة بالمسار. |
