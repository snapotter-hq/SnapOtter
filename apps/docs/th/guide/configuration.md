# การกำหนดค่า {#configuration}

การกำหนดค่าทั้งหมดทำผ่านตัวแปรสภาพแวดล้อม ทุกตัวแปรมีค่าเริ่มต้นที่เหมาะสม SnapOtter จึงใช้งานได้ทันทีโดยไม่ต้องตั้งค่าใด ๆ

## ตัวแปรสภาพแวดล้อม {#environment-variables}

### เซิร์ฟเวอร์ {#server}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `PORT` | `1349` | พอร์ตที่เซิร์ฟเวอร์รับการเชื่อมต่อ |
| `HOST` | `0.0.0.0` | ที่อยู่ IP ที่เซิร์ฟเวอร์รับการเชื่อมต่อ บนเครือข่ายแบบ bridge (ค่าเริ่มต้นของ `docker run` และ Compose) ให้คง `0.0.0.0` (หรือ `::`) ไว้ มิฉะนั้นพอร์ตที่เผยแพร่จะใช้งานไม่ได้ บนการติดตั้งแบบเนทีฟหรือคอนเทนเนอร์บนเครือข่ายของโฮสต์ `127.0.0.1` จะทำให้ API ไม่เปิดสู่เครือข่าย สำหรับการเข้าถึงจากระยะไกล ให้วางรีเวิร์สพร็อกซีไว้ด้านหน้า [โหมดฝังตัว](#embedded-mode) ทำงานได้เฉพาะกับ `0.0.0.0`, `::` หรือ `127.0.0.1` เพราะการตรวจสอบตอนเริ่มต้นของโหมดนี้เรียกไปที่ `127.0.0.1` หากใช้ที่อยู่อื่นใด รวมถึง `::1` คอนเทนเนอร์จะไม่ถูกนับว่าเริ่มทำงานแล้ว และหากเกิดข้อขัดข้องในภายหลัง คอนเทนเนอร์จะหยุดแทนที่จะรีสตาร์ตเซิร์ฟเวอร์ ค่าใดก็ตามที่ไม่ใช่ที่อยู่ IP รวมถึง `localhost` จะทำให้เซิร์ฟเวอร์หยุดตั้งแต่ตอนเริ่มต้น |
| `BASE_PATH` | (ว่าง) | เส้นทางการติดตั้งสาธารณะ เช่น `/snapotter` หากว่างหรือเป็น `/` จะให้บริการที่รากของโดเมน มีผลขณะรันโดยไม่ต้องสร้างอิมเมจใหม่ |
| `RATE_LIMIT_PER_MIN` | `1000` | จำนวนคำขอสูงสุดต่อนาทีต่อ IP ตั้งเป็น 0 เพื่อปิดการจำกัดอัตรา |
| `API_KEYS_RATE_LIMIT_PER_MIN` | `30` | จำนวนคำขอสูงสุดต่อนาทีต่อ IP ไปยัง endpoint จัดการคีย์ API (แสดงรายการ สร้าง เพิกถอน) คีย์ที่ใช้เรียกเครื่องมือไม่ได้รับผลกระทบ ตั้งเป็น `0` เพื่อไม่จำกัด |
| `CORS_ORIGIN` | (ว่าง) | รายการ origin ที่อนุญาตสำหรับ CORS คั่นด้วยจุลภาค หรือเว้นว่างเพื่ออนุญาตเฉพาะ origin เดียวกัน |
| `LOG_LEVEL` | `info` | ระดับความละเอียดของบันทึก ใช้ได้หนึ่งในค่าต่อไปนี้ `fatal`, `error`, `warn`, `info`, `debug`, `trace` |
| `TRUST_PROXY` | `loopback,linklocal,uniquelocal` | กำหนดว่าเพียร์ใดตั้งค่า IP ของไคลเอนต์ผ่าน `X-Forwarded-For` ได้ ค่าเริ่มต้นเชื่อถือเฉพาะเพียร์ในเครือข่ายส่วนตัว ดังนั้นรีเวิร์สพร็อกซีบนเครือข่าย Docker หรือ LAN จะได้รับความเชื่อถือ ส่วนเฮดเดอร์ปลอมจากไคลเอนต์สาธารณะจะไม่ได้รับ ตั้งค่า `true` เฉพาะเมื่อมีพร็อกซีที่คุณควบคุมอยู่ด้านหน้าบนที่อยู่สาธารณะ |
| `SNAPOTTER_ANALYTICS_DEFAULT` | `on` | ตั้งเป็น `off` เพื่อเริ่มอินสแตนซ์ใหม่โดยปิด "Anonymous Product Analytics" ไว้ จึงไม่ส่งข้อมูลใด ๆ ตั้งแต่การบูตครั้งแรก ตัวแปรนี้เพียงกรอกค่าให้การตั้งค่านั้นในขณะที่ยังไม่มีใครเลือกค่า เมื่อบันทึกการตั้งค่าแล้ว ไม่ว่าโดยผู้ดูแลระบบหรือโดยตัวแปรนี้ การเปลี่ยนตัวแปรจะไม่มีผลใด ๆ แต่ผู้ดูแลระบบยังเปิดการวิเคราะห์ได้ที่ Settings > System > Privacy |

### การยืนยันตัวตน {#authentication}

ค่าบูลีนสองตัวด้านล่างรับเฉพาะ `true` และ `false` ค่าอื่นใด ไม่ว่าจะเป็น `1` หรือ `yes` หรือ `on` จะไม่ผ่านการตรวจสอบ และเซิร์ฟเวอร์จะหยุดทำงานก่อนเริ่มรับการเชื่อมต่อ

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `AUTH_ENABLED` | `true` | บังคับให้เข้าสู่ระบบ หากตั้งเป็น `false` จะทำงานโดยไม่มีบัญชีผู้ใช้เลย ซึ่งให้สิทธิ์ผู้ดูแลระบบแก่ทุกคำขอ จึงควรใช้เฉพาะในเครือข่ายที่เชื่อถือได้ |
| `DEFAULT_USERNAME` | `admin` | ชื่อผู้ใช้ของบัญชีผู้ดูแลระบบเริ่มต้น ใช้เฉพาะในการรันครั้งแรก |
| `DEFAULT_PASSWORD` | `admin` | รหัสผ่านของบัญชีผู้ดูแลระบบเริ่มต้น ควรเปลี่ยนหลังจากเข้าสู่ระบบครั้งแรก |
| `MAX_USERS` | `0` (ไม่จำกัด) | จำนวนบัญชีผู้ใช้ที่ลงทะเบียนได้สูงสุด ตั้งเป็น 0 เพื่อไม่จำกัด |
| `SESSION_DURATION_HOURS` | `168` | อายุของเซสชันการเข้าสู่ระบบเป็นชั่วโมง (ค่าเริ่มต้นคือ 7 วัน) |
| `SKIP_MUST_CHANGE_PASSWORD` | `false` | ตั้งเป็น `true` เพื่อข้ามหน้าต่างบังคับเปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบครั้งแรก |
| `LOGIN_ATTEMPT_LIMIT` | `30` | จำนวนคำขอเข้าสู่ระบบสูงสุดต่อนาทีต่อ IP ความพยายามถัดไปจะได้รับ `429` จนกว่าจะครบนาที การล้มเหลวซ้ำของชื่อผู้ใช้เดียวมักถึง `LOGIN_THROTTLE_MAX_FAILURES` ก่อน ผู้ดูแลระบบสามารถแทนที่ค่านี้ได้ที่ Settings > System ตั้งเป็น `0` เพื่อไม่จำกัด การสร้างจากซอร์สเริ่มที่ 10 |
| `LOGIN_THROTTLE_MAX_FAILURES` | `10` | จำนวนครั้งที่เข้าสู่ระบบด้วยรหัสผ่านล้มเหลวที่ชื่อผู้ใช้หนึ่งมีได้ภายใน `LOGIN_THROTTLE_WINDOW_S` ก่อนที่ความพยายามถัดไปของชื่อนั้นจะได้รับ `429` ไม่ว่าจะมาจาก IP ใด ระบบจะอนุญาตอีกครั้งเมื่อความล้มเหลวที่เก่าที่สุดหลุดออกจากช่วงเวลา ตั้งเป็น 0 เพื่อปิดการจำกัด |
| `LOGIN_THROTTLE_WINDOW_S` | `900` | ความยาวของช่วงเวลานั้น เป็นวินาที ต้องมีค่าอย่างน้อย 1 เซิร์ฟเวอร์จะไม่ยอมเริ่มทำงานเมื่อเป็น 0 |

### พื้นที่จัดเก็บ {#storage}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `STORAGE_MODE` | `local` | `local` หรือ `s3` S3 และ MinIO ต้องใช้ไลเซนส์ที่มีฟีเจอร์ s3_storage รวมถึงตัวแปร `S3_*` ด้านล่าง |
| `DATABASE_URL` | `postgres://snapotter:snapotter@localhost:5432/snapotter` | สตริงการเชื่อมต่อ PostgreSQL และเป็นการเชื่อมต่อที่ใช้รับทุกคำขอ ตั้งแต่ 2.3.0 เป็นต้นไป หากตั้ง `DATABASE_MIGRATION_URL` ด้วย ตัวแปรนี้จะกลายเป็นบทบาทขณะรันที่มีสิทธิ์น้อยที่สุด คือมีเพียง DML บนตารางของแอปและไม่มีสิทธิ์อื่น สแตก Compose ชี้ตัวแปรนี้ไปที่เซอร์วิส `postgres` ของมัน หากไม่ตั้งค่า (พร้อมกับ `REDIS_URL`) จะเข้าสู่โหมดฝังตัว หากต้องการเชื่อมต่อผ่าน unix socket ให้ระบุไดเรกทอรีของซ็อกเก็ตใน `host` ดังเช่น `postgres://user:pass@localhost/snapotter?host=/var/run/postgresql` แล้วเมานต์ไดเรกทอรีนั้นเข้าไปในคอนเทนเนอร์ |
| `DATABASE_MIGRATION_URL` | (ว่าง) | การเชื่อมต่อแบบมีสิทธิ์สูง ใช้เฉพาะระหว่างบูตเพื่อรันการย้ายข้อมูลและมอบสิทธิ์ให้บทบาทขณะรัน แล้วปิดก่อนคำขอแรก หากเว้นว่าง SnapOtter จะทำงานแบบบทบาทเดียว โดยให้ `DATABASE_URL` ทำทั้งสองหน้าที่ ดู [บทบาทที่มีสิทธิ์น้อยที่สุด](/th/guide/database#least-privilege-roles) |
| `REDIS_URL` | `redis://localhost:6379` | สตริงการเชื่อมต่อ Redis (ใช้สำหรับคิวงานของ BullMQ) Compose ชี้ตัวแปรนี้ไปที่เซอร์วิส `redis` ของมัน สำหรับ unix socket ให้ใช้ `unix:///run/redis/redis.sock?db=5` (เพิ่ม `&password=...` หาก Redis ต้องใช้) แล้วเมานต์ซ็อกเก็ตเข้าไปในคอนเทนเนอร์ |
| `WORKSPACE_PATH` | `./tmp/workspace` | ไดเรกทอรีสำหรับไฟล์ชั่วคราวระหว่างการประมวลผล ล้างโดยอัตโนมัติ อิมเมจตั้งค่า `/tmp/workspace` |
| `FILES_STORAGE_PATH` | `./data/files` | ไดเรกทอรีสำหรับไฟล์ผู้ใช้ที่เก็บถาวร (รูปภาพที่อัปโหลด ผลลัพธ์ที่บันทึกไว้) อิมเมจตั้งค่า `/data/files` |
| `MAX_STORAGE_PER_USER_MB` | `5000` | เพดานเป็นเมกะไบต์ของสิ่งที่ผู้ใช้แต่ละคนเก็บไว้ในไลบรารีไฟล์ การบันทึกที่จะเกินเพดานจะถูกปฏิเสธพร้อมแจ้งปริมาณที่ใช้และขีดจำกัด โควตาที่ตั้งไว้ให้ผู้ใช้จะมีผลเหนือกว่า ตั้งเป็น 0 เพื่อไม่จำกัด |

### พื้นที่จัดเก็บอ็อบเจกต์ S3 {#s3-object-storage}

อ่านค่าเฉพาะเมื่อ `STORAGE_MODE=s3` หากขาดตัวแปรที่จำเป็นทั้งสามตัวใดตัวหนึ่ง การเริ่มต้นจะล้มเหลวพร้อมระบุชื่อตัวแปรที่ขาด

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `S3_BUCKET` | (ว่าง) | บักเก็ตที่เก็บไฟล์อัปโหลดและผลลัพธ์ จำเป็นต้องระบุ |
| `S3_ACCESS_KEY_ID` | (ว่าง) | access key จำเป็นต้องระบุ ในคอนเทนเนอร์สามารถเมานต์ไฟล์แทนได้ ผ่าน `S3_ACCESS_KEY_ID_FILE` |
| `S3_SECRET_ACCESS_KEY` | (ว่าง) | secret key จำเป็นต้องระบุ ใช้แนวทางไฟล์เดียวกัน `S3_SECRET_ACCESS_KEY_FILE` |
| `S3_REGION` | `us-east-1` | ภูมิภาคของบักเก็ต |
| `S3_ENDPOINT` | (ว่าง) | endpoint แบบกำหนดเองสำหรับ MinIO, R2, Backblaze และที่เก็บอื่นที่เข้ากันได้กับ S3 หากว่างหมายถึง AWS |
| `S3_FORCE_PATH_STYLE` | `false` | ตั้งเป็น `true` สำหรับ MinIO และระบบอื่นที่ต้องการ `endpoint/bucket/key` แทนการระบุที่อยู่แบบ virtual-host |
| `S3_PREFIX` | (ว่าง) | คำนำหน้าของคีย์ เพื่อให้บักเก็ตเดียวเก็บได้หลายอินสแตนซ์ |

### การเข้ารหัสข้อมูลที่เก็บอยู่ {#encryption-at-rest}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `DATA_ENCRYPTION_KEY` | (ว่าง) | อักขระเลขฐานสิบหก 64 ตัว (32 ไบต์) ใช้เข้ารหัสการตั้งค่าที่ละเอียดอ่อนซึ่งเก็บในฐานข้อมูล ค่าที่ไม่ใช่เลขฐานสิบหก 64 ตัวจะถูกปฏิเสธเมื่อเริ่มต้น |
| `DATA_ENCRYPTION_KEY_PREVIOUS` | (ว่าง) | คีย์เดิมที่กำลังจะเปลี่ยนออก รูปแบบเดียวกัน ตั้งทั้งสองตัวระหว่างการหมุนเวียนคีย์เพื่อให้แถวที่มีอยู่ยังถอดรหัสได้ จากนั้นจึงเอาตัวนี้ออก |

### โหมดฝังตัว {#embedded-mode}

หากรันอิมเมจโดยไม่มี `DATABASE_URL` และ `REDIS_URL` อิมเมจจะเริ่ม PostgreSQL 17 และ Redis ของตัวเองภายในคอนเทนเนอร์ ผูกกับ loopback และเก็บข้อมูลทั้งหมดบนวอลุ่ม `/data` วิธีนี้ทำให้ประสบการณ์แบบคำสั่งเดียว `docker run` กลับมา สำหรับการเริ่มต้นอย่างรวดเร็ว โฮมแล็บ และการอัปเกรดจาก 1.x นี่เป็นเส้นทางที่เน้นความสะดวก ไม่ใช่การติดตั้งสำหรับโปรดักชัน สำหรับโปรดักชัน ให้รันสแตก Compose แบบ 3 คอนเทนเนอร์ที่แยก PostgreSQL และ Redis ออกจากกัน โหมดฝังตัวต้องรันคอนเทนเนอร์เป็น root และใช้ไม่ได้กับรันไทม์ที่กำหนด UID ตามอำเภอใจ (OpenShift, Kubernetes `runAsNonRoot`) ในกรณีนั้นให้ใช้ Compose

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `EMBEDDED` | `auto` | เปิดใช้อัตโนมัติเมื่อไม่ได้ตั้งทั้ง `DATABASE_URL` และ `REDIS_URL` ตั้งเป็น `0` เพื่อปิด (แอปจะล้มเหลวทันทีหากไม่มี `DATABASE_URL`/`REDIS_URL` ภายนอก แทนที่จะเริ่มฐานข้อมูลในคอนเทนเนอร์อย่างเงียบ ๆ) |
| `REDIS_MAXMEMORY` | `512mb` | เพดานหน่วยความจำของ Redis แบบฝังตัว (เฉพาะโหมดฝังตัว) ลดค่านี้บนโฮสต์ที่มีหน่วยความจำจำกัด เช่น Raspberry Pi |
| `EMBEDDED_PG_PORT` | `5432` | พอร์ต loopback สำหรับ PostgreSQL แบบฝังตัว (เฉพาะโหมดฝังตัว) เปลี่ยนค่านี้เฉพาะเมื่อคอนเทนเนอร์ใช้เครือข่ายร่วมกันซึ่งพอร์ต 5432 ถูกใช้ไปแล้ว เช่น `--network host` ค่านี้ต้องต่างจาก `EMBEDDED_REDIS_PORT` และต้องมากกว่า 1023 เพราะ PostgreSQL ทำงานในฐานะผู้ใช้ที่ไม่มีสิทธิ์พิเศษ ซึ่งไม่สามารถ bind พอร์ตที่ต้องใช้สิทธิ์พิเศษบนเครือข่ายของโฮสต์ได้ |
| `EMBEDDED_REDIS_PORT` | `6379` | เช่นเดียวกัน สำหรับ Redis แบบฝังตัว ซึ่งทำงานในฐานะผู้ใช้ที่ไม่มีสิทธิ์พิเศษเช่นกัน |
| `EMBEDDED_DB_PASSWORDS` | (ว่าง) | ตั้งเป็น `1` เพื่อสร้างรหัสผ่านแบบสุ่มสำหรับบทบาทของ PostgreSQL แบบฝังตัวและสำหรับ Redis ในการบูตครั้งถัดไป โดยเก็บไว้ใน `/data/.embedded-db-secrets` จากนั้นการล็อกอินผ่าน TCP จะต้องใช้รหัสผ่านเหล่านี้ บนวอลุ่มที่สร้างครั้งแรกโดยเวอร์ชัน 2.3.0 ขึ้นไป superuser ของ PostgreSQL จะล็อกอินผ่าน TCP ไม่ได้เลย ส่วนบนวอลุ่มที่เก่ากว่า เจ้าของฐานข้อมูลคือ superuser และรหัสผ่านของบัญชีนั้นคือสิ่งที่ปกป้องบัญชีไว้ ให้ใช้ตัวเลือกนี้ทุกครั้งที่มีโปรแกรมอื่นใช้เครือข่ายของคอนเทนเนอร์ร่วมกัน เช่น เมื่อใช้ `--network host` ตัวเลือกนี้จะยังเปิดอยู่สำหรับวอลุ่มนั้น รหัสผ่านจะถูกใช้ในทุกการบูตแม้คุณจะเลิกตั้งค่าตัวแปรนี้ และการลบ `/data/.embedded-db-secrets` จะทำให้ได้เพียงรหัสผ่านใหม่ หรือได้การบูตที่ล้มเหลวหากไม่ได้ตั้งค่าตัวแปรไว้ หากคอนเทนเนอร์เริ่มไม่ได้เพราะไฟล์ใดไฟล์หนึ่งในนั้นเสียหาย ให้ลบไฟล์นั้นด้วย `docker run --rm -v <volume>:/data --entrypoint rm snapotter/snapotter:<your tag> -r /data/.embedded-db-secrets/<name>` แล้วเริ่มคอนเทนเนอร์อีกครั้ง การบูตครั้งถัดไปจะสร้างไฟล์ใหม่ขึ้นมา ตัวแปรนี้รับค่า `1`, `0` หรือค่าว่าง และค่าอื่นใดจะทำให้การบูตหยุด |
| `EMBEDDED_REDIS_TIMEOUT_S` | `180` | จำนวนวินาทีที่การบูตรอให้ Redis แบบฝังตัวตอบ `PING` ก่อนยอมแพ้ เมื่อหมดเวลา คอนเทนเนอร์จะหยุดและบันทึกสาเหตุ แทนที่จะค้าง เป็นจำนวนวินาทีเต็มตั้งแต่ 1 ถึง 999999 ไม่มีค่าแบบไม่จำกัด เพราะการรอตลอดไปคือความล้มเหลวที่ขอบเขตนี้มีไว้ป้องกัน เพิ่มค่านี้เฉพาะเมื่อโฮสต์ที่ช้าทำให้หมดเวลา |
| `EMBEDDED_POSTGRES_TIMEOUT_S` | `600` | เช่นเดียวกัน สำหรับ PostgreSQL แบบฝังตัว การจับเวลาเริ่มหลังจาก `initdb` ในการบูตครั้งแรกเสร็จสิ้น จึงครอบคลุมการเริ่มเซิร์ฟเวอร์และการกู้คืนหลังขัดข้อง ไม่รวมการสร้างฐานข้อมูลเริ่มต้น |

การอัปเกรดจาก 1.x ให้วาง `snapotter.db` เดิมของคุณไว้ที่ `/data/snapotter.db` ในวอลุ่ม แล้วโหมดฝังตัวจะนำเข้าไปยัง PostgreSQL แบบฝังตัวในการบูตครั้งแรก การนำเข้าทำเพียงครั้งเดียว การบูตครั้งต่อไปจะข้าม

หมายเหตุเรื่องการเก็บข้อมูลการใช้งาน โหมดฝังตัวรับค่าเริ่มต้นด้านการวิเคราะห์ข้อมูลของอิมเมจเหมือนการกำหนดค่าอื่น ๆ อิมเมจที่เผยแพร่เปิดการวิเคราะห์ข้อมูลไว้มาให้ หากต้องการปิด ให้สร้างอิมเมจด้วย `--build-arg SNAPOTTER_ANALYTICS=off` ตั้งค่า `SNAPOTTER_ANALYTICS_DEFAULT=off` ก่อนการบูตครั้งแรก หรือใช้การเลือกไม่เข้าร่วมของผู้ดูแลระบบในแอป

| `MAX_VIDEO_BITRATE_KBPS` | `0` (ไม่จำกัด) | บิตเรตรวมสูงสุดที่เครื่องมือวิดีโอรับได้ เป็นกิโลบิตต่อวินาที ตั้งเป็น 0 เพื่อไม่จำกัด |
| `PREVIEW_TIMEOUT_S` | `300` | ขีดจำกัดเวลาในการเข้ารหัสคลิปตัวอย่างในเบราว์เซอร์หนึ่งคลิปของไฟล์วิดีโอหรือเสียง เป็นวินาที ตัวอย่างเอกสารใช้ `LIBREOFFICE_TIMEOUT_S` แทน ตั้งเป็น 0 เพื่อไม่จำกัด |
| `LIBREOFFICE_TIMEOUT_S` | `120` | ขีดจำกัดเวลาของการแปลง LibreOffice หนึ่งครั้ง (Word, Excel และ PowerPoint เป็น PDF ตัวแปลงเอกสาร และตัวอย่างเอกสาร) เป็นวินาที ตั้งเป็น `0` เพื่อไม่จำกัด |
| `GIF_BG_MAX_FRAMES` | `150` | จำนวนเฟรมมากที่สุดที่ลบพื้นหลัง GIF รับได้ในหนึ่งแอนิเมชัน แอนิเมชันที่ยาวกว่านั้นจะได้รับ `400` ที่ระบุจำนวนเฟรม ตั้งเป็น 0 เพื่อไม่จำกัดจำนวนเฟรม ส่วนงบพิกเซลแยกต่างหากยังคงมีผล |
| `SUBPROCESS_MEMORY_LIMIT_MB` | `0` (ปิด) | เพดานพื้นที่แอดเดรสเป็นเมกะไบต์ สำหรับแต่ละโพรเซสตัวช่วยเหล่านี้ ได้แก่ ffmpeg, ffprobe, Ghostscript, qpdf, LibreOffice, pandoc และ pdfcpu ในเอนจินสื่อและเอกสาร รวมถึงสำหรับภาพ คือ exiftool ตัวถอดรหัสและตัวเข้ารหัส HEIF, JPEG XL และ JPEG 2000 ตัวถอดรหัส RAW และตัวถอดรหัสสำรองของ ffmpeg ImageMagick ไม่ถูกจำกัดเพราะมีขีดจำกัดหน่วยความจำของตัวเอง และ AI sidecar ก็ไม่ถูกจำกัดเช่นกัน โพรเซสที่เกินเพดานจะถูกปิดแทนที่จะดันทั้งคอนเทนเนอร์เข้าสู่กลไก out-of-memory killer ค่านี้จำกัดหน่วยความจำเสมือน ไม่ใช่หน่วยความจำที่ใช้จริง จึงควรตั้งให้สูงกว่าที่โพรเซสใช้จริงอย่างมาก ตัวเข้ารหัส JPEG XL ต้องการมากที่สุด ภาพ 24 MP ต้องใช้ราว 1.8 GB และล้มเหลวที่ 1 GB และการเพิ่มเธรดหรือ CPU ก็ไม่ช่วยมากนัก ขณะที่ตั้งเพดานนี้ ตัวเข้ารหัส HEIF จะถูกจำกัดไว้ที่สองเวิร์กเกอร์เธรด ซึ่งทำให้การเข้ารหัสภาพ 24 MP ใช้ราว 0.8 GB โดยแลกกับการเข้ารหัสที่ช้าลง เริ่มที่ `2048` แล้วลดลงหลังจากทดสอบไฟล์ที่ใหญ่ที่สุดของคุณเท่านั้น ตั้งเป็น 0 เพื่อปิดและพึ่งขีดจำกัดหน่วยความจำของคอนเทนเนอร์ |
| `MAX_SETTINGS_PAYLOAD_KB` | `64` | ขนาดสูงสุดของฟิลด์ `settings` ที่คำขอเครื่องมือส่งมาได้ เป็นกิโลไบต์ นับเป็นไบต์ UTF-8 คำขอที่เกินขีดจำกัดจะได้รับ `400` ตั้งเป็น 0 เพื่อไม่จำกัด การตั้งค่าเครื่องมือจริงมีขนาดเล็กกว่า 64 KB มาก ดังนั้นให้เพิ่มค่านี้เฉพาะเมื่อไคลเอนต์ส่งการตั้งค่าที่ใหญ่ผิดปกติ |
| `MAX_SUBTITLE_SIZE_MB` | `1` | ไฟล์คำบรรยาย (`.srt`, `.vtt`, `.ass`) ที่ใหญ่ที่สุดที่ฝังคำบรรยายลงภาพและฝังคำบรรยายรับได้ เป็นเมกะไบต์ ไฟล์ที่ใหญ่กว่านั้นจะได้รับ `400` ที่ระบุขนาดไฟล์และขีดจำกัด ตั้งเป็น 0 เพื่อไม่จำกัด ไฟล์คำบรรยายของภาพยนตร์ความยาวปกติมักเล็กกว่า 1 MB มาก |
| `MAX_METADATA_TAG_LENGTH` | `10000` | ค่าที่ยาวที่สุดที่แก้ไขเมทาดาทาเขียนลงในแท็กเดียว (ศิลปิน คำอธิบาย คีย์เวิร์ด และอื่น ๆ) เป็นจำนวนอักขระ ค่าที่ยาวกว่านั้นจะได้รับ `400` ที่ระบุแท็กและขีดจำกัด ตั้งเป็น 0 เพื่อไม่จำกัด เพิ่มค่านี้หากคุณเก็บคำบรรยายภาพหรือคำอธิบายที่ยาว ค่าของแท็กต้องพอดีภายใน `MAX_SETTINGS_PAYLOAD_KB` และขีดจำกัดต่ออาร์กิวเมนต์ของระบบปฏิบัติการ (128 KB บน Linux) ด้วย |

### เอนจิน {#engines}

SnapOtter ค้นหาไบนารีประมวลผลแต่ละตัวบน `$PATH` ภายในคอนเทนเนอร์ ดังนั้นตัวแปรเหล่านี้จะว่างไว้ เว้นแต่คุณเมานต์บิลด์ของคุณเอง

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `FFMPEG_PATH` | (ว่าง) | พาธไปยังไบนารี `ffmpeg` ที่อยู่เบื้องหลังเครื่องมือวิดีโอและเสียง |
| `FFPROBE_PATH` | (ว่าง) | พาธไปยัง `ffprobe` ซึ่งอ่านไฟล์สื่อก่อนประมวลผล ชี้ไปที่บิลด์เดียวกับ `FFMPEG_PATH` |
| `QPDF_PATH` | (ว่าง) | พาธไปยัง `qpdf` ที่เครื่องมือ PDF ใช้ และใช้ตรวจสอบ PDF ที่อัปโหลด |
| `SOFFICE_PATH` | (ว่าง) | พาธไปยัง `soffice` ของ LibreOffice ใช้สำหรับการแปลงเอกสารสำนักงาน |
| `PDFCPU_PATH` | (ว่าง) | พาธไปยัง `pdfcpu` ที่เครื่องมือ PDF บางตัวใช้ |
| `GS_PATH` | (ว่าง) | พาธไปยัง `gs` ของ Ghostscript ที่เครื่องมือ PDF และ PDF OCR ใช้ |
| `PANDOC_PATH` | (ว่าง) | พาธไปยัง `pandoc` ที่ใช้สำหรับการแปลงเอกสาร |
| `SNAPOTTER_FONT_FILE` | (ว่าง) | ไฟล์ฟอนต์สำหรับข้อความที่วาดลงบนวิดีโอ (ฝังคำบรรยาย ลายน้ำวิดีโอ) หากว่างจะใช้ฟอนต์แรกที่อิมเมจพบ |
| `SNAPOTTER_FONT_FAMILY` | (ว่าง) | ชื่อตระกูลฟอนต์ของ `SNAPOTTER_FONT_FILE` หากว่างหมายถึง `Sans` |
| `SNAPOTTER_HW_ACCEL` | (ว่าง) | กลุ่มตัวเข้ารหัสวิดีโอด้วยฮาร์ดแวร์ `nvenc` หรือ `vaapi` หากว่างจะเข้ารหัสด้วยซอฟต์แวร์ |

`SNAPOTTER_HW_ACCEL` ต้องใช้ ffmpeg ที่สร้างพร้อมกลุ่มตัวเข้ารหัสนั้น และ ffmpeg ในอิมเมจไม่มีทั้งสองแบบ เมื่อใช้ไบนารีของอิมเมจเอง การตั้งค่านี้จะถอยกลับไปเข้ารหัสด้วยซอฟต์แวร์ และแจ้งไว้ในบันทึกตอนเริ่มต้น หากต้องการใช้งาน ให้เมานต์บิลด์ ffmpeg ของคุณเอง ชี้ `FFMPEG_PATH` และ `FFPROBE_PATH` ไปที่มัน และให้อุปกรณ์ GPU แก่คอนเทนเนอร์ สำหรับ `nvenc` ให้ตั้ง `NVIDIA_DRIVER_CAPABILITIES=compute,utility,video` ด้วย เพราะอิมเมจขอเพียง `compute,utility` และหากไม่มี `video` รันไทม์ของ NVIDIA จะไม่เมานต์ไลบรารีเข้ารหัส ทำให้ตัวเข้ารหัสปรากฏในรายการแต่ทุกการเข้ารหัสล้มเหลว การแทนที่พาธที่ไม่มีอยู่จริงหรือรันไม่ได้ก็จะถูกระบุชื่อในบันทึกตอนเริ่มต้นเช่นกัน และทุกงานที่ต้องใช้ไบนารีนั้นจะล้มเหลวจนกว่าคุณจะแก้พาธหรือเลิกตั้งค่า

ไฟล์ Compose ที่เผยแพร่ส่งต่อตัวแปรทั้งหมดนี้จาก `.env` ดังนั้นตั้งค่าที่นั่นก็เพียงพอ

## ตัวอย่าง Docker {#docker-example}

```yaml
services:
  SnapOtter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - SnapOtter-data:/data
      - SnapOtter-workspace:/tmp/workspace
    environment:
      - AUTH_ENABLED=true
      - DEFAULT_USERNAME=admin
      - DEFAULT_PASSWORD=changeme
      - DATABASE_URL=postgres://snapotter:snapotter@postgres:5432/snapotter
      - REDIS_URL=redis://redis:6379
      - MAX_UPLOAD_SIZE_MB=200
      - CONCURRENT_JOBS=4
      - FILE_MAX_AGE_HOURS=12
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: snapotter
      POSTGRES_PASSWORD: snapotter     # Change this for non-local deployments
      POSTGRES_DB: snapotter
    volumes:
      - SnapOtter-pgdata:/var/lib/postgresql/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U snapotter -d snapotter"]
      interval: 10s
      timeout: 5s
      retries: 12

  redis:
    image: redis:8-alpine
    command: ["redis-server", "--maxmemory-policy", "noeviction", "--appendonly", "yes"]
    volumes:
      - SnapOtter-redisdata:/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 12

volumes:
  SnapOtter-data:
  SnapOtter-workspace:
  SnapOtter-pgdata:
  SnapOtter-redisdata:
```

## วอลุ่ม {#volumes}

สแตก Docker Compose ใช้สี่วอลุ่ม

- `/data` (แอป) - โมเดล AI, Python venv และไฟล์ผู้ใช้ เมานต์วอลุ่มนี้เพื่อเก็บไฟล์ที่อัปโหลดและชุด AI ที่ติดตั้งไว้ข้ามการรีสตาร์ต
- `/tmp/workspace` (แอป) - พื้นที่ชั่วคราวสำหรับไฟล์ที่กำลังประมวลผล วอลุ่มนี้เป็นแบบชั่วคราวได้ แต่การเมานต์ช่วยไม่ให้เลเยอร์ที่เขียนได้ของคอนเทนเนอร์เต็ม
- `SnapOtter-pgdata` (postgres) - ไดเรกทอรีข้อมูล PostgreSQL เก็บข้อมูลเชิงสัมพันธ์ทั้งหมด (ผู้ใช้ การตั้งค่า ไปป์ไลน์ งาน บันทึกการตรวจสอบ) สำรองข้อมูลผ่าน `pg_dump` หรือสแนปช็อตของวอลุ่ม
- `SnapOtter-redisdata` (redis) - ไฟล์ append-only ของ Redis สำหรับคิวงานที่คงทน
