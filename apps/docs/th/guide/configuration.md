# การกำหนดค่า {#configuration}

การกำหนดค่าทั้งหมดทำผ่านตัวแปรสภาพแวดล้อม ทุกตัวแปรมีค่าเริ่มต้นที่เหมาะสม SnapOtter จึงใช้งานได้ทันทีโดยไม่ต้องตั้งค่าใด ๆ

## ตัวแปรสภาพแวดล้อม {#environment-variables}

### เซิร์ฟเวอร์ {#server}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `PORT` | `1349` | พอร์ตที่เซิร์ฟเวอร์รับการเชื่อมต่อ |
| `BASE_PATH` | (ว่าง) | เส้นทางการติดตั้งสาธารณะ เช่น `/snapotter` หากว่างหรือเป็น `/` จะให้บริการที่รากของโดเมน มีผลขณะรันโดยไม่ต้องสร้างอิมเมจใหม่ |
| `RATE_LIMIT_PER_MIN` | `1000` | จำนวนคำขอสูงสุดต่อนาทีต่อ IP ตั้งเป็น 0 เพื่อปิดการจำกัดอัตรา |
| `CORS_ORIGIN` | (ว่าง) | รายการ origin ที่อนุญาตสำหรับ CORS คั่นด้วยจุลภาค หรือเว้นว่างเพื่ออนุญาตเฉพาะ origin เดียวกัน |
| `LOG_LEVEL` | `info` | ระดับความละเอียดของบันทึก ใช้ได้หนึ่งในค่าต่อไปนี้ `fatal`, `error`, `warn`, `info`, `debug`, `trace` |
| `TRUST_PROXY` | `loopback,linklocal,uniquelocal` | กำหนดว่าเพียร์ใดตั้งค่า IP ของไคลเอนต์ผ่าน `X-Forwarded-For` ได้ ค่าเริ่มต้นเชื่อถือเฉพาะเพียร์ในเครือข่ายส่วนตัว ดังนั้นรีเวิร์สพร็อกซีบนเครือข่าย Docker หรือ LAN จะได้รับความเชื่อถือ ส่วนเฮดเดอร์ปลอมจากไคลเอนต์สาธารณะจะไม่ได้รับ ตั้งค่า `true` เฉพาะเมื่อมีพร็อกซีที่คุณควบคุมอยู่ด้านหน้าบนที่อยู่สาธารณะ |

### การยืนยันตัวตน {#authentication}

ค่าบูลีนสองตัวด้านล่างรับเฉพาะ `true` และ `false` ค่าอื่นใด ไม่ว่าจะเป็น `1` หรือ `yes` หรือ `on` จะไม่ผ่านการตรวจสอบ และเซิร์ฟเวอร์จะหยุดทำงานก่อนเริ่มรับการเชื่อมต่อ

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `AUTH_ENABLED` | `true` | บังคับให้เข้าสู่ระบบ หากตั้งเป็น `false` จะทำงานโดยไม่มีบัญชีผู้ใช้เลย ซึ่งให้สิทธิ์ผู้ดูแลระบบแก่ทุกคำขอ จึงควรใช้เฉพาะในเครือข่ายที่เชื่อถือได้ |
| `DEFAULT_USERNAME` | `admin` | ชื่อผู้ใช้ของบัญชีผู้ดูแลระบบเริ่มต้น ใช้เฉพาะในการรันครั้งแรก |
| `DEFAULT_PASSWORD` | `admin` | รหัสผ่านของบัญชีผู้ดูแลระบบเริ่มต้น ควรเปลี่ยนหลังจากเข้าสู่ระบบครั้งแรก |
| `MAX_USERS` | `0` (ไม่จำกัด) | จำนวนบัญชีผู้ใช้ที่ลงทะเบียนได้สูงสุด ตั้งเป็น 0 เพื่อไม่จำกัด |
| `SESSION_DURATION_HOURS` | `168` | อายุของเซสชันการเข้าสู่ระบบเป็นชั่วโมง (ค่าเริ่มต้นคือ 7 วัน) |
| `SKIP_MUST_CHANGE_PASSWORD` | `false` | ตั้งเป็น `true` เพื่อข้ามหน้าต่างบังคับเปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบครั้งแรก |

### พื้นที่จัดเก็บ {#storage}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `STORAGE_MODE` | `local` | `local` หรือ `s3` S3 และ MinIO ต้องใช้ไลเซนส์ที่มีฟีเจอร์ s3_storage รวมถึงตัวแปร `S3_*` ด้านล่าง |
| `DATABASE_URL` | `postgres://snapotter:snapotter@localhost:5432/snapotter` | สตริงการเชื่อมต่อ PostgreSQL และเป็นการเชื่อมต่อที่ใช้รับทุกคำขอ ตั้งแต่ 2.3.0 เป็นต้นไป หากตั้ง `DATABASE_MIGRATION_URL` ด้วย ตัวแปรนี้จะกลายเป็นบทบาทขณะรันที่มีสิทธิ์น้อยที่สุด คือมีเพียง DML บนตารางของแอปและไม่มีสิทธิ์อื่น สแตก Compose ชี้ตัวแปรนี้ไปที่เซอร์วิส `postgres` ของมัน หากไม่ตั้งค่า (พร้อมกับ `REDIS_URL`) จะเข้าสู่โหมดฝังตัว |
| `DATABASE_MIGRATION_URL` | (ว่าง) | การเชื่อมต่อแบบมีสิทธิ์สูง ใช้เฉพาะระหว่างบูตเพื่อรันการย้ายข้อมูลและมอบสิทธิ์ให้บทบาทขณะรัน แล้วปิดก่อนคำขอแรก หากเว้นว่าง SnapOtter จะทำงานแบบบทบาทเดียว โดยให้ `DATABASE_URL` ทำทั้งสองหน้าที่ ดู [บทบาทที่มีสิทธิ์น้อยที่สุด](/th/guide/database#least-privilege-roles) |
| `REDIS_URL` | `redis://localhost:6379` | สตริงการเชื่อมต่อ Redis (ใช้สำหรับคิวงานของ BullMQ) Compose ชี้ตัวแปรนี้ไปที่เซอร์วิส `redis` ของมัน |
| `WORKSPACE_PATH` | `./tmp/workspace` | ไดเรกทอรีสำหรับไฟล์ชั่วคราวระหว่างการประมวลผล ล้างโดยอัตโนมัติ อิมเมจตั้งค่า `/tmp/workspace` |
| `FILES_STORAGE_PATH` | `./data/files` | ไดเรกทอรีสำหรับไฟล์ผู้ใช้ที่เก็บถาวร (รูปภาพที่อัปโหลด ผลลัพธ์ที่บันทึกไว้) อิมเมจตั้งค่า `/data/files` |

### พื้นที่จัดเก็บอ็อบเจกต์ S3 {#s3-object-storage}

อ่านค่าเฉพาะเมื่อ `STORAGE_MODE=s3` หากขาดตัวแปรที่จำเป็นทั้งสามตัวใดตัวหนึ่ง การเริ่มต้นจะล้มเหลวพร้อมระบุชื่อตัวแปรที่ขาด

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `S3_BUCKET` | (ว่าง) | บักเก็ตที่เก็บไฟล์อัปโหลดและผลลัพธ์ จำเป็นต้องระบุ |
| `S3_ACCESS_KEY_ID` | (ว่าง) | access key จำเป็นต้องระบุ ในคอนเทนเนอร์สามารถเมานต์ไฟล์แทนได้ ผ่าน `S3_ACCESS_KEY_ID_FILE` |
| `S3_SECRET_ACCESS_KEY` | (ว่าง) | secret key จำเป็นต้องระบุ ใช้แนวทางไฟล์เดียวกัน `S3_SECRET_ACCESS_KEY_FILE` |
| `S3_REGION` | `us-east-1` | ภูมิภาคของบักเก็ต |
| `S3_ENDPOINT` | (ว่าง) | endpoint แบบกำหนดเองสำหรับ MinIO, R2, Backblaze และที่เก็บอื่นที่เข้ากันได้กับ S3 หากว่างหมายถึง AWS |
| `S3_FORCE_PATH_STYLE` | `false` | ตั้งเป็น `true` สำหรับ MinIO และระบบอื่นที่ต้องการ `endpoint/bucket/key` แทนการระบุที่อยู่แบบ virtual-host |
| `S3_PREFIX` | (ว่าง) | คำนำหน้าของคีย์ เพื่อให้บักเก็ตเดียวเก็บได้หลายอินสแตนซ์ |

### การเข้ารหัสข้อมูลที่เก็บอยู่ {#encryption-at-rest}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `DATA_ENCRYPTION_KEY` | (ว่าง) | อักขระเลขฐานสิบหก 64 ตัว (32 ไบต์) ใช้เข้ารหัสการตั้งค่าที่ละเอียดอ่อนซึ่งเก็บในฐานข้อมูล ค่าที่ไม่ใช่เลขฐานสิบหก 64 ตัวจะถูกปฏิเสธเมื่อเริ่มต้น |
| `DATA_ENCRYPTION_KEY_PREVIOUS` | (ว่าง) | คีย์เดิมที่กำลังจะเปลี่ยนออก รูปแบบเดียวกัน ตั้งทั้งสองตัวระหว่างการหมุนเวียนคีย์เพื่อให้แถวที่มีอยู่ยังถอดรหัสได้ จากนั้นจึงเอาตัวนี้ออก |

### โหมดฝังตัว {#embedded-mode}

หากรันอิมเมจโดยไม่มี `DATABASE_URL` และ `REDIS_URL` อิมเมจจะเริ่ม PostgreSQL 17 และ Redis ของตัวเองภายในคอนเทนเนอร์ ผูกกับ loopback และเก็บข้อมูลทั้งหมดบนวอลุ่ม `/data` วิธีนี้ทำให้ประสบการณ์แบบคำสั่งเดียว `docker run` กลับมา สำหรับการเริ่มต้นอย่างรวดเร็ว โฮมแล็บ และการอัปเกรดจาก 1.x นี่เป็นเส้นทางที่เน้นความสะดวก ไม่ใช่การติดตั้งสำหรับโปรดักชัน สำหรับโปรดักชัน ให้รันสแตก Compose แบบ 3 คอนเทนเนอร์ที่แยก PostgreSQL และ Redis ออกจากกัน โหมดฝังตัวต้องรันคอนเทนเนอร์เป็น root และใช้ไม่ได้กับรันไทม์ที่กำหนด UID ตามอำเภอใจ (OpenShift, Kubernetes `runAsNonRoot`) ในกรณีนั้นให้ใช้ Compose

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `EMBEDDED` | `auto` | เปิดใช้อัตโนมัติเมื่อไม่ได้ตั้งทั้ง `DATABASE_URL` และ `REDIS_URL` ตั้งเป็น `0` เพื่อปิด (แอปจะล้มเหลวทันทีหากไม่มี `DATABASE_URL`/`REDIS_URL` ภายนอก แทนที่จะเริ่มฐานข้อมูลในคอนเทนเนอร์อย่างเงียบ ๆ) |
| `REDIS_MAXMEMORY` | `512mb` | เพดานหน่วยความจำของ Redis แบบฝังตัว (เฉพาะโหมดฝังตัว) ลดค่านี้บนโฮสต์ที่มีหน่วยความจำจำกัด เช่น Raspberry Pi |
| `EMBEDDED_REDIS_TIMEOUT_S` | `180` | จำนวนวินาทีที่การบูตรอให้ Redis แบบฝังตัวตอบ `PING` ก่อนยอมแพ้ เมื่อหมดเวลา คอนเทนเนอร์จะหยุดและบันทึกสาเหตุ แทนที่จะค้าง เป็นจำนวนวินาทีเต็มตั้งแต่ 1 ถึง 999999 ไม่มีค่าแบบไม่จำกัด เพราะการรอตลอดไปคือความล้มเหลวที่ขอบเขตนี้มีไว้ป้องกัน เพิ่มค่านี้เฉพาะเมื่อโฮสต์ที่ช้าทำให้หมดเวลา |
| `EMBEDDED_POSTGRES_TIMEOUT_S` | `600` | เช่นเดียวกัน สำหรับ PostgreSQL แบบฝังตัว การจับเวลาเริ่มหลังจาก `initdb` ในการบูตครั้งแรกเสร็จสิ้น จึงครอบคลุมการเริ่มเซิร์ฟเวอร์และการกู้คืนหลังขัดข้อง ไม่รวมการสร้างฐานข้อมูลเริ่มต้น |

การอัปเกรดจาก 1.x ให้วาง `snapotter.db` เดิมของคุณไว้ที่ `/data/snapotter.db` ในวอลุ่ม แล้วโหมดฝังตัวจะนำเข้าไปยัง PostgreSQL แบบฝังตัวในการบูตครั้งแรก การนำเข้าทำเพียงครั้งเดียว การบูตครั้งต่อไปจะข้าม

หมายเหตุเรื่องการเก็บข้อมูลการใช้งาน โหมดฝังตัวรับค่าเริ่มต้นด้านการวิเคราะห์ข้อมูลของอิมเมจเหมือนการกำหนดค่าอื่น ๆ อิมเมจที่เผยแพร่เปิดการวิเคราะห์ข้อมูลไว้ หากต้องการปิด ให้สร้างอิมเมจด้วย `--build-arg SNAPOTTER_ANALYTICS=off` หรือใช้การเลือกไม่เข้าร่วมของผู้ดูแลระบบในแอป

### ขีดจำกัดการประมวลผล {#processing-limits}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `MAX_UPLOAD_SIZE_MB` | `0` (ไม่จำกัด) | ขนาดไฟล์สูงสุดต่อการอัปโหลดเป็นเมกะไบต์ ตั้งเป็น 0 เพื่อไม่จำกัด อิมเมจที่เผยแพร่ตั้งค่า `0` ส่วนการสร้างจากซอร์สเริ่มที่ 100 |
| `MAX_BATCH_SIZE` | `0` (ไม่จำกัด) | จำนวนไฟล์สูงสุดในคำขอแบบแบตช์หนึ่งครั้ง ตั้งเป็น 0 เพื่อไม่จำกัด อิมเมจที่เผยแพร่ตั้งค่า `0` ส่วนการสร้างจากซอร์สเริ่มที่ 100 |
| `CONCURRENT_JOBS` | `0` (อัตโนมัติ) | จำนวนงานแบตช์ที่รันพร้อมกัน ตั้งเป็น 0 เพื่อตรวจหาอัตโนมัติตามจำนวนคอร์ CPU ที่มี |
| `MAX_MEGAPIXELS` | `0` (ไม่จำกัด) | ความละเอียดภาพสูงสุดที่อนุญาตเป็นเมกะพิกเซล ตั้งเป็น 0 เพื่อไม่จำกัด |
| `MAX_WORKER_THREADS` | `0` (อัตโนมัติ) | จำนวนเวิร์กเกอร์เธรดสูงสุดสำหรับการประมวลผลภาพ ตั้งเป็น 0 เพื่อตรวจหาอัตโนมัติตามจำนวนคอร์ CPU ที่มี |
| `PROCESSING_TIMEOUT_S` | `0` (ไม่จำกัด) | เวลาประมวลผลสูงสุดต่อคำขอเป็นวินาที ตั้งเป็น 0 เพื่อไม่ให้หมดเวลา |
| `MAX_PIPELINE_STEPS` | `20` | จำนวนขั้นตอนสูงสุดในไปป์ไลน์ ตั้งเป็น 0 เพื่อไม่จำกัด |
| `MAX_CANVAS_PIXELS` | `0` (ไม่จำกัด) | ขนาดแคนวาสสูงสุดเป็นพิกเซลสำหรับภาพผลลัพธ์ ตั้งเป็น 0 เพื่อไม่จำกัด |
| `MAX_SVG_SIZE_MB` | `50` | SVG ที่ใหญ่ที่สุดที่ยอมรับก่อนทำความสะอาด เป็นเมกะไบต์ `0` ทำงานต่างจากแถวรอบข้างในกรณีนี้ โดยจะเอาขีดจำกัดขนาดก่อนการแยกวิเคราะห์ออกทั้งหมด ไม่ใช่เพิ่มขีดจำกัด จึงควรคงการตั้งค่าตัวนี้ไว้ |
| `MAX_PDF_PAGES` | `0` (ไม่จำกัด) | จำนวนหน้า PDF สูงสุดสำหรับการแปลง PDF เป็นรูปภาพ ตั้งเป็น 0 เพื่อไม่จำกัด |

### เอนจิน {#engines}

SnapOtter ค้นหาไบนารีประมวลผลแต่ละตัวบน `$PATH` ภายในคอนเทนเนอร์ ดังนั้นตัวแปรเหล่านี้จะว่างไว้ เว้นแต่คุณเมานต์บิลด์ของคุณเอง

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `FFMPEG_PATH` | (ว่าง) | พาธไปยังไบนารี `ffmpeg` ที่อยู่เบื้องหลังเครื่องมือวิดีโอและเสียง |
| `FFPROBE_PATH` | (ว่าง) | พาธไปยัง `ffprobe` ซึ่งอ่านไฟล์สื่อก่อนประมวลผล ชี้ไปที่บิลด์เดียวกับ `FFMPEG_PATH` |
| `QPDF_PATH` | (ว่าง) | พาธไปยัง `qpdf` ที่เครื่องมือ PDF ใช้ และใช้ตรวจสอบ PDF ที่อัปโหลด |
| `SOFFICE_PATH` | (ว่าง) | พาธไปยัง `soffice` ของ LibreOffice ใช้สำหรับการแปลงเอกสารสำนักงาน |
| `PDFCPU_PATH` | (ว่าง) | พาธไปยัง `pdfcpu` ที่เครื่องมือ PDF บางตัวใช้ |
| `SNAPOTTER_HW_ACCEL` | (ว่าง) | กลุ่มตัวเข้ารหัสวิดีโอด้วยฮาร์ดแวร์ `nvenc` หรือ `vaapi` หากว่างจะเข้ารหัสด้วยซอฟต์แวร์ |

`SNAPOTTER_HW_ACCEL` ต้องใช้ ffmpeg ที่สร้างพร้อมกลุ่มตัวเข้ารหัสนั้น และ ffmpeg ในอิมเมจไม่มีทั้งสองแบบ เมื่อใช้ไบนารีของอิมเมจเอง การตั้งค่านี้จะถอยกลับไปเข้ารหัสด้วยซอฟต์แวร์ และแจ้งไว้ในบันทึกตอนเริ่มต้น หากต้องการใช้งาน ให้เมานต์บิลด์ ffmpeg ของคุณเอง ชี้ `FFMPEG_PATH` และ `FFPROBE_PATH` ไปที่มัน และให้อุปกรณ์ GPU แก่คอนเทนเนอร์ สำหรับ `nvenc` ให้ตั้ง `NVIDIA_DRIVER_CAPABILITIES=compute,utility,video` ด้วย เพราะอิมเมจขอเพียง `compute,utility` และหากไม่มี `video` รันไทม์ของ NVIDIA จะไม่เมานต์ไลบรารีเข้ารหัส ทำให้ตัวเข้ารหัสปรากฏในรายการแต่ทุกการเข้ารหัสล้มเหลว การแทนที่พาธที่ไม่มีอยู่จริงหรือรันไม่ได้ก็จะถูกระบุชื่อในบันทึกตอนเริ่มต้นเช่นกัน และทุกงานที่ต้องใช้ไบนารีนั้นจะล้มเหลวจนกว่าคุณจะแก้พาธหรือเลิกตั้งค่า

ไฟล์ Compose ที่เผยแพร่ส่งต่อทั้งหกตัวจาก `.env` ดังนั้นตั้งค่าที่นั่นก็เพียงพอ

### การล้างข้อมูล {#cleanup}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `FILE_MAX_AGE_HOURS` | `72` | ระยะเวลาที่เก็บผลลัพธ์การประมวลผลที่ยังไม่ได้บันทึก (ไฟล์ที่อัปโหลดดิบและผลลัพธ์ของเครื่องมือ) ก่อนลบโดยอัตโนมัติ ไฟล์ที่คุณบันทึกลงไลบรารีไฟล์อย่างชัดเจนจะไม่ได้รับผลกระทบและคงอยู่จนกว่าคุณจะลบ |
| `CLEANUP_INTERVAL_MINUTES` | `60` | ความถี่ในการรันงานล้างข้อมูล |

### รูปลักษณ์ {#appearance}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `DEFAULT_THEME` | `light` | ธีมเริ่มต้นสำหรับเซสชันใหม่ `light`, `dark` หรือ `system` |
| `DEFAULT_LOCALE` | `en` | ภาษาเริ่มต้นของอินเทอร์เฟซ |
| `DEFAULT_TOOL_VIEW` | `sidebar` | เลย์เอาต์เครื่องมือเริ่มต้น `sidebar` หรือ `fullscreen` |

### สิทธิ์ของ Docker {#docker-permissions}

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|

## ตัวอย่าง Docker {#docker-example}

```yaml
services:
  SnapOtter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - SnapOtter-data:/data
      - SnapOtter-workspace:/tmp/workspace
    environment:
      - AUTH_ENABLED=true
      - DEFAULT_USERNAME=admin
      - DEFAULT_PASSWORD=changeme
      - DATABASE_URL=postgres://snapotter:snapotter@postgres:5432/snapotter
      - REDIS_URL=redis://redis:6379
      - MAX_UPLOAD_SIZE_MB=200
      - CONCURRENT_JOBS=4
      - FILE_MAX_AGE_HOURS=12
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: snapotter
      POSTGRES_PASSWORD: snapotter     # Change this for non-local deployments
      POSTGRES_DB: snapotter
    volumes:
      - SnapOtter-pgdata:/var/lib/postgresql/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U snapotter -d snapotter"]
      interval: 10s
      timeout: 5s
      retries: 12

  redis:
    image: redis:8-alpine
    command: ["redis-server", "--maxmemory-policy", "noeviction", "--appendonly", "yes"]
    volumes:
      - SnapOtter-redisdata:/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 12

volumes:
  SnapOtter-data:
  SnapOtter-workspace:
  SnapOtter-pgdata:
  SnapOtter-redisdata:
```

## วอลุ่ม {#volumes}

สแตก Docker Compose ใช้สี่วอลุ่ม

- `/data` (แอป) - โมเดล AI, Python venv และไฟล์ผู้ใช้ เมานต์วอลุ่มนี้เพื่อเก็บไฟล์ที่อัปโหลดและชุด AI ที่ติดตั้งไว้ข้ามการรีสตาร์ต
- `/tmp/workspace` (แอป) - พื้นที่ชั่วคราวสำหรับไฟล์ที่กำลังประมวลผล วอลุ่มนี้เป็นแบบชั่วคราวได้ แต่การเมานต์ช่วยไม่ให้เลเยอร์ที่เขียนได้ของคอนเทนเนอร์เต็ม
- `SnapOtter-pgdata` (postgres) - ไดเรกทอรีข้อมูล PostgreSQL เก็บข้อมูลเชิงสัมพันธ์ทั้งหมด (ผู้ใช้ การตั้งค่า ไปป์ไลน์ งาน บันทึกการตรวจสอบ) สำรองข้อมูลผ่าน `pg_dump` หรือสแนปช็อตของวอลุ่ม
- `SnapOtter-redisdata` (redis) - ไฟล์ append-only ของ Redis สำหรับคิวงานที่คงทน
