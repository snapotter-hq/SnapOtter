# สิ่งที่ SnapOtter เก็บรวบรวม {#what-snapotter-collects}

Anonymous Product Analytics เปิดอยู่โดยค่าเริ่มต้นในทุกอินสแตนซ์ และไม่มีข้อความถามตอนเปิดใช้ครั้งแรก ผู้ดูแลระบบปิดได้ทั้งอินสแตนซ์ที่ Settings > System > Privacy และการปิดจะหยุดการส่งข้อมูลวิเคราะห์ทั้งหมดไปยัง PostHog และ Sentry

เมื่อเปิดการวิเคราะห์ SnapOtter จะส่งให้ PostHog ว่ามีเครื่องมือและ pipeline ใดทำงาน ใช้เวลานานเท่าใด สำเร็จหรือไม่ รหัสข้อผิดพลาด และจำนวนไฟล์ พร้อมกับ ID แบบไม่ระบุตัวตนของอินสแตนซ์ เวอร์ชัน สถาปัตยกรรม CPU ระบบปฏิบัติการ ประเภทการติดตั้ง และมี GPU หรือไม่ รายงานข้อขัดข้องจะถูกส่งไปยัง Sentry โดยตัดชื่อไฟล์ พาธ อีเมล และค่าที่อยู่ในเครื่องหมายคำพูดออกแล้ว SnapOtter จะไม่ส่งไฟล์ของคุณ ชื่อหรือพาธของไฟล์ เนื้อหาในไฟล์ ผลลัพธ์ OCR หรือข้อความที่ดึงออกมา เมทาดาทาของรูปภาพ หรือตัวตนบัญชีของคุณเลย PostHog และ Sentry เป็นปลายทางเพียงสองแห่งที่ส่งข้อมูลไป และเมื่อปิดการวิเคราะห์จะไม่ส่งอะไรไปยังทั้งสองแห่ง

## เหตุการณ์ที่เราส่ง (เมื่อเปิดใช้งาน) {#events-we-send-when-enabled}

- tool_used: id เครื่องมือ, สถานะ, ระยะเวลา, หมวดหมู่, เป็นเครื่องมือ AI หรือไม่, รหัสข้อผิดพลาดเมื่อล้มเหลว, ชื่อขั้นตอนสำหรับเครื่องมือที่รายงานขั้นตอนหนึ่งแยกต่างหาก (ขั้นตอนวิเคราะห์ของ Passport Photo)
- pipeline_executed: จำนวนขั้นตอน, id เครื่องมือ, แฟล็ก batch, จำนวนไฟล์, ระยะเวลา, สถานะ
- ai_bundle_action: id ชุด, การกระทำ (`install_started`, `installed`, `install_failed`, `uninstalled`, `reset_environment`, หรือ `imported`), ระยะเวลา และเมื่อติดตั้งไม่สำเร็จ จะมีหมวดหมู่ความล้มเหลวจากรายการตายตัว (`oom`, `network`, `disk`, `checksum`, `cpu_unsupported`, `timeout`, หรือ `other`) ไม่มีการส่งเอาต์พุตของตัวติดตั้ง พาธ หรือข้อความแสดงข้อผิดพลาด
- การใช้งานฟรอนต์เอนด์: หน้าเครื่องมือใดที่เปิด, ไฟล์ที่เพิ่ม (นับจำนวนเท่านั้น), เครื่องมือที่เริ่มใช้, การดาวน์โหลด, การบันทึก, การค้นหา (นับจำนวนผลลัพธ์เท่านั้น), การประมวลผลแบบ batch
- รายงานข้อขัดข้อง: ประเภทข้อผิดพลาด ข้อความแสดงข้อผิดพลาดที่ปกปิดข้อมูลแล้ว (นำชื่อไฟล์ พาธ อีเมล และค่าที่อยู่ในเครื่องหมายคำพูดออก) source stack ที่มีชื่อฐานของไฟล์ และสำหรับเครื่องมือ AI จะมี Python traceback ที่มีเฉพาะชื่อฐานของไฟล์เท่านั้น

## สิ่งที่เราไม่เก็บเลย {#what-we-never-collect}

- ชื่อไฟล์หรือพาธ
- เนื้อหาในไฟล์
- ข้อความผลลัพธ์ OCR
- เมทาดาทาของรูปภาพ (EXIF)
- ข้อความที่ดึงออกจากเอกสาร
- ตัวตนบัญชีของคุณ

PostHog เห็นที่อยู่ IP ที่แต่ละคำขอส่งมา เช่นเดียวกับเซิร์ฟเวอร์ทั่วไป โปรเจกต์ PostHog ของเราทิ้งที่อยู่นั้นแทนที่จะจัดเก็บ และเหตุการณ์จากเซิร์ฟเวอร์ของ SnapOtter เองจะส่งค่าตัวแทนไปแทน

## การแจ้งเตือนอัปเดต {#update-notices}

ขณะที่เปิดการวิเคราะห์ เซิร์ฟเวอร์จะถาม PostHog ทุกไม่กี่ชั่วโมงว่า SnapOtter รุ่นใดใหม่ที่สุด โดยใช้ ID แบบไม่ระบุตัวตนของอินสแตนซ์และเวอร์ชันของมัน เมื่อมีรุ่นที่ใหม่กว่า ผู้ดูแลระบบจะเห็นการแจ้งเตือนพร้อมลิงก์ไปยังบันทึกการออกรุ่น หากปิดการแจ้งเตือน มันจะถูกซ่อนไว้จนกว่าจะมีรุ่นถัดไป ระบบจะไม่ติดตั้งหรือดาวน์โหลดอะไรให้คุณ และเมื่อปิดการวิเคราะห์ เซิร์ฟเวอร์จะไม่ถามเลย

## การปิดใช้งาน {#turning-it-off}

ผู้ดูแลระบบ: ไปที่ Settings > System > Privacy แล้วปิด "Anonymous Product Analytics" การส่งจะหยุดทันทีทั้งอินสแตนซ์ และจะไม่มีอะไรถูกส่งไปยัง PostHog หรือ Sentry อีก หากต้องการสร้างอิมเมจที่ไม่มีวันส่งข้อมูลได้ ให้ตั้งค่า build arg `SNAPOTTER_ANALYTICS=off` การตั้ง `SNAPOTTER_TELEMETRY=off` ในสภาพแวดล้อมของเซิร์ฟเวอร์ให้ผลเหมือนกันขณะรันโดยไม่ต้องสร้างอิมเมจใหม่

หากต้องการเริ่มอินสแตนซ์ใหม่โดยปิดการวิเคราะห์ไว้แล้ว ให้เพิ่ม `SNAPOTTER_ANALYTICS_DEFAULT=off` ลงในสภาพแวดล้อมของเซิร์ฟเวอร์ก่อนบูตครั้งแรก เมื่อใช้ Docker Compose ให้ใส่ไว้ใต้ `environment:` ของบริการแอป เพราะการตั้งค่าไว้ใน `.env` เพียงอย่างเดียวจะไม่ส่งถึงคอนเทนเนอร์
