# การตั้งค่าสำหรับทรัพยากรจำกัด {#low-resource-setups}

SnapOtter ทำงานได้ดีบนฮาร์ดแวร์ขนาดเล็ก เช่น Raspberry Pi 4 หรือ 5 แล็ปท็อปเก่า หรือ VPS ขนาด 2 GB หน้านี้เป็นคู่มือเชิงปฏิบัติสำหรับเครื่องเหล่านั้น ได้แก่ สิ่งที่คาดหวังได้ การตั้งค่าแบบคัดลอกไปวางได้พร้อมขีดจำกัดที่เหมาะสม และฟีเจอร์ที่ควรข้าม ข้อมูลเบนช์มาร์กฉบับเต็มที่อยู่เบื้องหลังตัวเลขเหล่านี้อยู่ใน [ความต้องการด้านฮาร์ดแวร์](/th/guide/deployment#hardware-requirements)

ข้อจำกัดสำคัญสองข้อที่ต้องรู้ก่อน:

- **รองรับเฉพาะ 64 บิต** อิมเมจสร้างขึ้นสำหรับ `linux/amd64` และ `linux/arm64` ไม่รองรับ ARM 32 บิต (`armv7`/`armhf`) ดังนั้น Pi รุ่นแรกและตระกูล Pi Zero จึงใช้ไม่ได้
- **หน่วยความจำขั้นต่ำ 2 GB (เครื่องมือที่ไม่ใช่ AI)** หน่วยความจำ 512 MB ไม่สามารถเริ่มสแต็กได้ และ 1 GB ล้มเหลวเมื่อประมวลผลหลายไฟล์เป็นชุด การตั้งค่า 2 GB และ 2 คอร์เป็นขนาดเล็กที่สุดที่รันเครื่องมือที่ไม่ใช่ AI ได้อย่างสบาย

## สิ่งที่ทำงานได้ดีบนฮาร์ดแวร์ขนาดเล็ก {#what-runs-well}

เครื่องมือที่ไม่ใช่ AI ทุกตัวทำงานได้บนเครื่อง 2 GB / 2 คอร์ ได้แก่ ส่วนภาพและไฟล์ทั้งหมด เครื่องมือ PDF และการทำงานกับวิดีโอและเสียงแบบ stream-copy (ตัดช่วง ปิดเสียง remux คอนเทนเนอร์) ส่วนใหญ่เสร็จภายในไม่ถึงหนึ่งวินาที

มีสองงานที่เป็นข้อยกเว้น:

- **การเข้ารหัสวิดีโอใหม่** (การแปลงระหว่างโคเดก) ใช้ CPU หนัก คลิป 1080p ที่ใช้เวลาราว 40 วินาทีบน CPU เดสก์ท็อปที่เร็ว อาจใช้เวลาหลายนาทีบน CPU ระดับ Pi ส่วนการทำงานแบบ stream-copy ยังคงเสร็จทันที
- **เครื่องมือ AI** มีเกณฑ์ขั้นต่ำของหน่วยความจำ CPU ต่อบันเดิล คือ RAM โฮสต์ 2 GB (ว่าง 0.5 GB) สำหรับ Face Detection และ Fast OCR ในตัว หน่วยความจำที่กำหนดใช้งานจริง 4 GiB สำหรับ Accurate OCR, RAM โฮสต์ 4 GB (ว่าง 2 ถึง 3 GB) สำหรับ Transcription, Object Eraser & Colorize, Background Removal, Upscale & Enhance และ Photo Restoration และ RAM โฮสต์ 8 GB (ว่าง 6 GB) สำหรับ High-Quality Inpainting เครื่อง 2 GB ไม่สามารถรัน Whisper, RealESRGAN, rembg หรือ LaMa ได้โดยไม่ถูก OOM kill ดังนั้น SnapOtter จึงตรวจสอบหน่วยความจำว่างก่อนส่งงานไปยัง Python sidecar และปฏิเสธการรันที่ต่ำกว่าเกณฑ์ของบันเดิลทันที

ทั้งสองอย่างจะไม่ถูกติดตั้งหรือทำงานเว้นแต่คุณใช้งาน เมื่อไม่ได้ติดตั้งบันเดิล AI แอปจะใช้หน่วยความจำขณะว่างราว 360 MB และบันเดิล AI จะดาวน์โหลดก็ต่อเมื่อผู้ดูแลระบบเปิดใช้งานเท่านั้น

## ขั้นตอนสำหรับ Raspberry Pi / แล็ปท็อปเก่า {#walkthrough}

นี่คือการติดตั้ง Compose มาตรฐานจาก [เริ่มต้นใช้งาน](/th/guide/getting-started) เพิ่มขีดจำกัดทรัพยากรและเพดานแบบระมัดระวัง โดยสมมติว่าใช้ระบบปฏิบัติการ 64 บิต (บน Pi: Raspberry Pi OS 64-bit หรือ Ubuntu Server arm64)

```yaml
services:
  snapotter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - ./snapotter-data:/data
    environment:
      - DATABASE_URL=postgres://${POSTGRES_APP_USER:-snapotter_app}:${POSTGRES_APP_PASSWORD:-snapotter_app}@db:5432/${POSTGRES_DB:-snapotter}
      - DATABASE_MIGRATION_URL=postgres://${POSTGRES_USER:-snapotter}:${POSTGRES_PASSWORD:-snapotter}@db:5432/${POSTGRES_DB:-snapotter}
      - REDIS_URL=redis://redis:6379
      # Small-box profile: see the table below for what each cap does.
      - CONCURRENT_JOBS=1
      - MAX_WORKER_THREADS=2
      - MAX_BATCH_SIZE=5
      - MAX_UPLOAD_SIZE_MB=100
      - MAX_MEGAPIXELS=50
      - MAX_VIDEO_DURATION_S=300
    deploy:
      resources:
        limits:
          cpus: "2"
          memory: 2G
    depends_on:
      - db
      - redis
    restart: unless-stopped

  db:
    image: postgres:17-alpine
    environment:
      - POSTGRES_USER=${POSTGRES_USER:-snapotter}
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD:-snapotter}     # Change this for non-local deployments
      - POSTGRES_DB=${POSTGRES_DB:-snapotter}
    volumes:
      - ./postgres-data:/var/lib/postgresql/data
    restart: unless-stopped

  redis:
    image: redis:8-alpine
    command: redis-server --maxmemory 256mb --maxmemory-policy noeviction
    restart: unless-stopped
```

หมายเหตุสำหรับเครื่องระดับ Pi:

- **ใช้ SSD แบบ USB แทนการ์ด SD** สำหรับวอลุ่มข้อมูลและ Postgres เวิร์กสเปซของงานมีการอ่านเขียนดิสก์จริง และการ์ด SD ทั้งช้าและเสื่อมเร็ว
- **คอนเทนเนอร์เดี่ยวแบบ all-in-one ก็ใช้งานได้ที่นี่เช่นกัน** (Postgres และ Redis แบบฝังในตัวเมื่อไม่ได้ตั้งค่า `DATABASE_URL`/`REDIS_URL`) และบนโฮสต์ที่หน่วยความจำจำกัด คุณควรลดเพดานของ Redis แบบฝังในตัวด้วย `REDIS_MAXMEMORY` (ดู [การกำหนดค่า](/th/guide/configuration)) Compose ให้การควบคุมรายบริการที่ละเอียดกว่า จึงเป็นเหตุผลที่ขั้นตอนนี้ใช้ Compose
- **เพิ่ม swap บนอุปกรณ์ 2 GB** ช่วยให้ช่วงที่ใช้หน่วยความจำพุ่งขึ้นเป็นครั้งคราว (PDF ขนาดใหญ่ หรือชุดงานที่ลืมจำกัด) ไม่จบลงด้วยการถูกปิดเพราะหน่วยความจำไม่พอ zram เป็นตัวเลือกที่เป็นมิตรกับการ์ด SD
- อิมเมจ arm64 ใช้ CPU เท่านั้น บนบอร์ด ARM ไม่มี CUDA

## ตัวปรับแต่ง {#tuning-knobs}

เพดานทั้งหมดเป็นตัวแปรสภาพแวดล้อม ซึ่งอธิบายอย่างครบถ้วนใน [การกำหนดค่า](/th/guide/configuration) `0` หมายถึงไม่จำกัดหรืออัตโนมัติ ตัวที่สำคัญบนฮาร์ดแวร์ขนาดเล็ก:

| ตัวแปร | ค่าที่แนะนำสำหรับเครื่องเล็ก | สิ่งที่ปกป้อง |
|---|---|---|
| `CONCURRENT_JOBS` | `1` | จำนวนงานที่รันพร้อมกัน การตรวจหาอัตโนมัติใช้จำนวนคอร์ CPU ลบหนึ่ง ซึ่งเหมาะกับเครื่องใหญ่ แต่ร้อนรนเกินไปสำหรับเครื่อง 2 คอร์ที่หน่วยความจำตึง |
| `MAX_WORKER_THREADS` | `2` | เธรดพูลสำหรับประมวลผลภาพ |
| `MAX_BATCH_SIZE` | `5` | การประมวลผลเป็นชุดคือจุดแรกที่เครื่อง 1-2 GB หน่วยความจำหมด |
| `MAX_UPLOAD_SIZE_MB` | `100` | ป้องกันไม่ให้ไฟล์ขนาดใหญ่มากไฟล์เดียวครอบครองเวิร์กสเปซทั้งหมด |
| `MAX_MEGAPIXELS` | `50` | การถอดรหัสภาพกว่า 100 MP ใช้ RAM ไม่ว่าไฟล์จะใหญ่เพียงใด |
| `MAX_VIDEO_DURATION_S` | `300` | การทรานส์โค้ดนาน ๆ ยึด CPU เล็ก ๆ ไว้เป็นเวลานานหลายนาทีถึงหลายชั่วโมง |
| `PROCESSING_TIMEOUT_S` | `600` | เพดานเด็ดขาด เพื่อให้งานที่ทำงานเกินการควบคุมคืนทรัพยากรให้เครื่องในที่สุด |

เพดานเหล่านี้ใช้กับสิ่งที่เซิร์ฟเวอร์ยอมรับ ดังนั้นควรตั้งให้ตรงกับที่คุณใช้จริง แทนที่จะตั้งให้เล็กที่สุดเท่าที่เป็นไปได้ หากคุณไม่เคยแตะวิดีโอ การจำกัด `MAX_VIDEO_DURATION_S` ก็ไม่มีต้นทุนอะไร แต่หากคุณสแกนเอกสารทุกวัน อย่าจำกัด `MAX_PDF_PAGES`

## สิ่งที่ควรข้าม {#what-to-skip}

- **บันเดิล AI ขนาดหนัก** การขยายภาพ การฟื้นฟูภาพถ่าย และการลบพื้นหลังต้องใช้ GPU หรือ CPU หลายคอร์ที่เร็ว และแต่ละบันเดิลใช้พื้นที่ดิสก์ 4-5 GB บนเครื่องเล็กก็แค่ไม่ต้องติดตั้ง เครื่องมือที่ไม่มีบันเดิลจะแสดงข้อความให้ติดตั้งแทนที่จะรัน
- **การเข้ารหัสวิดีโอใหม่เป็นงานประจำ** การทรานส์โค้ดเป็นครั้งคราวไม่มีปัญหา (แค่ช้า) แต่คิวทรานส์โค้ดที่ต่อเนื่องต้องการคอร์ CPU ไม่ใช่ Pi
- **เครื่องมือที่ไม่ได้ใช้โดยทั่วไป** ผู้ดูแลระบบสามารถปิดเครื่องมือแต่ละตัวได้ใน Settings ซึ่งจะนำออกจาก UI และหยุดการลงทะเบียนเส้นทาง API ของเครื่องมือนั้น การทำเช่นนี้ไม่ได้ประหยัดหน่วยความจำโดยตรง แต่ช่วยไม่ให้อินสแตนซ์เล็กที่ใช้ร่วมกันถูกใช้กับงานเดียวที่ฮาร์ดแวร์รับไม่ไหว

หากภายหลังคุณย้ายอินสแตนซ์ไปยังฮาร์ดแวร์ที่ใหญ่กว่า ให้เอาเพดานออก (ตั้งกลับเป็น `0`) แล้ววอลุ่มข้อมูลเดิมก็ใช้ต่อได้เลย
