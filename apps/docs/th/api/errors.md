# รหัสข้อผิดพลาด {#error-codes}

ทุกการตอบกลับข้อผิดพลาดแบบ JSON มีรูปแบบเดียวกัน:

```json
{
  "error": "Job not found",
  "code": "NOT_FOUND",
  "requestId": "req-42"
}
```

| ฟิลด์ | มีเสมอ | ความหมาย |
|-------|----------------|---------|
| `error` | ใช่ | ข้อความที่มนุษย์อ่านได้ แสดงให้ผู้ใช้เห็นได้อย่างปลอดภัย อย่านำไปแยกวิเคราะห์ |
| `code` | ใช่ | รหัสคงที่ที่เครื่องอ่านได้ ให้ใช้รหัสนี้ในการแตกกิ่งตรรกะ |
| `requestId` | ใช่ | ID ของคำขอนี้ฝั่งเซิร์ฟเวอร์ ให้ระบุค่านี้เมื่อรายงานปัญหา โดยตรงกับบันทึกของเซิร์ฟเวอร์ |
| `details` | บางครั้ง | บริบทเพิ่มเติมสำหรับข้อผิดพลาด 4xx บางรายการ เช่น ข้อความการตรวจสอบความถูกต้อง |

ข้อความอาจเปลี่ยนแปลงระหว่างรุ่น แต่รหัสจะไม่เปลี่ยน ดังนั้นให้เขียนตรรกะฝั่งไคลเอนต์โดยอิงกับ `code`

## รหัสจากสถานะ HTTP {#status-codes}

เมื่อเส้นทางไม่ได้กำหนดรหัสของตัวเอง เซิร์ฟเวอร์จะสร้างรหัสจากสถานะดังนี้:

| สถานะ HTTP | `code` |
|-------------|--------|
| 400 | `BAD_REQUEST` |
| 401 | `AUTH_REQUIRED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `UNPROCESSABLE_ENTITY` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` |
| 501 | `NOT_IMPLEMENTED` |
| 503 | `SERVICE_UNAVAILABLE` |
| 507 | `INSUFFICIENT_STORAGE` |

สถานะ 4xx อื่นๆ จะใช้ `BAD_REQUEST` และสถานะ 5xx อื่นๆ จะใช้ `INTERNAL_ERROR`

เส้นทางสามารถกำหนดรหัสที่เฉพาะเจาะจงกว่านี้ได้ และการตอบกลับจะใช้รหัสนั้นแทน ตัวอย่างเช่น เครื่องมือที่ทำงานไม่ได้เพราะไม่มีชุด AI จะส่งรหัสเฉพาะของฟีเจอร์กลับมา รหัสเหล่านั้นอธิบายไว้ร่วมกับฟีเจอร์ที่ทำให้เกิดรหัส

## การยืนยันตัวตนและการเข้าถึง {#auth-codes}

| `code` | สถานะ | สิ่งที่ควรทำ |
|--------|--------|------------|
| `AUTH_REQUIRED` | 401 | ส่ง `Authorization: Bearer <token>` พร้อมโทเค็นเซสชันหรือคีย์ API (`si_...`) |
| `FORBIDDEN` | 403 | ข้อมูลรับรองถูกต้องแต่ไม่มีสิทธิ์ที่จำเป็น ให้ขอสิทธิ์จากผู้ดูแลระบบ |
| `MUST_CHANGE_PASSWORD` | 403 | บัญชีต้องเปลี่ยนรหัสผ่านก่อนจึงจะเรียกปลายทางอื่นได้ ให้เรียก `POST /api/auth/change-password` ด้วยโทเค็นเซสชัน แล้วลองใหม่ |
| `USER_DISABLED` | 403 | บัญชีถูกปิดใช้งาน ผู้ดูแลระบบต้องเปิดใช้งานอีกครั้ง |
| `LOGIN_THROTTLED` | 429 | ลงชื่อเข้าใช้ไม่สำเร็จหลายครั้งเกินไป โปรดรอสักครู่ก่อนลองใหม่ |
| `VALIDATION_ERROR` | 400 | เนื้อหาหรือพารามิเตอร์ของคำขอไม่ผ่านการตรวจสอบความถูกต้อง `details` ระบุปัญหาที่พบ |

บัญชีผู้ดูแลระบบเริ่มต้นคือ `admin` ที่มีรหัสผ่าน `admin` เว้นแต่ `DEFAULT_USERNAME` หรือ `DEFAULT_PASSWORD` จะเปลี่ยนค่าไว้ หากไม่ได้ตั้ง `SKIP_MUST_CHANGE_PASSWORD` บัญชีนั้นจะได้รับ `MUST_CHANGE_PASSWORD` ในทุกการเรียกจนกว่าจะเปลี่ยนรหัสผ่าน

## งาน {#job-codes}

งานที่ล้มเหลวจะรายงานสาเหตุในตัวงานเอง ไม่ใช่ในข้อผิดพลาด HTTP ให้อ่าน `error.code` และ `error.message` จาก `GET /api/v1/jobs/{jobId}` ดู [การติดตามความคืบหน้า](/th/api/rest#progress-tracking)

งานที่ล้มเหลวจะเก็บ `error.code` ไว้เฉพาะเมื่อความล้มเหลวเกิดจากข้อผิดพลาดของอินพุตหรือความผิดปกติของเซิร์ฟเวอร์ ความล้มเหลวอื่นๆ จะมีเพียงข้อความเท่านั้น

| `code` | ความหมาย | สิ่งที่ควรทำ |
|--------|---------|------------|
| `CANCELED` | ผู้ใช้ยกเลิกงาน นี่ไม่ใช่สถานะ HTTP เหตุการณ์ความคืบหน้าจะมี `phase: failed` พร้อมรหัสนี้ | ให้ถือว่าเป็นการยกเลิกโดยผู้ใช้ อย่าลองใหม่โดยอัตโนมัติ |
| `INPUT_MISSING` | อินพุตถูกลบก่อนที่งานจะทำงาน | อัปโหลดไฟล์อีกครั้ง |
| `ENGINE_UNAVAILABLE` | เอนจินที่จำเป็นเริ่มทำงานบนเซิร์ฟเวอร์ไม่ได้ | ลองใหม่หลังจากผู้ดูแลระบบซ่อมแซมการติดตั้งแล้ว |
| `JOB_STALLED` | ไม่ส่งกลับให้ไคลเอนต์ ใช้เป็นป้ายกำกับรายงานข้อผิดพลาดของเซิร์ฟเวอร์ เวิร์กเกอร์สูญเสียล็อกของงานบ่อยกว่าที่คิวอนุญาต ซึ่งมักเกิดจากเซิร์ฟเวอร์รีสตาร์ตหรือหน่วยความจำหรือ CPU ไม่พอ งานจะล้มเหลวพร้อมข้อความว่าถูกขัดจังหวะ | ลองใหม่ หากยังเกิดซ้ำ ให้เพิ่มหน่วยความจำให้เซิร์ฟเวอร์หรือลด `CONCURRENT_JOBS` |

## การยืนยันตัวตนและ MFA {#mfa-codes}

| `code` | สถานะ | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|---------|------------|
| `MFA_ENROLLMENT_REQUIRED` | 403 | นโยบาย MFA กำหนดให้ลงทะเบียน แต่อินสแตนซ์นี้ลงทะเบียนผู้ใช้ไม่ได้ (ไม่มีใบอนุญาต enterprise) อินสแตนซ์ที่มีใบอนุญาตจะตอบกลับ 200 พร้อม `requiresMfaEnrollment: true` และพาผู้ใช้ลงทะเบียนแทน | อย่าลองใหม่ ผู้ดูแลระบบต้องเปลี่ยนนโยบายหรือใช้ CLI กู้คืนแบบออฟไลน์ |
| `MFA_POLICY_UNAVAILABLE` | 503 | เซิร์ฟเวอร์อ่านนโยบาย MFA ไม่ได้ระหว่างลงชื่อเข้าใช้ | ลองลงชื่อเข้าใช้ใหม่อีกครั้งในไม่ช้า |
| `INVALID_CODE` | 401 | รหัส TOTP หรือรหัสกู้คืนไม่ถูกต้อง | ขอรหัสใหม่จากผู้ใช้แล้วลองใหม่ หากล้มเหลวซ้ำจะจบด้วย `MFA_ATTEMPTS_EXHAUSTED` |
| `MFA_ATTEMPTS_EXHAUSTED` | 401 | ใส่รหัสผิดหลายครั้งเกินไป ระบบทิ้งชาเลนจ์นั้น | เริ่มลงชื่อเข้าใช้ใหม่เพื่อรับชาเลนจ์ใหม่ |
| `MFA_EXPIRED` | 401 | ชาเลนจ์ MFA หรือการลงทะเบียนหมดอายุหรือไม่ตรงกัน | เริ่มลงชื่อเข้าใช้ใหม่ |
| `MFA_NOT_CONFIGURED` | 401 | บัญชีไม่มีความลับ TOTP จึงตรวจสอบรหัสไม่ได้ | ลงทะเบียน MFA ก่อนลงชื่อเข้าใช้ด้วยรหัส |
| `MFA_ALREADY_ENABLED` | 409 | บัญชีเปิดใช้ MFA อยู่แล้ว | อย่าลงทะเบียนซ้ำ |
| `NO_PENDING_ENROLLMENT` | 400 | มีการยืนยันการลงทะเบียนเข้ามาโดยไม่มีการลงทะเบียนที่รอดำเนินการ | เรียกปลายทางลงทะเบียนก่อน |
| `MFA_NOT_ENABLED` | 400 | การดำเนินการนี้ต้องเปิด MFA แต่ผู้ใช้รายนี้ปิดอยู่ | ข้ามการดำเนินการนี้ หรือเปิด MFA ก่อน |
| `MFA_DECRYPTION_FAILED` | 500 | ถอดรหัสความลับ TOTP ที่เก็บไว้ไม่ได้ | ผู้ดูแลระบบต้องดำเนินการ ซึ่งมักหมายความว่าคีย์เข้ารหัสเปลี่ยนไป ให้ตรวจสอบ `DATA_ENCRYPTION_KEY` และ `DATA_ENCRYPTION_KEY_PREVIOUS` |
| `DECRYPTION_FAILED` | 500 | ถอดรหัสค่าที่เก็บไว้ (การตั้งค่า เฮดเดอร์การยืนยันตัวตนของเว็บฮุก หรือความลับ TOTP) ไม่ได้ | ผู้ดูแลระบบต้องดำเนินการ เช่นเดียวกับข้างต้น อย่าลองใหม่ |
| `IDLE_TIMEOUT` | 401 | เซสชันหมดอายุหลังไม่มีการใช้งานเป็นระยะเวลาหนึ่ง | ลงชื่อเข้าใช้อีกครั้ง |
| `INVALID_PASSWORD` | 401 | รหัสผ่านปัจจุบันไม่ถูกต้องขณะเปลี่ยนรหัสผ่าน | ขอรหัสผ่านปัจจุบันจากผู้ใช้ |
| `PASSWORD_CHANGED` | 409 | รหัสผ่านถูกเปลี่ยนในเซสชันอื่น หรือผู้ดูแลระบบรีเซ็ตให้ ขณะที่คำขอนี้กำลังทำงานอยู่ | ลงชื่อเข้าใช้อีกครั้ง |
| `OIDC_NO_PASSWORD` | 400 | มีการขอเปลี่ยนหรือรีเซ็ตรหัสผ่านสำหรับบัญชีที่สร้างผ่าน SSO | แนะนำผู้ใช้ไปที่ผู้ให้บริการข้อมูลประจำตัว |

## OIDC {#oidc-codes}

ความล้มเหลวของ OIDC ระหว่างลงชื่อเข้าใช้จะไม่ส่งเนื้อหา JSON กลับมา เส้นทางล็อกอินจะเปลี่ยนเส้นทางไปยังหน้าล็อกอินพร้อมเหตุผลทั่วไป และบันทึกการตรวจสอบจะเก็บรหัสไว้ เส้นทางล็อกเอาต์ยังคงจบเซสชันในเครื่องได้เมื่อติดต่อผู้ให้บริการข้อมูลประจำตัวไม่ได้

| `code` | สถานะ | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|---------|------------|
| `OIDC_ISSUER_SCHEME_MISMATCH` | ไม่มี (เปลี่ยนเส้นทาง) | URL ของผู้ออกเป็น `http` แต่ `EXTERNAL_URL` เป็น `https` ไคลเอนต์จึงปฏิเสธการค้นหา | ผู้ดูแลระบบ: ให้บริการผู้ออกผ่าน `https` หรือรันอินสแตนซ์ผ่าน `http` |
| `OIDC_DISCOVERY_TIMEOUT` | ไม่มี (เปลี่ยนเส้นทาง) | การค้นหาผู้ออกหมดเวลา | ตรวจสอบว่าเซิร์ฟเวอร์เข้าถึงผู้ออกได้ แล้วลองใหม่ |
| `OIDC_DISCOVERY_FAILED` | ไม่มี (เปลี่ยนเส้นทาง) | การค้นหาล้มเหลวด้วยสาเหตุอื่น | ตรวจสอบ URL ของผู้ออกและการเข้าถึงขาออกของเซิร์ฟเวอร์ |
| `OIDC_END_SESSION_INVALID` | ไม่มี (ล็อกเอาต์ดำเนินต่อ) | `end_session_endpoint` ของผู้ให้บริการข้อมูลประจำตัวไม่ใช่ URL ที่ถูกต้อง เซสชันในเครื่องยังคงถูกล้าง | ผู้ดูแลระบบ: แก้ไขเมทาดาทาของผู้ให้บริการ |
| `OIDC_END_SESSION_SCHEME` | ไม่มี (ล็อกเอาต์ดำเนินต่อ) | `end_session_endpoint` ใช้สกีมที่เซิร์ฟเวอร์ไม่อนุญาต เซสชันในเครื่องยังคงถูกล้าง | ผู้ดูแลระบบ: แก้ไขเมทาดาทาของผู้ให้บริการ |

## SAML {#saml-codes}

ความล้มเหลวของ SAML จะไม่กำหนด `code` การยืนยันที่ล้มเหลวจะเปลี่ยนเส้นทางไปยังหน้าล็อกอินพร้อม `saml_auth_failed` และเหตุการณ์การตรวจสอบ `SAML_LOGIN_FAILED` จะบันทึกเหตุผลไว้

## SCIM {#scim-codes}

เส้นทาง SCIM ตอบกลับด้วยซองข้อผิดพลาดตาม RFC 7644 (`schemas`, `detail`, `status` และบางครั้งมี `scimType`) เส้นทางเหล่านี้ไม่กำหนด `code` ให้แตกกิ่งตรรกะตามสถานะ HTTP

## ทีม บทบาท และผู้ใช้ {#team-role-codes}

ชื่อทีมหรือบทบาทซ้ำจะส่ง `CONFLICT` ทั่วไปกลับมา และทีมหรือบทบาทที่ไม่มีอยู่จะส่ง `NOT_FOUND` กลับมา

| `code` | สถานะ | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|---------|------------|
| `ESCALATION_DENIED` | 403 | บทบาทของผู้เรียกไม่อนุญาตให้เปลี่ยนแปลงนี้ เป้าหมายอยู่เหนืออำนาจของผู้เรียก บทบาทนั้นเป็นบทบาทในตัว หรือคำขอมอบสิทธิ์ที่ผู้เรียกไม่มี | อย่าลองใหม่ ให้ขอผู้ใช้ที่มีอำนาจมากกว่า |
| `UNKNOWN_ROLE` | 400 | ID บทบาทไม่ตรงกับบทบาทที่มีอยู่ | แก้ไข ID บทบาท ดูรายการบทบาทเพื่อค้นหา |
| `UNKNOWN_TEAM` | 400 | ID ทีมไม่ตรงกับทีมที่มีอยู่ | แก้ไข ID ทีม |
| `SELF_DEMOTE` | 400 | ผู้ดูแลระบบพยายามลบบทบาทผู้ดูแลระบบของตัวเอง | ให้ผู้ดูแลระบบคนอื่นทำการเปลี่ยนแปลง |
| `SELF_DELETE` | 400 | ผู้ดูแลระบบพยายามลบบัญชีของตัวเอง | ให้ผู้ดูแลระบบคนอื่นเป็นผู้ลบ |
| `LAST_ADMIN` | 400 บนเส้นทางผู้ใช้, 409 บนเส้นทางล้างข้อมูล GDPR | การเปลี่ยนแปลงจะทำให้ไม่เหลือผู้ดูแลระบบ หรือล้างทีมที่มีผู้ดูแลระบบทุกคนอยู่ | ตั้งผู้ใช้คนอื่นเป็นผู้ดูแลระบบก่อน |
| `USER_LIMIT_REACHED` | 403 | อินสแตนซ์ถึงขีดจำกัด `MAX_USERS` แล้ว | ลบผู้ใช้ หรือเพิ่ม `MAX_USERS` |

## ฟีเจอร์และชุด AI {#feature-codes}

เครื่องมือ การรันแบบแบตช์ และไปป์ไลน์ที่ต้องใช้ชุด AI เสริมจะใช้รหัสเหล่านี้

| `SIEM_DECRYPTION_FAILED` | รายงานไปยังระบบติดตามข้อผิดพลาดโดยการส่งต่อ SIEM ถอดรหัสเฮดเดอร์การยืนยันตัวตนของ SIEM ไม่ได้ |
| `WEBHOOK_DECRYPTION_FAILED` | รายงานไปยังระบบติดตามข้อผิดพลาด คำขอที่พบความล้มเหลวเดียวกันจะตอบกลับด้วย `DECRYPTION_FAILED` |
| `STAGED_DISCARD_FAILED` | รายงานไปยังระบบติดตามข้อผิดพลาดเมื่อลบไฟล์อัปโหลดที่พักไว้ไม่ได้ |
| `RETENTION_DEADLINE_BACKFILLED` | รายงานไปยังระบบติดตามข้อผิดพลาดโดยการกวาดตาม TTL ของพื้นที่จัดเก็บ เมื่อเติมกำหนดเวลาเก็บรักษาของทีมที่ขาดหายไปให้งานที่เสร็จแล้ว จากนั้นไฟล์ของงานจะเป็นไปตามการเก็บรักษาของทีม |
| `USERNAME_RACE_EXHAUSTED` | เกิดขึ้นเมื่อการสร้างบัญชีอัตโนมัติของ SSO แพ้การแข่งขันชื่อผู้ใช้ในทุกการลองใหม่ หน้าล็อกอินจะแสดงข้อผิดพลาดแทน |
| `ERR_OUT_OF_RANGE` | โยนโดยตัวอ่านพื้นที่จัดเก็บอ็อบเจกต์สำหรับช่วงไบต์ที่ไม่ถูกต้อง |
| `ETIMEDOUT` | ตั้งไว้ที่ข้อผิดพลาดหมดเวลาของการส่งออก GDPR การส่งออกล้มเหลว และขอส่งออกใหม่ได้ |
| `FST_REQ_FILE_TOO_LARGE` | รหัสของ Fastify สำหรับการอัปโหลดที่เกินขีดจำกัด ไคลเอนต์จะได้รับ 413 พร้อม `PAYLOAD_TOO_LARGE` หรือข้อความ 413 ของเส้นทางนั้นเอง |
| `TARGET_SIZE_EXCEEDED` | โยนเมื่อการบีบอัดตามขนาดเป้าหมายทำไม่ถึงเป้าหมาย ข้อผิดพลาดนี้ไม่มีสถานะหรือรหัส ไคลเอนต์จึงได้รับความล้มเหลวทั่วไป |
| `OCR_CACHE_PERMISSIONS` | รายงานไปยังระบบติดตามข้อผิดพลาดเป็นความผิดปกติในการปฏิบัติการ เมื่อวอลุ่มข้อมูล AI ทำให้แคชรันไทม์ OCR เขียนได้โดยทุกคน งานติดตั้งจะล้มเหลวพร้อมข้อความที่ระบุปัญหาพื้นที่จัดเก็บ |
| `OCR_RUNTIME_UNREACHABLE` | รายงานไปยังระบบติดตามข้อผิดพลาดเป็นความผิดปกติในการปฏิบัติการ เมื่อเซิร์ฟเวอร์ไม่เคยเข้าถึง huggingface.co เพื่อดาวน์โหลดรันไทม์ OCR งานติดตั้งจะล้มเหลวพร้อมข้อความเกี่ยวกับการเข้าถึงเครือข่าย `HTTPS_PROXY`, `HF_ENDPOINT` และการนำเข้าแบบออฟไลน์ |
