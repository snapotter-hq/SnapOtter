# รหัสข้อผิดพลาด {#error-codes}

ทุกการตอบกลับข้อผิดพลาดแบบ JSON มีรูปแบบเดียวกัน:

```json
{
  "error": "Job not found",
  "code": "NOT_FOUND",
  "requestId": "req-42"
}
```

| ฟิลด์ | มีเสมอ | ความหมาย |
|-------|----------------|---------|
| `error` | ใช่ | ข้อความที่มนุษย์อ่านได้ แสดงให้ผู้ใช้เห็นได้อย่างปลอดภัย อย่านำไปแยกวิเคราะห์ |
| `code` | ใช่ | รหัสคงที่ที่เครื่องอ่านได้ ให้ใช้รหัสนี้ในการแตกกิ่งตรรกะ |
| `requestId` | ใช่ | ID ของคำขอนี้ฝั่งเซิร์ฟเวอร์ ให้ระบุค่านี้เมื่อรายงานปัญหา โดยตรงกับบันทึกของเซิร์ฟเวอร์ |
| `details` | บางครั้ง | บริบทเพิ่มเติมสำหรับข้อผิดพลาด 4xx บางรายการ เช่น ข้อความการตรวจสอบความถูกต้อง |

ข้อความอาจเปลี่ยนแปลงระหว่างรุ่น แต่รหัสจะไม่เปลี่ยน ดังนั้นให้เขียนตรรกะฝั่งไคลเอนต์โดยอิงกับ `code`

## รหัสจากสถานะ HTTP {#status-codes}

เมื่อเส้นทางไม่ได้กำหนดรหัสของตัวเอง เซิร์ฟเวอร์จะสร้างรหัสจากสถานะดังนี้:

| สถานะ HTTP | `code` |
|-------------|--------|
| 400 | `BAD_REQUEST` |
| 401 | `AUTH_REQUIRED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `UNPROCESSABLE_ENTITY` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` |
| 501 | `NOT_IMPLEMENTED` |
| 503 | `SERVICE_UNAVAILABLE` |
| 507 | `INSUFFICIENT_STORAGE` |

สถานะ 4xx อื่นๆ จะใช้ `BAD_REQUEST` และสถานะ 5xx อื่นๆ จะใช้ `INTERNAL_ERROR`

เส้นทางสามารถกำหนดรหัสที่เฉพาะเจาะจงกว่านี้ได้ และการตอบกลับจะใช้รหัสนั้นแทน ตัวอย่างเช่น เครื่องมือที่ทำงานไม่ได้เพราะไม่มีชุด AI จะส่งรหัสเฉพาะของฟีเจอร์กลับมา รหัสเหล่านั้นอธิบายไว้ร่วมกับฟีเจอร์ที่ทำให้เกิดรหัส

## การยืนยันตัวตนและการเข้าถึง {#auth-codes}

| `code` | สถานะ | สิ่งที่ควรทำ |
|--------|--------|------------|
| `AUTH_REQUIRED` | 401 | ส่ง `Authorization: Bearer <token>` พร้อมโทเค็นเซสชันหรือคีย์ API (`si_...`) |
| `FORBIDDEN` | 403 | ข้อมูลรับรองถูกต้องแต่ไม่มีสิทธิ์ที่จำเป็น ให้ขอสิทธิ์จากผู้ดูแลระบบ |
| `MUST_CHANGE_PASSWORD` | 403 | บัญชีต้องเปลี่ยนรหัสผ่านก่อนจึงจะเรียกปลายทางอื่นได้ ให้เรียก `POST /api/auth/change-password` ด้วยโทเค็นเซสชัน แล้วลองใหม่ |
| `USER_DISABLED` | 403 | บัญชีถูกปิดใช้งาน ผู้ดูแลระบบต้องเปิดใช้งานอีกครั้ง |
| `LOGIN_THROTTLED` | 429 | ลงชื่อเข้าใช้ไม่สำเร็จหลายครั้งเกินไป โปรดรอสักครู่ก่อนลองใหม่ |
| `VALIDATION_ERROR` | 400 | เนื้อหาหรือพารามิเตอร์ของคำขอไม่ผ่านการตรวจสอบความถูกต้อง `details` ระบุปัญหาที่พบ |

บัญชีผู้ดูแลระบบเริ่มต้นคือ `admin` ที่มีรหัสผ่าน `admin` เว้นแต่ `DEFAULT_USERNAME` หรือ `DEFAULT_PASSWORD` จะเปลี่ยนค่าไว้ หากไม่ได้ตั้ง `SKIP_MUST_CHANGE_PASSWORD` บัญชีนั้นจะได้รับ `MUST_CHANGE_PASSWORD` ในทุกการเรียกจนกว่าจะเปลี่ยนรหัสผ่าน

## งาน {#job-codes}

งานที่ล้มเหลวจะรายงานสาเหตุในตัวงานเอง ไม่ใช่ในข้อผิดพลาด HTTP ให้อ่าน `error.code` และ `error.message` จาก `GET /api/v1/jobs/{jobId}` ดู [การติดตามความคืบหน้า](/th/api/rest#progress-tracking)

## ยังไม่ได้จัดทำแค็ตตาล็อก {#not-yet-cataloged}

รหัสที่เกิดจากแต่ละฟีเจอร์ (เช่น การเข้ารหัส OIDC SCIM และทีม) ยังไม่ได้อธิบายไว้ในหน้านี้ ทุกรหัสเป็นรหัสคงที่ ให้ถือว่ารหัสที่ไม่อยู่ในรายการเป็นค่าทึบแสง และจัดการตามสถานะของรหัสนั้น
