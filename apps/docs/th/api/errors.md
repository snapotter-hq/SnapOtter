# รหัสข้อผิดพลาด {#error-codes}

ทุกการตอบกลับข้อผิดพลาดแบบ JSON มีรูปแบบเดียวกัน:

```json
{
  "error": "Job not found",
  "code": "NOT_FOUND",
  "requestId": "req-42"
}
```

| ฟิลด์ | มีเสมอ | ความหมาย |
|-------|----------------|---------|
| `error` | ใช่ | ข้อความที่มนุษย์อ่านได้ แสดงให้ผู้ใช้เห็นได้อย่างปลอดภัย อย่านำไปแยกวิเคราะห์ |
| `code` | ใช่ | รหัสคงที่ที่เครื่องอ่านได้ ให้ใช้รหัสนี้ในการแตกกิ่งตรรกะ |
| `requestId` | ใช่ | ID ของคำขอนี้ฝั่งเซิร์ฟเวอร์ ให้ระบุค่านี้เมื่อรายงานปัญหา ค่านี้ตรงกับบันทึกของเซิร์ฟเวอร์ |
| `details` | บางครั้ง | บริบทเพิ่มเติมสำหรับข้อผิดพลาด 4xx บางรายการ เช่น ข้อความการตรวจสอบความถูกต้อง |

ข้อความอาจเปลี่ยนแปลงระหว่างรุ่น แต่รหัสจะไม่เปลี่ยน ดังนั้นให้เขียนตรรกะฝั่งไคลเอนต์โดยอิงกับ `code`

## รหัสจากสถานะ HTTP {#status-codes}

เมื่อเส้นทางไม่ได้กำหนดรหัสของตัวเอง เซิร์ฟเวอร์จะสร้างรหัสจากสถานะดังนี้:

| สถานะ HTTP | `code` |
|-------------|--------|
| 400 | `BAD_REQUEST` |
| 401 | `AUTH_REQUIRED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `UNPROCESSABLE_ENTITY` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` |
| 501 | `NOT_IMPLEMENTED` |
| 503 | `SERVICE_UNAVAILABLE` |
| 507 | `INSUFFICIENT_STORAGE` |

สถานะ 4xx อื่นๆ จะใช้ `BAD_REQUEST` และสถานะ 5xx อื่นๆ จะใช้ `INTERNAL_ERROR`

เส้นทางสามารถกำหนดรหัสที่เฉพาะเจาะจงกว่านี้ได้ และการตอบกลับจะใช้รหัสนั้นแทน ตัวอย่างเช่น เครื่องมือที่ทำงานไม่ได้เพราะไม่มีชุด AI จะส่งรหัสเฉพาะของฟีเจอร์กลับมา รหัสเหล่านั้นอธิบายไว้ร่วมกับฟีเจอร์ที่ทำให้เกิดรหัส

## การยืนยันตัวตนและการเข้าถึง {#auth-codes}

| `code` | สถานะ | สิ่งที่ควรทำ |
|--------|--------|------------|
| `AUTH_REQUIRED` | 401 | ส่ง `Authorization: Bearer <token>` พร้อมโทเค็นเซสชันหรือคีย์ API (`si_...`) |
| `FORBIDDEN` | 403 | ข้อมูลรับรองถูกต้องแต่ไม่มีสิทธิ์ที่จำเป็น ให้ขอสิทธิ์จากผู้ดูแลระบบ |
| `MUST_CHANGE_PASSWORD` | 403 | บัญชีต้องเปลี่ยนรหัสผ่านก่อนจึงจะเรียกปลายทางอื่นได้ ให้เรียก `POST /api/auth/change-password` ด้วยโทเค็นเซสชัน แล้วลองใหม่ |
| `USER_DISABLED` | 403 | บัญชีถูกปิดใช้งาน ผู้ดูแลระบบต้องเปิดใช้งานอีกครั้ง |
| `LOGIN_THROTTLED` | 429 | ลงชื่อเข้าใช้ไม่สำเร็จหลายครั้งเกินไป โปรดรอสักครู่ก่อนลองใหม่ |
| `VALIDATION_ERROR` | 400 | เนื้อหาหรือพารามิเตอร์ของคำขอไม่ผ่านการตรวจสอบความถูกต้อง `details` ระบุปัญหาที่พบ |

บัญชีผู้ดูแลระบบเริ่มต้นคือ `admin` ที่มีรหัสผ่าน `admin` เว้นแต่ `DEFAULT_USERNAME` หรือ `DEFAULT_PASSWORD` จะเปลี่ยนค่าไว้ หากไม่ได้ตั้ง `SKIP_MUST_CHANGE_PASSWORD` บัญชีนั้นจะได้รับ `MUST_CHANGE_PASSWORD` ในทุกการเรียกจนกว่าจะเปลี่ยนรหัสผ่าน

## งาน {#job-codes}

งานที่ล้มเหลวจะรายงานสาเหตุในตัวงานเอง ไม่ใช่ในข้อผิดพลาด HTTP ให้อ่าน `error.code` และ `error.message` จาก `GET /api/v1/jobs/{jobId}` ดู [การติดตามความคืบหน้า](/th/api/rest#progress-tracking)

งานที่ล้มเหลวจะเก็บ `error.code` ไว้เฉพาะเมื่อความล้มเหลวเป็นข้อผิดพลาดของอินพุตหรือความผิดพลาดของเซิร์ฟเวอร์ ความล้มเหลวแบบอื่นจะมีเพียงข้อความ

| `code` | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|------------|
| `CANCELED` | ผู้ใช้ยกเลิกงาน นี่ไม่ใช่สถานะ HTTP เหตุการณ์ความคืบหน้ามี `phase: failed` พร้อมรหัสนี้ | ถือว่าเป็นการยกเลิกโดยผู้ใช้ อย่าลองใหม่โดยอัตโนมัติ |
| `INPUT_MISSING` | อินพุตถูกลบออกก่อนที่งานจะรัน | อัปโหลดไฟล์อีกครั้ง |
| `ENGINE_UNAVAILABLE` | เอนจินที่จำเป็นเริ่มทำงานบนเซิร์ฟเวอร์ไม่ได้ | ลองใหม่หลังจากผู้ดูแลระบบซ่อมแซมการติดตั้ง |

## การยืนยันตัวตนและ MFA {#mfa-codes}

| `code` | สถานะ | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|---------|------------|
| `MFA_ENROLLMENT_REQUIRED` | 403 | นโยบาย MFA กำหนดให้ลงทะเบียน แต่อินสแตนซ์นี้ลงทะเบียนผู้ใช้ไม่ได้ (ไม่มีใบอนุญาตระดับองค์กร) อินสแตนซ์ที่มีใบอนุญาตจะตอบ 200 พร้อม `requiresMfaEnrollment: true` และพาผู้ใช้ลงทะเบียนแทน | อย่าลองใหม่ ผู้ดูแลระบบต้องเปลี่ยนนโยบายหรือใช้ CLI กู้คืนแบบออฟไลน์ |
| `MFA_POLICY_UNAVAILABLE` | 503 | เซิร์ฟเวอร์อ่านนโยบาย MFA ไม่ได้ระหว่างลงชื่อเข้าใช้ | ลองลงชื่อเข้าใช้ใหม่อีกครั้งในอีกสักครู่ |
| `INVALID_CODE` | 401 | รหัส TOTP หรือรหัสกู้คืนไม่ถูกต้อง | ขอรหัสใหม่จากผู้ใช้แล้วลองอีกครั้ง หากผิดซ้ำจะจบด้วย `MFA_ATTEMPTS_EXHAUSTED` |
| `MFA_ATTEMPTS_EXHAUSTED` | 401 | ใส่รหัสผิดหลายครั้งเกินไป ระบบทิ้งความท้าทายนี้ | เริ่มลงชื่อเข้าใช้ใหม่เพื่อรับความท้าทายใหม่ |
| `MFA_EXPIRED` | 401 | ความท้าทายของ MFA หรือการลงทะเบียนหมดอายุหรือไม่ตรงกัน | เริ่มลงชื่อเข้าใช้ใหม่ |
| `MFA_NOT_CONFIGURED` | 401 | บัญชีไม่มีความลับ TOTP จึงตรวจสอบรหัสไม่ได้ | ลงทะเบียน MFA ก่อนลงชื่อเข้าใช้ด้วยรหัส |
| `MFA_ALREADY_ENABLED` | 409 | MFA เปิดใช้งานอยู่แล้วในบัญชี | อย่าลงทะเบียนซ้ำ |
| `NO_PENDING_ENROLLMENT` | 400 | มีการยืนยันการลงทะเบียนเข้ามาโดยไม่มีการลงทะเบียนที่รอดำเนินการ | เรียกปลายทางลงทะเบียนก่อน |
| `MFA_NOT_ENABLED` | 400 | การดำเนินการนี้ต้องเปิด MFA แต่ผู้ใช้รายนี้ปิดอยู่ | ข้ามการดำเนินการนั้น หรือเปิด MFA ก่อน |
| `MFA_DECRYPTION_FAILED` | 500 | ถอดรหัสความลับ TOTP ที่เก็บไว้ไม่ได้ | ต้องให้ผู้ดูแลระบบดำเนินการ ปกติหมายความว่าคีย์เข้ารหัสเปลี่ยนไป ตรวจสอบ `DATA_ENCRYPTION_KEY` และ `DATA_ENCRYPTION_KEY_PREVIOUS` |
| `DECRYPTION_FAILED` | 500 | ถอดรหัสค่าที่เก็บไว้ (การตั้งค่า ส่วนหัวการยืนยันตัวตนของเว็บฮุก หรือความลับ TOTP) ไม่ได้ | ต้องให้ผู้ดูแลระบบดำเนินการ เช่นเดียวกับข้างต้น อย่าลองใหม่ |
| `IDLE_TIMEOUT` | 401 | เซสชันหมดอายุหลังไม่มีการใช้งานช่วงหนึ่ง | ลงชื่อเข้าใช้อีกครั้ง |
| `INVALID_PASSWORD` | 401 | รหัสผ่านปัจจุบันไม่ถูกต้องเมื่อเปลี่ยนรหัสผ่าน | ขอรหัสผ่านปัจจุบันจากผู้ใช้ |
| `PASSWORD_CHANGED` | 409 | รหัสผ่านถูกเปลี่ยนในเซสชันอื่น หรือผู้ดูแลระบบรีเซ็ตระหว่างที่คำขอนี้กำลังทำงาน | ลงชื่อเข้าใช้อีกครั้ง |
| `OIDC_NO_PASSWORD` | 400 | มีคำขอเปลี่ยนหรือรีเซ็ตรหัสผ่านสำหรับบัญชีที่สร้างผ่าน SSO | แนะนำให้ผู้ใช้ไปที่ผู้ให้บริการข้อมูลประจำตัว |

## OIDC {#oidc-codes}

ความล้มเหลวของ OIDC ระหว่างลงชื่อเข้าใช้จะไม่ส่งเนื้อหา JSON กลับมา เส้นทางเข้าสู่ระบบจะเปลี่ยนเส้นทางไปยังหน้าเข้าสู่ระบบพร้อมเหตุผลทั่วไป และบันทึกการตรวจสอบจะเก็บรหัสไว้ เส้นทางออกจากระบบยังคงสิ้นสุดเซสชันภายในเครื่องแม้ติดต่อผู้ให้บริการข้อมูลประจำตัวไม่ได้

| `code` | สถานะ | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|---------|------------|
| `OIDC_ISSUER_SCHEME_MISMATCH` | ไม่มี (เปลี่ยนเส้นทาง) | URL ผู้ออกเป็น `http` แต่ `EXTERNAL_URL` เป็น `https` ไคลเอนต์จึงปฏิเสธการค้นหา | ผู้ดูแลระบบ: ให้บริการผู้ออกผ่าน `https` หรือรันอินสแตนซ์ผ่าน `http` |
| `OIDC_DISCOVERY_TIMEOUT` | ไม่มี (เปลี่ยนเส้นทาง) | การค้นหาผู้ออกหมดเวลา | ตรวจสอบว่าเซิร์ฟเวอร์เข้าถึงผู้ออกได้ แล้วลองใหม่ |
| `OIDC_DISCOVERY_FAILED` | ไม่มี (เปลี่ยนเส้นทาง) | การค้นหาล้มเหลวด้วยสาเหตุอื่น | ตรวจสอบ URL ของผู้ออกและการเข้าถึงขาออกของเซิร์ฟเวอร์ |
| `OIDC_END_SESSION_INVALID` | ไม่มี (ออกจากระบบดำเนินต่อ) | `end_session_endpoint` ของผู้ให้บริการข้อมูลประจำตัวไม่ใช่ URL ที่ถูกต้อง เซสชันภายในเครื่องยังคงถูกล้าง | ผู้ดูแลระบบ: แก้ไขเมทาดาทาของผู้ให้บริการ |
| `OIDC_END_SESSION_SCHEME` | ไม่มี (ออกจากระบบดำเนินต่อ) | `end_session_endpoint` ใช้สคีมที่เซิร์ฟเวอร์ไม่อนุญาต เซสชันภายในเครื่องยังคงถูกล้าง | ผู้ดูแลระบบ: แก้ไขเมทาดาทาของผู้ให้บริการ |

## SAML {#saml-codes}

ความล้มเหลวของ SAML จะไม่ตั้ง `code` การยืนยันที่ล้มเหลวจะเปลี่ยนเส้นทางไปยังหน้าเข้าสู่ระบบพร้อม `saml_auth_failed` และเหตุการณ์ตรวจสอบ `SAML_LOGIN_FAILED` จะบันทึกเหตุผล

## SCIM {#scim-codes}

เส้นทาง SCIM ตอบด้วยซองข้อผิดพลาดตาม RFC 7644 (`schemas`, `detail`, `status` และบางครั้ง `scimType`) เส้นทางเหล่านี้ไม่ตั้ง `code` ให้แตกกิ่งตามสถานะ HTTP

## ทีม บทบาท และผู้ใช้ {#team-role-codes}

ชื่อทีมหรือบทบาทที่ซ้ำกันจะได้ `CONFLICT` แบบทั่วไป และทีมหรือบทบาทที่ไม่พบจะได้ `NOT_FOUND`

| `code` | สถานะ | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|---------|------------|
| `ESCALATION_DENIED` | 403 | บทบาทของผู้เรียกไม่อนุญาตให้เปลี่ยนแปลง เป้าหมายอยู่เหนืออำนาจของผู้เรียก บทบาทนั้นเป็นบทบาทที่มีมาในตัว หรือคำขอให้สิทธิ์ที่ผู้เรียกไม่มี | อย่าลองใหม่ ขอให้ผู้ใช้ที่มีอำนาจมากกว่าดำเนินการ |
| `UNKNOWN_ROLE` | 400 | ID บทบาทไม่ตรงกับบทบาทที่มีอยู่ | แก้ ID บทบาท แสดงรายการบทบาทเพื่อหา ID |
| `UNKNOWN_TEAM` | 400 | ID ทีมไม่ตรงกับทีมที่มีอยู่ | แก้ ID ทีม |
| `SELF_DEMOTE` | 400 | ผู้ดูแลระบบพยายามถอดบทบาทผู้ดูแลระบบของตัวเอง | ให้ผู้ดูแลระบบอีกคนทำการเปลี่ยนแปลง |
| `SELF_DELETE` | 400 | ผู้ดูแลระบบพยายามลบบัญชีของตัวเอง | ให้ผู้ดูแลระบบอีกคนลบ |
| `LAST_ADMIN` | 400 บนเส้นทางผู้ใช้ 409 บนเส้นทางล้างข้อมูล GDPR | การเปลี่ยนแปลงจะทำให้ไม่เหลือผู้ดูแลระบบ หรือล้างทีมที่มีผู้ดูแลระบบทุกคน | ตั้งผู้ใช้คนอื่นเป็นผู้ดูแลระบบก่อน |
| `USER_LIMIT_REACHED` | 403 | อินสแตนซ์ถึงขีดจำกัด `MAX_USERS` แล้ว | ลบผู้ใช้ หรือเพิ่ม `MAX_USERS` |

## ฟีเจอร์และชุด AI {#feature-codes}

เครื่องมือ การรันแบบแบตช์ และไปป์ไลน์ที่ต้องใช้ชุด AI ที่เป็นทางเลือกจะใช้รหัสเหล่านี้

| `code` | สถานะ | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|---------|------------|
| `FEATURE_NOT_INSTALLED` | 501 | เครื่องมือ หรือหนึ่งขั้นตอนของไปป์ไลน์หรือแบตช์ ต้องใช้ชุดที่ยังไม่ได้ติดตั้ง เนื้อหามี `feature` (ID ของชุด) และ `featureName` | ติดตั้งชุดในการตั้งค่า แล้วลองใหม่ |
| `FEATURE_INCOMPATIBLE` | 501 | ฟีเจอร์ที่ติดตั้งไว้ไม่รองรับคุณภาพหรือภาษาที่ร้องขอ | เปลี่ยนการตั้งค่า หรือติดตั้งชุดที่รองรับ |
| `ENGINE_UNAVAILABLE` | 503 | เอนจินที่จำเป็นเริ่มทำงานไม่ได้ หรือรันไทม์ OCR ถูกลบออกหลังจากตรวจสอบคำขอแล้ว | ลองใหม่หลังจากผู้ดูแลระบบซ่อมแซมหรือติดตั้งฟีเจอร์ใหม่ |

## ไปป์ไลน์และแบตช์ {#pipeline-codes}

คำขอไปป์ไลน์และแบตช์จะคืนรหัสฟีเจอร์ข้างต้นสำหรับแต่ละขั้นตอนที่ต้องใช้ชุด ID งานที่ถูกใช้อยู่แล้วจะคืน `CONFLICT` พร้อมสถานะ 409 ให้ส่ง ID งานใหม่

## การตั้งค่า {#settings-codes}

| `code` | สถานะ | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|---------|------------|
| `UNKNOWN_SETTING` | 400 | คีย์นี้ไม่ใช่การตั้งค่าที่รู้จัก | ตรวจสอบชื่อคีย์ |
| `READONLY_SETTING` | 400 | เปลี่ยนการตั้งค่านี้ผ่าน API ไม่ได้ | เปลี่ยนผ่านตัวแปรสภาพแวดล้อมหรือ UI ผู้ดูแลระบบ |
| `DEPENDENCY_VALIDATION_FAILED` | 400 | ค่าใหม่ขัดแย้งกับการตั้งค่าอื่น เนื้อหาระบุการตั้งค่าใน `setting` และแสดงปัญหาใน `validationErrors` | แก้การตั้งค่าที่แสดงไว้ แล้วลองใหม่ |
| `SETTING_DECRYPTION_FAILED` | 500 | ถอดรหัสการตั้งค่าที่เก็บไว้ไม่ได้ | ต้องให้ผู้ดูแลระบบดำเนินการ เช่นเดียวกับ `DECRYPTION_FAILED` |

## องค์กร {#enterprise-codes}

| `code` | สถานะ | ความหมาย | สิ่งที่ควรทำ |
|--------|--------|---------|------------|
| `FEATURE_NOT_LICENSED` | 403 | การตั้งค่าหรือนโยบายนี้ต้องใช้ใบอนุญาตระดับองค์กร เช่น การบังคับใช้ SSO หรือนโยบาย MFA | ใช้อินสแตนซ์ที่มีใบอนุญาต หรือปิดการตั้งค่านั้นไว้ |
| `IP_NOT_ALLOWED` | 403 | ที่อยู่ IP ของคำขอไม่อยู่ในรายการอนุญาต | เชื่อมต่อจากเครือข่ายที่ได้รับอนุญาต |
| `INVALID_CIDR` | 400 | รายการในรายการอนุญาตไม่ใช่ CIDR ที่ถูกต้อง ข้อความจะแสดงรายการที่ไม่ถูกต้อง | แก้รายการแล้วบันทึกอีกครั้ง |
| `SELF_LOCKOUT` | 400 | การบันทึกรายการอนุญาตจะบล็อก IP ปัจจุบันของผู้เรียก | เพิ่ม IP ปัจจุบันของคุณลงในรายการก่อน |

เส้นทางล้างข้อมูล GDPR จะคืน `CONFLICT` แบบทั่วไปพร้อมสถานะ 409 เมื่อผู้ใช้หรือทีมอยู่ภายใต้การระงับทางกฎหมาย

## รหัสที่ไคลเอนต์ไม่ได้รับ {#internal-codes}

รหัสเหล่านี้มีอยู่ในซอร์สโค้ดของเซิร์ฟเวอร์สำหรับบันทึก เทเลเมทรี หรือข้อผิดพลาดของ Fastify เอง ไคลเอนต์จะไม่ได้รับรหัสเหล่านี้ในเนื้อหาการตอบกลับหรือแถวงาน จึงไม่ควรเขียนตรรกะฝั่งไคลเอนต์โดยอิงกับรหัสเหล่านี้

| `code` | ไปที่ไหน |
|--------|---------------|
| `ALERT_DECRYPTION_FAILED` | รายงานไปยังการติดตามข้อผิดพลาดโดยตัวประเมินการแจ้งเตือน ถอดรหัสส่วนหัวการยืนยันตัวตนของเว็บฮุกการแจ้งเตือนไม่ได้ |
| `SIEM_DECRYPTION_FAILED` | รายงานไปยังการติดตามข้อผิดพลาดโดยการส่งต่อไปยัง SIEM ถอดรหัสส่วนหัวการยืนยันตัวตนของ SIEM ไม่ได้ |
| `WEBHOOK_DECRYPTION_FAILED` | รายงานไปยังการติดตามข้อผิดพลาด คำขอที่เจอความล้มเหลวเดียวกันจะตอบด้วย `DECRYPTION_FAILED` |
| `STAGED_DISCARD_FAILED` | รายงานไปยังการติดตามข้อผิดพลาดเมื่อลบการอัปโหลดที่พักไว้ไม่ได้ |
| `USERNAME_RACE_EXHAUSTED` | เกิดขึ้นเมื่อการสร้างบัญชีอัตโนมัติของ SSO แพ้การแย่งชื่อผู้ใช้ในทุกครั้งที่ลองใหม่ หน้าเข้าสู่ระบบจะแสดงข้อผิดพลาดแทน |
| `ERR_OUT_OF_RANGE` | ถูกโยนโดยตัวอ่านพื้นที่จัดเก็บออบเจ็กต์สำหรับช่วงไบต์ที่ไม่ถูกต้อง |
| `ETIMEDOUT` | ตั้งบนข้อผิดพลาดหมดเวลาของการส่งออก GDPR การส่งออกล้มเหลว และสามารถขอใหม่ได้ |
| `FST_REQ_FILE_TOO_LARGE` | รหัสของ Fastify สำหรับการอัปโหลดที่เกินขีดจำกัด ไคลเอนต์จะได้ 413 พร้อม `PAYLOAD_TOO_LARGE` หรือข้อความ 413 ของเส้นทางเอง |
| `TARGET_SIZE_EXCEEDED` | ถูกโยนเมื่อการบีบอัดตามขนาดเป้าหมายทำไม่ถึงเป้า ข้อผิดพลาดนี้ไม่มีสถานะหรือรหัส ไคลเอนต์จึงได้ความล้มเหลวทั่วไป |
