# Конфігурація {#configuration}

Уся конфігурація задається через змінні середовища. Кожна змінна має розумне значення за замовчуванням, тому SnapOtter працює одразу після встановлення, навіть якщо не задавати жодної з них.

## Змінні середовища {#environment-variables}

### Сервер {#server}

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `PORT` | `1349` | Порт, який прослуховує сервер. |
| `BASE_PATH` | (порожньо) | Публічний шлях розгортання, наприклад `/snapotter`. Порожнє значення або `/` означає обслуговування з кореня домену. Застосовується під час роботи, перебудовувати образ не потрібно. |
| `RATE_LIMIT_PER_MIN` | `1000` | Максимальна кількість запитів на хвилину з одного IP. Значення 0 вимикає обмеження частоти запитів. |
| `CORS_ORIGIN` | (порожньо) | Дозволені джерела для CORS, розділені комами, або порожнє значення, щоб дозволити лише те саме джерело. |
| `LOG_LEVEL` | `info` | Докладність журналу. Одне зі значень: `fatal`, `error`, `warn`, `info`, `debug`, `trace`. |
| `TRUST_PROXY` | `loopback,linklocal,uniquelocal` | Які вузли можуть задавати IP клієнта через `X-Forwarded-For`. За замовчуванням довіра надається лише вузлу з приватної мережі, тому зворотний проксі в мережі Docker або в локальній мережі вважається довіреним, а підроблений заголовок від публічного клієнта ні. Задавайте `true` лише тоді, коли перед сервером стоїть підконтрольний вам проксі з публічною адресою. |

### Автентифікація {#authentication}

Два булеві параметри нижче приймають лише `true` і `false`. Будь-яке інше значення, зокрема `1`, `yes` чи `on`, не проходить перевірку, і сервер завершує роботу ще до початку прослуховування.

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `AUTH_ENABLED` | `true` | Вимагати вхід. Значення `false` запускає систему взагалі без облікових записів, і тоді кожен запит отримує права адміністратора, тому використовуйте це лише в довіреній мережі. |
| `DEFAULT_USERNAME` | `admin` | Ім'я користувача початкового облікового запису адміністратора. Використовується лише під час першого запуску. |
| `DEFAULT_PASSWORD` | `admin` | Пароль початкового облікового запису адміністратора. Змініть його після першого входу. |
| `MAX_USERS` | `0` (без обмежень) | Максимальна кількість зареєстрованих облікових записів. Значення 0 означає без обмежень. |
| `SESSION_DURATION_HOURS` | `168` | Тривалість сеансу входу в годинах (за замовчуванням 7 днів). |
| `SKIP_MUST_CHANGE_PASSWORD` | `false` | Задайте `true`, щоб пропустити примусовий запит зміни пароля під час першого входу. |

### Сховище {#storage}

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `STORAGE_MODE` | `local` | `local` або `s3`. Для S3 і MinIO потрібна ліцензія з функцією s3_storage, а також змінні `S3_*`, наведені нижче. |
| `DATABASE_URL` | `postgres://snapotter:snapotter@localhost:5432/snapotter` | Рядок підключення до PostgreSQL, через яке обробляється кожен запит. Починаючи з 2.3.0, задайте також `DATABASE_MIGRATION_URL`, і це підключення стане роллю виконання з мінімально необхідними привілеями: лише DML для таблиць застосунку і більше нічого. Стек Compose спрямовує його на свій сервіс `postgres`; залиште змінну незаданою (разом із `REDIS_URL`), щоб отримати вбудований режим. |
| `DATABASE_MIGRATION_URL` | (порожньо) | Привілейоване підключення, яке використовується лише під час запуску для виконання міграцій і видачі прав ролі виконання, а потім закривається до першого запиту. Якщо залишити порожнім, SnapOtter працює з однією роллю, і `DATABASE_URL` виконує обидві функції. Див. [Ролі з мінімальними привілеями](/uk/guide/database#least-privilege-roles). |
| `REDIS_URL` | `redis://localhost:6379` | Рядок підключення до Redis (використовується для черг завдань BullMQ). Compose спрямовує його на свій сервіс `redis`. |
| `WORKSPACE_PATH` | `./tmp/workspace` | Каталог для тимчасових файлів під час обробки. Очищається автоматично. Образ задає `/tmp/workspace`. |
| `FILES_STORAGE_PATH` | `./data/files` | Каталог для постійних файлів користувачів (завантажені зображення, збережені результати). Образ задає `/data/files`. |

### Об'єктне сховище S3 {#s3-object-storage}

Читається лише коли `STORAGE_MODE=s3`. Якщо пропустити будь-яку з трьох обов'язкових змінних, запуск завершиться помилкою з назвою пропущеної змінної.

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `S3_BUCKET` | (порожньо) | Бакет, у якому зберігаються завантаження та результати. Обов'язково. |
| `S3_ACCESS_KEY_ID` | (порожньо) | Ключ доступу. Обов'язково. У контейнері його можна змонтувати як файл через `S3_ACCESS_KEY_ID_FILE`. |
| `S3_SECRET_ACCESS_KEY` | (порожньо) | Секретний ключ. Обов'язково. Та сама угода про файли: `S3_SECRET_ACCESS_KEY_FILE`. |
| `S3_REGION` | `us-east-1` | Регіон бакета. |
| `S3_ENDPOINT` | (порожньо) | Власна кінцева точка для MinIO, R2, Backblaze та інших S3-сумісних сховищ. Порожнє значення означає AWS. |
| `S3_FORCE_PATH_STYLE` | `false` | Задайте `true` для MinIO і всього, що потребує `endpoint/bucket/key` замість адресації через віртуальний хост. |
| `S3_PREFIX` | (порожньо) | Префікс ключів, щоб в одному бакеті могло зберігатися кілька екземплярів. |

### Шифрування даних у спокої {#encryption-at-rest}

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `DATA_ENCRYPTION_KEY` | (порожньо) | 64 шістнадцяткові символи (32 байти). Шифрує чутливі налаштування, що зберігаються в базі даних. Усе, що не складається з 64 шістнадцяткових символів, відхиляється під час запуску. |
| `DATA_ENCRYPTION_KEY_PREVIOUS` | (порожньо) | Ключ, від якого ви переходите, у тому самому форматі. Задайте обидва під час ротації, щоб наявні рядки й надалі розшифровувалися, а потім приберіть цей. |

### Вбудований режим {#embedded-mode}

Запустіть образ без `DATABASE_URL` і без `REDIS_URL`, і він запустить власні PostgreSQL 17 та Redis усередині контейнера, прив'язані до loopback, з усіма даними на томі `/data`. Це повертає зручність запуску однією командою `docker run` для швидкого старту, домашньої лабораторії та оновлення з 1.x. Це шлях для зручності, а не промислове розгортання: для production запускайте стек Compose з трьох контейнерів з окремими PostgreSQL і Redis. Вбудований режим вимагає запуску контейнера від імені root і несумісний із середовищами, що працюють з довільним UID (OpenShift, Kubernetes `runAsNonRoot`); там використовуйте Compose.

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `EMBEDDED` | `auto` | Вмикається автоматично, коли `DATABASE_URL` і `REDIS_URL` обидві не задані. Задайте `0`, щоб вимкнути (тоді застосунок одразу завершиться з помилкою, якщо не задано зовнішній `DATABASE_URL`/`REDIS_URL`, замість того щоб непомітно запускати базу даних усередині контейнера). |
| `REDIS_MAXMEMORY` | `512mb` | Обмеження пам'яті для вбудованого Redis (лише у вбудованому режимі). Зменшуйте його на хостах з обмеженою пам'яттю, як-от Raspberry Pi. |
| `EMBEDDED_REDIS_TIMEOUT_S` | `180` | Кількість секунд, протягом яких запуск чекає, поки вбудований Redis відповість на `PING`, перш ніж здатися. Після тайм-ауту контейнер зупиняється і записує в журнал причину, а не зависає. Цілі секунди від 1 до 999999; значення «без обмежень» немає, бо нескінченне очікування є саме тим збоєм, який це обмеження має запобігти. Збільшуйте лише якщо повільний хост його перевищує. |
| `EMBEDDED_POSTGRES_TIMEOUT_S` | `600` | Те саме для вбудованого PostgreSQL. Відлік починається після завершення `initdb` під час першого запуску, тож він охоплює запуск сервера та відновлення після збою, а не початкове створення бази даних. |

Оновлення з 1.x: покладіть свій старий `snapotter.db` за шляхом `/data/snapotter.db` на томі, і вбудований режим імпортує його у вбудований PostgreSQL під час першого запуску. Імпорт виконується один раз, наступні запуски його пропускають.

Примітка щодо телеметрії: вбудований режим успадковує значення аналітики за замовчуванням з образу, як і будь-яка інша конфігурація. Опублікований образ постачається з увімкненою аналітикою; щоб вимкнути її, зберіть образ з `--build-arg SNAPOTTER_ANALYTICS=off` або скористайтеся відмовою в адмін-панелі застосунку.

### Рушії {#engines}

SnapOtter шукає кожен виконуваний файл обробки в `$PATH` усередині контейнера, тому ці змінні залишаються порожніми, якщо ви не монтуєте власну збірку.

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `FFMPEG_PATH` | (порожньо) | Шлях до виконуваного файлу `ffmpeg`, на якому працюють інструменти відео та аудіо. |
| `FFPROBE_PATH` | (порожньо) | Шлях до `ffprobe`, який читає медіафайли перед їх обробкою. Вкажіть ту саму збірку, що й для `FFMPEG_PATH`. |
| `QPDF_PATH` | (порожньо) | Шлях до `qpdf`, який використовують інструменти PDF і перевірка завантажених PDF. |
| `SOFFICE_PATH` | (порожньо) | Шлях до `soffice` з LibreOffice, який використовується для перетворення офісних документів. |
| `PDFCPU_PATH` | (порожньо) | Шлях до `pdfcpu`, який використовують деякі інструменти PDF. |
| `SNAPOTTER_HW_ACCEL` | (порожньо) | Сімейство апаратних відеокодувальників: `nvenc` або `vaapi`. Порожнє значення кодує програмно. |

`SNAPOTTER_HW_ACCEL` потребує ffmpeg, зібраного з підтримкою цього сімейства кодувальників, а в ffmpeg з образу немає жодного з них. З власним виконуваним файлом образу налаштування повертається до програмного кодування і повідомляє про це в журналі запуску. Щоб скористатися ним, змонтуйте власну збірку ffmpeg, вкажіть на неї `FFMPEG_PATH` і `FFPROBE_PATH` та надайте контейнеру пристрій GPU. Для `nvenc` також задайте `NVIDIA_DRIVER_CAPABILITIES=compute,utility,video`: образ запитує лише `compute,utility`, а без `video` середовище виконання NVIDIA не монтує бібліотеку кодування, тож кодувальник присутній у списку, але кожне кодування завершується помилкою. Перевизначення шляху, що не існує або не є виконуваним, також зазначається в журналі запуску, і кожне завдання, якому потрібен цей файл, завершуватиметься помилкою, доки ви не виправите шлях або не приберете його.

Опубліковані файли Compose передають усі шість змінних з `.env`, тому достатньо задати їх там.

## Приклад для Docker {#docker-example}

```yaml
services:
  SnapOtter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - SnapOtter-data:/data
      - SnapOtter-workspace:/tmp/workspace
    environment:
      - AUTH_ENABLED=true
      - DEFAULT_USERNAME=admin
      - DEFAULT_PASSWORD=changeme
      - DATABASE_URL=postgres://snapotter:snapotter@postgres:5432/snapotter
      - REDIS_URL=redis://redis:6379
      - MAX_UPLOAD_SIZE_MB=200
      - CONCURRENT_JOBS=4
      - FILE_MAX_AGE_HOURS=12
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: snapotter
      POSTGRES_PASSWORD: snapotter     # Change this for non-local deployments
      POSTGRES_DB: snapotter
    volumes:
      - SnapOtter-pgdata:/var/lib/postgresql/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U snapotter -d snapotter"]
      interval: 10s
      timeout: 5s
      retries: 12

  redis:
    image: redis:8-alpine
    command: ["redis-server", "--maxmemory-policy", "noeviction", "--appendonly", "yes"]
    volumes:
      - SnapOtter-redisdata:/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 12

volumes:
  SnapOtter-data:
  SnapOtter-workspace:
  SnapOtter-pgdata:
  SnapOtter-redisdata:
```

## Томи {#volumes}

Стек Docker Compose використовує чотири томи:

- `/data` (app) - моделі ШІ, віртуальне середовище Python та файли користувачів. Змонтуйте його, щоб зберігати завантажені файли та встановлені пакети ШІ між перезапусками.
- `/tmp/workspace` (app) - тимчасове сховище для файлів, що обробляються. Може бути ефемерним, але монтування запобігає заповненню доступного для запису шару контейнера.
- `SnapOtter-pgdata` (postgres) - каталог даних PostgreSQL. Тут зберігаються всі реляційні дані (користувачі, налаштування, конвеєри, завдання, журнал аудиту). Резервне копіювання через `pg_dump` або знімок тому.
- `SnapOtter-redisdata` (redis) - файл Redis лише для додавання для довговічних черг завдань.
