# Налаштування для обмежених ресурсів {#low-resource-setups}

SnapOtter добре працює на невеликому обладнанні: Raspberry Pi 4 або 5, старому ноутбуці чи VPS на 2 ГБ. Ця сторінка є практичним посібником для таких машин: чого очікувати, готове до копіювання налаштування з розумними обмеженнями та які функції краще пропустити. Повні дані бенчмарків, на яких ґрунтуються ці цифри, наведено в розділі [Вимоги до обладнання](/uk/guide/deployment#hardware-requirements).

Два жорсткі обмеження наперед:

- **Лише 64-бітні системи.** Образ збирається для `linux/amd64` і `linux/arm64`. 32-бітний ARM (`armv7`/`armhf`) не підтримується, тож Pi першого покоління та сімейство Pi Zero не підходять.
- **Мінімум 2 ГБ пам'яті (для інструментів без AI).** 512 МБ недостатньо для запуску стеку, а 1 ГБ не вистачає для пакетної обробки кількох файлів. 2 ГБ з 2 ядрами це найменша конфігурація, що комфортно запускає інструменти без AI.

## Що добре працює на невеликому обладнанні {#what-runs-well}

Кожен інструмент без AI працює на машині з 2 ГБ / 2 ядрами: уся секція зображень і файлів, інструменти PDF, а також відео- й аудіооперації з копіюванням потоку (обрізання, вимкнення звуку, ремукс контейнера). Більшість завершується менш ніж за секунду.

Два типи навантаження є винятками:

- **Перекодування відео** (конвертація між кодеками) залежить від CPU. Кліп 1080p, який на швидкому настільному CPU обробляється приблизно за ~40 с, на CPU класу Pi може займати кілька хвилин. Операції з копіюванням потоку лишаються миттєвими.
- **AI-інструменти** мають пороги пам'яті CPU для кожного пакета: 2 ГБ RAM хоста (0,5 ГБ вільно) для Face Detection і вбудованого Fast OCR, 4 ГіБ налаштованої ефективної пам'яті для Accurate OCR, 4 ГБ RAM хоста (2-3 ГБ вільно) для Transcription, Object Eraser & Colorize, Background Removal, Upscale & Enhance і Photo Restoration, та 8 ГБ RAM хоста (6 ГБ вільно) для High-Quality Inpainting. Машина на 2 ГБ не може запускати Whisper, RealESRGAN, rembg чи LaMa без примусового завершення через брак пам'яті, тому SnapOtter перевіряє вільну пам'ять перед передаванням у Python sidecar і одразу відхиляє запуски нижче порога пакета.

Жодне з них не встановлюється і не працює, доки ви ним не користуєтеся: без встановлених AI-пакетів застосунок у спокої займає близько 360 МБ, а AI-пакети завантажуються лише тоді, коли адміністратор їх вмикає.

## Покрокова інструкція для Raspberry Pi / старого ноутбука {#walkthrough}

Це стандартне встановлення Compose з розділу [Початок роботи](/uk/guide/getting-started) плюс обмеження ресурсів і обережні ліміти. Передбачається 64-бітна ОС (на Pi: Raspberry Pi OS 64-bit або Ubuntu Server arm64).

```yaml
services:
  snapotter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - ./snapotter-data:/data
    environment:
      - DATABASE_URL=postgres://${POSTGRES_APP_USER:-snapotter_app}:${POSTGRES_APP_PASSWORD:-snapotter_app}@db:5432/${POSTGRES_DB:-snapotter}
      - DATABASE_MIGRATION_URL=postgres://${POSTGRES_USER:-snapotter}:${POSTGRES_PASSWORD:-snapotter}@db:5432/${POSTGRES_DB:-snapotter}
      - REDIS_URL=redis://redis:6379
      # Small-box profile: see the table below for what each cap does.
      - CONCURRENT_JOBS=1
      - MAX_WORKER_THREADS=2
      - MAX_BATCH_SIZE=5
      - MAX_UPLOAD_SIZE_MB=100
      - MAX_MEGAPIXELS=50
      - MAX_VIDEO_DURATION_S=300
    deploy:
      resources:
        limits:
          cpus: "2"
          memory: 2G
    depends_on:
      - db
      - redis
    restart: unless-stopped

  db:
    image: postgres:17-alpine
    environment:
      - POSTGRES_USER=${POSTGRES_USER:-snapotter}
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD:-snapotter}     # Change this for non-local deployments
      - POSTGRES_DB=${POSTGRES_DB:-snapotter}
    volumes:
      - ./postgres-data:/var/lib/postgresql/data
    restart: unless-stopped

  redis:
    image: redis:8-alpine
    command: redis-server --maxmemory 256mb --maxmemory-policy noeviction
    restart: unless-stopped
```

Примітки для машин класу Pi:

- **Віддавайте перевагу USB SSD замість SD-карти** для тому даних і Postgres. Робочі простори завдань виконують реальне дискове введення-виведення, а SD-карти і повільні, і швидко зношуються.
- **Єдиний контейнер «все в одному» теж тут працює** (вбудовані Postgres і Redis, коли `DATABASE_URL`/`REDIS_URL` не задано), і на хості з обмеженою пам'яттю слід зменшити ліміт його вбудованого Redis через `REDIS_MAXMEMORY` (див. [Конфігурація](/uk/guide/configuration)). Compose дає точніший контроль над кожним сервісом, тому в цій інструкції використовується саме він.
- **Додайте swap на пристроях із 2 ГБ.** Це не дає випадковому сплеску (великий PDF, пакет, для якого ви забули задати ліміт) закінчитися примусовим завершенням через брак пам'яті. zram є зручним для SD-карт варіантом.
- Образ arm64 працює лише на CPU; на ARM-платах CUDA немає.

## Параметри налаштування {#tuning-knobs}

Усі ліміти задаються змінними середовища, повністю описаними в розділі [Конфігурація](/uk/guide/configuration). `0` означає «без обмежень» або «авто». Ті, що важливі на невеликому обладнанні:

| Змінна | Рекомендація для малої машини | Що захищає |
|---|---|---|
| `CONCURRENT_JOBS` | `1` | Скільки завдань виконується паралельно. Автовизначення бере кількість ядер CPU мінус одне, що нормально для великих машин і надто агресивно для 2-ядерної машини під тиском пам'яті. |
| `MAX_WORKER_THREADS` | `2` | Пул потоків обробки зображень. |
| `MAX_BATCH_SIZE` | `5` | Саме на пакетах машинам з 1-2 ГБ першими не вистачає пам'яті. |
| `MAX_UPLOAD_SIZE_MB` | `100` | Не дає одному величезному файлу зайняти весь робочий простір. |
| `MAX_MEGAPIXELS` | `50` | Декодування зображення понад 100 МП потребує RAM незалежно від розміру файла. |
| `MAX_VIDEO_DURATION_S` | `300` | Довгі транскодування монополізують слабкий CPU на хвилини чи години. |
| `PROCESSING_TIMEOUT_S` | `600` | Жорстка межа, щоб завдання, що вийшло з-під контролю, зрештою звільнило машину. |

Ці ліміти стосуються того, що приймає сервер, тож задавайте їх відповідно до того, чим ви реально користуєтеся, а не якомога меншими. Якщо ви ніколи не працюєте з відео, ліміт `MAX_VIDEO_DURATION_S` нічого не коштує; якщо ви щодня скануєте документи, не обмежуйте `MAX_PDF_PAGES`.

## Що пропустити {#what-to-skip}

- **Важкі AI-пакети.** Збільшення, відновлення фотографій і видалення фону потребують GPU або швидкого багатоядерного CPU, а кожен пакет займає 4-5 ГБ на диску. На малій машині просто не встановлюйте їх; інструменти, для яких пакет відсутній, показують пропозицію встановити замість запуску.
- **Перекодування відео як регулярне навантаження.** Поодинокі транскодування прийнятні (вони просто повільні); постійна черга транскодування потребує ядер CPU, а не Pi.
- **Невикористовувані інструменти загалом.** Адміністратор може вимкнути окремі інструменти в Settings, що прибирає їх з інтерфейсу й припиняє реєстрацію їхніх API-маршрутів. Це саме по собі не економить пам'ять, але не дає спільному малому екземпляру використовуватися для єдиного навантаження, яке обладнання не витримує.

Якщо пізніше ви перенесете екземпляр на потужніше обладнання, зніміть ліміти (поверніть їх до `0`), і той самий том даних працюватиме далі.
