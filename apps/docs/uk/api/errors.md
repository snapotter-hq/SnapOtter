# Коди помилок {#error-codes}

Кожна JSON-відповідь із помилкою має однакову структуру:

```json
{
  "error": "Job not found",
  "code": "NOT_FOUND",
  "requestId": "req-42"
}
```

| Поле | Завжди присутнє | Значення |
|-------|----------------|---------|
| `error` | Так | Зрозуміле людині повідомлення. Його безпечно показувати користувачам. Не розбирайте його програмно. |
| `code` | Так | Стабільний машинозчитуваний код. Розгалужуйте логіку за ним. |
| `requestId` | Так | Ідентифікатор цього запиту на сервері. Наводьте його, повідомляючи про проблему: він збігається із записом у журналі сервера. |
| `details` | Іноді | Додатковий контекст для деяких помилок 4xx, наприклад повідомлення про валідацію. |

Повідомлення можуть змінюватися між релізами. Коди не змінюються, тому клієнтську логіку слід писати на основі `code`.

## Коди за HTTP-статусом {#status-codes}

Якщо маршрут не задає власний код, сервер виводить його зі статусу:

| HTTP-статус | `code` |
|-------------|--------|
| 400 | `BAD_REQUEST` |
| 401 | `AUTH_REQUIRED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `UNPROCESSABLE_ENTITY` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` |
| 501 | `NOT_IMPLEMENTED` |
| 503 | `SERVICE_UNAVAILABLE` |
| 507 | `INSUFFICIENT_STORAGE` |

Будь-який інший код 4xx зводиться до `BAD_REQUEST`, а будь-який інший код 5xx до `INTERNAL_ERROR`.

Маршрут може задати конкретніший код, і тоді відповідь міститиме саме його. Наприклад, інструмент, який не може запуститися через відсутній AI-пакет, повертає код, специфічний для функції. Такі коди описані разом із функцією, яка їх генерує.

## Автентифікація та доступ {#auth-codes}

| `code` | Статус | Що робити |
|--------|--------|------------|
| `AUTH_REQUIRED` | 401 | Надішліть `Authorization: Bearer <token>` разом із токеном сесії або API-ключем (`si_...`). |
| `FORBIDDEN` | 403 | Облікові дані дійсні, але не мають потрібного дозволу. Попросіть адміністратора надати дозвіл. |
| `MUST_CHANGE_PASSWORD` | 403 | Обліковий запис має змінити пароль, перш ніж викликати інші ендпоінти. Викличте `POST /api/auth/change-password` із токеном сесії, потім повторіть спробу. |
| `USER_DISABLED` | 403 | Обліковий запис вимкнено. Адміністратор має знову його ввімкнути. |
| `LOGIN_THROTTLED` | 429 | Забагато невдалих спроб входу. Зачекайте перед наступною спробою. |
| `VALIDATION_ERROR` | 400 | Тіло або параметри запиту не пройшли валідацію. `details` вказує на проблему. |

Обліковий запис адміністратора першого запуску має ім'я `admin` і пароль `admin`, якщо їх не змінили `DEFAULT_USERNAME` чи `DEFAULT_PASSWORD`. Якщо не задано `SKIP_MUST_CHANGE_PASSWORD`, цей обліковий запис отримує `MUST_CHANGE_PASSWORD` на кожен виклик, доки пароль не буде змінено.

## Завдання {#job-codes}

Завдання, що завершилося помилкою, повідомляє причину у самому завданні, а не в HTTP-помилці. Прочитайте `error.code` і `error.message` з `GET /api/v1/jobs/{jobId}`. Див. [Відстеження прогресу](/uk/api/rest#progress-tracking).

Завдання, що завершилося помилкою, зберігає `error.code` лише тоді, коли збій є помилкою вхідних даних або збоєм сервера. В інших випадках передається лише повідомлення.

| `code` | Значення | Що робити |
|--------|---------|------------|
| `CANCELED` | Користувач скасував завдання. Це не HTTP-статус. Події прогресу містять `phase: failed` із цим кодом. | Сприймайте це як скасування користувачем. Не повторюйте спробу автоматично. |
| `INPUT_MISSING` | Вхідні дані було видалено до запуску завдання. | Завантажте файл ще раз. |
| `ENGINE_UNAVAILABLE` | Потрібний рушій не вдалося запустити на сервері. | Повторіть спробу після того, як адміністратор відновить встановлення. |
| `JOB_STALLED` | Клієнтам не повертається, а позначає звіт сервера про помилку. Воркер втратив блокування завдання більше разів, ніж дозволяє черга, зазвичай через перезапуск сервера або нестачу пам'яті чи CPU. Завдання завершується помилкою з повідомленням про переривання. | Повторіть спробу. Якщо це повторюється, дайте серверу більше пам'яті або зменште `CONCURRENT_JOBS`. |

## OIDC {#oidc-codes}

Збої OIDC під час входу не повертають тіло JSON. Маршрут входу перенаправляє на сторінку входу із загальною причиною, а журнал аудиту записує код. Маршрут виходу все одно завершує локальну сесію, коли постачальник ідентифікації недоступний.

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `OIDC_ISSUER_SCHEME_MISMATCH` | Немає (перенаправлення) | URL емітента `http`, але `EXTERNAL_URL` має значення `https`, тому клієнт відмовляється від виявлення. | Адміністратор: віддавайте емітента через `https` або запускайте екземпляр через `http`. |
| `OIDC_DISCOVERY_TIMEOUT` | Немає (перенаправлення) | Час виявлення емітента вичерпано. | Перевірте, чи сервер має доступ до емітента, і повторіть спробу. |
| `OIDC_DISCOVERY_FAILED` | Немає (перенаправлення) | Виявлення не вдалося з іншої причини. | Перевірте URL емітента та вихідний доступ сервера. |
| `OIDC_END_SESSION_INVALID` | Немає (вихід триває) | `end_session_endpoint` постачальника ідентифікації не є дійсним URL. Локальну сесію все одно очищено. | Адміністратор: виправте метадані постачальника. |
| `OIDC_END_SESSION_SCHEME` | Немає (вихід триває) | `end_session_endpoint` використовує схему, яку сервер не дозволяє. Локальну сесію все одно очищено. | Адміністратор: виправте метадані постачальника. |

## SAML {#saml-codes}

Збої SAML не задають `code`. Невдале твердження перенаправляє на сторінку входу з `saml_auth_failed`, а подія аудиту `SAML_LOGIN_FAILED` записує причину.

## SCIM {#scim-codes}

Маршрути SCIM відповідають конвертом помилки за RFC 7644 (`schemas`, `detail`, `status` і іноді `scimType`). Вони не задають `code`. Розгалужуйте логіку за HTTP-статусом.

## Команди, ролі та користувачі {#team-role-codes}

Дублікати назв команд або ролей повертають загальний `CONFLICT`, а відсутня команда чи роль повертає `NOT_FOUND`.

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `ESCALATION_DENIED` | 403 | Роль викликача не дозволяє цю зміну. Ціль стоїть вище за повноваження викликача, роль є вбудованою, або запит надає дозволи, яких викликач не має. | Не повторюйте спробу. Попросіть користувача з більшими повноваженнями. |
| `UNKNOWN_ROLE` | 400 | Ідентифікатор ролі не відповідає жодній наявній ролі. | Виправте ідентифікатор ролі. Перегляньте список ролей, щоб його знайти. |
| `UNKNOWN_TEAM` | 400 | Ідентифікатор команди не відповідає жодній наявній команді. | Виправте ідентифікатор команди. |
| `SELF_DEMOTE` | 400 | Адміністратор спробував прибрати власну роль адміністратора. | Нехай інший адміністратор внесе цю зміну. |
| `SELF_DELETE` | 400 | Адміністратор спробував видалити власний обліковий запис. | Нехай інший адміністратор його видалить. |
| `LAST_ADMIN` | 400 на маршрутах користувачів, 409 на маршрутах очищення GDPR | Зміна не залишила б жодного адміністратора або очистила б команду, у якій є всі адміністратори. | Спершу зробіть адміністратором іншого користувача. |
| `USER_LIMIT_REACHED` | 403 | Екземпляр досяг свого ліміту `MAX_USERS`. | Видаліть користувача або збільште `MAX_USERS`. |

## Функції та AI-пакети {#feature-codes}

Інструменти, пакетні запуски та конвеєри, яким потрібен додатковий AI-пакет, використовують ці коди.

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `FEATURE_NOT_INSTALLED` | 501 або 400 від режиму облич Smart Crop | Інструменту або одному кроку конвеєра чи пакетного запуску потрібен пакет, який не встановлено. Тіло містить `feature` (ідентифікатор пакета) і `featureName`. | Встановіть пакет у Налаштуваннях і повторіть спробу. |
| `FEATURE_CPU_UNSUPPORTED` | 409 | Встановлення або офлайновий імпорт відхилено, бо бібліотекам x86-64 цього пакета потрібен AVX, а процесор цього сервера його не має. Нічого не завантажено і не встановлено. Тіло містить `feature` (ідентифікатор пакета) і `reason` (`cpu-no-avx`). `GET /api/v1/features` повідомляє про той самий пакет із `compatibility: "incompatible"` і `compatibilityReason: "cpu-no-avx"`. | Запустіть SnapOtter на процесорі з AVX або на arm64. Інші пакети все одно встановлюються. |
| `FEATURE_INCOMPATIBLE` | 501 або 400, коли Fast OCR отримує мову, яку не може прочитати | Встановлена функція не підтримує запитану якість або мову. | Змініть налаштування або встановіть пакет, який її підтримує. |
| `ENGINE_UNAVAILABLE` | 503 | Потрібний рушій не вдалося запустити, або середовище виконання OCR було видалено після валідації запиту. | Повторіть спробу після того, як адміністратор відновить або перевстановить функцію. |
| `BROWSER_NOT_AVAILABLE` | 503 | Chromium не встановлено, тому HTML to image не може працювати. | Попросіть адміністратора встановити браузер. |
| `BROWSER_CRASHED` | 503 | Браузер для знімків екрана аварійно завершився під час рендерингу. | Повторіть запит. |

| `INVALID_SETTINGS` | 400 | Налаштування виходить за межі діапазону або не підходить до цього файлу: обрізання за межами зображення, зміна розміру до нуля, кадр GIF, якого немає в анімації, специфікація паспорта, якої не існує. Текст `error` називає налаштування. | Виправте налаштування, назване в `error`, і повторіть спробу. |
| `CHART_DATA_INVALID` | 400 | Chart Maker не зміг прочитати дані діаграми з файлу: CSV або JSON не розбирається, не має числового стовпця, має понад 100 рядків або містить від'ємне значення. Текст `error` вказує, яка саме причина. | Надішліть CSV або JSON, що містить до 100 рядків, кожен із підписом і числом, не меншим за нуль. |
| `NO_FACE_DETECTED` | 400 | Passport Photo не знайшов обличчя на зображенні. | Надішліть чітке фото анфас з гарним освітленням. |
| `TARGET_SIZE_UNREACHABLE` | 400 | Стиснення або обмеження розміру фото на паспорт не може зменшити файл до запитаного розміру, навіть після зменшення масштабу. | Запитайте більший цільовий розмір або спершу обріжте зображення. |
| `TOO_MANY_PAGES` | 400 | OCR попросили обробити більше сторінок, ніж він обробляє за одне завдання. | Виберіть менше сторінок за допомогою діапазону сторінок. |
| `METADATA_DAMAGED` | 400 | Edit Metadata виявив пошкодженими наявні дані EXIF зображення, тому не може безпечно їх переписати. | Спершу видаліть метадані за допомогою Remove Image Metadata, потім редагуйте. |
| `REMOTE_RESOURCES_DISABLED` | 400 | HTML або Markdown to PDF знайшов посилання на зображення, таблицю стилів або шрифт у мережі, які сервер не завантажує. | Вбудуйте ресурс у файл (наприклад як URI `data:`) і повторіть спробу. |

## Конвеєри та пакетна обробка {#pipeline-codes}

Запити конвеєрів і пакетної обробки повертають наведені вище коди функцій для кожного кроку, якому потрібен пакет. Ідентифікатор завдання, який уже використовується, повертає `CONFLICT` зі статусом 409. Надішліть новий ідентифікатор завдання.

## Налаштування {#settings-codes}

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `UNKNOWN_SETTING` | 400 | Ключ не є відомим налаштуванням. | Перевірте назву ключа. |
| `READONLY_SETTING` | 400 | Налаштування не можна змінити через API. | Змініть його через середовище або адмін-інтерфейс. |
| `DEPENDENCY_VALIDATION_FAILED` | 400 | Нове значення суперечить іншим налаштуванням. Тіло називає налаштування в `setting` і перелічує проблеми в `validationErrors`. | Виправте перелічені налаштування і повторіть спробу. |
| `SETTING_DECRYPTION_FAILED` | 500 | Збережене налаштування неможливо розшифрувати. | Дія оператора, як для `DECRYPTION_FAILED`. |

Для `VALIDATION_ERROR` щодо налаштування `details` містить проблеми схеми.

## Корпоративні функції {#enterprise-codes}

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `FEATURE_NOT_LICENSED` | 403 | Налаштування або політика потребує корпоративної ліцензії, наприклад примусове SSO чи політика MFA. | Використовуйте ліцензований екземпляр або залиште налаштування вимкненим. |
| `IP_NOT_ALLOWED` | 403 | IP-адреси запиту немає в списку дозволених. | Підключіться з дозволеної мережі. |
| `INVALID_CIDR` | 400 | Запис списку дозволених не є дійсним CIDR. Повідомлення перелічує неправильні записи. | Виправте записи й збережіть знову. |
| `SELF_LOCKOUT` | 400 | Збереження списку дозволених заблокувало б поточну IP-адресу викликача. | Спершу додайте свою поточну IP-адресу до списку. |

Маршрути очищення GDPR повертають простий `CONFLICT` зі статусом 409, коли користувач або команда перебуває під юридичним утриманням.

## Коди, яких клієнти не отримують {#internal-codes}

Ці коди існують у вихідному коді сервера для журналів, телеметрії або власних помилок Fastify. Клієнт не отримує їх у тілі відповіді чи рядку завдання, тому не пишіть клієнтську логіку на їхній основі.

| `code` | Куди потрапляє |
|--------|---------------|
| `ALERT_DECRYPTION_FAILED` | Передається до відстеження помилок обчислювачем сповіщень. Заголовок автентифікації вебхука сповіщення неможливо розшифрувати. |
| `SIEM_DECRYPTION_FAILED` | Передається до відстеження помилок пересиланням до SIEM. Заголовок автентифікації SIEM неможливо розшифрувати. |
| `WEBHOOK_DECRYPTION_FAILED` | Передається до відстеження помилок. Запит, що зіткнувся з тим самим збоєм, відповідає `DECRYPTION_FAILED`. |
| `STAGED_DISCARD_FAILED` | Передається до відстеження помилок, коли проміжне завантаження неможливо видалити. |
| `USERNAME_RACE_EXHAUSTED` | Виникає, коли автостворення SSO програє гонитву за ім'я користувача на кожній повторній спробі. Натомість сторінка входу показує помилку. |
| `ERR_OUT_OF_RANGE` | Викидається читачем об'єктного сховища для недійсного діапазону байтів. |
| `ETIMEDOUT` | Задається в помилці тайм-ауту для експорту GDPR. Експорт завершується помилкою, і його можна запросити знову. |
| `FST_REQ_FILE_TOO_LARGE` | Код Fastify для завантаження понад ліміт. Клієнти отримують 413 з `PAYLOAD_TOO_LARGE` або власне повідомлення 413 від маршруту. |
| `TARGET_SIZE_EXCEEDED` | Викидається, коли стиснення до цільового розміру не досягає цілі. Помилка не має статусу чи коду, тому клієнти отримують загальну помилку. |
| `OCR_CACHE_PERMISSIONS` | Передається до відстеження помилок як операційний збій, коли том AI-даних лишає кеш середовища виконання OCR доступним для запису всім. Завдання встановлення завершується помилкою з повідомленням, що називає проблему сховища. |
| `OCR_RUNTIME_UNREACHABLE` | Передається до відстеження помилок як операційний збій, коли сервер не зміг дістатися huggingface.co, щоб завантажити середовище виконання OCR. Завдання встановлення завершується помилкою з повідомленням про мережевий доступ, `HTTPS_PROXY` та офлайновий імпорт. |
