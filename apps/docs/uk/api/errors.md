# Коди помилок {#error-codes}

Кожна JSON-відповідь із помилкою має однакову структуру:

```json
{
  "error": "Job not found",
  "code": "NOT_FOUND",
  "requestId": "req-42"
}
```

| Поле | Завжди присутнє | Значення |
|------|-----------------|----------|
| `error` | Так | Зрозуміле людині повідомлення. Його безпечно показувати користувачам. Не розбирайте його програмно. |
| `code` | Так | Стабільний машинозчитуваний код. Розгалужуйте логіку за ним. |
| `requestId` | Так | Ідентифікатор цього запиту на сервері. Наводьте його, повідомляючи про проблему: він збігається із записом у журналі сервера. |
| `details` | Іноді | Додатковий контекст для деяких помилок 4xx, наприклад повідомлення про валідацію. |

Повідомлення можуть змінюватися між релізами. Коди не змінюються, тому клієнтську логіку слід писати на основі `code`.

## Коди за HTTP-статусом {#status-codes}

Якщо маршрут не задає власний код, сервер виводить його зі статусу:

| HTTP-статус | `code` |
|-------------|--------|
| 400 | `BAD_REQUEST` |
| 401 | `AUTH_REQUIRED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `UNPROCESSABLE_ENTITY` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` |
| 501 | `NOT_IMPLEMENTED` |
| 503 | `SERVICE_UNAVAILABLE` |
| 507 | `INSUFFICIENT_STORAGE` |

Будь-який інший код 4xx зводиться до `BAD_REQUEST`, а будь-який інший код 5xx до `INTERNAL_ERROR`.

Маршрут може задати конкретніший код, і тоді відповідь міститиме саме його. Наприклад, інструмент, який не може запуститися через відсутній AI-пакет, повертає код, специфічний для функції. Такі коди описані разом із функцією, яка їх генерує.

## Автентифікація та доступ {#auth-codes}

| `code` | Статус | Що робити |
|--------|--------|------------|
| `AUTH_REQUIRED` | 401 | Надішліть `Authorization: Bearer <token>` разом із токеном сесії або API-ключем (`si_...`). |
| `FORBIDDEN` | 403 | Облікові дані дійсні, але не мають потрібного дозволу. Попросіть адміністратора надати дозвіл. |
| `MUST_CHANGE_PASSWORD` | 403 | Обліковий запис має змінити пароль, перш ніж викликати інші ендпоїнти. Викличте `POST /api/auth/change-password` із токеном сесії, а потім повторіть спробу. |
| `USER_DISABLED` | 403 | Обліковий запис вимкнено. Адміністратор має знову його ввімкнути. |
| `LOGIN_THROTTLED` | 429 | Забагато невдалих спроб входу. Зачекайте, перш ніж спробувати знову. |
| `VALIDATION_ERROR` | 400 | Тіло або параметри запиту не пройшли валідацію. `details` вказує на проблему. |

Обліковий запис адміністратора першого запуску має ім'я `admin` і пароль `admin`, якщо їх не змінили `DEFAULT_USERNAME` або `DEFAULT_PASSWORD`. Якщо не задано `SKIP_MUST_CHANGE_PASSWORD`, цей обліковий запис отримує `MUST_CHANGE_PASSWORD` на кожен виклик, доки пароль не буде змінено.

## Завдання {#job-codes}

Завдання, що завершилося помилкою, повідомляє причину у самому завданні, а не в HTTP-помилці. Прочитайте `error.code` та `error.message` із `GET /api/v1/jobs/{jobId}`. Див. [Відстеження прогресу](/uk/api/rest#progress-tracking).

Невдале завдання зберігає `error.code` лише тоді, коли збій спричинено помилкою вхідних даних або несправністю сервера. Інші збої містять лише повідомлення.

| `code` | Значення | Що робити |
|--------|---------|------------|
| `CANCELED` | Завдання скасував користувач. Це не HTTP-статус. Події прогресу передають `phase: failed` із цим кодом. | Сприймайте це як скасування користувачем. Не повторюйте спробу автоматично. |
| `INPUT_MISSING` | Вхідні дані було видалено до запуску завдання. | Завантажте файл ще раз. |
| `ENGINE_UNAVAILABLE` | Потрібний рушій не вдалося запустити на сервері. | Повторіть спробу після того, як адміністратор виправить встановлення. |

|--------|--------|---------|------------|
| `MFA_ENROLLMENT_REQUIRED` | 403 | Політика MFA вимагає реєстрації, а цей екземпляр не може зареєструвати користувача (немає корпоративної ліцензії). Ліцензовані екземпляри натомість повертають 200 із `requiresMfaEnrollment: true` і проводять користувача через реєстрацію. | Не повторюйте спробу. | `MFA_ALREADY_ENABLED` | 409 | MFA уже активна в обліковому записі. | Не реєструйте повторно. |
| `NO_PENDING_ENROLLMENT` | 400 | Підтвердження реєстрації надійшло без незавершеної реєстрації. | Спершу викличте ендпоїнт реєстрації. |

| `IDLE_TIMEOUT` | 401 | Сесія завершилася після періоду неактивності. | Увійдіть знову. |
| `INVALID_PASSWORD` | 401 | Під час зміни пароля поточний пароль неправильний. | Попросіть користувача ввести поточний пароль. |
| `PASSWORD_CHANGED` | 409 | Пароль змінили в іншій сесії або його скинув адміністратор, поки виконувався цей запит. | Увійдіть знову. |
| `OIDC_NO_PASSWORD` | 400 | Змінити або скинути пароль запитали для облікового запису, створеного через SSO. | Направте користувача до постачальника ідентифікації. |

## OIDC {#oidc-codes}

Збої OIDC під час входу не повертають тіло JSON. Маршрут входу перенаправляє на сторінку входу із загальною причиною, а журнал аудиту записує код. Маршрут виходу все одно завершує локальну сесію, якщо постачальник ідентифікації недоступний.

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `OIDC_ISSUER_SCHEME_MISMATCH` | Немає (перенаправлення) | URL емітента `http`, але `EXTERNAL_URL` має значення `https`, тому клієнт відмовляється від виявлення. | Адміністратор: віддавайте емітента через `https` або запускайте екземпляр через `http`. |
| `OIDC_DISCOVERY_TIMEOUT` | Немає (перенаправлення) | Час очікування виявлення емітента вичерпано. | Перевірте, що сервер має доступ до емітента, і повторіть спробу. |
| `OIDC_DISCOVERY_FAILED` | Немає (перенаправлення) | Виявлення не вдалося з іншої причини. | Перевірте URL емітента та вихідний доступ сервера. |
| `OIDC_END_SESSION_INVALID` | Немає (вихід триває) | `end_session_endpoint` постачальника ідентифікації не є коректним URL. Локальну сесію все одно очищено. | Адміністратор: виправте метадані постачальника. |
| `OIDC_END_SESSION_SCHEME` | Немає (вихід триває) | `end_session_endpoint` використовує схему, яку сервер не дозволяє. Локальну сесію все одно очищено. | Адміністратор: виправте метадані постачальника. |

## SAML {#saml-codes}

Збої SAML не встановлюють `code`. Невдале твердження перенаправляє на сторінку входу з `saml_auth_failed`, а подія аудиту `SAML_LOGIN_FAILED` записує причину.

## SCIM {#scim-codes}

Маршрути SCIM відповідають конвертом помилки за RFC 7644 (`schemas`, `detail`, `status` і подекуди `scimType`). Вони не встановлюють `code`. Розгалужуйте логіку за HTTP-статусом.

## Команди, ролі та користувачі {#team-role-codes}

Повторювані назви команд або ролей повертають загальний `CONFLICT`, а відсутня команда чи роль повертає `NOT_FOUND`.

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `ESCALATION_DENIED` | 403 | Роль викликача не дозволяє цю зміну. Ціль має вищі повноваження за викликача, роль вбудована, або запит надає дозволи, яких викликач не має. | Не повторюйте спробу. Зверніться до користувача з більшими повноваженнями. |
| `UNKNOWN_ROLE` | 400 | ID ролі не відповідає жодній наявній ролі. | Виправте ID ролі. Перегляньте список ролей, щоб знайти його. |
| `UNKNOWN_TEAM` | 400 | ID команди не відповідає жодній наявній команді. | Виправте ID команди. |
| `SELF_DEMOTE` | 400 | Адміністратор намагався зняти з себе роль адміністратора. | Нехай зміну виконає інший адміністратор. |
| `SELF_DELETE` | 400 | Адміністратор намагався видалити власний обліковий запис. | Нехай його видалить інший адміністратор. |
| `LAST_ADMIN` | 400 на маршрутах користувачів, 409 на маршрутах очищення GDPR | Зміна залишила б систему без адміністраторів або очистила б команду, до якої входять усі адміністратори. | Спершу призначте адміністратором іншого користувача. |
| `USER_LIMIT_REACHED` | 403 | Екземпляр досяг ліміту `MAX_USERS`. | Видаліть користувача або збільште `MAX_USERS`. |

## Функції та AI-пакети {#feature-codes}

Інструменти, пакетні запуски та конвеєри, яким потрібен додатковий AI-пакет, використовують ці коди.

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `FEATURE_NOT_INSTALLED` | 501 | Інструменту або одному з кроків конвеєра чи пакетного запуску потрібен пакет, який не встановлено. Тіло містить `feature` (ID пакета) і `featureName`. | Встановіть пакет у Налаштуваннях і повторіть спробу. |
| `FEATURE_INCOMPATIBLE` | 501 | Встановлена функція не може забезпечити запитану якість або мову. | Змініть налаштування або встановіть пакет, що це підтримує. |
| `ENGINE_UNAVAILABLE` | 503 | Потрібний рушій не вдалося запустити, або середовище виконання OCR було видалено після перевірки запиту. | Повторіть спробу після того, як адміністратор відремонтує чи перевстановить функцію. |
| `BROWSER_NOT_AVAILABLE` | 503 | Chromium не встановлено, тому HTML у зображення не може працювати. | Попросіть адміністратора встановити браузер. |
| `BROWSER_CRASHED` | 503 | Браузер для знімків екрана аварійно завершився під час відтворення. | Повторіть запит. |

## Конвеєри та пакетна обробка {#pipeline-codes}

Запити конвеєрів і пакетної обробки повертають наведені вище коди функцій для кожного кроку, якому потрібен пакет. ID завдання, який уже використовується, повертає `CONFLICT` зі статусом 409. Надішліть новий ID завдання.

## Налаштування {#settings-codes}

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `UNKNOWN_SETTING` | 400 | Ключ не є відомим налаштуванням. | Перевірте назву ключа. |
| `READONLY_SETTING` | 400 | Це налаштування не можна змінити через API. | Змініть його через середовище або адмінпанель. |
| `DEPENDENCY_VALIDATION_FAILED` | 400 | Нове значення суперечить іншим налаштуванням. Тіло вказує налаштування в `setting` і перелічує проблеми в `validationErrors`. | Виправте перелічені налаштування і повторіть спробу. |
| `SETTING_DECRYPTION_FAILED` | 500 | Збережене налаштування не вдається розшифрувати. | Дія для оператора, як для `DECRYPTION_FAILED`. |

Для `VALIDATION_ERROR` у налаштуванні `details` містить проблеми зі схемою.

## Enterprise {#enterprise-codes}

| `code` | Статус | Значення | Що робити |
|--------|--------|---------|------------|
| `FEATURE_NOT_LICENSED` | 403 | Налаштування або політика потребує корпоративної ліцензії, наприклад примусовий SSO чи політика MFA. | Скористайтеся ліцензованим екземпляром або залиште налаштування вимкненим. |
| `IP_NOT_ALLOWED` | 403 | IP-адреси запиту немає в списку дозволених. | Підключіться з дозволеної мережі. |
| `INVALID_CIDR` | 400 | Запис списку дозволених не є коректним CIDR. Повідомлення перелічує некоректні записи. | Виправте записи й збережіть знову. |
| `SELF_LOCKOUT` | 400 | Збереження списку дозволених заблокувало б поточну IP-адресу викликача. | Спершу додайте свою поточну IP-адресу до списку. |

Маршрути очищення GDPR повертають звичайний `CONFLICT` зі статусом 409, коли користувач або команда перебуває під юридичним утриманням.

## Коди, яких клієнти не отримують {#internal-codes}

Ці коди існують у вихідному коді сервера для журналів, телеметрії або власних помилок Fastify. Клієнт не отримує їх у тілі відповіді чи рядку завдання, тому не будуйте на них клієнтську логіку.

| `code` | Куди потрапляє |
|--------|---------------|
| `ALERT_DECRYPTION_FAILED` | Передається у відстеження помилок обчислювачем сповіщень. Заголовок автентифікації вебхука сповіщення не вдається розшифрувати. |
| `SIEM_DECRYPTION_FAILED` | Передається у відстеження помилок під час пересилання до SIEM. Заголовок автентифікації SIEM не вдається розшифрувати. |
| `WEBHOOK_DECRYPTION_FAILED` | Передається у відстеження помилок. Запит, що зіткнувся з тією самою несправністю, відповідає `DECRYPTION_FAILED`. |
| `STAGED_DISCARD_FAILED` | Передається у відстеження помилок, коли проміжно збережене завантаження не вдається видалити. |
| `USERNAME_RACE_EXHAUSTED` | Виникає, коли автостворення SSO програє змагання за ім'я користувача на кожній повторній спробі. Сторінка входу натомість показує помилку. |
| `ERR_OUT_OF_RANGE` | Видається читачем об'єктного сховища для некоректного діапазону байтів. |
| `ETIMEDOUT` | Встановлюється для помилки тайм-ауту експорту GDPR. Експорт завершується невдало, і його можна запросити знову. |
| `FST_REQ_FILE_TOO_LARGE` | Код Fastify для завантаження понад ліміт. Клієнти отримують 413 із `PAYLOAD_TOO_LARGE` або власне повідомлення 413 від маршруту. |
| `TARGET_SIZE_EXCEEDED` | Видається, коли стиснення до цільового розміру не досягає цілі. Помилка не має ні статусу, ні коду, тому клієнти отримують загальний збій. |
