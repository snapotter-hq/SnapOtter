# Коди помилок {#error-codes}

Кожна JSON-відповідь із помилкою має однакову структуру:

```json
{
  "error": "Job not found",
  "code": "NOT_FOUND",
  "requestId": "req-42"
}
```

| Поле | Завжди присутнє | Значення |
|-------|----------------|---------|
| `error` | Так | Зрозуміле людині повідомлення. Його безпечно показувати користувачам. Не розбирайте його програмно. |
| `code` | Так | Стабільний машинозчитуваний код. Розгалужуйте логіку за ним. |
| `requestId` | Так | Ідентифікатор цього запиту на сервері. Наводьте його, повідомляючи про проблему: він збігається із записом у журналі сервера. |
| `details` | Іноді | Додатковий контекст для деяких помилок 4xx, наприклад повідомлення про валідацію. |

Повідомлення можуть змінюватися між релізами. Коди не змінюються, тому клієнтську логіку слід писати на основі `code`.

## Коди за HTTP-статусом {#status-codes}

Якщо маршрут не задає власний код, сервер виводить його зі статусу:

| HTTP-статус | `code` |
|-------------|--------|
| 400 | `BAD_REQUEST` |
| 401 | `AUTH_REQUIRED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 413 | `PAYLOAD_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `UNPROCESSABLE_ENTITY` |
| 429 | `RATE_LIMITED` |
| 500 | `INTERNAL_ERROR` |
| 501 | `NOT_IMPLEMENTED` |
| 503 | `SERVICE_UNAVAILABLE` |
| 507 | `INSUFFICIENT_STORAGE` |

Будь-який інший код 4xx зводиться до `BAD_REQUEST`, а будь-який інший код 5xx до `INTERNAL_ERROR`.

Маршрут може задати конкретніший код, і тоді відповідь міститиме саме його. Наприклад, інструмент, який не може запуститися через відсутній AI-пакет, повертає код, специфічний для функції. Такі коди описані разом із функцією, яка їх генерує.

## Автентифікація та доступ {#auth-codes}

| `code` | Статус | Що робити |
|--------|--------|------------|
| `AUTH_REQUIRED` | 401 | Надішліть `Authorization: Bearer <token>` разом із токеном сесії або API-ключем (`si_...`). |
| `FORBIDDEN` | 403 | Облікові дані дійсні, але не мають потрібного дозволу. Попросіть адміністратора надати дозвіл. |
| `MUST_CHANGE_PASSWORD` | 403 | Обліковий запис має змінити пароль, перш ніж викликати інші ендпоінти. Викличте `POST /api/auth/change-password` із токеном сесії, потім повторіть спробу. |
| `USER_DISABLED` | 403 | Обліковий запис вимкнено. Адміністратор має знову його ввімкнути. |
| `LOGIN_THROTTLED` | 429 | Забагато невдалих спроб входу. Зачекайте перед наступною спробою. |
| `VALIDATION_ERROR` | 400 | Тіло або параметри запиту не пройшли валідацію. `details` вказує на проблему. |

Обліковий запис адміністратора першого запуску має ім'я `admin` і пароль `admin`, якщо їх не змінили `DEFAULT_USERNAME` чи `DEFAULT_PASSWORD`. Якщо не задано `SKIP_MUST_CHANGE_PASSWORD`, цей обліковий запис отримує `MUST_CHANGE_PASSWORD` на кожен виклик, доки пароль не буде змінено.

## Завдання {#job-codes}

Завдання, що завершилося помилкою, повідомляє причину у самому завданні, а не в HTTP-помилці. Прочитайте `error.code` і `error.message` з `GET /api/v1/jobs/{jobId}`. Див. [Відстеження прогресу](/uk/api/rest#progress-tracking).

## Ще не каталогізовано {#not-yet-cataloged}

Коди, які генерують окремі функції (наприклад шифрування, OIDC, SCIM і команди), поки не описані на цій сторінці. Кожен із них є стабільним кодом; ставтеся до неописаного коду як до непрозорого й обробляйте його за статусом.
