# 變更記錄 {#changelog}

## 未發布 {#unreleased}

### 已棄用 {#unreleased-deprecated}

- **五個圖片壓縮至指定大小的操作已棄用。** `/api/v1/tools/image/compress-image-to-20kb`、`-50kb`、`-100kb`、`-200kb` 與 `-500kb` 已在 OpenAPI 規格中標示為已棄用，且至少會保留一個次要版本。請改為傳送 `POST /api/v1/tools/image/compress`，並將 `settings` 設為 `{"mode":"targetSize","targetSizeKb":20}`（或 50、100、200、500）。輸出結果相同。PDF 預設組合的路徑不變。

## v2.3.0 {#v2-3-0}

SnapOtter 在 Docker Hub 與 GHCR 的映像檔拉取次數剛剛突破一百萬次，GitHub 上也達到 3,000 顆星。這代表有非常多自行託管的伺服器，所以這個版本是我們獻給每一位使用者的感謝。

請儘早升級。2.3.0 修補了六項安全公告，其中一項為高嚴重性。詳情請見下方的安全性章節。

除了修正之外，還有新的工具：PDF 多功能工具頁面編輯器、圖片與 PDF 的一鍵壓縮至指定大小預設組合，以及整理 PDF 中的拖放式頁面排序。OCR 現在可以辨識阿拉伯文，pdf-to-text 在遇到掃描版 PDF 時也會提供 OCR。SnapOtter 可以在反向代理後方以子路徑（例如 `/snapotter`）執行。應用程式不再需要 Postgres 超級使用者才能執行。被鎖在外面的管理員可以從命令列恢復存取。其餘約 1,400 項修正，大部分都是針對您回報的問題。

> [!IMPORTANT]
> 下列六項安全公告都影響 2.2.0，部分甚至可追溯到 2.0.0。如果您與其他使用者共用同一個執行個體，或將它開放到自己的網路之外，請升級。

### 安全性 {#v2-3-0-security}

- **SVG 上傳可能略過清理（GHSA-9c7h-xjrp-8gh3，高）。** 被圖片解碼器拒絕的 SVG 會原封不動地儲存並提供，而不會經過清理。受影響版本：2.2.0 及更早版本。由 @xaferima 回報。（#1211）
- **工作進度串流沒有檢查請求者身分（GHSA-ff22-w6x2-fm98，中）。** 現在需要登入並確認工作擁有權。受影響版本：2.0.0 至 2.2.0。（#1750）
- **結果下載連結也會提供原始上傳檔案（GHSA-jgv3-2jc6-f628，中）。** 受影響版本：2.2.0 及更早版本。由 @emirhancatkin 回報。（#3623）
- **證件照與背景效果信任用戶端提供的工作 ID（GHSA-3c8g-8v4x-qq9j，中）。** 受影響版本：2.2.0 及更早版本。由 @shaoyuuuuu 回報。（#3623）
- **URL 匯入、上傳與預覽略過了角色與 API 金鑰的權限檢查（GHSA-8xxr-g2w8-7f9r，中）。** 受影響版本：2.2.0 及更早版本。由 @nguyenvantiennani 回報。（#3780、#707）
- **SSO 強制執行時洩漏了緊急存取使用者名稱（GHSA-q6fg-vvw9-cr8r，低）。** 被拒絕的本機登入現在會收到與其他登入失敗相同的 401。受影響版本：2.0.0 至 2.2.0。（#2148）
- **Postgres 不再以超級使用者身分執行。** 應用程式現在以只能讀寫資料的角色連線。遷移使用另一個選用的連線。請參閱升級說明。（#918）
- **已修補的相依套件**：dompurify 與 handlebars 的覆寫下限已提高至修正後的版本。（#4247）

### 新功能 {#v2-3-0-new-features}

- **PDF 多功能工具**：頁面編輯器，可重新排序、複製、旋轉、刪除頁面，並從其他 PDF 匯入頁面。最終檔案由伺服器組合。（#1338）
- **一鍵壓縮至目標大小**：五個圖片預設組合（20、50、100、200、500 KB）與五個 PDF 預設組合（100、200、500 KB、1 MB、2 MB）。（#1250、#1377）
- **在子路徑下執行 SnapOtter**：設定 `BASE_PATH=/snapotter`，同一個映像檔即可從該路徑提供服務。結果連結、Cookie、SSO 重新導向與 API 文件都會跟著調整。（#1252、#1324）
- **阿拉伯文 OCR**：可明確選擇阿拉伯文，或讓自動模式偵測。圖片與 PDF 的 OCR 皆適用。（#4130、#4183）
- **pdf-to-text 提供 OCR**：當 PDF 或整批檔案沒有文字層時，會提供 OCR，而不是回傳空白檔案。（#4142、#4198）
- **整理 PDF 支援拖放式頁面排序**，滑鼠與觸控皆可使用。（#1249、#2601）
- **執行多檔案作業前可重新排序檔案**：合併、拼接、拼貼及其他多檔案工具都會保留您設定的順序。（#756、#757）
- **可取消批次與管線執行**，且伺服器上的工作確實會停止。（#807）
- **`snapotter-admin` 復原指令**：`reset-password`、`create-admin`、`unlock-user` 與 MFA 重設，供被鎖在網頁 UI 之外的管理員使用。（#4016）
- **登入時註冊 MFA**：當要求 MFA 時，尚未設定的使用者可以當場完成設定，而不會被擋住。
- **相機擷取與可安裝的應用程式**：在行動裝置上直接拍照並送入工具，也可以將 SnapOtter 安裝為 PWA。（#773）
- **編輯器「畫布大小」對話方塊支援透明邊距。**（#4111）
- **管理員更新通知**：有較新的 SnapOtter 版本時，管理員會看到可關閉的通知，並附有版本說明的連結。檢查透過現有的分析連線執行，因此在關閉分析時也會停用。

### 改進 {#v2-3-0-improvements}

- **重複執行時移除背景更快**：模型會在請求之間保持載入，而不是每次都重新載入。（#4144）
- **批次上傳使用的記憶體大幅減少**：每個檔案都寫入暫存磁碟並逐一處理，而不是佔用 RAM。（#2687）
- **AI 套件組合安裝會乾淨地失敗並回復**，而不是留下安裝到一半的虛擬環境。Proxmox LXC 的移除背景安裝再度可用，低記憶體主機也會在工作開始前取得合理的 CPU 限制。（#2628、#2597、#2526、#2546）
- **GPU 偵測更可靠**：透過驅動程式偵測 CUDA，RTX 50 系列顯示卡會退回 CPU 而不是失敗，硬體影片編碼器在使用前也會先進行測試執行。（#4225、#4075、#3980、#3983）
- **`MAX_WORKER_THREADS` 現在生效了。** 它先前只被解析，卻從未被套用。（#3249）
- **長時間工具使用較長的逾時**：pdf-to-word、compress-pdf、convert-document 與內容感知縮放，處理大型檔案時不再過早逾時。（#3276）
- **壓縮 PDF 會保持掃描檔的可讀性**，並在無法達到目標大小時如實告知，而不是產生無法閱讀的檔案。（#4112）
- **登入失敗依使用者名稱節流**：十五分鐘內超過十次會收到 429，並附帶 `Retry-After`。（#827）
- **錯誤訊息會說明問題所在**：缺少執行檔、儲存空間故障、記憶體不足而被終止，以及上傳限制，現在都有明確的訊息，而不是單純的 500 或 422。
- **稽核日誌涵蓋工具、批次與管線執行**，使用者、角色、團隊與 GDPR 事件也會記錄誰對誰做了什麼。（#3991、#3984）
- **一體化容器在首次啟動失敗時會停止**，而不是無止盡地重新啟動，內嵌的 Postgres 與 Redis 也設有啟動期限。（#3008、#1130）
- **日期與複數形式遵循您的語言**，最後幾個寫死的英文字串也已翻譯。
- **行動裝置與編輯器的細節打磨**：手機上的滑桿、簽署 PDF 與裁切版面配置、觸控拖曳、更快的像素筆刷，以及色階與曲線納入復原與自動儲存。

### 錯誤修正 {#v2-3-0-bug-fixes}

- **調整色彩錯誤地合併設定**：色溫、飽和度、色相、對比與復古色調會互相覆蓋，而不是疊加。（#3153、#3120、#3469）
- **像素化沒有產生像素化效果**，且各個圖片工具的 PNG 輸出被悄悄減少了調色盤色彩。（#709、#716）
- **動畫 GIF 與 WebP 在多個工具中遺失影格**，GIF 調色盤與透明度也出現錯誤。（#1184、#1225、#3407、#2573）
- **旋轉後的上傳檔案畫質下降**：自動調整方向會捨棄無損編碼、透明度與 16 位元色彩深度。動畫 WebP 現在會旋轉每一個影格。（#2384、#2529）
- **含透明度的 TIFF、AV1 HEIF 檔案與數種 RAW 格式**會失敗或遺失 Alpha 通道。（#2609、#2572、#1120）
- **調整編輯器畫布大小時會縮放圖片**，而不是在周圍增加空間。（#2081）
- **輸出檔名被弄亂**：`.jpeg` 與 `.tif` 會變成其他名稱，以點開頭的檔案或名稱重複副檔名的檔案也會出錯。（#3495、#3382）
- **檔案庫自動儲存忽略了儲存配額**，儲存空間計數也可能變成負數。（#2389、#2585）
- **重新啟動後卡住的工作**現在會在啟動時結算，而不會永遠顯示「處理中」。（#3219、#3193）
- **OIDC 登入將每位新使用者都命名為「admin」**，而 iOS Safari 登入成功後卻停在錯誤頁面。（#862、#4021）
- **已停用的密碼規則在建立使用者時仍被強制執行。**（#1028）
- **損毀的 PDF 會卡住 30 秒**才失敗。（#920）
- **AI 套件組合的磁碟檢查為了安裝單一套件組合，要求約 18 GB。**（#1248）
- **壓縮影片在可變影格率的螢幕錄影上失敗。**（#2427）
- **瀏覽器重試請求時，批次移除背景會遺失已完成的結果。**（#2015）
- **設定中的數字欄位在輸入時無法清除。**（#1449）
- **關閉分析後，佇列中的事件仍會在約 30 秒後送出。** 現在選擇退出時會將它們捨棄。（#4270）

### 升級說明 {#v2-3-0-upgrade-notes}

遷移會在啟動時自動執行。您不需要執行任何 SQL。

- **資料庫角色。** 標準的 Compose 檔案現在為應用程式配置只能讀寫資料的角色（`DATABASE_URL`），以及另一個特權連線（`DATABASE_MIGRATION_URL`），後者僅在啟動時用於遷移與授權。既有的 Compose 檔案仍照常運作：不設定 `DATABASE_MIGRATION_URL`，SnapOtter 就會以單一角色執行。對於非本機的部署，請在設定 `POSTGRES_APP_PASSWORD` 的同時設定 `POSTGRES_PASSWORD`。
- **更嚴格的啟動檢查。** 這些問題過去會較晚才失敗，或悄悄被忽略。現在它們會讓容器停止，並顯示指出變數名稱的訊息：不支援的 `DEFAULT_LOCALE`（請使用 `de` 這類受支援的代碼，而不是 `de_DE`）、啟用 SSO 時格式錯誤的 `SAML_IDP_SSO_URL`、`SAML_CALLBACK_URL` 或 `OIDC_ISSUER_URL`、無效的 `TRUST_PROXY` 清單、不正確的 `BASE_PATH`，以及無法寫入的 `LOG_DIR`。
- **`TRUST_PROXY` 不再接受躍點數。** 像 `TRUST_PROXY=2` 這樣的數字現在會在啟動時讓容器停止，而不是悄悄地不信任任何代理。請將它設為代理位址或具名範圍（預設值為 `loopback,linklocal,uniquelocal`）；當沒有任何代理位於 SnapOtter 前方時設為 `false`；只有在您掌控的代理位於公開位址前端時，才設為 `true`。（#998）
- **`MAX_WORKER_THREADS` 現在會生效。** 如果您先前設定了它卻沒有看到變化，現在就會看到了。
- **API 狀態碼。** 引擎與儲存空間故障會回傳 503 `ENGINE_UNAVAILABLE`（批次端點過去回傳 422）。超過限制的上傳回傳 413（過去為 400）。格式錯誤的 `clientJobId` 回傳 400，重複使用的則回傳 409（過去為 500）。重播您自己的管線批次會回傳 202。沒有 `mode=targetSize` 的 `targetSizeKb` 回傳 400。SSO 強制執行下被拒絕的本機登入回傳 401，而不是 403 `SSO_ENFORCED`。被節流的登入回傳 429 `LOGIN_THROTTLED`。移除背景的結果不再包含 `originalUrl`。
- **新增選用變數**：`BASE_PATH`、`DATABASE_MIGRATION_URL`、`GDPR_EXPORT_TIMEOUT_MS`（預設 15 分鐘，`0` 表示停用）、`EMBEDDED_REDIS_TIMEOUT_S`（180）與 `EMBEDDED_POSTGRES_TIMEOUT_S`（600）。
- **Compose 檔案隨版本發佈。** `docker-compose.yml` 與 `docker-compose-gpu.yml` 已附加在此版本中，您可以直接從版本頁面下載。

## v2.2.0 {#v2-2-0}

2.2 的大部分內容是安全強化。持有委派的 `users:manage` 角色的非管理員可以接管整個執行個體，而且每個工具端點都缺少權限檢查。如果您有多位使用者，請升級。

其餘則是自行託管時的各種零碎問題：開始後卻從未完成的下載、加入第二個檔案就壞掉的預設組合，以及在 Postgres 還在啟動時就不斷當機重啟的容器。另外還新增了兩個工具。文件與網站現在已翻譯成 21 種語言，介面也終於通過 WCAG AA 對比度標準。

> [!IMPORTANT]
> 如果您透過自訂角色將 `users:manage` 授予非管理員，則在 2.0.0 至 2.1.0 中，該角色可以接管管理員帳號。詳情請見安全性。

### 安全性 {#v2-2-0-security}

- **透過委派的 `users:manage` 角色提升權限（GHSA-9xgh-95qh-2x7h）。** 透過自訂角色持有 `users:manage` 的非管理員，可以重設或刪除更高權限的帳號（包括內建管理員），進而接管整個執行個體。密碼重設與帳號刪除現在會驗證呼叫者對目標的權限，因此委派的角色無法超越自己的層級。受影響版本：2.0.0 至 2.1.0。由李春來（Chunlai Li）回報。（#616）
- **現在所有工具端點都受到把關。** 工具存取過去是逐一路由強制執行，所以全部 45 個手寫路由都必須記得呼叫同一個檢查，而它們都沒有這麼做。沒有 `tools:use` 的角色仍然可以執行 image-to-pdf、erase-object、upscale、sign-pdf 等工具。現在這項檢查集中在一個 preHandler 中，依符合的路由運作，因此涵蓋子路徑以及日後新增的任何路由。（#646）
- **Docker 安裝上的速率限制可被繞過。** 映像檔預設為 `TRUST_PROXY=true`，所以用戶端 IP 來自請求標頭，偽造的 `X-Forwarded-For` 就能繞過登入限制器。預設值現在是私有網路的信任清單。（#649）
- **設定寫入現在逐項設定檢查**，而不是只在入口檢查一次，設定匯入也改為交易式，因此被拒絕的金鑰不會讓設定只套用一半。（#618）
- **檔案庫檔名無法逃出其儲存根目錄。** 精心構造的儲存名稱（惡意的 1.x SQLite 匯入會原封不動複製）可以讀取或刪除檔案目錄以外的檔案。只有在營運者匯入攻擊者提供的 1.x SQLite 資料庫之後才可能觸發，這是唯一能讓人選定儲存名稱的途徑。由 @Alpastx 回報。（GHSA-55w2-8cqf-w969、#600）
- **工作取消會強制檢查擁有權**，因此已驗證的使用者不能再憑工作 ID 取消其他使用者的工作。由 @Alpastx 回報。（GHSA-wqxf-gj2p-689x、#599）
- **對整個 2.0 程式碼樹的重新稽核找出了仍未解決的問題**：攔截到的 SAML 斷言可以被重放、MFA 挑戰在輸入任意次錯誤代碼後仍然有效、每個請求的 API 金鑰查詢是全表掃描、`MAX_WORKSPACE_SIZE_GB` 是無作用的設定，以及 SVG 清理器放行了未加引號的 `javascript:` href。（#620）
- **修補了九項已公開的 CVE**：fast-uri、svgo、sharp 與 tar 的傳遞相依（#619），以及 Pillow 12.3.0（#517）。arm64 上的 RAW 解碼現在改為從原始碼建置 LibRaw 0.22.2，而不是連結未修補的系統版本。（#649）

### 新功能 {#v2-2-0-new-features}

- **圓角裁切**：圓角方形與 iOS 風格的超橢圓遮罩，並可控制圓角半徑。專為 favicon 與應用程式圖示而設計。（#602）
- **移除 GIF 背景**：逐影格移除動畫 GIF、WebP 或 APNG 的背景，並取回透明的動畫。（#502）
- **物件橡皮擦的套索與高品質模式**：拖曳自由形狀的圈選，而不必塗抹每個像素，並可選擇安裝擴散式修補套件組合，使大面積填補更乾淨。（#503、#566）
- **另存新檔，或覆寫。** 編輯檔案庫中的檔案過去會悄悄取代原始檔案。現在可以逐次編輯選擇，預設則是保留原檔。（#564、#577）
- **調整大小的長寬比預設組合。** 選擇 1:1、4:3 或 16:9，兩個維度就會保持鎖定，且不會放大。（#530）
- **雙層 OCR**：快速層內建於映像檔中，可離線執行、無需下載；較精準的執行階段則可依需求安裝。（#519）
- **隨處輸入即可搜尋。** 在儀表板或首頁開始輸入，文字就會進入搜尋框。（#644）
- **21 種語言的文件與網站**：文件網站、登陸頁面與 API 參考現在都已翻譯，與應用程式介面並列。新的低資源部署指南涵蓋 Raspberry Pi 與 2 GB 的機器。（#548）
- **更清楚的工具名稱**：18 個含糊的名稱現在自帶限定詞，因此「壓縮」變成「壓縮圖片」。工具 ID 與路由不變，所以您加入書籤的連結不會失效。（#520）

### 改進 {#v2-2-0-improvements}

- **整個介面符合 WCAG AA 對比度**：色盤經過重新調整，鮮豔的橙色只用於填色，文字與標籤則使用符合無障礙的墨色代碼，全部 57 個焦點指示器也都達到 3:1 的非文字標準。（#567、#574）
- **放大與移除背景不再看起來像當掉**：進度列會在推論期間前進，而不是停在 30%，這兩個工具現在也會警告僅使用 CPU 的主機會慢很多。（#605、#608）
- **逾時訊息會指出真正的原因**，並考量僅使用 CPU 的主機，而不是怪罪上傳。（#596）
- **SnapOtter 在啟動時會等待 Postgres 與 Redis**，而不是不斷當機重啟，Compose 與一體化映像檔皆是如此。在此之前，某個 Proxmox LXC 安裝曾重新啟動 76 次。（#537、#595）
- **下載可通過反向代理**：SnapOtter 會要求 nginx 與相容的代理不要緩衝檔案回應，這正是自行託管的下載開始後卻從未完成的常見原因。（#604、#607）
- **壓縮 PDF 會接近目標大小**，並在目標無法達成時誠實說明。（#522）
- **行動裝置的工具控制項保持可觸及**，因為應用程式外殼現在依動態視口調整大小。（#559）
- **轉換音訊提供取樣率設定。**（#561）
- **管理員可以放寬最小密碼長度**，對受信任的區域網路執行個體最低可設為 1。（#543）
- **MFA 可自助設定**，政策鎖定的問題已解決，OIDC 或 SAML 登入也會收到真正的 MFA 挑戰，而不是被直接封鎖。（#531、#536）
- **單純的 `Error: Error` 現在會指出原因。** Sharp 編碼失敗、AI 附屬程序結束、文件附屬程序輸出非 JSON，以及移除背景失敗，過去抵達時都被刪掉了原因。（#532、#534、#535、#538、#612）
- **說明對話方塊已翻譯。** 它的快速鍵標籤與入門文字過去是寫死的英文，而完成的翻譯卻一直閒置在全部 21 個語言檔案中。（#647）

### 升級說明 {#v2-2-0-upgrade-notes}

無需遷移，但有兩項隨附的預設值已變更：

- **`TRUST_PROXY` 現在預設為 `loopback,linklocal,uniquelocal`**，而不是信任所有對等端。Docker 橋接網路與 Compose 網路都在此範圍內，因此大多數設定無需變更。如果您的反向代理從公開位址連到 SnapOtter，請明確設定 `TRUST_PROXY`，否則速率限制與稽核日誌會將每個請求都歸因於該代理。

## v2.0.0 {#v2-0-0}

SnapOtter 2.0 將圖片工具組升級為完整的檔案處理套件：橫跨五種類型（圖片、影片、音訊、PDF 與檔案）的 200 多種工具，以 Postgres 17 與 Redis 支援的工作佇列重新打造，並提供單一指令的 `docker run`。這是重大版本；從 1.x 升級之前，請先閱讀重大變更。

### 新功能 {#new-features}

- **四種新的工具類型**：影片、音訊、PDF 與檔案加入圖片行列，使工具目錄擴增到 200 多種。
- **持久的背景工作**：由 Redis 支援的佇列（BullMQ）將每個工具作為受追蹤的工作執行，並透過 SSE 即時回報進度。
- **一體化單一容器模式**：只需一個 `docker run`，即可啟動內含內嵌 Postgres 與 Redis 的完整執行個體。
- **依需求安裝的 AI 套件組合**：移除背景、OCR、轉錄、放大、人臉偵測與增強、物件橡皮擦、上色與照片修復都可從 UI 安裝。GPU 加速會依框架偵測。
- **簽署 PDF**：在瀏覽器中手繪、輸入或上傳簽名，並放置到 PDF 上。
- **自動化**：串連多個工具的視覺化管線建置器，附有九個預先建置的範本。
- **83 個一鍵轉換預設組合**：專用的 JPG 轉 PNG、MP4 轉 GIF 等轉換器，並支援模糊搜尋。
- **以圖層為基礎的圖片編輯器**：位於 `/editor`、以 Konva 驅動的編輯器，具備筆刷、形狀、調整、濾鏡與曲線。
- **檔案庫**：儲存任何結果，並可作為另一個工具的輸入重複使用。
- 釘選工具、畫布內縮放與平移、21 種語言，以及企業版功能（OIDC/SSO、SAML、SCIM、S3 儲存、逐工具權限、稽核匯出、分散式追蹤）。

### 改進 {#improvements}

- 可取消正在執行的程序。（#137）
- 透過 LibRaw 進行完整解析度的 RAW 解碼，包括 DNG。（#289）
- 非 root 與外來 UID 的部署（TrueNAS、Unraid、OpenShift、PUID/PGID）。（#230、#127）
- 準確的 AI 安裝偵測與強化後的安裝流程。（#214、#352）
- 隱私強化：不會自動對第三方傳送資料，並提供選用的嚴格離線模式。
- 即使關閉分析，意見回饋按鈕也始終可用。

### 錯誤修正 {#bug-fixes}

- `RATE_LIMIT_PER_MIN=0` 再度能停用工具路由的速率限制。（#271）
- 修復了 Docker 映像檔內的 AI 虛擬環境路徑。（#390）
- 相容 sharp 0.35.2 以上版本。（#362）
- 圖片編輯器版面配置修正：尺規、填色行為、側邊欄與畫布大小。（#258、#259）
- 完成義大利文翻譯。（#231、#206、#425）
- 音訊正規化與 loudnorm 會保留來源取樣率。
- SSRF 強化：數字式 IPv6 CIDR 比對，以及擴大的 URL 預先掃描。（#287）
- 產生的 PDF 會標記 SnapOtter 為 Producer。
- mediapipe 可在 Python 3.13 與 Debian 13 上安裝。

### 重大變更 {#breaking-changes}

2.0 以 Postgres 17 取代內嵌的 SQLite 資料庫，並加入 Redis 8 作為工作佇列。您的 1.x 資料會在首次啟動時自動遷移，但容器堆疊已有變動，因此請先備份整個 `/data` 磁碟區（1.x 以 WAL 模式執行 SQLite，所以已提交的資料通常位於 `snapotter.db-wal`）。接著選擇單一容器映像檔（內嵌 Postgres 與 Redis，僅限 root）或 Compose 堆疊（應用程式加上 Postgres 17 與 Redis 8）。請參閱[遷移指南](https://github.com/snapotter-hq/SnapOtter/blob/main/MIGRATING.md)與[升級指南](/zh-TW/guide/upgrading)。

- 含輔助影像的 iPhone HEIC 解碼。（#183、#199）
- Real-ESRGAN 在 8GB GPU 上發生 CUDA OOM。（#200）
- 6 項正式環境 Sentry 錯誤與 7 項 QA 錯誤。（#208）

## v1.17.0 {#v1-17-0}

五個新工具、完整的圖片編輯器、SSO 登入、20 種語言。這原本或許該拆成三個獨立版本，但事已至此。

### 新功能 {#new-features-3}

- **圖片編輯器** - 圖層、筆刷、形狀、調整、濾鏡、曲線、鍵盤快速鍵。在您的瀏覽器中執行，在您的硬體上處理。
- **OIDC / SSO 驗證** - 使用 Google、GitHub、Okta 或任何 OpenID Connect 提供者登入。只需設定幾個環境變數，您的團隊就能使用既有的帳號。
- **迷因產生器** - 100 個內建範本，透過 opentype.js 繪製文字。也可以上傳自己的圖片。
- **美化** - 放入一張螢幕截圖，取得一張精緻的圖片。包含裝置外框（macOS、Windows、瀏覽器）、陰影、漸層與社群媒體預設組合。
- **色盲模擬** - 預覽圖片在第一型色盲、第二型色盲、第三型色盲及其他色覺缺陷下的外觀。
- **PNG 透明度修復器** - 偵測假透明的 PNG，並以 BiRefNet HR-matting 修復。可透過 LaMa 修補選擇性移除浮水印。
- **AI 畫布擴展** - 以 AI 填補擴展圖片邊界。依您願意投入多少 GPU 時間，提供三種品質等級（快速、平衡、高品質）。
- **20 種語言** - 阿拉伯文、中文（簡體/繁體）、捷克文、荷蘭文、法文、德文、印地文、印尼文、義大利文、日文、韓文、波蘭文、葡萄牙文、俄文、西班牙文、泰文、土耳其文、烏克蘭文、越南文。阿拉伯文支援由右至左（RTL）。
- **URL 匯入** - 將 URL 貼到拖放區，或從清單批次匯入。於伺服器端擷取，並具備 SSRF 防護。
- **多檔案橡皮擦** - 在多張圖片上繪製擦除遮罩，一鍵全部處理。筆觸會依圖片各自保留。
- **管線匯入/匯出** - 將工具鏈儲存為 JSON，並與他人分享。
- **透過 exiftool 新增 17 種相機 RAW 格式**，以及 QOI、JP2、EPS、DDS、CUR、DPX、FITS、PPM/PGM/PBM、SVGZ 與 APNG 輸入。新增 BMP、ICO、JP2、QOI 的輸出編解碼器。AVIF、TIFF、GIF、JXL 與 PSD 匯出則是從先前遺失的分支中找回。

### 改進 {#improvements-2}

- **圖片增強** - 以 CLAHE + 正規化 + 伽瑪取代舊的管線。新的「深度增強」切換會使用 AI 模型，取得更強烈的效果。
- **修復照片** - 刮痕偵測以 8 角度 Otsu 濾波重寫。LaMa 修補現在以原生解析度執行。
- **各處皆支援特殊格式** - OCR、image-to-PDF、favicon 產生器、合成、拼接與向量化現在都能解碼 HEIC、RAW、PSD。
- **壓縮** - 目標大小容差從 5% 收緊到 1%。目標大小成為預設模式。新增步進按鈕與 KB/MB 單位選擇器。
- **Sentry 清理** - 篩除了 644 個無需處理的事件。真正的錯誤現在得到妥善處理。
- **GPU 偵測** - 針對有 CUDA 卻沒有 nvidia-smi 的容器，提供更好的診斷。
- **停用驗證模式** - 匿名使用者會以管理員角色預先寫入資料庫。API 金鑰、管線與使用者檔案不再因外部索引鍵限制而損壞。
- **新增 2,705 個以上的測試**，涵蓋單元、整合與 E2E。

### 錯誤修正 {#bug-fixes-3}

- 在 CPU 上放大時，不再於 NAS 機器與低功耗硬體上逾時。
- QR 碼標誌不再使預覽永久消失。
- 修正高瘦直式圖片的裁切溢出。
- 含 Alpha 的 TIFF 檔案會正確強制輸出 PNG，而不是產生損毀。
- HDR/EXR 解碼會在 CLAHE 之前轉換為 8 位元，解決解碼失敗。
- 人臉特徵點的輸入緩衝區在傳給 Python 附屬程序前先轉換為 PNG，解決當機。
- 尋找重複項目可處理混合格式的批次與網路錯誤。
- 美化預覽即時更新。
- 拼接與向量化加入進度列。
- SVG 轉點陣圖現在可處理 SVGZ。
- 透過百分比編碼的 X-File-Results 標頭修正非 ASCII 檔名。
