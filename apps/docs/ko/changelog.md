# 변경 이력 {#changelog}

## 미출시 {#unreleased}

### 지원 중단 예정 {#unreleased-deprecated}

- **이미지 용량 맞춤 압축 작업 다섯 가지가 지원 중단 예정입니다.** `/api/v1/tools/image/compress-image-to-20kb`, `-50kb`, `-100kb`, `-200kb`, `-500kb`는 OpenAPI 사양에서 지원 중단 예정으로 표시되었으며, 최소 한 번의 마이너 릴리스 동안 유지됩니다. `POST /api/v1/tools/image/compress`에 `settings`를 `{"mode":"targetSize","targetSizeKb":20}`(또는 50, 100, 200, 500)로 설정해 보내세요. 출력은 동일합니다. PDF 프리셋 경로는 변경되지 않습니다.

## v2.3.0 {#v2-3-0}

SnapOtter가 Docker Hub와 GHCR을 합쳐 이미지 풀 100만 회를 넘겼고, GitHub 스타도 3,000개를 달성했습니다. 그만큼 많은 셀프 호스팅 서버가 돌아가고 있다는 뜻이며, 이번 릴리스는 서버를 운영해 주시는 모든 분께 드리는 감사 인사입니다.

가능한 한 빨리 업그레이드하세요. 2.3.0은 보안 권고 여섯 건을 해결하며, 그중 하나는 심각도가 높습니다. 자세한 내용은 아래 보안 섹션에 있습니다.

수정 사항 외에도 새로운 도구가 있습니다. PDF 멀티 툴 페이지 편집기, 이미지와 PDF를 원클릭으로 목표 용량에 맞추는 압축 프리셋, PDF 정리의 드래그 앤 드롭 페이지 순서 변경입니다. OCR이 이제 아랍어를 읽고, pdf-to-text는 스캔한 PDF를 만나면 OCR을 제안합니다. 리버스 프록시 뒤에서 `/snapotter` 같은 하위 경로로 SnapOtter를 실행할 수도 있습니다. 앱을 실행하는 데 더 이상 Postgres 슈퍼유저가 필요하지 않습니다. 잠긴 관리자는 명령줄에서 복구할 수 있습니다. 나머지는 약 1,400건의 수정이며, 대부분 여러분이 신고해 주신 문제입니다.

> [!IMPORTANT]
> 아래 여섯 건의 권고는 모두 2.2.0에 영향을 주며, 일부는 2.0.0까지 거슬러 올라갑니다. 다른 사용자와 인스턴스를 공유하거나 내 네트워크 밖에 노출하고 있다면 업그레이드하세요.

- **결과 다운로드 링크로 원본 업로드도 받을 수 있었습니다 (GHSA-jgv3-2jc6-f628, 중간).** 영향 범위: 2.2.0 및 이전 버전. @emirhancatkin 님이 신고했습니다. (#3623)

- **의존성 패치**: dompurify와 handlebars의 override 하한을 수정된 버전으로 올렸습니다. (#4247)

### 새로운 기능 {#v2-3-0-new-features}

- **PDF 멀티 툴**: 페이지를 재정렬, 복제, 회전, 삭제하고 다른 PDF에서 페이지를 가져오는 페이지 편집기입니다. 최종 파일은 서버가 조립합니다. (#1338)
- **원클릭으로 목표 용량에 맞춰 압축**: 이미지 프리셋 다섯 가지(20, 50, 100, 200, 500 KB)와 PDF 프리셋 다섯 가지(100, 200, 500 KB, 1 MB, 2 MB)입니다. (#1250, #1377)
- **하위 경로에서 SnapOtter 실행**: `BASE_PATH=/snapotter`를 설정하면 같은 이미지가 그 경로에서 서비스됩니다. 결과 링크, 쿠키, SSO 리디렉션, API 문서가 모두 이를 따릅니다. (#1252, #1324)
- **아랍어 OCR**: 아랍어를 직접 선택하거나 자동 모드가 감지하게 할 수 있습니다. 이미지 OCR과 PDF OCR 모두 동작합니다. (#4130, #4183)
- **pdf-to-text가 OCR을 제안합니다.** PDF 또는 일괄 작업 전체에 텍스트 레이어가 없을 때 빈 파일을 반환하는 대신 제안합니다. (#4142, #4198)
- **PDF 정리의 드래그 앤 드롭 페이지 순서 변경**: 마우스와 터치를 모두 지원합니다. (#1249, #2601)
- **여러 파일 실행 전에 파일 순서 변경**: 병합, 스티치, 콜라주 등 여러 파일을 쓰는 도구가 설정한 순서를 유지합니다. (#756, #757)
- **일괄 및 파이프라인 실행 취소**: 서버에서도 작업이 실제로 중단됩니다. (#807)
- **`snapotter-admin` 복구 명령**: 웹 UI에서 잠긴 관리자를 위한 `reset-password`, `create-admin`, `unlock-user`, MFA 재설정입니다. (#4016)
- **로그인 시 MFA 등록**: MFA가 필수일 때 MFA를 설정하지 않은 사용자는 차단되는 대신 그 자리에서 설정합니다.
- **카메라 촬영과 설치 가능한 앱**: 모바일에서 사진을 찍어 바로 도구에 넣을 수 있고, SnapOtter를 PWA로 설치할 수 있습니다. (#773)
- **편집기의 캔버스 크기 대화상자에서 투명 패딩 지원.** (#4111)
- **관리자용 업데이트 알림**: 더 새로운 SnapOtter가 나오면 관리자에게 릴리스 노트 링크가 있는 닫을 수 있는 알림이 표시됩니다. 확인은 기존 분석 연결을 통해 이루어지므로 분석이 꺼져 있으면 함께 꺼집니다.

### 개선 사항 {#v2-3-0-improvements}

- **반복 실행 시 배경 제거가 더 빨라졌습니다**: 요청마다 모델을 다시 불러오지 않고 요청 사이에도 모델을 메모리에 유지합니다. (#4144)
- **일괄 업로드의 메모리 사용량이 크게 줄었습니다**: 각 파일이 RAM에 머무는 대신 스크래치 디스크로 보내져 하나씩 처리됩니다. (#2687)
- **AI 번들 설치가 깔끔하게 실패하고 롤백됩니다.** 반쯤 설치된 venv가 남지 않습니다. Proxmox LXC의 배경 제거 설치가 다시 동작하며, 메모리가 적은 호스트는 작업이 시작되기 전에 적절한 CPU 제한을 받습니다. (#2628, #2597, #2526, #2546)
- **GPU 감지가 더 안정적입니다**: CUDA를 드라이버를 통해 감지하고, RTX 50 시리즈 카드는 실패하는 대신 CPU로 대체되며, 하드웨어 비디오 인코더는 사용 전에 시험 실행합니다. (#4225, #4075, #3980, #3983)
- **`MAX_WORKER_THREADS`이 이제 동작합니다.** 이전에는 파싱만 되고 적용되지 않았습니다. (#3249)
- **오래 걸리는 도구에 긴 타임아웃을 적용합니다**: pdf-to-word, compress-pdf, convert-document, 콘텐츠 인식 크기 조정이 큰 파일에서 더 이상 일찍 시간 초과되지 않습니다. (#3276)
- **PDF 압축이 스캔본의 가독성을 유지하며**, 목표 용량에 도달할 수 없으면 읽을 수 없는 파일을 만드는 대신 그 사실을 알려 줍니다. (#4112)
- **로그인 실패를 사용자 이름별로 제한합니다**: 15분 안에 10회를 넘으면 `Retry-After`와 함께 429를 반환합니다. (#827)
- **오류가 무엇이 잘못되었는지 알려 줍니다**: 바이너리 누락, 스토리지 장애, 메모리 부족으로 인한 강제 종료, 업로드 제한에 대해 단순한 500이나 422 대신 구체적인 메시지가 표시됩니다.
- **감사 로그가 도구, 일괄, 파이프라인 실행을 포함합니다.** 사용자, 역할, 팀, GDPR 이벤트에는 누가 누구에게 무엇을 했는지가 기록됩니다. (#3991, #3984)
- **올인원 컨테이너가 첫 부팅에 실패하면 무한히 재시작하는 대신 중지합니다.** 임베디드 Postgres와 Redis에는 시작 제한 시간이 있습니다. (#3008, #1130)
- **날짜와 복수형이 사용자의 언어를 따르며**, 마지막까지 하드코딩되어 있던 영어 문자열도 번역되었습니다.
- **모바일과 편집기 다듬기**: 휴대폰에서의 슬라이더, PDF 서명, 자르기 레이아웃, 터치 드래그, 더 빨라진 픽셀 브러시, 실행 취소와 자동 저장에 포함된 레벨 및 커브입니다.

### 업그레이드 참고 사항 {#v2-3-0-upgrade-notes}

마이그레이션은 시작할 때 자동으로 실행됩니다. SQL을 직접 실행할 필요는 없습니다.

- **데이터베이스 역할.** 기본 Compose 파일은 이제 앱에 데이터를 읽고 쓰기만 할 수 있는 역할(`DATABASE_URL`)과, 부팅할 때 마이그레이션과 권한 부여에만 쓰는 별도의 권한 있는 연결(`DATABASE_MIGRATION_URL`)을 제공합니다. 기존 Compose 파일은 이전과 같이 계속 동작합니다. `DATABASE_MIGRATION_URL`을 설정하지 않으면 SnapOtter는 단일 역할로 실행됩니다. 로컬이 아닌 배포에서는 `POSTGRES_PASSWORD`와 함께 `POSTGRES_APP_PASSWORD`을 설정하세요.
- **시작 검사가 더 엄격해졌습니다.** 이전에는 나중에 실패하거나 조용히 넘어가던 항목입니다. 이제 변수 이름을 알려 주는 메시지와 함께 컨테이너가 중지됩니다: 지원되지 않는 `DEFAULT_LOCALE`(`de_DE` 대신 `de` 같은 지원되는 코드를 사용), SSO가 켜져 있을 때 형식이 잘못된 `SAML_IDP_SSO_URL`, `SAML_CALLBACK_URL`, `OIDC_ISSUER_URL`, 잘못된 `TRUST_PROXY` 목록, 잘못된 `BASE_PATH`, 쓰기 불가능한 `LOG_DIR`입니다.
- **`TRUST_PROXY`은 더 이상 홉 수를 받지 않습니다.** `TRUST_PROXY=2` 같은 숫자는 이제 프록시를 신뢰하지 않은 채로 조용히 넘어가는 대신 시작할 때 컨테이너를 중지시킵니다. 프록시 주소나 이름이 있는 범위로 설정하세요(기본값은 `loopback,linklocal,uniquelocal`). SnapOtter 앞에 프록시가 없으면 `false`로, 직접 관리하는 프록시가 공개 주소 앞단에 있을 때만 `true`으로 설정합니다. (#998)
- **`MAX_WORKER_THREADS`이 이제 적용됩니다.** 이전에 설정했는데 변화가 없었다면 이제 효과가 나타납니다.
- **API 상태 코드.** 엔진과 스토리지 장애는 503 `ENGINE_UNAVAILABLE`을 반환합니다(일괄 엔드포인트는 이전에 422를 반환했습니다). 제한을 초과한 업로드는 413을 반환합니다(이전에는 400). 형식이 잘못된 `clientJobId`는 400을, 재사용된 경우는 409를 반환합니다(이전에는 500). 내 파이프라인 일괄 작업을 다시 실행하면 202를 반환합니다. `targetSizeKb` 없이 `mode=targetSize`을 보내면 400을 반환합니다. SSO 강제 적용 상태에서 거부된 로컬 로그인은 403 `SSO_ENFORCED` 대신 401을 반환합니다. 제한된 로그인은 429 `LOGIN_THROTTLED`을 반환합니다. 배경 제거 결과에는 더 이상 `originalUrl`이 포함되지 않습니다.
- **새로운 선택적 변수**: `BASE_PATH`, `DATABASE_MIGRATION_URL`, `GDPR_EXPORT_TIMEOUT_MS`(기본값 15분, `0`이면 비활성화), `EMBEDDED_REDIS_TIMEOUT_S`(180), `EMBEDDED_POSTGRES_TIMEOUT_S`(600)입니다.
- **Compose 파일이 릴리스와 함께 제공됩니다.** `docker-compose.yml`과 `docker-compose-gpu.yml`가 이번 릴리스에 첨부되어 있으므로 릴리스 페이지에서 바로 내려받을 수 있습니다.

## v2.2.0 {#v2-2-0}

2.2의 대부분은 보안 강화입니다. 위임된 `users:manage` 역할을 가진 비관리자가 인스턴스를 장악할 수 있었고, 모든 도구 엔드포인트에 권한 검사가 빠져 있었습니다. 사용자가 둘 이상이라면 업그레이드하세요.

나머지는 셀프 호스팅에서 흔히 겪는 자잘한 문제들입니다. 시작만 하고 끝나지 않던 다운로드, 두 번째 파일을 추가하는 순간 깨지던 프리셋, Postgres가 아직 올라오는 중에 계속 충돌하며 재시작하던 컨테이너 등입니다. 새 도구도 두 개 추가되었습니다. 문서와 웹사이트는 이제 21개 언어로 번역되며, 인터페이스는 마침내 WCAG AA 대비를 충족합니다.

> [!IMPORTANT]
> 사용자 지정 역할을 통해 비관리자에게 `users:manage`을 부여했다면, 그 역할은 2.0.0부터 2.1.0까지에서 관리자 계정을 장악할 수 있었습니다. 자세한 내용은 보안을 참고하세요.

### 보안 {#v2-2-0-security}

- **위임된 `users:manage` 역할을 통한 권한 상승 (GHSA-9xgh-95qh-2x7h).** 사용자 지정 역할을 통해 `users:manage`을 가진 비관리자가 기본 제공 관리자를 포함한 더 높은 권한의 계정 비밀번호를 재설정하거나 계정을 삭제하여 인스턴스를 장악할 수 있었습니다. 이제 비밀번호 재설정과 계정 삭제는 대상에 대한 호출자의 권한을 확인하므로, 위임된 역할은 자기 수준보다 위에 닿을 수 없습니다. 영향 범위: 2.0.0부터 2.1.0까지. 李春来 (Chunlai Li) 님이 신고했습니다. (#616)
- **이제 모든 도구 엔드포인트가 보호됩니다.** 도구 접근은 라우트마다 개별적으로 적용되었기 때문에 직접 작성한 라우트 45개가 모두 같은 호출을 기억해야 했는데, 어느 것도 그러지 않았습니다. `tools:use`이 없는 역할도 image-to-pdf, erase-object, upscale, sign-pdf 등을 실행할 수 있었습니다. 이제 검사는 일치한 라우트를 기준으로 하나의 preHandler에서 이루어지므로 하위 경로와 이후에 추가되는 라우트까지 모두 포함합니다. (#646)
- **Docker 설치에서 속도 제한을 우회할 수 있었습니다.** 이미지가 `TRUST_PROXY=true`을 포함해 제공되어 클라이언트 IP가 요청 헤더에서 결정되었고, 위조한 `X-Forwarded-For`로 로그인 제한기를 통과할 수 있었습니다. 기본값은 이제 사설 네트워크 신뢰 목록입니다. (#649)
- **설정 쓰기는 입구에서 한 번이 아니라 설정별로 검사하며**, 구성 가져오기는 이제 트랜잭션으로 처리되어 거부된 키 때문에 구성이 반쯤만 적용되는 일이 없습니다. (#618)
- **라이브러리 파일 이름이 스토리지 루트를 벗어날 수 없습니다.** 악의적인 1.x SQLite 가져오기가 그대로 복사하는, 조작된 저장 이름으로 파일 디렉터리 밖의 파일을 읽거나 삭제할 수 있었습니다. 운영자가 공격자가 제공한 1.x SQLite 데이터베이스를 가져온 경우에만 접근할 수 있으며, 이것이 저장 이름을 고를 수 있는 유일한 경로입니다. @Alpastx 님이 신고했습니다. (GHSA-55w2-8cqf-w969, #600)
- **작업 취소가 소유권을 확인합니다.** 인증된 사용자가 더 이상 작업 ID만으로 다른 사용자의 작업을 취소할 수 없습니다. @Alpastx 님이 신고했습니다. (GHSA-wqxf-gj2p-689x, #599)
- **2.0 트리 전체를 다시 감사하여 아직 열려 있던 문제를 잡아냈습니다**: 가로챈 SAML 어서션을 재생할 수 있었고, MFA 챌린지가 잘못된 코드를 몇 번을 입력해도 유지되었으며, 요청마다 하는 API 키 조회가 전체 테이블 스캔이었고, `MAX_WORKSPACE_SIZE_GB`이 동작하지 않는 설정이었으며, SVG 정리기가 따옴표 없는 `javascript:` href를 통과시켰습니다. (#620)

### 새로운 기능 {#v2-2-0-new-features}

- **둥근 자르기**: 둥근 사각형과 iOS 스타일 스쿼클 마스크이며 모서리 반경 조절을 지원합니다. 파비콘과 앱 아이콘을 위해 만들었습니다. (#602)
- **GIF 배경 제거**: 애니메이션 GIF, WebP, APNG에서 프레임별로 배경을 지워 투명한 애니메이션으로 돌려받습니다. (#502)

- **새로 저장 또는 덮어쓰기.** 이전에는 라이브러리 파일을 편집하면 원본이 조용히 대체되었습니다. 이제 편집할 때마다 선택할 수 있으며 기본값은 원본을 유지합니다. (#564, #577)

- **어디서나 입력해서 검색.** 대시보드나 홈페이지에서 입력을 시작하면 검색창으로 들어갑니다. (#644)
- **문서와 웹사이트를 21개 언어로 제공**: 앱 인터페이스에 이어 문서 사이트, 랜딩 페이지, API 레퍼런스가 모두 번역되었습니다. 새로운 저사양 배포 가이드는 Raspberry Pi와 2 GB 머신을 다룹니다. (#548)
- **더 분명한 도구 이름**: 모호했던 이름 18개에 구분어를 붙여, "Compress"가 "Compress Image"가 되었습니다. 도구 ID와 라우트는 그대로이므로 북마크한 주소는 깨지지 않습니다. (#520)

### 개선 사항 {#v2-2-0-improvements}

- **인터페이스 전반의 WCAG AA 대비**: 선명한 주황색은 채우기에만 쓰고 텍스트와 레이블은 접근성을 갖춘 잉크 토큰을 쓰도록 팔레트를 조정했으며, 57개 포커스 표시기가 모두 비텍스트 대비 3:1 기준을 충족합니다. (#567, #574)
- **업스케일과 배경 제거가 멈춘 것처럼 보이지 않습니다**: 진행률 표시줄이 30%에서 멈추지 않고 추론 중에도 진행되며, 두 도구 모두 CPU만 있는 호스트는 훨씬 느리다고 경고합니다. (#605, #608)
- **시간 초과 메시지가 실제 원인을 알려 주며**, 업로드 탓으로 돌리는 대신 CPU만 있는 호스트를 고려합니다. (#596)
- **SnapOtter가 시작할 때 Postgres와 Redis를 기다립니다.** 충돌하며 재시작하는 대신 기다리며, Compose와 올인원 이미지 모두 마찬가지입니다. Proxmox LXC 설치는 이전에 76번 재시작되었습니다. (#537, #595)
- **다운로드가 리버스 프록시를 견딥니다**: SnapOtter가 nginx와 호환 프록시에 파일 응답을 버퍼링하지 말라고 요청합니다. 셀프 호스팅 다운로드가 시작만 하고 끝나지 않는 일반적인 원인이 이것입니다. (#604, #607)
- **PDF 압축이 목표 용량에 가깝게 맞춰지며**, 목표에 도달할 수 없으면 솔직하게 알려 줍니다. (#522)
- **앱 셸이 동적 뷰포트에 맞춰 크기가 조절되므로** 모바일 도구 컨트롤에 계속 접근할 수 있습니다. (#559)
- **오디오 변환에 샘플링 레이트 설정이 추가되었습니다.** (#561)
- **관리자가 최소 비밀번호 길이를 완화할 수 있습니다.** 신뢰하는 LAN 인스턴스에서는 1까지 낮출 수 있습니다. (#543)
- **MFA를 사용자가 직접 관리합니다.** 정책으로 인한 잠금이 해소되었고, OIDC 또는 SAML 로그인은 완전히 막히는 대신 실제 MFA 챌린지를 받습니다. (#531, #536)
- **단순한 `Error: Error`가 이제 원인을 알려 줍니다.** Sharp 인코딩 실패, AI 사이드카 종료, JSON이 아닌 문서 사이드카 출력, 배경 제거 실패는 모두 이전에 이유가 지워진 채 전달되었습니다. (#532, #534, #535, #538, #612)
- **도움말 대화상자가 번역되었습니다.** 단축키 레이블과 시작 안내 텍스트가 하드코딩된 영어였고, 완성된 번역은 21개 로케일 파일 모두에서 쓰이지 않은 채 남아 있었습니다. (#647)

### 업그레이드 참고 사항 {#v2-2-0-upgrade-notes}

마이그레이션할 것은 없지만 기본값 두 가지가 바뀌었습니다.

- **`TRUST_PROXY`의 기본값이 이제 `loopback,linklocal,uniquelocal`입니다.** 모든 피어를 신뢰하던 방식에서 바뀌었습니다. Docker 브리지와 Compose 네트워크는 이 범위 안에 있으므로 대부분의 구성은 변경할 필요가 없습니다. 리버스 프록시가 공개 주소에서 SnapOtter에 접속한다면 `TRUST_PROXY`을 명시적으로 설정하세요. 그렇지 않으면 속도 제한과 감사 로그가 모든 요청을 프록시의 것으로 기록합니다.
- **`MAX_AI_JOBS_PER_USER`의 기본값은 5입니다.** 사용자당 처리 중인 단일 파일 AI 작업 수입니다. 일괄 및 파이프라인 AI 실행에는 여전히 제한이 없습니다.

새로운 선택적 설정: `DB_STARTUP_TIMEOUT_MS`, `SUBPROCESS_MEMORY_LIMIT_MB`(기본적으로 꺼짐), `GIF_BG_MAX_FRAMES`입니다.

## v2.0.0 {#v2-0-0}

SnapOtter 2.0은 이미지 툴킷을 전체 파일 처리 제품군으로 확장합니다. 이미지, 비디오, 오디오, PDF, 파일의 다섯 가지 모달리티에 걸친 200개 이상의 도구를 제공하며, Postgres 17과 Redis 기반 작업 큐로 다시 만들었고, 한 줄 `docker run`로 시작할 수 있습니다. 메이저 릴리스이므로 1.x에서 업그레이드하기 전에 호환성 변경 사항을 읽어 보세요.

### 새로운 기능 {#new-features}

- **새로운 도구 모달리티 네 가지**: 비디오, 오디오, PDF, 파일이 이미지에 합류하여 카탈로그가 200개 이상의 도구로 늘었습니다.
- **내구성 있는 백그라운드 작업**: Redis 기반 큐(BullMQ)가 모든 도구를 추적되는 작업으로 실행하며 SSE로 실시간 진행률을 제공합니다.
- **올인원 단일 컨테이너 모드**: `docker run` 한 번으로 임베디드 Postgres와 Redis를 갖춘 완전한 인스턴스가 시작됩니다.
- **필요할 때 설치하는 AI 번들**: 배경 제거, OCR, 전사, 업스케일, 얼굴 감지 및 보정, 지우개, 컬러화, 사진 복원을 UI에서 설치합니다. GPU 가속은 프레임워크별로 감지됩니다.
- **PDF 서명**: 서명을 그리거나 입력하거나 업로드하여 브라우저에서 PDF에 배치합니다.
- **자동화**: 도구를 연결하는 시각적 파이프라인 빌더이며 기본 제공 템플릿이 아홉 개 있습니다.
- **원클릭 변환 프리셋 83개**: JPG-to-PNG, MP4-to-GIF 같은 전용 변환기이며 퍼지 검색을 지원합니다.
- **레이어 기반 이미지 편집기**: `/editor`에 있는 Konva 기반 편집기이며 브러시, 도형, 조정, 필터, 커브를 지원합니다.
- **파일 라이브러리**: 어떤 결과든 저장해서 다른 도구의 입력으로 재사용할 수 있습니다.
- 고정 도구, 캔버스 내 확대/축소 및 이동, 21개 언어, 엔터프라이즈 기능(OIDC/SSO, SAML, SCIM, S3 스토리지, 도구별 권한, 감사 내보내기, 분산 추적)도 포함됩니다.

### 개선 사항 {#improvements}

- 실행 중인 프로세스 취소. (#137)
- LibRaw를 통한 전체 해상도 RAW 디코딩(DNG 포함). (#289)
- 비루트 및 외부 UID 배포(TrueNAS, Unraid, OpenShift, PUID/PGID). (#230, #127)
- 정확한 AI 설치 감지와 강화된 설치 흐름. (#214, #352)
- 개인정보 보호 강화: 제3자로의 자동 외부 전송이 없으며, 선택적인 엄격한 오프라인 모드가 있습니다.
- 분석을 꺼도 항상 켜져 있는 피드백 버튼.

### 버그 수정 {#bug-fixes}

- `RATE_LIMIT_PER_MIN=0`이 다시 도구 라우트의 속도 제한을 해제합니다. (#271)
- Docker 이미지 안의 AI 가상 환경 경로를 복구했습니다. (#390)
- sharp 0.35.2 이상 호환. (#362)
- 이미지 편집기 레이아웃 수정: 눈금자, 채우기 동작, 사이드바, 캔버스 크기. (#258, #259)
- 이탈리아어 번역을 완성했습니다. (#231, #206, #425)
- 오디오 normalize와 loudnorm이 원본 샘플링 레이트를 유지합니다.
- SSRF 강화: 숫자형 IPv6 CIDR 매칭과 확장된 URL 사전 검사. (#287)
- 생성된 PDF에 Producer로 SnapOtter가 기록됩니다.
- mediapipe가 Python 3.13과 Debian 13에서 설치됩니다.

### 호환성 변경 사항 {#breaking-changes}

2.0은 내장 SQLite 데이터베이스를 Postgres 17로 교체하고 작업 큐용으로 Redis 8을 추가합니다. 1.x 데이터는 첫 부팅 때 자동으로 마이그레이션되지만 컨테이너 스택이 바뀌었으므로, 먼저 `/data` 볼륨 전체를 백업하세요(1.x는 SQLite를 WAL 모드로 실행하므로, 커밋된 데이터가 보통 `snapotter.db-wal`에 있습니다). 그런 다음 단일 컨테이너 이미지(임베디드 Postgres와 Redis, root 전용)나 Compose 스택(앱에 Postgres 17과 Redis 8) 중 하나를 선택하세요. [마이그레이션 가이드](https://github.com/snapotter-hq/SnapOtter/blob/main/MIGRATING.md)와 [업그레이드 가이드](/ko/guide/upgrading)를 참고하세요.

- **밈 생성기** - opentype.js로 텍스트를 렌더링하는 기본 제공 템플릿 100개가 있습니다. 직접 이미지를 업로드해도 됩니다.
- **Beautify** - 스크린샷을 넣으면 다듬어진 이미지가 나옵니다. 기기 프레임(macOS, Windows, 브라우저), 그림자, 그라디언트, 소셜 미디어 프리셋을 지원합니다.
- **색맹 시뮬레이션** - 1형 색각(protanopia), 2형 색각(deuteranopia), 3형 색각(tritanopia) 등 색각 이상에서 이미지가 어떻게 보이는지 미리 봅니다.
- **PNG 투명도 수정** - 가짜 투명 PNG를 감지하고 BiRefNet HR-matting으로 고칩니다. LaMa 인페인팅으로 워터마크를 제거하는 기능은 선택 사항입니다.
- **AI 캔버스 확장** - AI 채우기로 이미지 경계를 넓힙니다. GPU 시간을 얼마나 쓸지에 따라 세 가지 품질 단계(빠름, 균형, 품질)가 있습니다.
- **20개 언어** - 아랍어, 중국어(간체/번체), 체코어, 네덜란드어, 프랑스어, 독일어, 힌디어, 인도네시아어, 이탈리아어, 일본어, 한국어, 폴란드어, 포르투갈어, 러시아어, 스페인어, 태국어, 터키어, 우크라이나어, 베트남어. 아랍어는 RTL이 동작합니다.
- **URL 가져오기** - 드롭존에 URL을 붙여넣거나 목록에서 일괄 가져옵니다. SSRF 보호가 적용된 서버 측 가져오기입니다.
- **여러 파일 지우개** - 여러 이미지에 걸쳐 지우기 마스크를 그리고 한 번에 모두 처리합니다. 획은 이미지별로 유지됩니다.
- **파이프라인 가져오기/내보내기** - 도구 체인을 JSON으로 저장하고 다른 사람과 공유합니다.
- exiftool을 통한 **카메라 RAW 형식 17종 추가**, 그리고 QOI, JP2, EPS, DDS, CUR, DPX, FITS, PPM/PGM/PBM, SVGZ, APNG 입력을 지원합니다. BMP, ICO, JP2, QOI의 새 출력 코덱도 추가되었습니다. AVIF, TIFF, GIF, JXL, PSD 내보내기는 이전에 유실된 브랜치에서 복구했습니다.

### 개선 사항 {#improvements-2}

- **이미지 보정** - 이전 파이프라인을 CLAHE + 정규화 + 감마로 교체했습니다. 새로운 심층 보정 토글은 AI 모델을 사용해 더 강한 결과를 냅니다.
- **사진 복원** - 스크래치 감지를 8방향 Otsu 필터링으로 다시 작성했습니다. LaMa 인페인팅이 이제 원본 해상도에서 실행됩니다.
- **모든 곳에서 특수 형식 지원** - OCR, image-to-PDF, 파비콘 생성기, 합성, 스티치, 벡터화가 이제 HEIC, RAW, PSD를 모두 디코딩합니다.
- **압축** - 목표 용량 허용 오차를 5%에서 1%로 좁혔습니다. 목표 용량이 기본 모드입니다. 증감 버튼과 KB/MB 단위 선택기를 추가했습니다.
- **Sentry 정리** - 조치할 수 없는 이벤트 644건을 걸러 냈습니다. 실제 오류는 이제 제대로 처리됩니다.
- **GPU 감지** - CUDA는 있지만 nvidia-smi가 없는 컨테이너에 대한 진단을 개선했습니다.
- **인증 비활성화 모드** - 익명 사용자가 관리자 역할로 DB에 시드됩니다. API 키, 파이프라인, 사용자 파일이 더 이상 FK 제약 조건 때문에 깨지지 않습니다.
- 단위, 통합, E2E에 걸쳐 **2,705개 이상의 새 테스트**를 추가했습니다.

### 버그 수정 {#bug-fixes-3}

- CPU에서의 업스케일이 NAS 장비와 저전력 하드웨어에서 더 이상 시간 초과되지 않습니다.
- QR 코드 로고가 더 이상 미리보기를 영구적으로 사라지게 하지 않습니다.
- 세로로 긴 인물 이미지의 자르기 오버플로를 고쳤습니다.
- 알파가 있는 TIFF 파일은 손상된 결과를 만드는 대신 PNG 출력을 올바르게 강제합니다.
- HDR/EXR 디코딩이 CLAHE 전에 8비트로 변환되어 디코딩 실패가 해결되었습니다.
- 얼굴 랜드마크 입력 버퍼가 Python 사이드카로 보내기 전에 PNG로 변환되어 충돌이 해결되었습니다.
- 중복 찾기가 혼합 형식 일괄 작업과 네트워크 오류를 처리합니다.
- Beautify 미리보기가 실시간으로 업데이트됩니다.
- 스티치와 벡터화에 진행률 표시줄을 추가했습니다.
- SVG-to-raster가 SVGZ를 처리합니다.
- 퍼센트 인코딩된 X-File-Results 헤더로 비 ASCII 파일 이름을 고쳤습니다.
