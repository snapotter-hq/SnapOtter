# 設定 {#configuration}

すべての設定は環境変数を通じて行います。各変数には妥当なデフォルト値があるため、SnapOtter は何も設定しなくてもそのまま動作します。

## 環境変数 {#environment-variables}

### サーバー {#server}

| 変数 | デフォルト | 説明 |
|---|---|---|
| `PORT` | `1349` | サーバーがリッスンするポート。 |
| `HOST` | `0.0.0.0` | サーバーが待ち受ける IP アドレスです。ブリッジネットワーク（`docker run` と Compose のデフォルト）では `0.0.0.0`（または `::`）のままにしてください。そうしないと公開ポートが機能しなくなります。ネイティブインストールやホストネットワーク上のコンテナでは、`127.0.0.1` にすると API がネットワークに公開されません。リモートアクセスには前段にリバースプロキシを置いてください。[組み込みモード](#embedded-mode)は起動チェックが `127.0.0.1` を呼び出すため、`0.0.0.0`、`::` または `127.0.0.1` でのみ動作します。それ以外のアドレス（`::1` を含む）では、コンテナは起動済みと見なされず、後でクラッシュするとサーバーを再起動する代わりにコンテナが停止します。IP アドレスではない値（`localhost` を含む）を指定すると、起動時にサーバーが停止します。 |
| `BASE_PATH` | (空) | 公開デプロイ用のパス（例: `/snapotter`）。空または `/` の場合、ドメインのルートで配信されます。実行時に適用されるため、イメージの再ビルドは不要です。 |
| `RATE_LIMIT_PER_MIN` | `1000` | IP ごとの 1 分あたりの最大リクエスト数。レート制限を無効にするには 0 に設定します。 |
| `API_KEYS_RATE_LIMIT_PER_MIN` | `30` | API キー管理エンドポイント（一覧、作成、失効）への IP ごとの 1 分あたりの最大リクエスト数。ツール呼び出しに使用中のキーは影響を受けません。無制限の値はありません。`0` にするとそれらのエンドポイントへのすべてのリクエストが拒否されます。 |
| `CORS_ORIGIN` | (空) | CORS で許可するオリジンのカンマ区切りリスト。空の場合は同一オリジンのみ。 |
| `LOG_LEVEL` | `info` | ログの詳細度。`fatal`、`error`、`warn`、`info`、`debug`、`trace` のいずれか。 |
| `TRUST_PROXY` | `loopback,linklocal,uniquelocal` | `X-Forwarded-For` でクライアント IP を設定できるピアを指定します。デフォルトはプライベートネットワークのピアだけを信じるため、Docker ネットワークや LAN 上のリバースプロキシは信頼され、公開クライアントが偽装したヘッダーは信頼されません。公開アドレスで自分が管理するプロキシを前段に置いている場合にのみ `true` に設定してください。 |
| `SNAPOTTER_ANALYTICS_DEFAULT` | （未設定） | 初回起動時の分析に関する質問に前もって答えるため、誰にも質問されません。未設定の場合、新しいインスタンスは管理者に質問し、回答があるまで何も送信しません。`off` では「Anonymous Product Analytics」をオフにした状態で、`on` ではオンにした状態で起動します。この変数は、まだ誰もこの設定を選んでいない間だけ設定値を埋めます。管理者またはこの変数によって設定が一度保存されると、変数を変更しても何も起きません。管理者は引き続き Settings > System > Privacy で変更できます。 |

### 認証 {#authentication}

以下の 2 つのブール値は `true` と `false` のみを受け付けます。`1`、`yes`、`on` などそれ以外の値は検証に失敗し、サーバーはリッスンを開始する前に終了します。

| 変数 | デフォルト | 説明 |
|---|---|---|
| `AUTH_ENABLED` | `true` | ログインを必須にします。アカウントをまったく持たずに実行するには `false` に設定します。その場合はすべてのリクエストに admin 権限が与えられるため、信頼できるネットワークに限定してください。 |
| `DEFAULT_USERNAME` | `admin` | 初期 admin アカウントのユーザー名。初回起動時のみ使用されます。 |
| `DEFAULT_PASSWORD` | `admin` | 初期 admin アカウントのパスワード。初回ログイン後に変更してください。 |
| `MAX_USERS` | `0` (無制限) | 登録済みユーザーアカウントの最大数。無制限にするには 0 に設定します。 |
| `SESSION_DURATION_HOURS` | `168` | ログインセッションの有効期間（時間単位、デフォルトは 7 日）。 |
| `SKIP_MUST_CHANGE_PASSWORD` | `false` | 初回ログイン時の強制パスワード変更プロンプトをスキップするには `true` に設定します。 |
| `LOGIN_ATTEMPT_LIMIT` | `30` | IP ごとの 1 分あたりの最大ログインリクエスト数。それ以降の試行には、その 1 分が経過するまで `429` が返されます。1 つのユーザー名に対する失敗の繰り返しは、通常は先に `LOGIN_THROTTLE_MAX_FAILURES` に達します。管理者は Settings > System で上書きできます。無制限の値はありません。`0` にするとすべてのログインが拒否されます。ソースからのビルドは 10 で始まります。 |
| `LOGIN_THROTTLE_MAX_FAILURES` | `10` | 1 つのユーザー名が `LOGIN_THROTTLE_WINDOW_S` の間に許容されるパスワードログインの失敗回数です。超えると、どの IP からでもそのユーザー名への以降の試行には `429` が返されます。最も古い失敗がウィンドウから外れるにつれて、再び通るようになります。0 に設定するとスロットルが無効になります。 |
| `LOGIN_THROTTLE_WINDOW_S` | `900` | そのウィンドウの長さ（秒単位）。1 以上である必要があり、0 ではサーバーが起動を拒否します。 |

### ストレージ {#storage}

| 変数 | デフォルト | 説明 |
|---|---|---|
| `STORAGE_MODE` | `local` | `local` または `s3`。S3 と MinIO には s3_storage 機能を含むライセンスに加えて、以下の `S3_*` 変数が必要です。 |
| `DATABASE_URL` | `postgres://snapotter:snapotter@localhost:5432/snapotter` | PostgreSQL 接続文字列であり、すべてのリクエストが処理される接続です。2.3.0 以降では `DATABASE_MIGRATION_URL` も設定すると、こちらはアプリのテーブルに対する DML のみを持つ最小権限のランタイムロールになります。Compose スタックではこれを自身の `postgres` サービスに向けます。組み込みモードにするには、（`REDIS_URL` と併せて）未設定のままにします。 |
| `DATABASE_MIGRATION_URL` | (空) | 特権接続で、起動時にのみマイグレーションの実行とランタイムロールへの権限付与に使用され、最初のリクエストの前に切断されます。空のままにすると SnapOtter は単一ロールで動作し、`DATABASE_URL` が両方の役割を担います。[最小権限ロール](/ja/guide/database#least-privilege-roles) を参照してください。 |
| `REDIS_URL` | `redis://localhost:6379` | Redis 接続文字列（BullMQ ジョブキューに使用）。Compose ではこれを自身の `redis` サービスに向けます。 |
| `WORKSPACE_PATH` | `./tmp/workspace` | 処理中の一時ファイル用ディレクトリ。自動的にクリーンアップされます。イメージでは `/tmp/workspace` が設定されます。 |
| `FILES_STORAGE_PATH` | `./data/files` | 永続的なユーザーファイル（アップロードした画像、保存した結果）用ディレクトリ。イメージでは `/data/files` が設定されます。 |
| `MAX_STORAGE_PER_USER_MB` | `5000` | 各ユーザーが Files ライブラリに保持できる量の上限（メガバイト単位）。上限を超える保存は、使用量と上限値を示して拒否されます。ユーザーに設定されたクォータがある場合はそちらが優先されます。無制限にするには 0 に設定します。 |

### S3 オブジェクトストレージ {#s3-object-storage}

`STORAGE_MODE=s3` のときにのみ読み取られます。必須の 3 つのうちどれか 1 つでも欠けていると起動は失敗し、設定し忘れた変数名が表示されます。

| 変数 | デフォルト | 説明 |
|---|---|---|
| `S3_BUCKET` | (空) | アップロードと出力を保持するバケット。必須。 |
| `S3_ACCESS_KEY_ID` | (空) | アクセスキー。必須。コンテナ内では、代わりに `S3_ACCESS_KEY_ID_FILE` でマウントすることもできます。 |
| `S3_SECRET_ACCESS_KEY` | (空) | シークレットキー。必須。同じファイル方式が使えます: `S3_SECRET_ACCESS_KEY_FILE`。 |
| `S3_REGION` | `us-east-1` | バケットのリージョン。 |
| `S3_ENDPOINT` | (空) | MinIO、R2、Backblaze など S3 互換ストア向けのカスタムエンドポイント。空の場合は AWS を指します。 |
| `S3_FORCE_PATH_STYLE` | `false` | MinIO のように、仮想ホスト形式ではなく `endpoint/bucket/key` を必要とするものでは `true` に設定します。 |
| `S3_PREFIX` | (空) | キーのプレフィックス。1 つのバケットで複数のインスタンスを扱えるようになります。 |

### 保存データの暗号化 {#encryption-at-rest}

| 変数 | デフォルト | 説明 |
|---|---|---|
| `DATA_ENCRYPTION_KEY` | (空) | 64 文字の 16 進数（32 バイト）。データベースに保存された機密設定を暗号化します。64 文字の 16 進数でないものは起動時に拒否されます。 |
| `DATA_ENCRYPTION_KEY_PREVIOUS` | (空) | ローテーションで置き換える前のキー。形式は同じです。ローテーション中は両方を設定して既存の行を復号できるようにし、その後こちらを削除します。 |

### 組み込みモード {#embedded-mode}

`DATABASE_URL` も `REDIS_URL` も指定せずにイメージを実行すると、コンテナ内で独自の PostgreSQL 17 と Redis を起動し、ループバックにバインドして、すべてのデータを `/data` ボリューム上に置きます。これにより、クイックスタート、ホームラボ、1.x からのアップグレード向けに、ワンコマンドの `docker run` 体験が復活します。これは利便性のための手段であり、本番デプロイではありません。本番環境では、PostgreSQL と Redis を分離した 3 コンテナの Compose スタックを実行してください。組み込みモードはコンテナを root として実行する必要があり、任意 UID のランタイム（OpenShift、Kubernetes `runAsNonRoot`）とは互換性がありません。その場合は Compose を使用してください。

| 変数 | デフォルト | 説明 |
|---|---|---|
| `EMBEDDED` | `auto` | `DATABASE_URL` と `REDIS_URL` の両方が未設定の場合に自動で有効になります。無効にするには `0` に設定します（その場合、外部の `DATABASE_URL`/`REDIS_URL` が設定されていなければ、アプリはコンテナ内データベースを黙って起動する代わりに即座に失敗します）。 |
| `REDIS_MAXMEMORY` | `512mb` | 組み込み Redis のメモリ上限（組み込みモードのみ）。Raspberry Pi のようなメモリ制約のあるホストでは下げてください。 |
| `EMBEDDED_PG_PORT` | `5432` | 組み込みの PostgreSQL が使うループバックポートです（組み込みモードのみ）。`--network host` のように、5432 がすでに使われているネットワークをコンテナが共有している場合にのみ変更してください。PostgreSQL はホストネットワーク上で特権ポートにバインドできない非特権ユーザーとして動作するため、この値は `EMBEDDED_REDIS_PORT` と異なり、かつ 1023 より大きくなければなりません。 |
| `EMBEDDED_REDIS_PORT` | `6379` | 同上で、組み込みの Redis 用です。Redis も非特権ユーザーとして動作します。 |
| `EMBEDDED_DB_PASSWORDS` | （空） | `1` に設定すると、次回の起動時に組み込みの PostgreSQL のロールと Redis 用のランダムなパスワードを生成し、`/data/.embedded-db-secrets` に保存します。以降、TCP でのログインにはこれらのパスワードが必要になります。2.3.0 以降で初めて作成されたボリュームでは、PostgreSQL のスーパーユーザーは TCP 経由で一切ログインできません。それより古いボリュームではデータベースの所有者がスーパーユーザーであり、それを守るのはそのパスワードです。`--network host` のように他のプログラムがコンテナのネットワークを共有する場合は、常にこの変数を使ってください。この設定はそのボリュームでは有効なままです。この変数を未設定に戻してもパスワードは毎回の起動で使われ、`/data/.embedded-db-secrets` を削除しても新しいパスワードが作られるだけで、変数が未設定の場合は起動が失敗します。これらのファイルのいずれかが破損してコンテナが起動しない場合は、`docker run --rm -v <volume>:/data --entrypoint rm snapotter/snapotter:<your tag> -r /data/.embedded-db-secrets/<name>` でそのファイルを削除し、コンテナを再度起動してください。次回の起動時に新しいファイルが作られます。この変数は `1`、`0` または空を受け付け、それ以外の値では起動が停止します。 |
| `EMBEDDED_REDIS_TIMEOUT_S` | `180` | 組み込み Redis が `PING` に応答するまで起動時に待機する秒数。タイムアウトすると、ハングする代わりにコンテナが停止し、理由をログに記録します。1 から 999999 までの整数で、無制限の値はありません。永久に待ち続けることが、この上限を設けている理由そのものだからです。遅いホストで引っかかる場合にのみ引き上げてください。 |
| `EMBEDDED_POSTGRES_TIMEOUT_S` | `600` | 組み込み PostgreSQL についても同様です。計測は初回起動の `initdb` 完了後に始まるため、初回のデータベース作成ではなく、サーバー起動とクラッシュリカバリを対象とします。 |

1.x からのアップグレード: 古い `snapotter.db` をボリューム内の `/data/snapotter.db` に配置すると、組み込みモードが初回起動時にそれを組み込み PostgreSQL へインポートします。インポートは一度だけ実行され、以降の起動ではスキップされます。

テレメトリに関する注記: 組み込みモードは、他の設定と同様にイメージの分析デフォルトを継承します。公開イメージは分析を送信できますが、新しいインスタンスはまず管理者に質問し、回答があるまで何も送信しません。無効にするには、「いいえ」と答えるか、`--build-arg SNAPOTTER_ANALYTICS=off` でビルドするか、最初の起動前に `SNAPOTTER_ANALYTICS_DEFAULT=off` を設定するか、アプリ内の admin オプトアウトを使用してください。

### 処理制限 {#processing-limits}

| 変数 | デフォルト | 説明 |
|---|---|---|
| `MAX_UPLOAD_SIZE_MB` | `0` (無制限) | アップロードあたりの最大ファイルサイズ（メガバイト単位）。無制限にするには 0 に設定します。公開イメージは `0` で出荷されます。ソースからのビルドは 100 で始まります。 |
| `MAX_BATCH_SIZE` | `0` (無制限) | 単一バッチリクエスト内の最大ファイル数。無制限にするには 0 に設定します。公開イメージは `0` で出荷されます。ソースからのビルドは 100 で始まります。 |
| `CONCURRENT_JOBS` | `0` (自動) | 並列実行されるバッチジョブの数。利用可能な CPU コア数に基づいて自動検出するには 0 に設定します。 |
| `MAX_MEGAPIXELS` | `0` (無制限) | 許可される最大画像解像度（メガピクセル単位）。無制限にするには 0 に設定します。 |
| `MAX_CPU_UPSCALE_MP` | `4` | GPU のないホストで AI アップスケーリングが受け付ける最大の入力サイズ（メガピクセル単位）。アップスケール後の出力もこの値の 16 倍（デフォルトでは 64 MP）に制限されるため、拡大率が高いと入力の上限はさらに下がります。それより大きな画像は、アップスケーリングの前に収まるよう縮小されます。その結果が元の画像より大きくならない場合は、代わりにリクエストが拒否されます。Lanczos は入力の上限は適用されませんが、出力の上限は適用されます。制限なしにするには 0 に設定しますが、多くの RAM が必要です。RealESRGAN は内部で常に 4 倍のバッファを作成します。 |
| `MAX_WORKSPACE_SIZE_GB` | `0` (無制限) | ワークスペース内のアップロードと保存済み結果の合計サイズの上限（GB 単位）。上限を超えると、`FILE_MAX_AGE_HOURS` の後にファイルが期限切れになるまで、アップロードとツールのリクエストには 503 が返されます。無制限にするには 0 に設定します。ローカルストレージでは、ディスクの空き容量が 0.5 GB を下回ると 503 で書き込みが拒否されます。公開イメージは `0` で出荷されます。ソースからのビルドは 10 で始まります。 |
| `MAX_WORKER_THREADS` | `0` (自動) | 画像処理の最大ワーカースレッド数。利用可能な CPU コア数に基づいて自動検出するには 0 に設定します。 |
| `PROCESSING_TIMEOUT_S` | `0` (制限なし) | AI ツールを実行する Python サイドカーへの各呼び出しのタイムアウト（秒）です。0 に設定すると制限なしになります。画像、PDF、メディアのジョブには上限を設けません。それは `JOB_TIMEOUT_FAST_S` と `JOB_TIMEOUT_LONG_S` が担います。 |
| `AI_SIDECAR_IDLE_TIMEOUT` | `600` | Python AI サイドカーと高精度 OCR ランタイムがアイドル状態のまま待機し、終了してメモリを解放する（ウォーム状態でそれぞれ約 1.3 GB と 0.7 GB）までの秒数です。どちらも次のリクエストで再び起動するため、アイドル終了後の最初の AI 呼び出しでは、ライブラリの起動コストとして数秒かかります。0 に設定すると実行し続けます。デフォルト値は `AI_SESSION_IDLE_TIMEOUT` と同じなので、読み込まれたモデルがその設定より早く破棄されることはありません。`AI_SESSION_IDLE_TIMEOUT` を引き上げる場合は、この値も合わせて引き上げてください。 |
| `AI_SESSION_IDLE_TIMEOUT` | `0` (自動) | 読み込まれた AI モデルが最後の使用後にサイドカーにキャッシュされたままになる秒数です。自動の場合は 600 です。Python サイドカーが読み取り、サイドカーは `AI_SIDECAR_IDLE_TIMEOUT` の後に終了する際にキャッシュ済みのモデルもすべて破棄します。 |
| `AI_SESSION_CACHE_BYTES` | `0` (自動) | キャッシュする AI モデルのメモリ予算（バイト単位）。自動の場合は GPU メモリの 40% で、CPU のみのホストではキャッシュは一切行われません。CPU ホストで RAM にモデルをキャッシュするには設定してください。GPU ホストでキャッシュを無効にするには 1 に設定します。Python サイドカーが読み取ります。 |
| `MAX_AI_JOBS_PER_USER` | `5` | 1 人のユーザーが同時にキュー待ちまたは実行中にできる単一ファイルの AI ジョブ数。それを超えると、1 つが完了するまで `429` が返されます。AI プールは一度に 1 つのジョブを実行するため、1 人のユーザーがプールを占有するのを防ぎます。バッチとパイプラインの AI 実行はカウントされません。無制限にするには 0 に設定します。 |
| `JOB_TIMEOUT_FAST_S` | `120` | 高速プール（画像およびドキュメントツール）での 1 つのジョブの期限（秒）です。それより長く実行されたジョブはタイムアウトエラーで失敗します。0 に設定すると制限なしになります。 |
| `JOB_TIMEOUT_LONG_S` | `7200` | ロングプール（AI およびメディアツールと、長時間実行としてマークされたすべてのツール）での 1 つのジョブの期限（秒）です。0 に設定すると制限なしになります。Balanced と Best の PDF OCR は、ページ数に応じて自身の期限を最大 6 時間まで延長する（1 ページあたりそれぞれ 2 分と 5 分）ため、大きな PDF のためにこの値を引き上げる必要はありません。 |
| `SYNC_WAIT_MS` | `8000` | API が待機をやめ、SSE で追跡するためのジョブ ID とともに `202` を返すまでに、ツールのリクエストがジョブを待つ時間（ミリ秒）です。ジョブ自体は停止しません。0 に設定すると、ジョブにどれだけ時間がかかっても待ちます。 |
| `MAX_PIPELINE_STEPS` | `20` | パイプライン内の最大ステップ数。制限なしにするには 0 に設定します。 |
| `MAX_PIPELINE_STEP_PIXELS` | `67108864` | パイプラインの 1 ステップが要求できる最大の出力サイズで、幅 × 高さのピクセル数です（デフォルトは 8192 x 8192）。設定がそれ以上を要求するステップは、パイプラインの実行前に拒否されます。制限なしにするには 0 に設定します。 |
| `MAX_CANVAS_PIXELS` | `0` (制限なし) | 出力画像の最大キャンバスサイズ（ピクセル単位）。制限なしにするには 0 に設定します。 |
| `MAX_SVG_SIZE_MB` | `50` | サニタイズ前に受け付ける SVG の最大サイズ（メガバイト単位）。ここでの `0` は前後の行とは動作が異なります。上限を引き上げるのではなく、解析前のサイズ上限そのものを取り除くため、この項目は設定したままにしてください。 |
| `MAX_PDF_PAGES` | `0` (無制限) | PDF-to-image 変換での PDF の最大ページ数。無制限にするには 0 に設定します。 |
| `MAX_VIDEO_DURATION_S` | `0` (無制限) | 動画ツールが受け付ける最長の動画の長さ（秒単位）。これより長いファイルは処理前に拒否され、エラーに動画の長さと上限値が含まれます。無制限にするには 0 に設定します。 |
| `MAX_AUDIO_DURATION_S` | `0` (無制限) | 同様に、音声ツールの上限です。 |
| `MAX_VIDEO_BITRATE_KBPS` | `0` (無制限) | 動画ツールが受け付ける全体の最大ビットレート（キロビット毎秒）。無制限にするには 0 に設定します。 |
| `PREVIEW_TIMEOUT_S` | `300` | 動画または音声ファイルのブラウザ内プレビュークリップを 1 つエンコードする際の制限時間（秒単位）。ドキュメントのプレビューには代わりに `LIBREOFFICE_TIMEOUT_S` が使われます。制限なしにするには 0 に設定します。 |
| `LIBREOFFICE_TIMEOUT_S` | `120` | LibreOffice の 1 回の変換（Word、Excel、PowerPoint から PDF への変換、ドキュメントコンバーター、ドキュメントのプレビュー）の制限時間（秒単位）。ここでは `0` は無制限を意味せず、120 にフォールバックします。 |
| `GIF_BG_MAX_FRAMES` | `150` | Remove GIF Background が 1 つのアニメーションで受け付ける最大フレーム数。これより長いアニメーションには、フレーム数を示す `400` が返されます。フレーム数の制限をなくすには 0 に設定します。別途ピクセル予算は引き続き適用されます。 |
| `SUBPROCESS_MEMORY_LIMIT_MB` | `0` (オフ) | メディアエンジンとドキュメントエンジンが起動する ffmpeg、Ghostscript、qpdf、LibreOffice、pandoc、pdfcpu の各プロセスに対するアドレス空間の上限（メガバイト単位）。アップロードされた画像を読み取るデコーダー（ImageMagick、exiftool、およびその ffmpeg フォールバック）は制限されません。上限を超えたプロセスは、コンテナ全体をメモリ不足キラーに追い込む代わりに強制終了されます。制限するのは常駐メモリではなく仮想メモリなので、余裕を持たせてください。AI サイドカーは制限されません。0 に設定すると無効になり、コンテナのメモリ制限に任せます。 |
| `MAX_SETTINGS_PAYLOAD_KB` | `64` | ツールのリクエストに含めることができる `settings` フィールドの最大サイズ（キロバイト、UTF-8 のバイト数で計算）です。上限を超えるリクエストには `400` が返されます。0 に設定すると制限なしになります。実際のツール設定は 64 KB よりはるかに小さいため、クライアントが異常に大きな設定を送信する場合にのみこの値を引き上げてください。 |
| `MAX_SUBTITLE_SIZE_MB` | `1` | Burn Subtitles と Embed Subtitles が受け付ける字幕ファイル（`.srt`、`.vtt`、`.ass`）の最大サイズ（メガバイト単位）。これより大きいファイルには、ファイルサイズと上限値を示す `400` が返されます。制限なしにするには 0 に設定します。長編映画の字幕ファイルは通常 1 MB をはるかに下回ります。 |
| `MAX_METADATA_TAG_LENGTH` | `10000` | Edit Metadata が 1 つのタグ（アーティスト、説明、キーワードなど）に書き込める最長の値（文字数）。これより長い値には、タグ名と上限値を示す `400` が返されます。制限なしにするには 0 に設定します。長いキャプションや説明を保存する場合は引き上げてください。タグの値は `MAX_SETTINGS_PAYLOAD_KB` とオペレーティングシステムの引数ごとの上限（Linux では 128 KB）にも収まる必要があります。 |

### エンジン {#engines}

SnapOtter は各処理バイナリをコンテナ内の `$PATH` から探すため、独自にビルドしたものを持ち込まない限り、これらは空のままで問題ありません。

| 変数 | デフォルト | 説明 |
|---|---|---|
| `FFMPEG_PATH` | （空） | ビデオおよびオーディオ ツールが使用する `ffmpeg` バイナリのパス。 |
| `FFPROBE_PATH` | （空） | メディア ファイルを処理前に読み取る `ffprobe` のパス。`FFMPEG_PATH` と同じビルドを指定してください。 |
| `QPDF_PATH` | （空） | `qpdf` のパス。PDF ツールと、アップロードされた PDF のチェックに使用されます。 |
| `SOFFICE_PATH` | （空） | LibreOffice の `soffice` のパス。オフィス ドキュメントの変換に使用されます。 |
| `PDFCPU_PATH` | （空） | `pdfcpu` のパス。一部の PDF ツールで使用されます。 |
| `GS_PATH` | （空） | PDF ツールと PDF OCR が使用する Ghostscript の `gs` へのパスです。 |
| `PANDOC_PATH` | （空） | ドキュメント変換で使用する `pandoc` へのパスです。 |
| `SNAPOTTER_FONT_FILE` | （空） | 動画に描画するテキスト（字幕の焼き込み、動画の透かし）に使うフォントファイルです。空の場合は、イメージが最初に見つけたフォントを使用します。 |
| `SNAPOTTER_FONT_FAMILY` | （空） | `SNAPOTTER_FONT_FILE` のフォントファミリー名です。空の場合は `Sans` になります。 |
| `SNAPOTTER_HW_ACCEL` | （空） | ハードウェア ビデオ エンコーダーのファミリー。`nvenc` または `vaapi`。空の場合はソフトウェア エンコードになります。 |

`SNAPOTTER_HW_ACCEL` には、そのエンコーダー ファミリーでビルドされた ffmpeg が必要ですが、イメージ内の ffmpeg はどちらも備えていません。イメージ同梱のバイナリを使う場合、この設定はソフトウェア エンコードにフォールバックし、起動ログでその旨が通知されます。使用するには、独自にビルドした ffmpeg をマウントし、`FFMPEG_PATH` と `FFPROBE_PATH` をそこに向け、コンテナに GPU デバイスを渡してください。`nvenc` の場合はさらに `NVIDIA_DRIVER_CAPABILITIES=compute,utility,video` を設定します。イメージは `compute,utility` のみを要求するため、`video` がないと NVIDIA ランタイムがエンコード ライブラリをマウントせず、エンコーダーは一覧に表示されるもののすべてのエンコードが失敗します。存在しない、または実行できないパスを上書きした場合も起動ログで通知され、パスを修正するか設定を解除するまで、そのバイナリを必要とするすべてのジョブが失敗します。

公開されている Compose ファイルはこれらすべてを `.env` から渡すため、そこで設定すれば十分です。

### クリーンアップ {#cleanup}

| 変数 | デフォルト | 説明 |
|---|---|---|
| `FILE_MAX_AGE_HOURS` | `72` | 未保存の処理結果（生のアップロードとツール出力）を自動削除するまで保持する期間。Files ライブラリに明示的に保存したファイルは影響を受けず、削除するまで保持されます。 |
| `CLEANUP_INTERVAL_MINUTES` | `60` | クリーンアップジョブを実行する頻度。 |
| `JOBS_RETENTION_DAYS` | `30` | 完了したジョブ記録（完了、失敗、キャンセル済み）が、6 時間ごとに実行される保持期間の清掃で削除されるまで保持される日数。管理者は Settings > System で上書きできます。リーガルホールド中のユーザーとチームの記録は保持されます。永久に保持するには 0 に設定します。 |
| `AUDIT_RETENTION_DAYS` | `0` (無期限) | 監査ログのエントリが保持される日数。上書きとリーガルホールドのルールは同じです。改ざん耐性のある監査ログが有効な間は何も削除されません。永久に保持するには 0 に設定します。 |
| `SNAPOTTER_LICENSE_KEY` | (空) | SAML、SCIM、S3 ストレージなどのエンタープライズ機能を有効にするライセンスキーです。起動時に読み込まれるため、変更後は再起動してください。無効または期限切れのキーは警告をログに記録し、サーバーはそれらの機能なしで動作します。コンテナでは、代わりに `SNAPOTTER_LICENSE_KEY_FILE` を使ってマウントすることもできます（[Docker シークレット](/guide/security#docker-secrets)を参照）。 |

## Docker の例 {#docker-example}

```yaml
services:
  SnapOtter:
    image: snapotter/snapotter:latest
    ports:
      - "1349:1349"
    volumes:
      - SnapOtter-data:/data
      - SnapOtter-workspace:/tmp/workspace
    environment:
      - AUTH_ENABLED=true
      - DEFAULT_USERNAME=admin
      - DEFAULT_PASSWORD=changeme
      - DATABASE_URL=postgres://snapotter:snapotter@postgres:5432/snapotter
      - REDIS_URL=redis://redis:6379
      - MAX_UPLOAD_SIZE_MB=200
      - CONCURRENT_JOBS=4
      - FILE_MAX_AGE_HOURS=12
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    restart: unless-stopped

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: snapotter
      POSTGRES_PASSWORD: snapotter     # 非ローカル展開の場合はこれを変更します
      POSTGRES_DB: snapotter
    volumes:
      - SnapOtter-pgdata:/var/lib/postgresql/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U snapotter -d snapotter"]
      interval: 10s
      timeout: 5s
      retries: 12

  redis:
    image: redis:8-alpine
    command: ["redis-server", "--maxmemory-policy", "noeviction", "--appendonly", "yes"]
    volumes:
      - SnapOtter-redisdata:/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 12

volumes:
  SnapOtter-data:
  SnapOtter-workspace:
  SnapOtter-pgdata:
  SnapOtter-redisdata:
```

## ボリューム {#volumes}

Docker Compose スタックは 4 つのボリュームを使用します:

- `/data` (app) - AI モデル、Python venv、ユーザーファイル。アップロードしたファイルとインストール済みの AI バンドルを再起動を越えて保持するには、これをマウントします。
- `/tmp/workspace` (app) - 処理中のファイルの一時ストレージ。エフェメラルでも構いませんが、マウントするとコンテナの書き込み可能レイヤーが埋まるのを防げます。
- `SnapOtter-pgdata` (postgres) - PostgreSQL データディレクトリ。すべてのリレーショナルデータ（ユーザー、設定、パイプライン、ジョブ、監査ログ）を保持します。`pg_dump` またはボリュームスナップショットでバックアップします。
- `SnapOtter-redisdata` (redis) - 永続的なジョブキュー用の Redis 追記専用ファイル。
